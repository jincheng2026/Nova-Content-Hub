## 2. 已明确的用户约束

- 技术继续 Electron、React、TypeScript、Semi UI，应用自己的名称与图标按根 AGENTS。源包的 shadcn 视觉／固定旧写入口不覆盖当前用户授权。
- 打开用户明确选中的第二大脑即可加载；不要求另起旧 8878/8879/8977 服务、不依赖作者 HOME、launchd 或默认 CWD 猜库。
- 知识库是用户全部新内容产出的根；每条内容稳定 T 编号，同篇产出集中。应用、插件、机器偏好、凭据与内容根分开。
- 原有操作、人工决策、Skill 业务步骤与产物语义保持；原来确定性的操作继续确定性执行，AI 环节才跳转。
- Nova 雷达、封面模板、图片预览、受控采集、文件冲突保护、任务回执和整库备份继续保留。
- 所有范围内的方法与完整依赖由对应助手插件安装；源码存在、安装成功、任务已打开、生成成功、人工采纳、实际发布分别验收。

## 3. 产品与数据设计

### 原创作页作为第一交付纵切

先接续 T020/T029/T026/T044 的实际历史状态。完整解析 `jc-doc` 的 info、items、稳定 ID、order、refs、baseline、mine、note、ai_state、suggestions、refnote、skeleton、steps、recorded、final、pubslot/pubcand 以及未知扩展。保留原件所有权与实际当前入口。

用户随后明确补充：原创作 HTML 的生成格式、功能划分和协作交互必须保持一致。优先复用已取得的受信原创作模板和界面逻辑，隔离执行并适配到 Electron 的受控保存桥；不执行用户旧 HTML 内任意脚本，不用通用 React 写稿页替代原功能。React/Semi 承担桌面外壳和应用交互。首次生成、重新生成、追加建议与结构修改都须遵守原生成器的身份、人工字段保留和拒绝隐式删除协议。更新 JSON 块之外的原文件字节与未知字段有明确保全验收。普通 Markdown、旧对照页、报告各走匹配的 adapter。原位字段和修订信息必须能被原格式读回；不能把仅抽出人工正文的新 Markdown 当完整迁移。

当前稿来自已确认用途、内容卡／草稿总览、文档内身份和实际未合并修改的联合判定。有矛盾时保留候选与诊断，必要时一次明确选择；不用最新 mtime、目录“已做”或相同 T 号跨库拼接。

### 协作动作与阶段门

- 对照／通读共用同一文档；通读选字意见回到原段落。
- 建议支持依据、先改建议再采纳、拒绝、部分采纳；人工正文不由 AI 候选直接覆盖。
- 用户意见、AI 已处理的意见版本、逐项回复分别保存；意见改变后原回复保留，重新待处理。
- 拆解保留 AI 自拆和作者先拆两条路；后者先隐藏 AI 分析，读回作者拆解，再给差异并等待裁决。
- 叙事确认、关键段确认、完整稿、锁稿、实际录完稿、包装选择、实际发布分别有证据与版本关系。复用原聊天，不要求用户在两处重复确认。
- 允许从想法、已有参考、已确认叙事、现成稿、只改一句等不同起点进入。原方法有确认门时保留，不能用一次最终整套 submit 代替途中协作。
- 十一个元问题按原阶段渐进补充；未到的写“还没到”，不做开篇大问卷。

### 选题与标题分开

新 `xindao-xuanti.zip` 五个实文件与当前插件内容逐字节相同；问题在业务接续，而非是否复制文件。依其原合同：资料输入 → 选题菜单／推荐理由 → 用户选定 → 受控建 T 卡和内容目录。未定题时不提前制造正式内容；最终发布标题留在后续包装。已有内容可带版本化引用进入选题，不改其正文。

保留该 Skill 的直接对话文字模式；工作台任务模式才使用固定请求与回执。所有真实落库与外部调用继续受显式库绑定、权限、预算和 CAS 保护。

### 唯一业务真源

选择、批注、建议裁决、叙事确认、当前包装等是正式业务数据，要在所选库内可读回、可备份；不能只在“可重建投影”中保存。任务不可变证据包保留其职责。移除并重建声明为投影的缓存后，正式业务状态必须仍在。

新库把所需正式视频档案、判断／案例和方法引用放在根内的明确位置并登记 SOURCE_OF_TRUTH；旧库外的正式视频档案、判断库、方法论先按实际来源显式关联或导入，保留历史路径用途。`06_发布复盘` 的分析副本不升级冒充发布事实，manifest v2 的 `work_id` 与 `content_id` 不混用。原媒体只引用，不因统一目录复制／移动录屏原片。

## 4. Skill 迁移原则

保留完整主体、references、schema、合法必要素材和校验职责；逐项登记“原规则 → 新数据类型／动作 → 保存 → 助手读回 → 验收”。路径、服务提供方、执行权限和宿主适配单列，不通过十几行摘要重写方法。

依据来源区分当前、历史、草稿、停用、仅引用未取得；处理版本矛盾，不按文件数量或时间戳激活全部方法。需要用户明确调用的教程 Skill 有显式入口；源包提案／尚未执行决定不自动升级为硬门槛。新库不把锦成个人经历自动当新用户事实。

评论研究保留 L4／L3／快卡、完整材料对账、引文统计同源、对象分析隔离及 findings 冻结，然后才加本人应用建议。研究、拆解、共创、反馈的独立合同分别保留，不合成一个泛化任务。

## 5. 验收与实施顺序

1. 原件版本、真实 UI 操作与业务字段／写入所有权对照冻结。
2. T020/T029/T026/T044 无损读取及一处受控修改、回读、重开、冲突的完整纵切。原建议裁决、回复、参考、录完稿和包装必须逐项对账。
3. 同源双视图和逐句反馈；阶段协作；xindao 建题；完整方法与研究评论合同并行接入。
4. 包装、Nova 封面／雷达、发布档案与反馈回流，原导航分区和辅助入口落地。
5. 从原库中途状态继续和空库从资料走到复盘两条旅程验收，再统一回归与最终 Mac arm64 安装交付。

其他平台／架构仍按根 AGENTS 单列构建、安装、原生运行状态；缺少环境不宣布通过。首轮精力集中在第一条真实业务纵切，不再以大批技术测试通过替代产品完成。
