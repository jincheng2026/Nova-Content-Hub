如果你刚刚安装好 Codex，你会发现，如果它修改错内容之后，你想让它还原，就没有办法完美回溯，因为如果没有记录，Codex 会默认重新再做一遍，那么结果就可能不是完全一样的。那有没有什么办法呢？今天 Fred 就给你分享一个小白必备的后悔药。

那什么是 Git 呢？你不用把它想得太复杂，它不是一个程序员专属的命令行，你可以把它理解为一个项目的存档系统，就跟游戏一样，打 Boss 之前要先存档，如果打输了，就回到上一个存档点。Git 的作用，就是在每次大改之前留一个可以回溯的点。

那怎么使用呢？我们确实不需要记很复杂的命令行。如果是本地使用，有三种场景：第一种，就是在项目初始存档的时候，你可以说，帮我本地初始化 Git 一下；那么如果本地初始化以后，但是有进度更新，你可以跟他说，帮我本地保存下进度，本次修改是什么什么；但如果你想回溯到之前的版本，你就跟他说，帮我回溯到之前那个版本。你看看是不是很简单，就跟玩游戏一样，对吧？

那我们简单用视频演示一下，比如说我已经做了一个 HTML 代办清单，长这个样子，但我跟他说，帮我本地 Git 一下，他就能够快速地帮我本地创建一个 Git 的清单，这个也就是 Git 的一个存档点。如果我继续让他修一个功能，他修改完了之后，我跟他说，帮我本地保存一下，然后他就能够快速地帮你保存，然后给你新增一个存档点，是不是跟玩游戏一样？然后如果让他帮我再增加一个其他的功能，但这个功能我不满意，我跟他说，帮我回滚到上一个版本，他就能够快速完美地复刻回到上一个版本去。所以说很简单，对吧？就是让他把以前的记忆拆分好，现在可以直接回到某个固定的版本。

很多人说 Git 跟 GitHub 有什么关系，是不是一样呢？你可以理解，GitHub 是全球最大的开源代码社区，它有个很重要的功能，就是云端存档，也就是你把项目同步上去之后，可以换电脑继续，或者跟其他人一起协作。怎么用呢？同样也没有那么复杂，三种场景：如果你要初始化存档的时候，你就说，帮我初始化推送到 GitHub 上去；如果你已经有 GitHub 存档之后，你就跟他说，帮我保存一下进度，推到（GitHub 上）；如果你要拉存档点，你就拉之前的存档点。

我们也简单用视频演示一下，比如说我们进入到 GitHub 的首页，点击这个 Home，我们就可以点击这个 New，也就是创建新的仓库，这里面去输入你对应的仓库名字。有一个注意点，就是如果你创建的是私密的项目，你要选 Private；如果创建的是公开的，那你可以选 Public。然后这个时候你就去点击这个创建仓库，创建完毕之后呢，它会快速给你出现两个东西，一个是 HTTPS，你不需要记住，你就可以把这个 SSH 复制，发给 Codex，说帮我把项目推送到这个仓库里面去，然后他就能够快速地推送进去。如果跟他说，帮我推送最新版本，然后他也能够更新，这一点就跟刚刚本地更新是一样的，就会有一个存档点。然后同理，我让他去修改一个功能，如果不满意的话，我跟他说，帮我把 GitHub 上面的项目拉下来，覆盖本地的项目，也就是跟刚刚回溯是一样的，它也能够快速完美地回溯。所以说很简单，对吧？

但当然也要注意，像 Git 不是所有东西都要存进去，比如说一些 API Key、一些其他的影视资源，或者一些大视频、或者临时的文件，那就不要上传，占空间。
