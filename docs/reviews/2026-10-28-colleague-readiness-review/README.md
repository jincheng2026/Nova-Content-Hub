## 与锦成原工作台的逐类对比

原工作台以 T 编号内容、原位资料、外部助手共创和原创作页为主线，许多环节刻意等待作者判断。不是点击一个按钮就把研究到发布全部自动跑完。Nova 新增了桌面安装、固定请求、受控工具、任务回执、来源身份和统一管理；这些是增强，但需要保持原业务方法的具体交付和确认方式。

| 范围 | 当前已有实现 | 差异／当前判断 |
|---|---|---|
| 打开第二大脑 | 原位扫描、运行投影、显式来源映射、库身份检查 | 是特定结构兼容，不是任意 Obsidian 库都能直接打开；无 `.workbench` 的库要求识别到 00个人背景/04选题/05草稿等目录 |
| 原数据与当前稿 | 稳定 T 身份、来源选择、冲突不猜最新文件、原创作页与 Markdown 分流 | 当前已比旧差异报告完整；未知格式只读、富媒体/双链仍不完整 |
| 个人定位与选题 | 定位访谈、候选与正式内容分离、原卡与状态保留 | 需验证真实助手逐问确认及选题质量；设置 profile 不等于完整原定位资料 |
| 对标与调研 | 真实服务代理、冻结预算、报告与来源、账号关系 | 页面管理生命周期与 linked 附件有缺口；不同平台不能套用同一个成功结论 |
| 素材入库与转写 | 原媒体、转写、校正、时码、去重和正式目录流程 | 严格媒体验收仍未成为正式入库的前置条件 |
| 拆解 | AI拆解和作者先拆分支、作者输入与精确版本确认 | 入口与门禁存在；真实助手是否按原片逐段完整拆、是否先隐藏AI答案尚需端到端质检 |
| 叙事／重点段／完整稿 | 显式教程分支有叙事和重点段确认，普通写作不强套教程 | 必要状态检查存在于特定 creation 命令，但通用结果验收未绑定同一交付语义 |
| 原创作页改稿 | 原HTML/`jc-doc`、字段保存、逐句建议、作者区域保护、评论与确认 | 不是简单正文编辑器替代原页；材料阶段及回执适配仍有断点 |
| 包装与封面 | 标题/封面字/简介候选、人工选用、模板/样张/人物与封面生成任务 | 字段和候选闭环有实现；生图由宿主能力承担，不能用 Qwen 转写成功证明封面或写作成功 |
| 录制／发布／复盘 | 录完与已发布分离、真实发布档案、快照与复盘、知识候选 | 需要真实平台、账号和作者确认；不能把分析副本或任务终态当真实已发布 |
| 分页／搜索／阅读 | 当前新增多集合分页，末项、筛选和动作ID专项通过 | 当前源码的新分页不在已冻结0.5.2包中；搜索语义、图片和恢复问题不由分页测试覆盖 |

## Skills、工具和本地 Qwen 实际如何分工

当前主链可概括为：工作台按钮 → 固定任务和来源版本 → 指定宿主/配套插件 → 读取请求与业务 skill → claim/进度 → 受控命令与服务 → 等待作者或权限 → 提交产物回执 → 人工采用/验收。原会话不可可靠定位时明确提示手动继续，不能靠猜会话实现“自动续写”。

- **业务方法**：插件包含原方法说明和适配规则，部分关键约束有代码门禁；更多写作方法、逐段深读和质量要求仍依赖宿主真的读 skill 并执行。
- **研究采集**：通过受控服务、冻结对象和请求预算执行，不是安装即拥有 TikHub Key；评论另有授权开关。
- **本地 Qwen**：Qwen3-ASR 做语音识别。词级/分段时码另有 faster-whisper 对齐路径。它不是这套工作台的研究、写稿、推理或生图模型。
- **文本与图像生成**：由已登录的外部助手及相应能力承担；工作台 `model` 服务目前显式禁用，不能说已经内置本地写作大模型。
- **执行证明**：协议单测证明 claim、两种等待、取消、失败、重试、提交回执等代码行为，不证明某个真实宿主会话已经逐个调用了所有方法工具，也不证明产物质量等同锦成本人。

因此，回答“是不是都是按照他的逻辑逐步使用 skills 和工具”：**目前是有明确映射、关键部分可执行，但不是所有环节已完整闭合，更没有最终安装版真实会话的全链路证据。**

## 用户未点名但必须补充的验收

1. **库适配与容量**：标准/旧版/自定义目录、空库、大库、Unicode/空格/长路径；扫描上限20,000条（含遍历条目）、层深24、普通文本8MiB等边界。超限应明确报错并帮助定位，不能声称任意数据全部渲染。
2. **数据守恒**：打开前后原件清单与哈希、关联数量、T号稳定、不将工作稿/分析副本冒充原真源；新增、编辑、删除、恢复后重启复核。
3. **双向手改与冲突**：Obsidian/Finder外部编辑、移动、删除；旧页面保存必须拒绝覆盖且能在保留输入的情况下恢复操作。
4. **备份和跨机迁移**：完整库、未知文件、隐藏运行记录和原方法一起保全；验证恢复到独立目录，旧路径/设备身份/密钥不能假装仍有效；中断任务明确恢复或重试。
5. **断电/进程退出/磁盘满**：已保存与待核验状态明确区分；重试不重复创建记录、调用服务、扣费或发布事实。
6. **成本与外部失败**：超时但服务可能已收费、预算耗尽、取消后的迟到结果、未知费用阻塞；不能只测正常返回。
7. **跨库与多实例**：切库后旧异步结果、旧图片能力、旧报告链接、旧任务不得污染新库；同一库被多进程打开时的写锁、冲突与提示。
8. **实际UI**：每个主页面、长文/多图、空态/加载/错误、960×680和1280×860、键盘焦点/Esc、脏输入、系统减少动画；按设计规则ID记录截图。CSS或虚拟hook断言不能替代。
9. **资料渲染安全与完整性并存**：相对图片、双链和附件可用必须建立在固定来源范围内；继续拒绝越界路径、脚本、未知远程加载，不能为“全渲染”改成任意文件浏览器。
10. **生成质量**：至少固定一个真实内容样本，逐段核原片/转写/时码/拆解/作者确认/稿件/包装/发布档案/复盘；检查事实来源、未证实事项、作者手改和不同阶段停点。结构正确不等于观点与表达质量达标。
