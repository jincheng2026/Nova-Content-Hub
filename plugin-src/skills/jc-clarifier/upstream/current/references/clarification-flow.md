# 澄清流程

## 总原则

一起想，不是审问。

不要把字段表甩给用户。先根据用户原话做合理猜测，再让用户确认、修正或排除。

## 第一轮：合并追问

一次问 2-4 个关键问题，用选项降低回答成本。

通用结构：

```text
我先帮你把需求压清楚。几个问题一起问：

1. 这是什么场景？我先猜几个方向：
   A. ____
   B. ____
   C. ____
   D. 其他

2. 结果给谁用？
   A. 自己看
   B. 团队/同事看
   C. 客户/学员/读者看
   D. 其他

3. 你最想让 AI 帮你完成什么？
   A. 理清方向
   B. 生成方案
   C. 写成提示词
   D. 判断怎么选

可以直接回「A B C」，也可以补几句。
```

问题设计：

- 识别优先于描述：给选项，不让用户从零描述。
- 排除优先于构造：问「不希望结果是什么样」。
- 场景拉回具体：问结果给谁用、什么时候用、用完做什么。

## 智能跳过

如果用户第一句话已经能回答这三个问题，可以跳过合并追问：

- 谁要做什么？
- 为什么要做？
- 做到什么程度算够？

跳过后直接显隐分离。

## 第二轮：边界探测

根据第一轮回答补最少的问题。

优先问：

- 你不希望结果是什么样？
- 哪些已经确定，不需要讨论？
- 做到什么程度算够？
- 这个结果会拿去做什么？
- 有哪些素材、限制或禁区？

如果第一轮信息已经足够，跳过这一轮。

## 第三轮：显隐分离

把信息分成「已清晰」和「待确认」。

```text
我整理一下：

已清晰：
- 场景：____
- 目标：____
- 约束：____

还需要确认：
- ____。我猜是 ____，你看对不对？
- ____。我建议先按 ____ 处理，除非你有别的要求。

确认一下，或者说「够了」我继续判断信息是否足够出提示词。
```

## 第四轮：镜像确认

用一句话复述用户真正要解决的问题。

```text
所以你真正要解决的问题是：

「____」

对吗？确认后我帮你转成提示词。
```

镜像确认前不能输出方案、成品或最终提示词。

镜像确认后也不能执行原任务。先过信息充分性闸门；信息足够才输出给新聊天使用的提示词。

## 第五轮：信息充分性闸门

镜像确认不等于信息充分。

用户确认真实问题后，必须判断：当前信息是否足以让下一个 AI 产出可用结果。

高依赖背景信息的任务必须过闸门，典型包括：

- 定位、个人 IP、品牌策略
- 商业方案、产品包装、销售转化
- 内容系统、课程设计、复杂决策
- 需要调用用户经历、案例、客户反馈、素材库或风格资产的任务

检查这些信息是否已经足够：

- 产品或服务是否具体
- 目标用户是否具体
- 已有素材、案例或可信证据是否明确
- 输出使用场景、渠道或交付对象是否明确
- 成功标准是否明确
- 风格、禁区、不要什么是否明确

判断规则：

- 如果缺失信息会改变最终方案方向，继续追问 1-3 个关键问题。
- 如果缺失信息只影响丰富度，可以输出提示词，但必须写入 `Missing Inputs` 和 `Assumptions`。
- 如果用户明确不想继续回答，输出提示词时要求执行 AI 先补问，不允许编造经历、案例、客户反馈或产品承诺。

可用话术：

```text
方向确认了，但现在直接出会空。还缺几个会影响结果质量的信息：

1. ____
2. ____
3. ____

你可以粗略回答；如果懒得补，我会把这些写成素材缺口，让执行 AI 先追问，不编经历。
```

## 用户回答「不知道」

不要继续逼问。改用排除法或保守默认值。

可用话术：

```text
没关系，反过来想：你最不想要的结果是什么？
```

```text
我先给一个保守默认：____。如果你没有反对，我就按这个写进提示词。
```

## 多需求混在一起

先拆，再建议优先级。

```text
你刚才说的其实是三件事：
1. ____
2. ____
3. ____

我建议先搞定第 __ 件，因为它决定后面两件怎么做。先按这个来？
```

## 用户给大量素材但没有需求

不要直接处理素材。先提炼任务。

```text
你给了很多背景，但还没说最终要 AI 做什么。我先帮你猜：
你现在可能想解决的是 ____，希望 AI 输出 ____。对吗？
```
