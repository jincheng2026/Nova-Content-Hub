# 锦成内容生产闭环模板

画内容生产闭环、AI 自媒体工作流总控、Skill 迭代关系图时读。结构来自 2026-09-13 与 Codex 的一整天讨论，锦成逐条确认过。画同类图先套这个结构，再按当次任务增删，不从零猜。

## 主线（居中，从上到下）

```text
目标：做内容为了赚钱（广告 / 知识产品 / 服务），单条内容任务是触达、建立信任、产生行动
→ 调研对标（当前参考 + 历史参考）
→ 拆解对标
→ 生成内容（AI 初稿 → 人工改稿 → 锁稿）
→ 发布前预测（判断框：哪里好、哪里有风险、完播和转化预期）
→ 人工发布（多次实践后最稳定的方式，不 AI 化）
→ 发布后复盘（12 小时数据 → 后续点赞收藏评论进线转化 → 定位问题）
→ 迭代对应 Skill → 下一轮
```

复盘一定拆成「发布前预测」和「发布后验证」两段，汇合到「定位问题」。这是锦成明确要求保留的三个节点，不能合并成一个「复盘」。

## 左侧栏：过程数据沉淀

调研记录和参考清单、拆解判断和改稿过程、最终逐字稿和标题简介封面、发布记录和复盘结论。用虚线连到对应主线节点。它是底部资产轨道的另一种放法，用户说「放左边」就放左边。

## 右侧栏：谁负责（四类，不只分人和 AI）

- 人：选题是否值得做、观点是否成立、是否像自己、是否锁稿、发布。
- AI 和 Skill：调研、转写、拆解、生成备选、数据分析。
- 工作台：承载、阅读、检索、批注、对比、整理版本。它不产出内容，不进主线。
- 平台：播放、完播、互动、进线、转化，是外部结果。

## 下方栏：复盘之后迭代什么

从「定位问题」分出短分支：调研 Skill、拆解 Skill、生成内容 Skill、复盘 Skill。主要迭代对象是 Skill；工作台只是让人看得更方便，很少是迭代对象。分支不必连回主线，下一轮从主线顶部自然开始。

## 密度与版本

- 主图每节点最多两行短标签；具体数据指标、Skill 全名、所有文件类型、所有修改版本不进主图。
- 需要「最大而全」时另建一版，用思维导图承载阶段展开：第一层是主线节点，第二层每个阶段固定五项：输入、AI 辅助、人的判断、产出、沉淀。
- 分享讲解版比自用版更简，评论讨论版把可能被讨论的点拆成独立节点。
- 三种线：主流程实线、沉淀虚线、回流绿线。多于三种就是密度过高。
