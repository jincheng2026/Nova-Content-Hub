| 语音识别 | 本地优先／仅本地／火山云端；本地模型状态与安装／下载进度；云端 ASR 凭据、资源 ID、使用状态 | 按任务冻结选项；本地优先不默认授权付费回退，云端处理须在设置中明确启用 |

密钥放库外的系统凭据存储或系统加密保护的应用配置，建立跨平台实现；不得落到内容库、备份、请求、URL、提示词、前端 localStorage 或发布资源。外部 Agent 通过受控采集／转写工具使用凭据，避免把完整 Key 注入普通对话和子进程命令行。库备份恢复后若本机凭据缺失，提示重新配置。

本聊天提供的 Key 仅作为用户已有凭据的上下文；本轮没有写入设置或验证有效性。开发时无需重复索要同一值，但不得在清单、日志或源码中回显。

### ASR 的最小可行选型

1. 已有可靠字幕可直接用，保留来源并标记复核状态；缺字幕才识别音频。
2. **Apple Silicon 首先评估复用同事已有 Qwen3-ASR-1.7B/MLX 路线**，以真实中文教程／口播片段确认质量、耗时、内存和时间码。0.6B 可作为资源较小的候选；不在无样本时承诺最佳识别率或固定模型体积。Qwen 官方列有 0.6B、1.7B 及独立对齐模型。[官方仓库，核对于 2026-10-26](https://github.com/QwenLM/Qwen3-ASR)
3. Intel Mac／Windows 的免费本地候选采用 **whisper.cpp** 做同样的短样本比较；官方列有跨平台与 CPU 支持。选择一个实际可交付的默认后端，不为首版同时维护多个未验证本地运行时。[官方仓库，核对于 2026-10-26](https://github.com/ggml-org/whisper.cpp)
4. **火山录音文件识别 2.0 作为可选云端后端**。官方文档列有语音服务的 `X-Api-Key` 和资源 ID；用户给出的方舟大模型 Key 不能在未验证前假定等同语音服务凭据／权限。设置中分开显示模型 Key 与 ASR 凭据状态，不因截图有试用额度就承诺长期免费。[官方接口说明，核对于 2026-10-26](https://docs.volcengine.com/docs/DoubaoVoice/LargemodelrecordingfilerecognitionstandardversionAPI?lang=zh)
5. 统一输出带时间码原稿，再由 skill＋Agent 完成术语纠错、断句及语义核对；纠错保留原句与修改依据，不把后续「优化表达」混成参考作者原话。改文后需要重新对齐或标明时间码精度，不能凭空补逐字时间。

TikHub 官方使用 Bearer Key 鉴权；接入时固定官方端点并去掉日志中的敏感头。价格／额度在接入和连接检查时核对，不从同事历史账本推定当前费用。[官方文档，核对于 2026-10-26](https://docs.tikhub.io/)

## 7. 工程落点与不返工约束

| 现有位置 | 本次复用／扩展 |
| --- | --- |
| `plugin-src/src/lib/file-library/`：`index.mjs`、`model-v5.mjs`、`backup.mjs`、`attempt-progress.mjs` | 复用锁、CAS、历史及事务；目前对象只有 workspace/collection/content/prompt/photo/template，新增类型须显式扩展 |
| `cover-jobs.mjs`、`template-jobs.mjs` | 参考请求／attempt／结果／回执规则；新增有限文本任务结果，不能把文本塞进图片提交协议 |
| `plugin-src/src/bridge/native-handoff.mjs` | 保持 launcher 行为，增加任务上下文与能力路由；可见输入、换行及长文本复制路径重新核对，不能仅带 36 字摘要就宣称已完整交接 |
| `workbench/src/main/assistant-runtime.mts`、`assistant-skill.mts` | 扩展能力注册、版本与完整性核验；继续使用原宿主适配 |
| `plugin-src/src/cli.mjs`、`content.mjs`、skills 与构建脚本 | 增加任务 context/claim/progress/submit 等入口和插件资源；`contract` 仍是原型校验，hooks 没有的宿主事件不虚构 |
| `workbench/src/shared/`、main boundary／worker／controller、preload、renderer client | 输入输出验证与 IPC 白名单逐层覆盖，renderer 不获得通用文件或 shell 权限 |
| `workbench/src/renderer/` 内容页、资料、设置、共用列表组件 | 扩现有页面与草稿保护；对标账号和报告使用同事习惯，沿用 Semi、PopupSelect 与本项目视觉规范 |

创作页优先保留模板、数据格式、指纹与用户稿保护的语义；同事 Python 服务只是复用候选，不能要求普通用户启动终端或依赖系统 Python。包内运行时、端口占用、回环监听、生命周期、请求认证、来源隔离、路径白名单和打包资源需一起解决。先确认保存规则与库锁如何协作，不允许两个服务各锁各的、同时修改同一稿件。

HTML 报告阅读器与可写创作页按不同权限处理：报告脚本可视化不获得 Node/IPC、凭据或任意本地网络能力；创作页的受控保存接口只接收本内容允许编辑的字段，复用 CAS 并阻止过期建议覆盖新稿。主进程验证资源、路径、媒体 URL 与导出目标，下载器也要限制重定向和访问地址。

## 8. 知识沉淀与费用从第一条任务开始记录

- **原始层**：采集响应、参考链接、媒体、原始转写，保留来源和采集时间；按引用与保留策略管理，不复制进每篇稿件。
- **内容层**：参考拆解、叙事、工作稿、创作页数据、候选、选定结果、改稿日志；沿同一 contentId／T 编号关联。
- **知识层**：可复用素材、已确认判断、方法与通用规则，能追到具体案例和用户采纳记录；AI 推断先放候选。
- **费用层**：请求 ID、端点、任务／attempt、估算与账单依据；工作台受控工具发起的模型请求保留实际返回的 usage，未返回的字段标未知。本地 ASR 标记无外部调用费用，硬件成本不虚报为 0。外部助手自身无法可信读取的 token／费用显示未知。

聊天中的否决、纠错与确认由 skill 主动登记为反馈，用户不用再填一遍表。用户未确认的经验不自动写成长期规则；不自动改源码、安装版 skills 或私人库。反馈汇总和技能更新是不同动作。

## 9. 开发与最后统一验收

按用户要求，不在每一项后跑整套 UI／跨平台回归。小批次执行相关类型／构建检查；新增非平凡的保存、迁移、凭据及任务边界保留小测试。每项登记「代码已落地／快速检查结果／待统一验收」，不提前写「完整可用」。

统一验收使用一套真实材料完整走通：

`设置凭据 → 新建调研 → 当前方式打开 Agent → 调研报告与账号入库 → 选题与参考 → 本地或云端转写 → 纠错与拆解 → 叙事与初稿 → 创作页用户修改 → AI 读回反馈 → 标题／封面／简介 → 发布素材与知识候选`。

必须覆盖：

- Codex 与 WorkBuddy 分别验证成功、等待用户、等待权限、恢复、失败、取消、重试、迟到结果、重复提交、继续原任务、切换助手；没有可靠会话标识不猜会话。
- 用户与 Agent 同时编辑、旧稿建议失效、保存冲突、应用退出重开、服务不可用、端口占用、任务中断、库升级和备份恢复。
- 凭据持久化但不回显／不进备份、预算拦截、鉴权失败、未知扣费、本地缺模型、云端未开通、媒体失效、空样本与缺失来源。
- 对照同事已安装版的账号卡、报告／创作页及导航习惯；UI 按 `Layout-01/02`、`Surface-03`、`Controls-01/02`、`Reading-02`、`Acceptance-01/02/03` 逐项留痕；本轮没有修改页面，也没有宣布新增 UI 验收通过。
- 包、安装后应用、配套插件的版本与平台按根 `AGENTS.md` 独立验收；Apple Silicon、Intel Mac、Windows x64 分开，Windows ARM 是否交付另列。暂不承诺缺少机器的平台已支持。

## 10. 保留但不阻塞核心链路的事项

会议明确暂不增加：X 收藏、私域客服／企微进线、运动、发布前评审页面及自动剪辑。保留现有人工发布与计划能力，自动社媒发布、充值代付、商业账号与登录权益系统不在本次核心开发中悄然扩展。

评论洞察是可配置可选功能，放在基础调研链路后；其他平台随后按真实端点和可验收能力接入。抖音为首个完整落地平台，不能因为 TikHub 提供某端点就宣称全平台产品能力已通过。

待补资料按局部影响处理：当前正式创作页版本／运行时差异影响精确复用；完整标题／简介／科普规则影响个性化质量；可发布知识库子集与第三方授权影响学生版种子；真实内容案例及各平台环境影响最终验收。其余模块继续实施，不整项等待所有资料齐全。
