## 1. 最终产品目标与边界

**安装应用并完成一次清楚的必要配置后，用户选中自己的第二大脑，能够按锦成原来的方式找材料、形成自己的观点、与助手逐段共创和手改、选定包装并制作封面，最后把逐字稿、标题、简介和封面保存回同一条内容。再次打开、换助手、更新应用或迁移电脑后仍可接续。**

主范围：调研对标、素材与选题支撑、拆解对标、本人观点与叙事、AI／人工反复改稿、标题／简介／封面文字、封面制作、最终资产保存。保留 Nova 爆款雷达、模板和已有受控助手能力。

排除 X 账号／收藏／专门 X 内容业务、私域、运动、dbskill。独立“创作知识”页沿用撤下决定；按需读取本人判断、案例与风格仍保留。拍摄剪辑、发布前预测、自动发布、12h／7d监测和商业转化复盘不作为本期主流程或完成门槛；已有文件与历史读取保留，不删除以便界面显得简单。

“使用体感一样”定义为**相同任务入口、相同协作动作、相同作者决定权、相同可读产物和顺畅续接**。技术栈仍是 Electron + React + TypeScript + Semi UI；不要求复制旧 Next/shadcn 技术，不复制旧 HOME、固定端口、自启服务或已有缺陷。使用方法和交互可等价，生成质量需样例评审，不承诺模型逐字输出或传播效果相同。

## 2. 三条必须分别通过的用户旅程

### J1 同事：安装后直接继续原内容

1. 在目标电脑安装对应架构的应用，正常启动；不需要项目源码、开发工具、手动 Node/Python 环境或旧工作台服务。
2. 选择自己的原始第二大脑，加载真实 T 内容、当前稿、参考和报告。读取不会覆盖作者 AGENTS／SOT、改写手稿或搬走素材。
3. 若原工作台使用库外资料，仅对确实缺失的账号、报告、提示词、VI、本人判断或媒体给出一次明确补充入口；缺一类资料不阻断无关功能，不把缺失称为空库。
4. 有旧 `.workbench` 绑定／设备身份时，识别“本人迁移的同一库”和“意外替换／不可信目录”；通过应用内明确迁移／重新绑定完成，保留冲突保护。不得让用户删除隐藏文件、改 JSON 或运行 CLI 来恢复使用。
5. 点击同一条内容“接着写”，进入真实当前页面；作者最后一笔修改写回原件，再到助手中读取最新状态。
6. 助手提出建议，作者采纳／拒绝；选标题、简介、封面字，生成和选图；未发布也能保存完整资产。
7. 关闭重开、更新应用、重启系统后仍定位到同一篇、同一采用版本。

### J2 学员：从空库做出第一条内容

1. 安装后选择“新建知识库”或“打开已有知识库”，不要求手工复制锦成私有库作为模板。
2. 新库有正确骨架、通用协作规则、真实可用导航和选题卡模板；不写入锦成的人生、口气、账号成果、人像或已发表内容作为学员事实。
3. 首次配置按需引导：选择助手、安装／启用匹配插件、登录宿主、配置本人所用服务。只呈现当前动作真正需要的项目；未配联网服务仍能读库、编辑和使用已有材料。
4. 可直接输入一个自主想法；也可选已提供资料先生成候选。自主想法不需要十条素材，候选未选定不占正式 T 编号。定位可渐进完成，不用先答长问卷。
5. 用户选普通共创、教程／口播或科普等适用方法；明确方法选择后遵循各自原合同。每一项面向学员显示为可用的能力必须实际可完成，不能只有 Skill 名称。
6. 形成首稿并生成原结构创作页；完成两轮手改与建议循环，再完成包装、封面和四资产保存。
7. 一次正常工作过程中无需填写 handoff UUID、复制目录路径、手工搬 JSON、重抄正文到另一系统，或在两个地方重复确认同一事实。

### J3 换电脑、升级与恢复

1. 备份或复制知识库到不同用户名、不同绝对路径／磁盘，使用应用内流程重新打开或迁移；同号跨库不自动合并。
2. 机器凭据与宿主登录按新机重新配置，业务内容、人工选择、批注和采用版本随库保留。
3. 外部媒体路径失效时可明确重新关联；不猜 HOME，不静默引用另一篇文件。
4. 应用升级和插件配套升级不让作者手改丢失；失败时有可恢复状态，卸载应用不删除知识库。
5. 若声称支持跨 OS 迁移，需要分别验证 Windows 路径、Unicode、空格、大小写／盘符、媒体和原生依赖；没有环境时只声明已验证的迁移范围。

## 4. 必须接通的数据与协作合同

### C1 同一内容、一个当前正文

- 用户显式选择的库身份 + 内容身份确定目标，T编号用于稳定业务关联；跨库同号不自动当同一篇。
- 当前权威来源按导航、原件用途、作者选择和未合并修改联合判定；不按 mtime 单独决定。
- jc-doc 是原创作页真源；Markdown当前稿走对应适配。普通 Nova 旧模型保留兼容，不把它变成原页旁边另一份可竞争正文。
- 原页稳定 ID、unknown 字段、作者mine/note/decision、录完稿及包装保全。AI提出建议不直接覆盖作者字段。

### C2 叙事、手改、建议与确认

- 本人观点来自实际原话和明确确认，AI整理与待确认内容分开保存。
- 教程的叙事／重点段门只适用于明确选择的方法；普通访谈素材包确认、已有稿续改各按自身合同。
- 作者先拆保留隐藏AI结果、差异对比、裁决、批注回读；不能只做一个文本框。
- 两轮修改需证明：作者改稿→AI读回最新版本→建议→人工采纳或拒绝→作者再改意见→重新待处理。
- 只有内容／版本实际改变，才使相应确认失效；不重复要求用户在聊天和桌面确认同一决定。

### C3 包装与封面唯一采用关系

- 定义统一的读取适配：从**当前权威原页**读标题、简介、封面文字和各自版本，提供给封面和最终资产操作；旧通用模型走旧模型适配。不要双向无条件同步两份可编辑正文／包装。
- 封面任务冻结 T身份、当前稿／包装版本、已确认文字、选中模板／样张、本人图片和生成参数。原文案改动后旧候选仍是旧版本，不能静默升级为当前最终封面。
- `jc-cover-design` 设计候选到现有cover任务继续复用固定契约；用户能在同篇自然接续，不用自行搬提示词和资产。实际生成仍需独立图片任务回执。
- 标题／简介／封面字可分别改选；封面图改选不会改逐字稿。已确认创作页分支应完整提供三种包装候选，不能漏简介。

### C4 最终四项资产独立收口

- 可读的最终逐字稿、标题、简介、封面文件在同一 T 内容关联；提供清楚的查看、复制／导出入口。
- 保存一次交接版本时记录实际来源版本和图片身份；四项要么完整确认成功，要么明确指出缺哪项／哪项未保存，不显示伪完成。
- 推荐实现为从当前真源生成**不可变交接快照及清单**，日常继续编辑仍在原真源。快照不是另一套独立编辑器；正文后来改变时旧快照保留并显示其版本，不自动更新已确认历史。
- 录完稿存在时可明确选择实际录完稿；不存在时只能称当前确认稿。不得把拍摄、发布链接或监测数据作为收口前置。
- 对已有封面可人工选用，无需为完成链路强制重新生图；图片、正文和清单能独立读取。

### C5 来源、迁移与权限

- 扫描仅限显式选库与关联来源；原资料作为数据读取，不执行其中任意脚本。
- 本人判断、市场候选、AI候选与最终采用各自留来源，不压平。
- 知识库承载正式业务内容和决定；应用/插件承载可信运行时；机器凭据不随内容库分发。
- 迁移需要显式操作时，用自然语言说明变化和保留内容，并在应用内完成。不能通过放宽所有根身份检查来实现“直接打开”。
- 删除可重建缓存后人工事实仍能恢复；正式配置、历史快照或待处理任务不应被误称缓存删掉。

## 6. 最终验收矩阵与证据格式

每条状态只能为：**通过／失败／待验／不支持／外部条件缺失**。不得用“有代码”“包已导入”“模拟通过”替代真实成功。

## 7. 平台与版本声明

以根 [AGENTS.md](../../AGENTS.md) 为交付权威，至少分别管理 `darwin-arm64`、`darwin-x64`、`win32-x64`；Windows ARM未纳入或未验证时明确标记。Apple Silicon先完成可以先交对应候选包，不意味着Intel/Windows也通过。

App最低OS、各功能最低OS、模型和原生依赖的实际支持范围分别列出。某平台ASR不可用时，只有经过验证的替代路径才能标可用；否则清楚说明该能力待支持，其他已支持功能仍可用。

“同事可用完整版”“学员体验可用”“学员受控开放”“全部承诺平台正式发行”分别有完成状态。**同事真实设备未验，不写同事设备通过；权益未接，不写学员解锁通过；签名／公证未完成，不写正式发行通过。** 完整目标继续推进，遇到缺环境或外部接口只报告具体缺口，不用改名掩盖。

## 8. 不应再发生的偏离

- 不再扩大成发布、商业转化和生活管理全功能平台。
- 不以大量Skill和按钮数量代替“作者能做完一篇”。
- 不把旧gap全部当现状重新开发，也不把新测试通过推广为所有功能完成。
- 不用只读HTML预览冒充可编辑创作页，不用恢复草稿冒充正式文件已保存。
- 不把撤下创作知识菜单做成删掉作者长期判断；不因打开某旧库就自动执行其中脚本。
- 不向学员默认分发锦成私人人像、账号数据、内容库、机器凭据和私有配置。源码包中为完整性保留的证据与实际可分发资源应单独列清；没有分发依据的资源不默认激活或随学员包暴露。
- 不要求普通用户安装开发环境、启动旧端口、修改配置代码或手工管理固定任务文件才能完成主流程。
- 不用修改auth开关、移除production阻断或填写公司名代替权益、功能、签名和原生验收。
