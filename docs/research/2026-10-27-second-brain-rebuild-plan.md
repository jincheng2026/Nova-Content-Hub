# 基于第二大脑和同事工作台的重构整体方案

日期：2026-10-27。状态：前版整体方案；交付范围、定位默认方法、内容目录及插件分发安排以 [完整交付计划](2026-10-27-local-workbench-delivery-plan.md) 为准。

目标：同事安装「自媒体工作台」，选择自己的第二大脑文件夹，已有内容能够进入对应页面，后续产出继续保存在这个知识库中；新用户创建同样结构的知识库。技术栈采用 Electron、React、TypeScript 和真实 Semi UI。

开发分支：`codex/second-brain-workbench-rebuild`，起点 `06d594ebf847f4afacf43a3a2a031ce4ca2e0d48`。原工作区已有未跟踪资料保持原状，不纳入本次方案变更。分支尚未推送。

## 1. 推荐的重构路径

以同事工作台的业务流程、文件关联和第二大脑组织方式为业务基线，逐模块重构；复用 Nova 已有的桌面边界、插件安装校验、固定任务协议、公共 Semi 控件及爆款雷达。最终形成一个桌面应用和一种知识库使用方式。

另外两条路径的取舍：直接包装同事原程序，会继续依赖 Next、本机双服务、launchd 和原作者固定目录，难以满足统一 Semi UI 与跨平台安装；把第二大脑一次性转入 Nova 旧库，会改变用户现有文件组织，增加两份内容与状态相互覆盖的风险。因此推荐原位兼容知识库、重构应用模块。

复用同事代码时逐模块保留适用的解析与业务规则，完成归属和依赖核对；UI 逐页改为 React、TypeScript、Semi，宿主服务和绝对路径改为应用现有平台适配能力。开发测试先使用保留相对路径的隔离副本，最终验收再检查用户指定的真实库及写入前后差异。

## 2. 已核实的架构条件

- 同事工作台 UI 是 Next 15、React 19、Radix/Tailwind；Electron 壳加载本机 8878/8879 服务，由 launchd 管理，当前分享说明仅面向 Apple Silicon Mac。
- 原工作台除第二大脑外，还读内容数据统计、视频项目、调研报告、提示词和视觉资料等库外来源；部分私域、X 收藏、媒体、凭据及其他模块没有完整打包。
- Nova 当前 `createLibrary` 要求空目录并建立 `内容库.json`、内容、模板等原模型，不能直接把用户已有 Vault 当作现有库打开。需要新增知识库适配能力，同时改通桌面和配套插件的存储入口。
- 第二大脑并非所有 Markdown 都是最终正文。例如导航指定部分 HTML 创作页为当前稿件，发布档案又可能在 Vault 外。不能按文件名、mtime 或目录位置自动推定当前版本及已发布事实。
- 第二大脑的 `AGENTS.md`、`SOURCE_OF_TRUTH.md` 与部分旧 Skill 存在不同阶段约定。它们用于核对用户当前工作流；资料里的脚本、私人路径和外部操作要求不会被自动执行。
- 同事版资料为 10 月 26 日快照，独立第二大脑来自 10 月 16 日交接包。分别识别、比较和验收；同名 T 编号不意味着两份内容字节或当前版本相同，不能直接合并或以包日期覆盖。

## 3. 知识库与应用职责

### 3.1 知识库保存内容

新建知识库生成以下骨架，文档采用准确文件名 `AGENTS.md` 和 `SOURCE_OF_TRUTH.md`：

```text
第二大脑/
├── 00_个人背景/
├── 01_对标账号/
├── 02_内容素材/
├── 03_内容规律/
├── 04_选题库/
├── 05_内容草稿/
├── 06_发布复盘/
├── skills/
├── AGENTS.md
├── CLAUDE.md
├── README.md
└── SOURCE_OF_TRUTH.md
```

- 初始化各目录的入口说明、必要总览及选题卡模板；保留“未参考/已参考”“待做/已做”的语义。内容类型按本人配置，不把同事的赛道和账号默认赋给新人。
- `AGENTS.md` 初始化目录职责、真实资料与引用规则、T 编号、任务边界、用户确认、锁稿与发布事实、导航维护及冲突处理要求。
- `SOURCE_OF_TRUTH.md` 初始化当前入口、原始来源、版本与打开方式、任务别名及内容关联；它是导航，不复制每篇正文，也不替代原文件中的事实。
- `README.md` 是人工入口；`CLAUDE.md` 提供同一约束入口，避免复制成另一套规则。存在该文件不表示 Claude 已通过正式助手支持验收。
- `skills/` 保留库内业务方法与个性化规则。新库初始化明确版本的通用适配方法及目录说明；已有库不批量覆盖原 Skill。
- 新产出的资料、报告、选题、稿件、封面、发布记录与复盘归入对应内容目录；一篇内容的前后阶段以同一 T 编号关联。新库发布档案归入 `06_发布复盘/`；已有库仍保留原档案真源与位置，迁移另留可核对计划。
- 已有的额外目录原位保留，例如 07、08、录屏素材或用户自建分类；不能只因不在基础骨架里就忽略或移动它们。

### 3.2 应用维护运行信息

建议使用库内独立的 `.workbench/` 管理版本化库描述、ID 映射、任务请求、回执、事务恢复和库级资源；缓存索引可重建，知识正文以内容目录中的文件为准。具体系统目录名和 schema 在首阶段设计中冻结。

应用内置组件、内置模板和默认插件资源随应用发行；用户自建模板、提示词、照片等库级资料随知识库保存。助手偏好与最近打开库等机器设置放应用数据目录，密钥使用系统安全存储，不随库导出。

已有库首先只读识别并展示接入清单；启用写入时仅补充所需的管理信息和受管理文档区块。原有正文、私人约束、链接和 Obsidian 配置保持原状，存在规则冲突时先呈现差异。

## 4. 文件到页面的映射

- `00_个人背景` → 个人背景、定位、账号包装；分别呈现已确认、候选与待补充。
- `01_对标账号` → 对标账号及账号分析。
- `02_内容素材` → 素材库、来源、参考状态、转写与可用媒体；调研产物单独标识，不混算成有效参考素材。
- `03_内容规律` → 写法候选、元问题及适用条件。
- `04_选题库` → 选题列表、分类、来源、T 编号、总览与卡片。
- `05_内容草稿` → 在做内容、参考拆解、素材包、叙事、写稿、锁定稿及封面；同时识别第一层与 `已做/`。
- `06_发布复盘` → 发布记录、真实数据、复盘及后续动作；发现库外正式档案时标明来源与可用性。
- 根导航及其他文件 → 当前任务入口、知识库浏览、搜索和资料阅读；无法结构化的文档仍可阅读和定位。
- 爆款雷达 → 保留 Nova 的查询、证据、指标判断、人工收录与加入选题路径；收录后使用第二大脑的统一编号与选题卡入口。

上述是新应用的页面映射目标。同事程序现有账号页实际读取库外 `选题研究/对标账号`，报告页读取库外 `调研报告库`，提示词页读取库外通用资源；适配时同时记录这些已有来源，不将 `01_对标账号` 等同于原账号页的全部数据。默认绑定用户本次选择的独立第二大脑，其他给定包先作为对照和可显式配置的数据来源，不偷偷跨库合并。

同事工作台已有的今天、任务、内容、封面、市场调研和提示词列入功能对照清单，每项记录来源文件、读取、编辑、助手动作和验收场景。私域、运动、X 收藏、飞书及网站统计等也登记，按真实依赖分别接入，不自动删除、不把未迁移功能标为完成。

索引层负责 ID、相对路径、T 编号、引用、当前入口及事实来源。外部编辑、改名或移动可触发增量刷新；无法可靠关联的冲突和重复编号需要显式处理。文件事件遗漏、重启与批量复制后有重新扫描校验。解析器保留未知字段和未识别内容，不能保存一次就重写整篇私人文档。

旧 HTML 分为可静态阅读、含结构化数据可适配编辑、依赖旧保存服务三类。读取实际数据，不直接在具有桌面权限的 renderer 中执行任意旧脚本；需要交互的页面逐项迁移至受控编辑器，明确唯一当前写入目标。

## 5. 所有助手入口采用同一任务协议

统一链路：点击业务动作 → 检查助手与配套插件 → 冻结库身份、任务范围、相关文件版本和业务 Skill → 生成固定 handoff → 打开助手并显式指定执行 Skill → 接单与进度回写 → 提交候选及回执 → 工作台校验、用户确认并入库。

采用两层 Skill：插件执行 Skill 负责读取固定请求、claim、进度、等待、取消、失败、重试和 submit；业务 Skill 负责定位、素材入库、规律提取、选题、写稿或复盘方法。不能只在提示词里提一个未安装的 Skill 名称，必须核对文件、版本、依赖和目标宿主可发现性。

初始路由候选包括 `shengcai-positioning-interview`、`jc-benchmark-intake`、`jc-pattern-extractor`、`jc-topic-generator`、`jc-content-writer`、`jc-media-review`，以及导航指定的创作页方法。它们需要逐项适配，不代表已可直接运行。教程写作 Skill 保留显式触发要求，停用/草稿的 B-roll 方法不自动启用；T020 等优先读取导航指定的当前工作稿，避免转而写旧 Markdown。

任务使用显式选择的库根与 UUID，不从 cwd 猜库。原入口中的 headless Claude、剪贴板提示词和直接 CLI 调用统一纳入任务契约。原始进度与用户采用、保存和发布分别记录；助手结束或打开成功均不能充当任务完成。

Codex、WorkBuddy 分别检查成功、`waiting-user`、`waiting-permission` 及恢复、失败、取消、重试、继续原任务和切换助手。缺少可靠会话 ID/审批事件时显示实际限制；其他助手经过同等契约验收后再标为支持。应用与插件配对升级，旧版插件不能被当作支持新知识库协议。

## 6. Semi UI 和桌面架构

遵循 `docs/research/2026-10-27-workbench-unified-standards.md` 及其引用的设计标准。React/TypeScript renderer 使用真实 Semi UI，公共 token、按钮、搜索、表格、分页、选择器、模态和通知集中实现；不是仅替换颜色或仅套一层 Semi 外壳。

应用边界为 React/Semi 页面 → 有限 preload API → Electron 主进程业务控制 → 知识库适配与任务 worker → 文件。沿用 sandbox、contextIsolation、sender 校验、路径边界、CAS、mutationId 与 pending 恢复要求。重构为随应用启动的受管服务/worker，普通内容操作无需用户自行安装 Node、运行安装脚本或维持固定端口服务；特殊媒体能力另按实际运行依赖验收。

视觉与交互按 Foundation、Layout、Surface、Controls、Reading、Image、Template、Interaction、Acceptance 等适用规则 ID 留证。包括 960×680、长文多图、空库/旧库、搜索分页、中文输入、键盘与焦点、未保存保护和系统减少动画。

## 7. 按可用结果分阶段实施

### 第一阶段 打开第二大脑并完整识别来源

交付打开/创建库、库身份、只读接入报告、文件索引与页面基础映射。用用户提供的第二大脑副本做集成测试，核对全部候选文件、已识别条目、排除原因和缺失链接；T 编号及原路径保留。缺失外部文件、媒体、技能和服务分别列明。现有 Nova 库继续可识别，不自动转换。

验收：选择库后真实数据进入对应页面；刷新、重开及文件外部修改可正确反映；读取不会改写用户正文；新建库骨架和初始化文档齐全。

### 第二阶段 重构同事的内容核心页面

交付今天、任务、定位、账号、素材、规律、选题、在做、稿件与资料阅读。优先让历史内容能找、能读，再接可靠编辑；兼容导航指定的 HTML 当前稿件。建立同一 T 编号的关联、编号分配及多文件写入恢复机制。

验收：用真实 T 卡与当前稿件核对页面、关联和状态；已发布目录不代替发布事实；外部编辑冲突保留双方版本，断电/重启不形成半更新总览。

### 第三阶段 打通一个助手闭环并覆盖全部业务入口

先完成“一个选题 → 插件 → 指定业务 Skill → 用户确认 → 真实文件回写 → 页面刷新”，再复制成熟契约到定位、素材、规律、选题、拆解、写稿与复盘。完善安装、版本不匹配、缺 Skill 和依赖说明。

验收：每个正式支持助手分别覆盖成功、两类等待、恢复和终态；提交回执、文件内容与工作台状态一致；无法执行的入口有具体原因。

### 第四阶段 接通雷达 封面 发布与复盘

保留并适配现有爆款雷达，将选中的结果写为同一知识库中的选题与来源；迁移模板、封面、发布、数据和复盘链。已有库外档案通过显式配置读取，新增产物归入知识库；历史迁移有清单、备份和回读。

验收：雷达不丢查询与证据，不自动把收录当选题采用；发布前后保持同一 T 编号；写入的封面、记录和复盘重开可用。

### 第五阶段 补齐附属模块并做完整使用验收

依据第一阶段对照清单逐项处理提示词、其他知识页面及库外集成，消除作者固定路径与默认私人账号。使用“新用户空库”和“同事已有完整库”分别走通全流程；当前交接包缺少的依赖单列补齐条件。

验收：已迁移功能都有真实来源；未连接、缺文件、无权限、未支持与正常空数据能区分。知识库可以移动或复制到另一台机器，通过重新选择完成绑定，不要求建立原作者目录。

### 第六阶段 平台安装与交付

按根 `AGENTS.md` 对 darwin-arm64、darwin-x64、win32-x64 分别构建、安装、原生运行；Windows ARM 若纳入范围另列。核对应用名称、图标、公司版权、版本、配套插件、最终安装产物及系统界面；验证升级、重开、卸载保库并记录 SHA256。

验收：每个平台单列已构建、已安装、已运行与缺口，不以本机或 Rosetta 结果宣布全部完成。安装应用及匹配插件后，选择知识库即可使用已验收功能；服务凭据由本人配置。

## 8. 统一完成标准

核心验收场景为：安装应用 → 打开本人第二大脑 → 看到真实定位、账号、素材、选题和当前稿件 → 从业务按钮进入带指定 Skill 的助手任务 → 确认后回传 → 内容保存在库内且页面刷新 → 重开或换电脑仍可使用。

“所有东西正常加载”以逐项功能清单和实际文件核对为依据。当前交接材料明确没有的媒体、外部程序和凭据保留缺口，不能承诺打开一个不完整 Vault 就恢复从未交付的文件。首个开发里程碑聚焦第一阶段，以及一个真实内容详情页，不先铺满所有空界面。
