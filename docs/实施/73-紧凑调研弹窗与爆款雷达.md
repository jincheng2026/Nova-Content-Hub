# 紧凑调研弹窗与爆款雷达

日期：2026-10-27；版本0.3.52。本轮按用户截图优化临时表单，增加方向驱动的雷达，并分别验证真实服务、原生界面和事务。最终构建、冻结提交及自动化计数见本页末尾交付记录；未完成的真实采集不列为已通过。

## 交互落地

账号新增/编辑、新建调研、报告导入使用同一720px居中原生弹窗，保留背后的列表。平台和账号名同排，备注、标签、截图为可选；截图和接入说明折叠，内部长文滚动，底部取消/提交固定可达。取消或Esc保留内存草稿，原入口可继续，主页面有明确放弃本次填写的恢复路径；空表单不误判脏数据。图片内层Esc只关当前层，关闭后回原图触发器；保存忙碌时不允许Esc误关，CAS错误在弹窗内保留输入。

市场调研下增加“爆款雷达”。方向为可输入/搜索的选择器，平台从既有TikHub目录选择。推荐筛选默认折叠；粉丝、点赞、赞粉比可选预设或输入自定义数值；非法输入禁提交。采样量最多3条，时间范围可选。一级菜单仍保持原分组，页面变化时展开对应组并将当前子项滚入侧栏可见区。

列表以作品标题、作者、平台、发布时间、粉丝、点赞及赞粉比为主，来源与判断依据可展开。新发现、待核验、已加入、不合适、全部各自筛选；不合适不会因另一次相同来源采样重新出现。同一来源加入选题时复用已有内容，标题写入、正文保持空、原文来源进入参考；原内容列表立即刷新，后续正文继续用原保存入口。

## 采集方案与能力边界

采用确定性采样器加既有外部助手：工作台冻结方向、平台、阈值、首屏和请求上限，仍打开用户所选Codex或WorkBuddy；助手选模型/发送逻辑不变。助手负责解释可借鉴方向与提交带来源的结果，字段和资格由本地重新计算。没有后台执行器冒充外部助手，也没有自动生成、发布或加入选题。

`production collect-radar --handoff UUID` 经原context/claim身份和本机broker调用固定采样器；具体输入见调研skill。首屏搜索一次，只为前三条中粉丝缺失且有真实作者ID的样本补资料，作者去重，最多4次外部请求。不采评论、不翻页、不扩词、不另调云模型、不自动重试；当前设置、冻结工具/预算和费用未知门禁共同生效。已测profile失败时保留首屏和已取得的资料，随后停止。

当前雷达确定性适配为抖音；其他平台可交助手处理可核验公开/手工资料。小红书搜索与资料操作已补到受控服务白名单，但其真实搜索返回402，尚无业务响应结构的实际验收，**没有将其标为雷达自动采集已支持**。[接口核对](74-TikHub雷达接口核对.md)列出官方来源、字段与缺口。

赞粉比为点赞数除以采集时粉丝数，followers必须大于零；未知指标为null，不能填零或算作达标。时间未知列为待核验；超时窗或不满足门槛的样本仍可在“全部”核对。零条达标是有效结果，不代表平台没有符合条件的作品，也不代表已经穷尽检索。来源正文和标题仅作为资料，不改变工具、平台、预算或提交路径。

## 持久化与恢复

不升级工作区schema。不可变观察由research产物提交，当前attempt的request/result/receipt哈希与accepted状态验证后，专用adopt写入report.meta.radar和转义HTML。普通报告导入与普通任务report产物不能写保留的radar类型/元数据；历史不可信同名记录不会进入雷达投影和跨批决策。

来源键按规范平台及作品ID稳定生成；报告ID关联task/attempt/receipt。加入选题使用固定子内容事务与父操作身份，重试核验原请求摘要，保全期间用户新写的正文和创作字段。workspace决策跨批同步；精确重放和复合恢复由原pending/worker路径验收，不以按钮禁用或内存去重代替幂等。
