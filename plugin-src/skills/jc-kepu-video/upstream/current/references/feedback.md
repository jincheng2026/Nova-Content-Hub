# 反馈怎么记、怎么变成规则

沿用 jc-jiaocheng-video 的做法（`~/.agents/skills/jc-jiaocheng-video/references/evaluation.md`）：忠实记录，不因一条样本升级成规则，用户原话和 AI 归纳分开写。

## 每轮记什么

对照页里锦成改过的每一处，追加到内容包的 `改稿日志.md`：

```markdown
## 第 N 轮｜YYYY-MM-DD｜框架 / 逐字稿

- 段号：
- 他改前（哪一列的原文）：
- 他改后：
- 他借了谁的说法（如果有）：
- AI 对原因的理解：标「AI 归纳」，写依据
- 用户回应：认可 / 修正 / 未单独裁决
```

同时在 `/Users/hejincheng/AIJinCheng/个人IP与内容/内容数据统计/科普视频迭代/feedback.md` 追加一条：

```markdown
## YYYY-MM-DD｜Txxx 题名

- 阶段：框架 / 逐字稿 / 最终稿 / 发布数据 / Skill
- 用户原话：
- 本次修改：几处，主要是什么
- AI 归纳：他这轮往哪个方向改（更短 / 更多细节 / 更多判断 / 去掉某类句子 / 偏向谁的讲法）
- 采用证据：对话中已确认 / 已实际发布 / 外部状态未知
- 结果：待观察
```

不记：纯提问、发散讨论、还没被他接受的 AI 建议、已有条目完整覆盖的重复表态。

## 什么时候进规则

- 一条视频上出现的改法：只记案例。
- 同一改法在两条独立视频上重复出现，且没有反例：写成候选规则，给锦成看一句「你在 T0xx 和 T0xx 都把 X 改成了 Y，要不要定成规矩」。
- 他确认后写进 `rules.md` 第四节「锦成版」，标日期和两条视频号；同时如果它和某条通用规矩冲突，通用规矩那条标「锦成版优先」。
- 范式清单本身的增删（他不认某条、漏了某条）直接改 `patterns.md`，改动写进反馈文件。

## 复盘时看什么

他说「复盘」「沉淀」时，读最近的改稿日志和反馈文件，回答：第一版框架保留了多少；逐字稿他改了多少字（粗算比例）；谁的说法被借得最多；同样的改法有没有第二次出现；实际从接题到最终稿花了几轮。只给结论，改规则要他点头。
