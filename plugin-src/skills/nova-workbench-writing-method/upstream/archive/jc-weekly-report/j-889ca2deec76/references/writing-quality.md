# 周报写作质量与风险规则

本文件只管内容取舍、表达和风险处理。标题、章节、表格、图片位置和语气仍以「用户本周要求 ＞ 上一周已确认周报 ＞ 兜底合同」为准。不得以写作规则更完整为理由改版。

## 1. 先保留全量证据，再做减法

- 建立证据包时保留所有真实事项；被周报删掉的细节仍留在原始任务、项目资料和证据包中，不另建本地留档。
- 结果总览默认保留 3～5 个最重要结果。
- 业务线较多时不强行把整份周报压成 3～5 条；要保持核心业务线完整，在每个项目内保留 1～3 个最有价值的结果。
- 按以下顺序取舍：需要对方知道才能决策的＞影响业务结果的＞体现锦成判断的＞有可验证证据的＞纯日常执行。
- 默认删除工具安装、命令、测试次数、文件搬运、会议流水和「投入很多」等纯努力描述；它们真正影响业务判断时例外。

## 2. 结果前置

- 每条按「结果或影响 → 必要过程」书写。
- 整篇按重要性排序，不按发生时间堆流水账。
- 过程只保留能解释结果、证明贡献或支撑下一步判断的部分。

## 3. 可验证锚点

重要成果至少使用一类锚点：

1. 数字：数量、前后变化、达成率、跨平台合计。
2. 日期：完成、发布、交付或计划时间。
3. 产物或链接：文档、视频、课程、Skill、SOP 或回放。
4. 截图：后台数据、页面状态或交付结果。
5. 相关方反馈：合作人、客户、学员或团队成员的可追溯反馈。

不能用「显著、大幅、良好、高效、顺利」代替锚点。锚点缺失且会影响可信度时，放入唯一一次确认；用户确认没有统计后，使用真实交付物或完成节点，仍无证据就删除程度判断。不猜测、不填 0、不把占位符写入最终文档。

## 4. 贡献边界

- 协作项目必须在证据包中标明锦成主导、锦成参与、他人负责或团队共同完成。
- 对外表达不得把团队成果全部写成锦成个人成果，也不得把锦成实际主导弱化成「参与」。
- 单人完成或上一周没有角色标签时，不为形式强行加标签；但正文的主语和动词必须准确。

## 5. 行动判断

在内部为重要条目判断对方需要做什么：

- 仅供知悉：对方看到即可。
- 需要决策：需要选方向、定优先级或拍板。
- 需要支援：需要人、钱、权限、资源或对外协调。
- 已闭环：已经完成，对方无需动作。

这些类型只用来决定条目的排序、风险位置和协同事项。上一周周报没有对应标签时，不得在正文中新增标签。

## 6. 去 AI 味

去 AI 味的首要动作是补事实，不是替换近义词。依次检查：

- 删除不承担必要精确含义的「赋能、抓手、颗粒度、全链路、方法论」等词。
- 打破机械的「一是、二是、三是」和字数整齐的对仗。
- 拆掉「通过…从而…进而…」式空转，直接写结果和原因。
- 删除「后续将持续跟进、继续保持」等无信息量收尾，换成具体下一步或不写。
- 不要把每个小节都写成总分总。

写完后问：「这句话换个人、换个项目是否仍然成立？」若成立，补具体事实或删除。

## 7. 风险识别与分流

不只检测已发生的延期、未达标、事故、数据下滑和资源被砍，也要检测正在变成问题的卡住、停滞、等待他人、一直没定和资源缺口。判断标准是：这件事是否会让具体某个人的预期落空。

### 7.1 留在周报里的普通风险

已经解决、没有残留影响，或短期内不影响他人决策的问题，按上一周格式写入「问题与风险」或对应项目段落。说清：

- 发生了什么。
- 影响什么，哪些不受影响。
- 已采取什么动作，下一个检查点是什么。

### 7.2 需要立即单独沟通的风险

满足任一条就不能只埋在周报里：

- 影响他人的决策或排期。
- 对方可能从客户、合作方、团队成员或其他渠道先知道。
- 拖延会扩大损失。
- 需要合作人或团队动用资源才能处理。
- 涉及对外承诺、合同、合规或口碑。

单独沟通文本必须包含：

1. 事实：第一句直接说清问题、原日期、新日期或实际差额。
2. 影响：说清影响谁、影响多大、持续到什么时候，以及哪些事不受影响。
3. 方案：给出可执行选项，说清各自代价和推荐选择。
4. 决策：说清需要谁在什么时间前拍板或给什么支持。

不点名甩锅；用具体交付时间和客观约束陈述事实。不写「是我能力不足」等泛化自责；承认具体判断失误，给出补救和防复发动作。

## 8. 缺口与失败处理

- 用户不知道精确数字时，只问会影响可信度的最小缺口；已有真实量级或交付物就不强求精确数字。
- 用户说「没统计」「就这些」或「别问了」后停止追问，用已有事实交付；不猜测、不注水。
- 本周产出确实少时，检查是否存在会影响下周的卡点、准备性交付或关键判断；仍然没有就如实生成简短周报，不把「了解背景」等不可验证的话当成成果。
- 用户要求凑条数或注水时，可以用已有事实拆解展开，但不得新增任何事件、数字或结论。
