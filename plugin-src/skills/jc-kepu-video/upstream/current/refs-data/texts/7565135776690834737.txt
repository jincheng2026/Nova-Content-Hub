Hello，朋友们。相信大家最近刷了一个消息，就是 DeepSeek 在 2025 年 10 月 20 号呢，发布了 DeepSeek-OCR 模型。这篇文章呢，提出了一种利用视觉模态压缩长文本上下文的新方法。这个可不是一个简单的技术迭代，而是对 AI 输入范式的一次根本性挑战。

当我们习惯性地认为，语言模型应该是“吃”文本的时候，DeepSeek 团队呢反其道而行之：为什么不让模型直接去看图像？Andrej Karpathy 在 Twitter 上表示，或许 LLM 的所有输入都应该是图像。即使是纯文本输入呢，也应该把它渲染成图像再输入。

这个观点听起来是不是很反直觉？我们花了几十年，把扫描文档转换成可以搜索的文本，现在呢，要去把文本转换成图像了。但这恰恰揭示了一个被忽视的真相：文本的 Token 化是一个充满妥协的过程。

让我们先来诚实地去审视文本 Token 化存在的问题。第一，信息损失的必然性。一个笑脸的 Emoji，这个在 Token ID 里面呢，只是一串抽象的符号，而不是一张富含视觉信息的笑脸。像粗体、颜色、字体大小，这些视觉元素在纯文本环境中，要么就是被抹去了，要么需要额外的标记语言来描述，这个增加了一个表达成本。

Karpathy 指出，Token 继承了 Unicode 的历史包袱，引入了编码问题，甚至增加了安全风险。不同语言的字符数量差异是巨大的，同一字符可能有多种的 Unicode 表示，这给模型带来了非常不必要的歧义。

另外呢，还有就是单向性的局限。自回归的 Token 生成模式，限制了模型只能从左到右地“盲打”，没有办法像人类阅读那样，进行双向注意力的一个全局理解。

所以呢，实验显示，当文本 Token 数量不超过视觉 Token 的十倍的时候，模型的 OCR 精度可以去达到 97%。即使是压缩比提高到二十倍，准确率呢仍能够去保持大约 60%。这个数据背后的哲学意义更加深远：信息密度才是关键，而不是信息的总量。

另外，参考文章也提到了用分辨率去模拟遗忘机制的想法，认为越来越模糊的分辨率更像是一个“近视”。这个质疑是有道理的，但我想提供另一个视角：这个不是模拟近视，而是模拟的叫做抽象能力。

人类记忆的遗忘，并非简单的一个信息删除，而是从具体的细节向抽象概念的转化。我们可能会忘记一篇文章的具体用词，但记得它的一个核心观点；忘记一张图中的细节，但记得它的一个整体印象。

而 DeepSeek 论文中包含了一个推测性的图表，展示这个方法如何实现类似于人类认知的一个记忆衰减机制。旧的对话轮次可以逐步地降采样到更低的分辨率，消耗更少的 Token，同时保持关键信息。而低分辨率的图像呢，恰恰强制模型进行这种抽象。它必须从模糊的视觉信号中提取出本质，而不是依赖清晰的像素，逐字逐句地去读取。这种强制抽象，可能会比保留更多细节来得更接近智能的一个本身。

另外呢，还有提到就是多尺度的表示。对于复杂文档，DeepSeek-OCR 的 Gundam 和 Gundam-Master 模式，结合了多个局部的视图加上全局视图，根据文档的复杂度去优化这个 Token 分配。这种设计呢，体现了一个重要的洞察：并非所有的信息都需要同等的精度表示。

想象你在阅读一份财报，表格和关键数字的时候，你需要高精度识别，而页眉页脚呢，可以用低分辨率快速地去扫过。DeepSeek-OCR 的多分辨率策略，正在这个计算资源有限的一个约束下面，模拟了这种选择性注意的机制。

另外呢，我觉得 DeepSeek 它不只是关于 OCR，而是它想做一个更宏大的叙事。看完文章，最后说：“不要只当做 OCR 模型来看，可能是醉翁之意不在酒。”完全同意这个判断，并想进一步展开一下。DeepSeek-OCR 呢，是在为多模态 AI 的未来去做铺路。

首先呢，我觉得视觉是能够去作为通用接口的。Karpathy 认为，OCR 只是众多的“视觉到文本”任务之一。“文本到文本”的任务可以转换成“视觉到文本”的任务，但反之不行。这个论断很值得深思。

我们的数字世界大量信息天然就是由视觉形式存在的。比如说像网页，它并不是纯文本，而是 CSS 渲染后的一个视觉呈现。文档呢，它包含版面、字体、表格等丰富的视觉结构。代码的缩进、高亮呢，本身也是视觉意义的一部分。所以数据可视化图表传达的信息，远远超过底层的一个数据表。

那你如果强行把这些转换成纯文本，就好像把彩色电影转换成黑白。技术上是可行的，但信息必然是会损失。如果视觉成为了 LLM 的一个原生输入，我们是不是就可以去保留这些信息的原貌呢？

所以呢，这又牵扯到另一个话题，对长上下文的一个根本性重构。比如 DeepSeek-OCR 可以在单个 A100 40G 的一个 GPU 上，每天处理 20 万页的一个数据。这个效率提升不仅仅是工程优化，它指向了一个可能性：就是通过视觉压缩，我们或许能够绕开 LLM 长上下文的根本瓶颈。

当前的长上下文技术，是 RoPE 扩展或者稀疏注意力，本质上都是在和 Token 数量的平方增长做斗争。而视觉压缩提供了一种全新的路径：不是让模型处理更多的 Token，而是用更少、更密集的视觉 Token 去表示同样的信息。通过这种方法，能够处理大量的文本，而不会产生相应的一个计算成本。

OK，另外再聊一聊学术继承和工程创新上的平衡。参考文章提到，DeepSeek-OCR 的思路和【疑似：字节跳动的 Vary 方法】，这个当时是拿到了一个会议的 Best Paper，以及【疑似：GOT-OCR 2.0 团队】的工作有相似之处，认为核心是去把研究成果进一步做扎实、做产品化。这个评价是公允的，但我认为工程化本身就是一种被低估的创新。

学术界往往在 Controlled Environment 里面，也就是在可控的环境中证明概念。但真正让技术可用，需要去解决无数的细节。比如如何去处理各种的边缘 Case，比如扫描质量差、图像倾斜、多语言混排；以及如何权衡速度和精度，比如不同分辨率档位的选择逻辑；第三，如何去设计友好的接口，让开发者能够方便集成。

而 DeepSeek-OCR 呢，在 GitHub 上发布，支持 vLLM 加速以及 PDF 处理，提供了完整的推理代码。这种从 Paper 到 Production Ready 的能力，恰恰是 DeepSeek 团队的一个核心竞争力。

OK，虽然我对 DeepSeek-OCR 的方向持的是乐观态度，但我还是想去抛出我自己的一些未解的问题。首先就是推理能力的代价。研究者里面承认了一个重要的开放性问题：模型是不是能像处理常规文本 Token 一样，智能地在这些压缩视觉 Token 上进行推理？强制进入视觉导向的模态，这个是一个关键问题。

文本 Token 虽然有缺陷，但它的离散性、可组合性，天然适合符号推理。当我们把文本转成连续的视觉表示，会不会损失这种符号的操作能力？一个模型能够去看懂数学公式，并不代表它能够去进行数学推导。

第二个呢，就是训练数据。如果未来的模型都是基于视觉输入的，那训练数据的准备成本会大幅地上升。你首先需要渲染大量的文本作为图像，需要标注复杂的视觉版面，需要处理不同的分辨率、字体、样式的组合爆炸。这可能会让数据成为新的瓶颈。

第三，回到了用户，用户体验的连续性。人类用户产生的输入往往就是纯文本，像打字、语音转文本。如果模型期望视觉的输入，就需要一个额外的渲染层。这个转换会不会引入新的 Latency 和复杂度？

之后呢，再抛出我的观点，我觉得范式之争才刚刚开始。DeepSeek-OCR 的价值，不在于它是否最终成为真正的主流方案，而在于它打开了一个新的可能之窗。它让我们意识到，文本的 Token 化不是唯一的，甚至可能不是最优的输入方式。Karpathy 说他骨子里也是搞视觉的，只是暂时在自然语言处理的圈子里面。这种半开玩笑的话，或许预示着 AI 的下一个时代，不是自然语言的处理，而是多模态的感知。

在这个世界里面，文本、图像、声音都只是信息的不同载体，而视觉可能恰恰是最通用的那个。我们现在正在站在一个十字路口：是继续去优化 Tokenization，让文本处理得更加高效，还是彻底地去拥抱视觉作为 Universal Input？

DeepSeek-OCR 的出现，让这个曾经看似比较荒诞的问题，变成一个值得严肃去探讨的战略选择。而无论最终答案如何，这种敢于去挑战既有范式的探索精神，正是推动 AI 不断进步的动力。正如 Karpathy 所说的，也许有一天，我们会回头看今天基于文本 Token 的 LLM，就好像我们今天看早期的字符界面。它曾经很实用，但终究会被更自然的交互方式所替代。

最后呢，再聊几个关键启示。第一，技术选择不只是效率问题，更是范式问题。DeepSeek-OCR 挑战的并不是如何去做好 OCR，而是我们对输入的一个根本假设。

第二，限制可以去催生创造力。这个正是在 Token 数量的约束下，视觉压缩才能够成为必然选择。

第三，工程化是最被低估的创新。怎么去把一个学术 Idea 变成一个可用产品，本身就是对真实世界复杂性的深刻理解。

第四，我们要保持批判性的乐观，拥抱新范式，同时清醒地认知它的局限和未解问题。所以呢，这个不是一场技术的终结，而是新一轮探索的开始。
