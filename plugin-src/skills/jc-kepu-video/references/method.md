# 科普方法的当前映射

仅当用户显式选择科普逐段口述方法时，完整读[原方法](../upstream/current/METHOD.md)及对应阶段的 patterns/rules/styles/facts/feedback/compare-page。解释一个概念、打开科普旧稿、普通 content-creation 本身均不启用此方法。当前保存与权限见[适配契约](../../../plugin-src/resources/method-adaptation-contract.md)。

## 逐阶段接续

1. 叙事五行、框架、每段参考和本人口述按原顺序推进。叙事与框架各等待本人真实确认后继续；逐段整理保留原意，AI 加句逐项标明，四查与最多一条范式建议交本人裁决。用户明确覆盖工序时记录本轮覆盖，不伪造确认。
2. 摆参考用本轮已授权索引／证据检索；`refs-data`、原作者样本与静态参考只证明来源，不当作用户自己的经历、已验证热点或当前数据。所用引文必须能定位真实文本与作品，缺少原片不能声称看过画面。
3. 原 `find_refs.py`、页面生成、注册和 compare_server 全部只读。没有已验收的等价检索／对照 adapter 时明确缺口，用已取得的来源继续可读候选，不扫描用户其他目录、不启动旧端口服务。
4. 当前内容的叙事、逐段确认、作者手改和日志保存于同一 contentId/T 的受控 checkpoint／候选；原页更新沿[现有 jc-doc 映射](../../jc-gongzuotai-write/references/method.md)，稳定 ID、未知字段、CAS、历史保全。原对照页仅为阅读表达参考，不替代当前作者稿真源。
5. 全稿本人确认后分别保留原方法的全篇检查、后台准确说法、提词稿和逐项改稿日志。动态事实按本轮合法工具核实，查不到标待确认；不把来源包旧价格、模型或限制当今日事实。
6. 反馈与规则候选记录后交本人，采纳反馈不自动改 Skill、全局资料或包内规则；封面、包装和发布收口继续各自明确任务及真实事实。

固定工作台任务依 doctor/context/claim，确认点先 waiting-user，额外权限先 waiting-permission，真实回复后恢复原 attempt；提交核对 taskId、attemptId、requestHash、结果 hash 和回执。直接对话只在当前聊天共创。runtimeStatus=contract-unverified，未宣称原页面／服务或两个宿主已可用。
