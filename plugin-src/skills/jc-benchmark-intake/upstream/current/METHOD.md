# 对标内容入库助手

把用户已经选中的社媒内容完整、可追溯地放进内容 Vault。只负责从「用户已提供材料」到 `02_内容素材/` 的入库，不替用户判断这条是否值得对标。

## 开工条件

1. 在包含 `02_内容素材/` 的 Vault 根目录工作；未指定时使用当前目录。找不到时停下说明，不在磁盘中广泛搜索。
2. 至少取得以下两类信息之一：
   - 社媒助手或平台页面复制的作品信息，最好含平台、作品 ID、标题、正文或描述、分享链接；
   - 用户已经下载的图片或视频文件，并能从用户提供的信息确认来源作品。
3. 缺少平台、作品 ID 和可稳定识别的分享链接，导致无法去重时，只追问这一项。其他缺失字段写「未提供」，不阻塞保存已有真实材料。

详细字段、命名和完成标准见 [入库契约](references/intake-contract.md)。

## 硬规则

1. 完整保存用户复制的原始内容，不概括、不改写、不分析；整理后的字段和原始复制内容分区保存。
2. 写入前按「平台＋作品 ID」「去掉时效参数后的分享链接」「已记录的媒体 SHA-256」三层去重。命中任一层时停止新建，报告现有目录；用户明确要求补资料时只补现有目录。
3. 本地媒体只复制，不移动、不删除原文件；目标文件已存在时不覆盖。使用 `.staging/` 暂存，目标验收通过后再改名为正式目录。
4. 视频必须先经 `file`、`ffprobe` 和短解码检查；文件存在不等于视频可用。
5. 视频没有完整逐字稿时，使用已安装的 `jc-zhuanxie`，用火山引擎豆包语音（录音文件识别标准版 2.0）转写。转写和验收阶段必须保留原始识别、分段复核、校正版和验收结果；校正版通过验收前不得清理中间证据。禁止换用 ChatCut 或其他转写模型（`jc-zhuanxie` 内置的本地 Qwen3-ASR 自动备用除外）。
6. 将校正版逐字稿完整并入 `笔记信息.md` 的「校正版逐字稿」部分，笔记只链接校正版文件和同名字幕。正式入库完成后，`转写/` 下只保留 `校正版逐字稿/`（校正版 `.md` 和同名时间码字幕 `.srt`）；原始识别、分段复核、分段源、manifest 和 validation 全部移入项目 `.trash/`，不得留在正式素材目录，也不得清理尚在 `.staging/` 或未通过验收的条目。
7. 有视频的素材必须带时间码字幕：校正版通过验收后、清理中间版本之前，用原始识别的时间给校正版生成同名 `.srt`（文字取校正版，时间取识别结果，不重新转写）。创作页「看原片」从某一段开头播、参考分析按时间找原句，都靠这份字幕；没有字幕的新视频素材不算入库完成。
8. 新素材只写入 `02_内容素材/未参考/{平台}/` 和 `02_内容素材/_入库检查报告.md`；不自动生成选题、不更新内容规律、不分析标题或结构。
9. 不保存 token、Cookie、带密钥的请求头或其他登录凭据。带时效签名的媒体 URL 只用于当次下载，不写入长期笔记。

## 入库流程

### 1. 读取并盘点输入

从用户消息和附件中列出：平台、作品 ID、标题、作者、发布时间、分享链接、正文或描述、可见数据、图片 URL、本地图片、本地视频、已有逐字稿。把「用户提供的事实」「从文件实际检测到的信息」「缺失信息」分开。

### 2. 去重并给出写入计划

递归扫描 `02_内容素材/已参考/*/*/笔记信息.md` 与 `02_内容素材/未参考/*/*/笔记信息.md`，执行三层去重。未重复时确定：

- 正式目录：`02_内容素材/未参考/{平台}/{平台}_{标题}_{作品ID或链接短哈希}/`
- 暂存目录：`02_内容素材/.staging/{同名目录}/`
- 媒体命名：图片按原顺序为 `01.jpg`、`02.jpg`……；单个视频为 `视频.原扩展名`

标题只替换操作系统不允许的字符，不改原文。写入前运行：

```bash
python3 skills/jc-benchmark-intake/scripts/validate_workspace.py . --target "准备写入的目录" --json
```

目标尚未创建时，这一步用于确认路径和现有重复项；不要因此创建空正式目录。

### 3. 写入暂存目录

创建 `笔记信息.md`，先写结构化字段，再原样写入「原始复制内容」。复制本地媒体；只有用户已经提供公开图片 URL 时才下载图片。不要自行登录平台、调用付费接口（逐字稿转写用的火山引擎接口除外）或扩展采集范围。

视频存在时记录：文件名、字节数、时长、编码检测结果和 SHA-256。没有封面图时，从可读视频第 1 秒截取 `01.jpg`，并在笔记中说明来源。

### 4. 补齐视频逐字稿

视频没有可靠逐字稿时，使用：

```bash
python3 ~/.agents/skills/jc-zhuanxie/scripts/transcribe_batch.py \
  "暂存目录" \
  "暂存目录/转写"
```

完成后读取 `转写/validation.json`。只有验收通过的校正版才能并入 `笔记信息.md`；不确定词保留 `【疑似：…】` 或 `【待确认】`，不得猜写。

校正版定稿后生成时间码字幕（逐字稿名以实际文件为准，常见是 `001-视频`）：

```bash
python3 skills/jc-benchmark-intake/scripts/transcript_srt.py build \
  --timing "暂存目录/转写/原始识别/001-视频.json" \
  --transcript "暂存目录/转写/校正版逐字稿/001-视频.md" \
  --video "暂存目录/视频.mp4"
```

输出 `暂存目录/转写/校正版逐字稿/001-视频.srt`：每条是校正版的一个小句，时间来自原始识别，校正时补的字按前后字的时间插值，`【疑似：…】` 标注跟着所在的句子。脚本在校正版只有不到八成的字能在原始识别里原样找到时停止，这通常说明两份文件不是同一条视频。之后再改校正版逐字稿，要用现有字幕当时间来源重建：`--timing "…/001-视频.srt" --force`。笔记「校正版逐字稿」部分在校正版文件链接下加一行 `- 时间码字幕：[[转写/校正版逐字稿/001-视频.srt]]`。

### 5. 严格验收并正式入库

对暂存目录运行：

```bash
python3 skills/jc-benchmark-intake/scripts/validate_workspace.py . \
  --target "02_内容素材/.staging/目标目录" \
  --strict --json
```

暂存区的严格检查会要求每份校正版逐字稿旁有同名 `.srt`，并检查字幕能解析、时间码递增不重叠、条数合理（按覆盖时长每分钟 6 到 120 条，单条不超过 60 秒）、末条不超出视频时长 1 秒以上、字幕文字和校正版正文逐字一致。验收通过后，把整个暂存目录移动到 `未参考/{平台}/` 下的正式目录。任何一步失败都保留暂存目录和原文件，报告具体失败，不用空文件或视频描述冒充逐字稿。

### 6. 清理中间转写版本并复验

暂存目录严格验收通过并改名到正式目录后：

1. 再次确认校正版文件非空，且全文已经写入 `笔记信息.md`。
2. 将 `转写/` 下除 `校正版逐字稿/`（含 `.md` 和 `.srt`）外的所有文件和目录，按原相对路径移入项目 `.trash/YYYY-MM-DD_对标素材逐字稿中间版本/`；只做可恢复移动，不永久删除。
3. 删除 `笔记信息.md` 中指向 `validation.json`、原始识别、分段复核、分段源或 manifest 的链接，只保留校正版文件和时间码字幕的链接。
4. 对正式目录重新运行严格检查，并要求字幕：

```bash
python3 skills/jc-benchmark-intake/scripts/validate_workspace.py . \
  --target "02_内容素材/未参考/{平台}/正式目录" \
  --strict --require-srt --json
```

正式目录中残留任何非校正版转写文件、失效链接，或缺少、检查不过的时间码字幕，都视为未完成入库。

不得清理 `.staging/` 下的条目或任何尚未通过校正版验收的内容。清理失败时停止并保留可恢复文件，不用删除命令强行收尾。

### 7. 更新检查报告

在 `02_内容素材/_入库检查报告.md` 追加本次结果：日期、正式目录、平台、作品 ID、图片数、视频数、逐字稿状态、时间码字幕（条数、原样对上比例）、重复检查结果、暂存验收结果、中间版本清理结果和正式目录严格验收结果。只追加，不覆盖旧记录。

## 完成后报告

只报告：正式目录、保存了哪些文件、图片和视频数量、逐字稿是否通过验收、时间码字幕是否生成并通过检查、是否发现重复、仍缺哪些真实信息。没有正式目录或严格检查未通过时，明确写「尚未完成入库」。

## 失败处理

- 输入信息与媒体对不上：停在暂存区，列出冲突，不猜哪份属于哪条内容。
- 作品 ID 或链接已存在：不新建目录；用户要求补资料时在原目录追加，并重新验收。
- 视频损坏、零字节或短解码失败：不转写、不正式入库，保留原文件位置和检测结果。
- 转写中断或校正版未通过验收：保留全部转写证据和暂存目录，单项重跑；不清理中间版本，不把部分 ASR 写成完整逐字稿。
- 生成字幕失败（对上比例不足、时间来源缺失）：停在暂存区，核对原始识别和校正版是不是同一条视频；不手写或估时间码冒充字幕，不清理中间版本。
- 只有原始识别 `.srt`、没有 `.json`：可以用 `.srt` 当 `--timing`，句内字的时间按均分估计，报告里说明。

## 旧素材补字幕

2026-09-27 之前入库的素材只留了校正版逐字稿，没有字幕。先盘点，不写文件：

```bash
python3 skills/jc-benchmark-intake/scripts/backfill_srt.py .
```

它按素材目录名到项目 `.trash/` 的逐字稿中间版本里找原始识别，只统计能不重新转写就补的条目。补字幕必须指定范围：`--apply --only 作品ID`；全库补齐（`--apply --all`）要锦成点头后才做。只新增 `.srt`，不覆盖已有字幕，不改笔记和逐字稿。只有 28 秒粗时间段或完全没有时间来源的旧素材，要重新识别才能补，先问锦成。
- 只有标题或一张截图，没有正文、链接和可读媒体：可以暂存，但不能算有效对标内容。
