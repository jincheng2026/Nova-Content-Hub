- 本机应用 0.5.2，WorkBuddy 登记与缓存仍 0.5.1，共用预检被同版门禁拦截。旧版被误报为未安装，封面、模板与设置丢失了具体诊断。现统一给出版本差异与升级步骤，未放松版本、完整性或运行环境检查。
- `production-dialog.css` 的 overflow:visible 导致白色 footer 覆盖下圆角。改为 hidden，沿用 24px 四角及内部滚动。
- `content-list.tsx` 内容与合集名称比较改降序，选项明确“名称（降序）”。保留中文与数字自然排序，先排序再分页，卡片和列表共用。

## 用户追加的完整工作流

完整验收以“新建内容 → 调研对标 → 拆解 → 创作 → 人工反复修改 → 封面 → 保存最终资产”为目标。封面以外阶段须能留在同一助手对话；新对话明确指定内容后可识别并受控续接。开发对话“继续开发账号切换续接”负责统一实现与冻结，已同步下述阻断：

| 验收项 | 当前证据 | 尚需完成 |
| --- | --- | --- |
| 同一对话切换阶段 | 当前各阶段独立冻结 handoff；新任务固定启动新聊天 | 内容绑定的受控后继任务领取与真实宿主验证 |
| 新聊天指定内容续接 | 有稳定 T、原页与工作流读取；CLI 仍需既有 handoff/领取身份 | 显式库＋T 的只读定位及明确建立新 attempt，不接管旧 claim |
| 关键词搜索后下载和 ASR | 直接视频和账号样本路径已有；topic 派生/下载实际返回 RESEARCH_TARGET_FORBIDDEN | 从已结算搜索 receipt 形成有界样本或受控后继请求 |
| 反复手改与最终资产 | 49 项临时库回归通过，作者区域、CAS、资产恢复和源失联导出已有覆盖 | 最终安装包整篇操作的实测证据 |

这些缺口不能被已有单模块通过或助手成功打开替代；0.5.3 首次轻量预览包与完整工作流交付分别记录。
