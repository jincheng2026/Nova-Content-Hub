# 本地文件库数据与 CRUD 规范

日期：2026-10-17。版本：主目录库 schema 4。此文定义正式桌面目标的文件契约；只有已有真实文件测试的部分才算实现。内容、模板、照片/素材、提示词、人工发布、封面执行任务与整库备份已实现文件单元；配置/合集/渠道文案增量、正式宿主自动交接、原型迁移与诊断仍待完成。

## 1. 权威数据与职责

- 内容库根描述文件保存 `format`、`schemaVersion`、`libraryId` 与创建时间。绑定时校验，未知产品或较新格式禁止写入。
- 每条内容一个稳定 ID 目录，显示标题变更不移动目录、不更换 ID。
- `内容.json` 是元信息真源；`正文.md` 是正文真源。两处不重复保存正文。
- 总览和日历从内容、发布记录和任务计算；缓存可删可重建，不承担业务事实。
- 图片是独立文件，原件、生成参考版、缩略图用途不同；历史请求引用固定字节/hash 与版本。
- 库内路径相对根目录；根位置由本机设置保存，移动整个库重新打开仍可定位。
- 同事素材与旅游资料只读参考；不会将其个人库结构、身份或脚本原样部署给用户。

## 2. 目标目录及分步落地

```text
自媒体内容库/
  内容库.json
  内容/<contentId>/
    内容.json
    正文.md
    发布快照/<publicationId>/快照.json + 正文.md
  模板/<templateId>/模板.json
  模板/<templateId>/版本/<version>/定义.json
  我的照片/<photoId>/照片.json
  提示词/<promptId>/提示词.json + 正文.md
  资产/sha256/<前2位>/<完整hash> # 原字节只保存一份，用途/原名在所属引用
  系统（别动）/               # 锁、事务恢复、可重建缓存
```

第一步内容删除采用 `deletedAt` 标记，目录保留原位，正常列表不返回；回收站视图查询该标记，因此恢复无需搬目录或重建关联。物理清理尚未实现时 UI 不提供假按钮。后续物理清理需独立检查历史引用。

## 3. 内容记录与版本

元信息最少包含产品格式、schema 版本、内容 ID、显示标题、递增 revision、创建/更新时间和 deletedAt。正文只在 `正文.md`。

读取返回由元信息原始字节和正文原始字节共同计算的 `editToken`。编辑、删除和恢复必须提交读取时 token；锁内重新读取，不一致则返回冲突，保留磁盘双方事实，不能用页面旧对象覆盖。

revision 用于顺序和历史，editToken 同时识别外部直接编辑 Markdown。外部修改正文不会被偷偷重置。损坏的 JSON、缺失正文、重复 ID 或非法路径属于损坏/异常，不当作空内容写回。

## 4. 首个单元的业务接口

采用纯 Node ESM 模块，主进程与 CLI 后续直接调用相同模块：

- `createLibrary(root)`：只在可安全创建的位置建库；已有非空未知目录不接管。
- `openLibrary(root)`：验证产品/格式/路径，重新定位已移动的内容库。
- `info`、`listContents()`、`readContent(id)`：返回真实文件记录；读取不能返回尚未恢复的半事务。
- `createContent({title, body})`：生成稳定 ID，两个文件全部提交后返回成功。
- `updateContent(id, patch, expectedToken)`：只接受明确业务字段，锁内重读并验证 token。
- `trashContent(id, expectedToken)`、`restoreContent(id, expectedToken)`：标记/清除 deletedAt，保存历史，ID 不变。
- `listTrash()`：供 UI 恢复，不要求用户寻找文件或改 JSON。

具体返回和错误码随实现附在模块说明中；字段非法、冲突、库格式过新、路径越界、忙、损坏、恢复冲突应能区分。renderer 不直接取得通用读写或 shell 能力。

## 5. 跨文件提交和故障恢复

单个 JSON 的原子替换不足以保证正文和元信息一起提交。采用每笔内容变更的事务意图记录：

1. 拿到库写锁，检查路径与格式，先恢复未完成事务。
2. 锁内重读元信息和 Markdown，核对 expectedToken。
3. 生成变更前后字节与 SHA256，完整保存事务记录并刷盘。
4. 逐文件以同目录临时文件独占安装；所有核心读取持同一锁，事务仍保留，直到正文和元信息均与 after hash 一致。
5. 写入完成判据并确认目标内容可重新读取，然后才回成功；历史保留可恢复的 before 快照。

对已有目标不使用“检查 hash 后覆盖 rename”的脆弱顺序：先把旧文件捕获到事务专属位置并核验字节，再以不覆盖已有目标的独占方式安装 after。若外部编辑器重新创建目标，则保留双方并停止，不能回退到覆盖式写入。捕获文件保留作为恢复依据。纯 Node 协议不承诺抵抗拥有相同系统权限的恶意进程任意替换目录。

崩溃后的重新打开/核心读写先恢复：当前文件等于 before 或 after 时可继续该笔提交；发现任何文件既不是 before 也不是 after，说明可能有外部编辑，停止自动写入并保留事务与现场。不能为让测试变绿而覆盖第三种内容。

磁盘满、权限错误、备份失败不能显示成功。多文件操作一旦记录提交意图，失败应说明可能待恢复，不能谎称完全没动；恢复成功后回读确认。

每笔修改有稳定 mutationId；结果不明确时可查询提交事实，再决定重试，不能因为超时就生成新的不关联请求。重放相同 mutationId 必须核对输入一致性，不能把不同变更误认为同一成功操作。

## 6. 跨进程锁与路径安全

- Node 主进程和插件使用同一锁。第一步可全库串行写入，避免提前设计多锁死锁与复杂调度。
- 锁带唯一持有令牌、主机和 PID。活进程、PID 复用、权限未知、异机持有均不自动超时抢占。
- 仅可证明同机旧 PID 已不存在时安全回收自己的目标令牌；回收或释放不能删除后来持有者的锁。
- 建锁后未写入持有令牌的异常空锁安全失败，由诊断指出需处理，不能靠超时猜测。
- 不接受任意路径或调用方指定文件名。拒绝穿越、符号链接逃逸、别的产品根目录和 ID 冲突；操作前重新检查受控路径。
- 首发必须正式支持 Windows 和 Mac，但每个平台只承诺经过实际验证的本地磁盘行为；网络盘和同步软件竞争另做实测，不套用本地互斥保证。目录刷盘不可用时的 Windows 策略要明确能力与错误分类，不能忽略所有 I/O 错误，也不将文件 fsync 宣称为硬件断电保证。

## 7. 后续 CRUD 与不变量

| 对象 | 创建/读取/修改 | 删除/恢复与历史 |
| --- | --- | --- |
| 模板组 | 稳定模板 ID，版本保存规则与多张样图；更新生成新版本 | 隐藏不破坏旧请求；物理清理检查引用 |
| 照片/资料 | 原件入库并校验 bytes/hash，参考版与缩略图独立 | 默认照片切换不改旧请求；引用文件不静默删除 |
| 提示词 | 标题/正文/变量一份真源，导入预览后确认，重复可识别 | 删除恢复可从 UI 操作，不需修 JSON |
| 发布计划 | 归属于 contentId，一条内容可有多渠道多次计划 | 改期不重复建计划；已发布快照固定当时正文/封面/时间 |
| 生成任务 | 固定请求/模板/资产快照，attempt 与结果归属明确 | 重试不混批；回执幂等；保留旧结果，删除内容后不自动复活 |
| 原型迁移 | 验证备份，逐项解码资产与关系，先写新库再核对 | 原备份不改；不把示例、演示授权或旧模拟任务变成执行事实 |

## 8. 首个单元测试矩阵

所有测试使用临时目录，不操作用户实际库：

- 真正创建文件、退出重新打开、两个对象互不影响、移动整个库再打开。
- 标题改变后 ID/目录不变；正文外部编辑可读，旧 token 修改被拒绝。
- 删除/恢复后正文、ID、历史保留；重复恢复/冲突不覆盖。
- 两个独立进程写同库，旧 token 冲突、活锁拒绝、已死持有者恢复。
- 在事务落盘后、第一份文件更新后、完成前注入失败，重新打开恢复一致结果。
- 未完成事务遇第三种外部字节停止，保留现场；磁盘写入失败不得返回成功。
- JSON 损坏、正文缺失、未知/较新格式、符号链接/穿越路径被拒绝且不改原文件。

通过以上测试只证明首个文件单元，不证明模板生图、Electron UI 或安装发行已验收。

## 9. 已实施的库格式 2 与专用升级（上一单元）

- 根 `内容库.json` 的 schemaVersion 为 2；`内容.json` 和事务意图的 schemaVersion 仍为 1，三者独立演进。
- `系统（别动）/事务/待恢复/` 放 staging 和未归档事务；`已提交/` 保存完成事务的原始字节。正常打开/读取只处理待恢复目录，query 按 mutationId 校验对应历史。
- COMMITTED 已生效的待恢复事务仅归档，不重放旧 after 覆盖新正文。归档失败保留 committed 结果与 mutationId，恢复完成前阻止新事务。
- 普通 open 遇旧库返回 UPGRADE_REQUIRED，不静默升级；显式 `upgradeLibrary(root)` 保存描述文件原字节、建立目录屏障、预检/移动/恢复，最后发布格式 2 描述文件。中断后可再次调用继续。
- 旧版遇升级目录屏障即停止旧布局写入；最终格式不匹配也拒写。这是拒写保护，不代表旧程序获得新的只读 UI。
- schema 1 描述文件备份仅用于证明和恢复升级过程，不是全库备份，不能只换回它进行降级。

## 10. 库格式 3 与业务扩展（上一单元）

- 根格式现在为 3；旧内容 schema 1 仍可用，首次使用资料/候选/计划/发布时升内容 schema 2。新 journal 2 仅支持内部四类型；旧 journal 1 严格映射 content，历史不改写。
- 同一 SHA256 资产只对应同一原字节和规范检测类型；原文件名、用途和本人照声明归所属引用。头部检测保留 `decoded:false`，不代表完整解码或生图验收。
- 模板原定义与资源映射保存为不可变版本包，读取和引用检查实际资产 hash/bytes/type。正式根发布前先在 staging 写完未登记标记；未提交包可以重试，损坏对象拒绝冒充空条目。内置同 ID/版本只允许相同包重入。
- 提示词正文只在 Markdown；builtinKey 在当前与回收站锁内唯一，重复安装不覆盖用户编辑与删除。本人照片独立记录身份声明，模板样张人物不会成为本人照。
- 内容内维护资料、候选、选定封面、计划与实际发布。候选初始不验收，显式挑选才选中；选定引用必须属于本内容。发布快照先持久保存原正文/标题/封面/模板，后事务登记，后续改稿不改历史。
- 2→3 显式升级先恢复旧事务，保存原 descriptor 字节，在事务根建立旧 v2 拒写屏障，创建受控目录，descriptor 最后发布。实际旧 v1/v2 模块的独立验证在生产证据目录。
- 本轮完整 293 项通过；只证明覆盖的 Mac 文件/进程和既有原型契约，不证明 Windows、UI、宿主生图或 Electron 就绪。下一单元边界见 `05-真实封面生成闭环实施边界.md`。

## 11. 当前库格式 4 与封面任务

- 内容首次使用执行任务时升 schema 3，`coverJobs` 是唯一可变任务状态；journal 仍是有限类型的 schema 2。完整请求、正文快照、实际选入图片、尝试交接、原始回执和核心报告先保存，引用后提交。
- 输入使用准确模板版本/packageHash、所选非空样张、本人照或明确 null、资料、正文/标题与尺寸/数量/格式快照。每个 request 独立 activeAttempt；不同尺寸请求可以同时进行；同请求换助手/重试保留 sourceAttemptId 与旧候选。
- 收件是单层名称/hash 原始回执；在短锁外稳定复制、完整解码，回到短锁重验根 dev/ino、库身份、有效尝试、固定输入及正文/标题。实际资产、报告准备完毕后，以最新 content before 一笔事务登记全部候选与完成状态。
- 成功回执绑定 receiptHash，重放返回原候选；不同回执冲突。未通过技术验证的回执保留现场，可修正技术问题后重提或明确失败/新尝试。已提交但归档失败不伪写拒绝报告，按 committed 事实恢复。
- 通用资产头部检测仍为 `decoded:false`；实际封面提交的报告明确完整解码 `decoded:true`。技术通过与用户文字/人物/视觉验收分开，候选不自动选中。
- 3→4 显式升级先恢复旧 pending、保存 descriptor 原字节、建立 `升级到4` 旧写入器屏障，最后发布新版本。实际旧 v3 代码、故障重入和旧 v1/v2 升至 4 的独立证据均已核对。
- 最新完整 350 项通过；当前 Codex 桌面线程的两张真实 PNG 已经同一打包 CLI 入库与重放。自动桥接、Windows、WorkBuddy、正式 Electron 与商用发行仍未验收。
