# 文件变化刷新与草稿保护

## 用户流程

助手把图片、规则或结果真正写回库以后，页面可自动重读当前库、内容列表、封面候选和模板学习记录。自动刷新不自行发起生成、认领、验收、清除 pending 或更换内容库。编辑正文时仍保留草稿，并按编辑令牌展示磁盘版本；其他管理表单沿用原未保存保护。

应用后台或某操作执行中收到的变化先合并，恢复前台或操作结束后重读。返回窗口、重新可见和手动刷新继续可用，不依赖每个系统必定上报每次文件变化。模板学习页刷新保留补充要求及已选历史；模板编辑令牌变化时取消旧验收勾选，避免旧确认自动用于新状态。

## 源码边界

- 新增独立 `main/library-watch.mts`，无 Electron 依赖，仅接主进程当前固定 binding。按 root、libraryId、dev/ino 比较；相同绑定不重建，明确切库、解除绑定、机器连接恢复和退出时关闭旧资源。
- 递归原生监听只提供刷新提示，不读取事件所带路径。忽略系统锁/事务/草稿、隐藏与临时文件噪声；300ms安静后通知，连续变化最长2秒触发一次。所有原生句柄、回调和计时器绑定 generation；旧绑定和旧监听的迟到事件不能影响替代句柄。
- 每5秒只核对根目录和最多64KiB的 descriptor，稳定读取且拒绝链接、目录身份或库ID变化。原目录暂时不可用时固定通知 unavailable，随后只按原绑定重新核验、重接；同ID克隆不会被自动接受。
- 主进程在启动和每次有限 IPC 结束后同步绑定；本机连接重置解除监听；退出释放。通知不抛入成功的业务 RPC。已关闭的原生句柄保留空错误处理器，避免迟到 error 变成未处理异常。
- preload 仅开放固定订阅 `onWorkspaceChanged`，消息只允许 changed/unavailable，返回取消订阅函数；不暴露任意 IPC channel、业务路径或文件内容。
- React 合并后台/忙碌时事件，复用现有读取与冲突处理；目录或监听不可用时展开维护入口并显示固定提示。所有写入、恢复和鉴权仍走原有限 IPC 和核心校验，监听消息本身不授权任何业务。

定点源码审查还修补了两项P2：自动读取保留原保存/交接错误，不因后台成功刷新清掉失败提示；初次成功绑定和原绑定重接均发送成功变化通知，明确清除旧库遗留的监听不可用状态。

原生 fs.watch 可能漏掉业务事件；周期检查只核验身份，不做全库哈希。焦点/可见性和手动刷新是明确兜底。同步文件系统调用不构成严格实时期限；当前仍按单人本机可信磁盘设计，不宣称共享网络盘、多写者或原子 openat 保证。
