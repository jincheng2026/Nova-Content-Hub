部署到底做了什么？你用 AI 写了一个网页，在自己电脑里面打开，非常好用、完美。然后你把这个链接发给朋友，朋友说打不开。原因很简单，就是那个网页只存在你的电脑里面，可能是 `127.0.0.1` 这样的一个网址，别人的电脑根本不知道它的存在，也无法访问它。

所以，把代码从只有我能用变成任何人都能用，这个过程就是今天我们要讲的部署，英文叫 Deploy。

OK，那部署到底做了什么？本质上，部署解决的是一个物理问题。你的代码要跑在一台 24 小时开机、连接公网、有固定地址的机器上，别人才能通过浏览器访问得到它。这台机器我们叫做服务器。它可以是你租来的，比如阿里云的虚拟机；也可以是一个专门的托管平台，比如 Vercel；或者是一个容器化的平台，比如 Docker。

部署的核心动作，就是把你前面写好的代码搬到这台服务器里面，启动它，让它开始响应来自全世界的请求。

这里我画了一个比较简单的图，去展示一个请求从用户的浏览器出发，到服务器返回响应的完整旅程。你看，用户在浏览器里面输入可能是 `www.某某某` 的网站，那它背后发生的事情是什么样的呢？

首先，DNS 把域名转换成 IP 地址。然后 CDN 在离用户最近的节点尝试返回缓存内容，如果没有缓存，才穿透到真正的服务器里面。服务器运行代码、查询数据库，然后数据库返回结果，再原路返回给浏览器去展示。

所以整条链路都需要用到部署来搭建、维护。部署不是一个动作，而是一整套体系。

从简单到复杂，我给大家大致分成三个层次去理解。

第一层，可以叫做静态部署。如果你做的只是一个纯前端网页，比如 HTML、CSS、JavaScript，没有后端逻辑、没有数据库，那部署就非常简单。把文件上传到一个静态托管平台，它能够帮你分发到全球用户。像 Vercel、Netlify、GitHub Pages，都是这一类平台。

你把代码 Push 到 GitHub，它自动构建、自动部署，几十秒内全球就可以访问。这是今天个人开发者最常用的一个起点。

做完静态部署以后，第二个就是应用部署。应用部署需要有后端逻辑，比如用户登录、数据读写、API 接口。你就需要一台持续运行的服务器来执行代码。

这个时候有两种选择。第一种就是租一台云服务器，比如阿里云 ECS、AWS，然后自己配置环境、安装依赖、启动服务。或者用平台即服务的一些平台、一些工具，比如 Railway、Render，把复杂的服务器管理交给平台，你只管提交代码。

第三层就是容器化部署。当你的应用变得复杂、团队变大，需要在多台服务器上运行的时候，你就需要有 Docker、Kubernetes。Docker 解决的就是「在我机器上好用，换一台机器就挂」的问题。你的容器可以被复制到各个服务器，服务器 A、服务器 B，可能服务器 N，在任何机器上都可以一致性运行。Kubernetes 就负责管理大量容器，是编排工具，负责自动扩容、故障恢复、负载均衡。

接下来再讲一讲，一次完整的部署流程是什么样。比如说从写好代码到用户能够使用，中间经历什么？现在大致的部署流程叫做 CI 或者 CD，中文叫持续集成或者持续部署。

具体就是每次你 `git push` 代码的时候，流水线会自动启动。比如先跑测试，测试如果失败就返回；测试成功，就自动构建、打包，然后部署到预发布环境，做最后的验证，确认没有问题以后再推上生产环境。整个过程可以做到几乎零人工干预。上一个视频我提到的 GitHub Actions，就是驱动这条流水线的工具之一。

在部署里面还有几个需要清楚的概念。首先叫做环境，Environment。代码在不同阶段运行，会区分成几个环境。开发环境就是你自己的电脑上，随便改、随便试；测试环境是模拟生产的沙盒，用来验证新功能；还有生产环境，生产环境是最关键的，是真实用户访问的那个，改动需要谨慎。

三个环境相互隔离，是为了防止开发的时候改了某个东西，直接把线上搞挂。

第二个叫做 Build，构建。构建就是把开发时使用的源代码，转换成浏览器或者服务器能够直接运行的格式。构建完成以后的产物，才是你真正需要部署的东西。

接下来就是回滚，Rollback。部署如果出问题怎么办？你需要回滚，把生产环境恢复到上一个正常版本。这个就是为什么 Git 版本记录如此重要，每次 Commit 都是一个可以回去的点。好的部署平台通常会支持一键回滚，几十秒就能够让出问题的版本下线，让旧版本重新上线。

还有一个叫做零停机部署，Zero Downtime。以前普通的部署方式，是先停掉旧版本，再部署新版本，再启动。这中间用户会看到报错或者无法访问，所以以前部署都是在半夜。

零停机部署通过蓝绿部署或者滚动更新的方式，让新旧版本短暂共存，用户无感知地切换。

OK，那最后，今天的个人开发者应该怎么部署呢？其实现在整个部署成本已经低到非常低的一个地步。

比如前端项目的标准部署路径可以是 Vercel、Netlify。具体就是把 GitHub 上的仓库连接上去，每次 Push 以后自动部署，有全球 CDN，免费额度对个人项目已经够用了。域名买好之后，再配置一下 DNS 就完成了。

后端和全栈项目，可以用 Railway 或者 Render，做类似的体验。连接仓库，选择运行命令，平台负责服务器、环境变量、日志、扩容。你不需要自己配置 Linux 服务器，也不需要自己再去盯。

如果是 AI 生成的应用，或者需要更多控制权，你也可以搞一个阿里云服务器或者腾讯云服务器，价格也就几十块钱一个月。自己装 Python，配环境变量，用 `nohup` 或者 `systemd` 让进程保持后台运行。

所以，部署就是让你的代码从只有在我的电脑上能跑，变成全世界都能访问的一个流程。它涉及服务器、网络、构建、流水线、环境管理这一整套体系。

对于今天的个人开发者和 AI 编程学习者来说，入门路径其实也很短：学会用 Vercel 部署前端、Railway 部署后端、GitHub Actions 自动触发。掌握这三件事情，你就已经能够完成 90% 的个人项目部署了。
