# 创作与调研 B 方案实施计划

用户已于本对话批准 B：保留内容库、版本、任务、预算、回执，采用 Semi UI 重构核心业务流程。先集中实施，最后统一测试；不逐项执行测试循环。

## 交付与边界

- 默认一个需求进入所选 Agent 对话，自动预填固定交接；工作台负责预览、人工验收、采用与精细编辑。
- 创作按稳定段落关联参考、拆解、稿件与录屏步骤；正文仍只有一份真源，保留 CAS、历史、原始逐字稿保护及旧库兼容。
- 独立调研的已验收证据可进入内容创作；报告提供来源核查、用途分组和兼容锦成元数据导入；保留新建调研。
- 雷达区分候选池与最终限额，先筛已知条件后补作者，逐来源保留采集时间；保留预算与来源证据，不暗增请求或平台能力。
- 包内不允许个人 TikHub/模型/语音 Key、加密凭据、本机设置与真实内容库；新安装由用户自行配置。原机器升级不清除本机凭据。
- 应用设计遵守 docs/design/内容工作台设计标准.md；交付与平台要求引用 AGENTS.md。

## 文件负责人和顺序

1. 主线程：跨对话收口、接收拒绝修订提交、调研→创作承接、报告阅读器与元数据、主 React 集成、最终统一测试与版本冻结。
2. 创作执行代理：production 段落/录屏模型及校验、独立段落组件、production-creation.html、产物采用记录与助手方法；生产聚合文件仅代理编辑，主线程待其完成后集成。
3. 雷达执行代理：radar.mjs、radar-collector.mjs、radar-policy 与 radar-workspace 及助手方法；不编辑 production.mjs 和共享主 UI。
4. 打包执行代理：打包源过滤与凭据检查工具、构建/分发门禁及文档；不读取或输出真实 Key。

## 集成验收（全部实现后集中运行）

- 类型检查、创作/调研/雷达/拒绝修订/凭据门禁专项契约测试，现有相关回归和构建。
- 真实页面检查对照写稿、通读、录制、来源打开、独立研究复用和错误/冲突保留，宽窄窗口按规则 ID 留痕。
- 安装版 Agent 自动预填、真实转写/研究/整篇回传、两种等待恢复、拒绝修订、采用后重开及归档；服务请求遵守已有预算与授权，不将模拟视为真实业务通过。
- 最终产物扫描和全新配置检查；版本冻结提交、tag、SHA256、安装与实际系统信息各自留证。

## 决策

- 用户要求覆盖技能默认测试优先及逐任务测试流程：实施阶段只做代码检查，统一测试阶段修复结果；实施提交明确标记未验证。
- 另外两个用户对话只交付现有成果，本对话负责最终合并与发布；不重复安装。
- 不复刻锦成的 macOS 固定路径或服务端口，业务参考适配现有跨平台入口。
