# 评论深读与报告

先说明对象、问题、样本与输入口径；资料齐全就推进。评论与作者材料分开：先只依据被研究作品的评论、回复和原视频形成观察，再用用户已授权的适用定位与本人材料提出应用建议。判断保留finding IDs和source/cid，建议可回指本人事实；不把用户私有业务资料当被研究人群的证据。

1. 复用当前任务真实评论，记录平台显示数量、实抓数量、去重、层级与回复覆盖，列出未覆盖的回复。费用只按共同契约，不沿用上游默认预算或自动批准。
2. 全读有实质信息的长评；短评按实际问题归类，规则和分母可复算。长短分界可沿用35字作为本轮口径并明确说明，不把刷屏当独立需求；保留未归类和多标签的计数口径。
3. 引文逐字核对cid、原文和回复。条数、获赞、分母分别报告；获赞不等于人数、购买意愿或需求价值。少样本标明方向性，0条真实说明，不造示例。
4. 解释具体场景、任务、困难、差异及其他解释，不强套心理层数或情绪标签；没有交易证据不推购买动机。引用公开昵称与私人访谈身份分开，对外报告将私人身份按授权匿名化。
5. 快版洞察卡包含：对象问题、提问原话/cid/赞数、原视频与置顶/作者回复是否承接、质疑与回复、明确顾虑、可验证补充方向、事实/推测、用户判断。未见获取路径先核对，不能推定作者故意不给。只在确有领取任务时讨论领取提示。
6. 完整报告给材料范围、主要发现、问题证据、解释与条件化建议；原文就近可见，长材料可展开，静态内容不依赖脚本才能理解。图形按真实问题选：比较用条形且零基线，时间变化用折线，构成说明分母；不以形状/面积装饰伪编码数量。无数据写缺口。
7. 逐项检查输入材料均有对应分析、引文与统计相符、解释和建议不串证据；修改后重新核对受影响项目。现有报告reader不等于上游HTML生成器，提交当前artifact允许的静态报告和明细，不调用上游publish脚本。

完成：每条结论可回到原文，样本与回复覆盖有对账，图表与明细一致，事实与推测分开；实际未做页面视觉验收时如实记录。用户采纳/否决及原因只留反馈候选，单条效果不升级为永久规律。
