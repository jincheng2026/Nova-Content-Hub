# 统一助手、内置模板与基础契约

日期：2026-10-17。实现继续使用现有浏览器原型，真实 Electron 文件库、身份服务和宿主执行适配器另行接入。

后续同日更新：本文件记录首批全局桥接与六套设计的交付。当前已扩为 **12 套（9 通用 / 3 AI）**、五份 Schema，并补六张真实 AI 风格参考及版本化人工评审；最新实现与验证范围见 [自媒体模板与生成流程升级](自媒体模板与生成流程升级.md)。下文 88 项及首批资产数量为该阶段验收记录。

## 全局助手与历史上下文

`SETTINGS.host` 是新任务唯一选择。侧栏可直接切换 Codex / WorkBuddy，更多页操作相同设置；项目内原来的独立下拉已移除。编辑某个宿主的安装/插件记录不切换当前助手。

| 入口 | 当前行为 |
|---|---|
| 侧栏、项目摘要 | 当前全局助手，统一交接弹窗 |
| 模板拆解、还原、封面生成 | 新任务快照当前助手、请求、模板版本与上下文 |
| 资料整理、排期、提示词辅助、诊断 | 当前全局助手，摘要明确本次动作与必要资料 |
| 已有任务 | 显示原助手；保留 host、会话与输入快照 |
| 跨助手 | 用户显式选择，创建新任务/请求/批次并保存 sourceTaskId，原记录不改 |

完整聊天保存在原宿主，工作台不能自动把聊天全文搬到另一个产品。跨助手交接保留项目标识、摘要、模板规则、请求快照和引用；图片与附件另行提供。收到的是结构化项目上下文，不能宣称新助手拥有所有旧聊天记忆。

## 统一桥接实现

`原型/shared/handoff.js` 是浏览器和插件共用模块，集中验证 handoff、构造提示及宿主 URL。UI 不另拼协议。现有生成 request v1 不变，外包一层 handoff v1，含目标 host、新建/续接意图、会话 ID、sourceTaskId、request 和最小 context。

- Codex 新任务与已有会话分别使用参考工程验证过的 `codex://new`、`codex://threads/<id>` 形式。
- WorkBuddy 新任务使用 `workbuddy://task?action=start`。原会话续接还需真实可信的 sidebarUrl，当前浏览器没有，因此明确不可用，由用户选择新建，不能静默转新会话。
- 页面展示协议链接实际预填文本和完整复制文本。链接超过 6000 字节只预填“等待交接文件”的短提示，用户下载并附上 HANDOFF.json；不会假装链接已携带全文或图片。
- 协议链接由用户点击，不自动发送。浏览器不能证明安装、预填、原会话仍存在、接单或生成成功；点击不会把任务改成 running/success。
- 鉴权版的演示状态不构成真实授权，仍阻止携内容实际跳转；无内容宿主导航、查看/导出保留。免鉴权版也经过协议和数据校验。

参考实现只读自旅游工程的 `workbench/src/main/codex.ts`、`workbuddy.ts`、`preload/index.ts`。本轮未修改旅游工程、读取其活动库或复制凭据。协议唤起仍需本机所安装宿主版本的实际兼容验收。

## 六套内置模板

内置大字几何、纸感清单、知识笔记、双栏对比、霓虹科技、杂志留白六套；每套一张设计原图和一张换标题参考，共十二张原创 SVG，实际尺寸均为 900×1200。生成弹窗展示所选设计、参考和规则。

它们不是同一张占位图换颜色：每套有不同信息结构、固定/变化规则、配色及排版约束。唯一清单是 [catalog.json](../builtin-templates/catalog.json)，生成器产出浏览器 manifest 与资源；原图和换标题 [视觉总览](../builtin-templates/README.md) 已按完整画面检查。

模板可直接用于创建封面请求；验证来源显示“内置原创设计 · AI还原未验证”。可信性来自程序随包 manifest 的关键定义匹配，不能靠备份内的 builtin=true 获得；改规则、原图或比例后重新验收。原有用户模板和自建内容保留，缺失内置模板按稳定 ID 增量安装。

公开方法参考为固定提交的 [baoyu-xhs-images](https://github.com/JimLiu/baoyu-skills/tree/1567581c26ec29f4216c6e6835415bf30343b0e3/skills/baoyu-xhs-images) 与 [baoyu-cover-image](https://github.com/JimLiu/baoyu-skills/tree/1567581c26ec29f4216c6e6835415bf30343b0e3/skills/baoyu-cover-image)。借鉴风格、布局及生成说明的组织方法，实际设计与代码为本项目原创；未搬运抖音/小红书账号图片、真人素材、平台截图或来源不明模板，不宣称平台官方推荐。上游许可与我方原创资产来源分别记录。

## JSON、Skills、Hooks

四份 JSON Schema 2020-12：workspace、request、handoff、template-catalog。Schema 验证结构，运行时再核对构建配对、跨字段一致、真实内置定义、路径、引用、日期、16 KiB 请求/64 KiB 交接与 4 MiB 浏览器容量。schema 1 旧备份兼容，保留隐私迁移与失败回退。

插件提供 `check-request`、`check-handoff`、`context`、`summary/doctor`。三个业务 Skills 识别两类交接文件，携带共享工作流、schemas 与许可；缺少库/授权/工具时停止，不自行拼路径或绕过执行边界。当前全部检查结果仍为 `executable:false`。

SessionStart 仅注入产品、构建模式和 CLI 使用指导；没有项目正文、登录凭据或真实路径。停止、中断等 Hooks 只反映会话，不能登记产物成功。显式订阅避免重复触发，异常输入和等待时间有上限。设计依据为 [官方插件文档](https://developers.openai.com/plugins/build/plugins) 与 [Hooks 文档](https://learn.chatgpt.com/docs/hooks)，WorkBuddy 仍须逐版本实际安装验证。

## 验证与桌面阶段

统一入口为 `npm ci --ignore-scripts` 后 `npm run verify`。Ajv 仅作为开发依赖，用独立 JSON Schema 引擎核对真实双构建数据；浏览器和交付插件保持无第三方运行依赖。

主线程最终运行 `npm run verify`：53 项原型/工作区/真实回调测试、20 项插件契约测试、15 项独立 Schema 与实际双构建 CLI 联调测试通过，共 88 项，0 失败；鉴权/免鉴权工作台及插件均重建成功。覆盖全局/历史路由、跨助手上下文、内置设计信任与编辑失效、协议编码与长内容降级、鉴权阻断、独立 Skill 文件闭合、Hooks 安全输出、旧备份和隐私迁移。

针对复核发现的“纯摘要跨宿主丢内容”和“整理/排期缺动作意图”，修复后独立复核 2 项回归通过。模板的 12 张 SVG 经原生图片渲染检查；页面测试使用隔离 DOM，没有真实浏览器布局或协议唤起成功的验收证据。

后续 Electron 首个真实闭环应验证：绑定库 → 登录/权益或免鉴权守卫 → 导出输入文件 → 接单回执和会话绑定 → 真实图像 → 校验登记 → 重启恢复。再验证第二宿主、第二系统、签名安装与升级。浏览器协议链接和模型测试不能替代这些证据。
