# 一次性信息收集问卷

## 使用原则

先读取现有证据并预填，再把所有缺口一次问完。不要机械重复询问已知信息，也不要把问题拆成多轮。

先用数字、日期、产物或链接、截图和相关方反馈检查证据。只有缺口会影响结果可信度、贡献归属、风险处理或下周验收时才追问；不要为填满模板而提问。

用户可以直接发截图、飞书链接、项目资料或聊天链接代替填写；接受口语化回答，由 Agent 负责归一化。

## 标准提问格式

开头使用：

> 我已从现有材料提取出以下已知信息：……  
> 还需你一次回答 X 组问题。没有的数据写「没统计」，不计入写「不计入」，没有事项写「无」。

然后按需保留以下字段：

### 1. 周报周期

- 周次：
- 总结周期：
- 计划周期：
- 标题是否沿用 `锦成·第 XX 周个人业务周报`：

如果日期可以可靠计算，直接给出建议值让用户纠正，不要让用户从零填写。

### 2. 当前推进项目

列出从上周周报和证据发现的项目，让用户对每项标记：

- `继续`
- `新增`
- `结束`
- `不计入`
- `已交给他人负责`

要求补充遗漏项目，防止只围绕短视频提问而漏掉直播、课程、产品、交付等工作线。

### 3. 每个项目的上周情况

每个计入项目一次填写：

```text
项目名称：
当前状态：
上周完成：
最终结果/业务影响：
关键数据：
产物或链接：
责任边界（仅协作项目）：
问题/风险：
是否需要写进结果总览：
```

若某项没有数据，允许使用交付物、完成节点或用户反馈作为验收证据。

若发现延期、未达标、数据下滑、卡住、等待他人或资源缺口，只对实际存在的风险加问：

```text
影响谁、影响什么：
是否影响对外承诺或他人排期：
已有方案及各自代价：
你推荐哪个：
需要谁在什么时间前决定或支持：
```

现有材料能推出以上内容时不再追问。用户说「没统计」或「就这些」后停止追问，不猜测、不注水。

### 4. 短视频专项（仅涉及账号时保留）

先确认统计口径：

- 独立视频选题数：
- 全平台发布条次：
- 删除、下架、限流内容是否计入实际发布记录：
- 全平台进线、成交是否有可验证的单条归因：

逐平台填写：

```text
平台：
账号总览（粉丝、累计赞藏等）：
本周发布数：
每条内容：主题｜发布时间｜播放/浏览｜点赞｜收藏｜评论｜转发｜进线｜状态
平台截图：
```

最后问：

- 哪些内容明显有效？证据是什么？
- 哪些内容失败或存在平台风险？
- 用户本人认为原因是什么？
- 下周准备继续测试、调整或停止什么？

### 5. 本周计划

逐项目填写：

```text
任务：
目标：
指标或明确交付物：
截止时间（有则填）：
依赖/风险（有则填）：
```

若沿用上周目标，必须让用户明确写「沿用」，不能自动复制。

### 6. 协同事项

```text
需要谁支持：
需要什么资源或决策：
希望何时完成：
```

无明确事项写「无」，最终隐藏该模块，不强行制造协同需求。

### 7. 资料补充

- 需要纳入的 Codex 对话：
- 飞书文档：
- 项目资料：
- 数据截图：
- 平台后台或链接：
- 不希望写入周报的信息：

## 结束语

只说一次：

> 你按编号一次回复即可；我会合并现有证据，直接给出经过合伙人视角审核的完整初稿，之后只请你做一次总确认。
