## 3. 关键接口与不能破坏的事实

1. **日程内部路由保留。** 可继续使用 `page = 'calendar'`、`nova-show-calendar`、既有元素 ID；改变可见名称不要求重命名 IPC、菜单事件或持久化值。
2. **总览与日程使用同一计划视图。** `publicationEntries(library)` 已排除删除内容、示例内容和取消计划；已发布项采用发布记录快照。阅读时它只按日排序，需补充日内时间顺序。不能用内容 `updatedAt` 排“下一条”。
3. **时间不能补造。** `date` 保持无时间；`local-minute` 使用已存时间并保留时区是否已记录；`instant` 按明确时区格式化。若 UI 采用统一日程时区，分日与时分必须在同一时区转换，不能只转换日期。跨时区场景不得把两种时区的钟面时间当成真实先后。
4. **封面有内容归属后再运行。** 未保存内容先保存；模板页选中模板后选择/创建内容；最终使用当前 `status.assistant`。任务固定输入中的模板版本、图片角色、人物选择和数量不能被页面切换静默改掉。
5. **合集是组织关系。** 移出成员只解除关联，不删除内容；合集有自己的发布计划时继续保留。复用 `createCollection/updateCollection/setCollectionMembers` 及既有 `editToken` 冲突检查。
6. **照片只决定身份。** 用户选择的本人照与模板样张分工明确；保留“这次不放人物”；模板样例里的其他人不能成为默认身份。外部助手只能接收本次固定输入授权的材料。
7. **设置迁移不改变归属。** 个人信息存内容库已有 profile；全局助手留在全局设置；库路径、恢复状态、插件安装状态维持现有主进程边界。不得把名称相同的多个设置做成彼此不同步的副本。
8. **草稿和恢复先于换页。** 现有 `guard`、`hasManagedDrafts`、库 epoch、pending mutation 和恢复入口需继续覆盖新入口。

## 6. 可直接供拆解与生图使用的规则

这些是对现有 `plugin-src/references/media-template.md` 的补充建议，可写入执行 Skill 的引用材料；不另造第二套生成协议。

### 6.1 拆解输出

每张实际读到的图记录：`sourceAssetHash`、可见文字与阅读顺序、主体角色、动作及接触点、镜头和遮挡、文字/人物相让、颜色用途、光线与材质、无法辨认项。以“图中事实 → 解释 → 迁移建议”区分证据强度。

从组内证据归纳固定/可变规则：每条规则必须能指向实际原图；说明适用分支和反例，不把出现一次的特征当作全组要求。比例未测量时标为估计；无法确认字体名称时描述字宽、字重、间距和轮廓。原报告对缺失图片的统计保留原范围，不冒充当前 hash 证据。

### 6.2 生图指令骨架

```text
目标：为【当前内容】制作【比例与真实尺寸约束】的封面，共【请求数量】张。
准确文字：【逐字标题、副标题；无额外文字】。
身份：【已选择的本人照片】；或【这次不放人物】。
风格依据：【模板 ID/版本、实际可读样张列表】。
本张选择：【组内构图分支】，适合本题因为【画面要表达的关系】。
保持：【本分支的标题层级、主体比例、叠层、色彩角色】。
替换：【主题物件、场景、动作、获准替换的文案】。
画面：【主体位置、镜头、谁对什么做什么、接触点、遮挡、光源】。
边界：样图只供风格与空间关系；不继承其人物身份、账号名、水印和原文事实。
核验：标题逐字、身份、手和接触点、前后层次、缩略图可读、尺寸、实际文件。
```

已选模板的整组样张都属于学习输入，生成前检查齐备。单张候选可以选一个适合的构图案例，但不能以此跳过对全组固定关系的理解。多个模板融合只有用户明确选择时执行：一套负责主要构图，另一套仅借明确的文字/颜色/装饰关系，不把互相冲突的完整提示词直接拼接。

失败时只围绕已发现偏差修订下一轮，旧候选与原请求保留。`TemplateRules.evidence`、`requestHash`、`sourceVersion`、`sourcePackageHash` 和验收绑定继续沿用；候选已生成不等于模板已人工验收。
