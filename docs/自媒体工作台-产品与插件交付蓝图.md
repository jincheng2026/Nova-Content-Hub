# 自媒体工作台：产品、鉴权与插件交付蓝图

更新：2026-10-17。依据本轮用户新要求制定，替代旧规格中“工程一期不做鉴权”的安排。

## 0. 从基本事实推导

| 类别 | 当前依据 | 对设计的直接影响 |
|---|---|---|
| 已确认的基本事实 | 原型运行于浏览器，外部 Agent 与后续桌面程序是不同执行者；图片、规则、项目和发布记录具有不同生命周期 | 显示状态必须有保存记录或真实产物支撑；跨执行者需要明确请求、回执和提交协议 |
| 已确认的基本事实 | 免鉴权版将主动分发给用户；用户掌握自己的电脑和文件 | 本地开关不能保护付费云资源；服务端仍需独立鉴权，客户端不保管权益签发私钥 |
| 尚未验证的假设 | 单人单机足够；三个业务 Skills 覆盖主要工作；人工验收能稳定识别模板质量；选定宿主能可靠接单和回传 | 先做小规模真实流程试验，再扩宿主、平台和自动化；不提前抽通用工作流平台 |
| 真正目标 | 用户能重复使用经过验证的模板，为具体内容获得可追溯、可选择、可导出的真实封面；到期、失败或升级不丢成果 | 优先保证输入快照、模板证据、真实结果、历史版本和恢复，再优化视觉细节 |
| 已知约束 | 本轮先优化原型，后做 Electron；当前未接本产品身份服务、真实文件库和宿主桥；浏览器工作区上限 4 MiB | 原型明确演示边界；插件先交付可测试契约；生产存储与授权在桌面阶段实现 |
| 待确认的资源 | 首发 OS/宿主、分发方式、本产品 Native clientId、权益签发接口和测试账号尚未完成交付验证 | 先选一个系统、一个宿主、一套模板、三个差异标题，做真实端到端竖切验收 |

**原方案中的表面修补：**只调整卡片、按钮或页面布局，靠计时器把任务标成成功，把“勾选还原”当作模板通过，或只隐藏账号入口。这些都不能证明图片已生成、数据已保存、授权有效或模板可复用。本轮移除伪完成逻辑，并补齐相应的流程与契约。

**重新推导的路径：**先让原型表达真实输入、待交接、实际产物与验收；随后由桌面主进程和 CLI 实现文件与权限边界；最后接一个真实宿主，验证模板到封面，再扩大覆盖范围。成立前提是具备可用的外部生成能力、本产品授权服务，以及愿意人工验收的小样本用户。第一步用同一模板和三个不同标题走完现有手动流程，记录规则遗漏、标题错误、返工原因和导出结果；桌面首个里程碑再将其中一次替换成真实自动交接。

## 1. 本轮交付边界与当前决策

本轮先完成可演示、可检查、能指导生产实现的产品原型，以及插件预接入契约。后续另行实现真实 Electron、本地文件夹存储、身份服务和宿主联调。原型的登录状态演示不是身份服务；请求校验通过不是 Agent 已接单；插件包可构建不等于已经通过宿主安装测试。

新的明确决定：

1. 参考旅游工作台的产品组织与成熟机制，保留自媒体自己的数据与流程。
2. 鉴权是目标产品的正式能力，打包时可选择鉴权版或免鉴权版。开关由构建者控制，用户界面不能关闭鉴权。
3. 核心交付链为：导入参考封面 → 辅助拆解 → 还原参考与换标题测试 → 人工验收模板 → 内容项目选择模板版本 → 生成候选 → 挑选和真实导出。
4. 外部 Agent 执行走插件。Skills 指导业务，CLI 执行校验和登记，Hooks 提供精简上下文与会话观察。
5. 模板不锁出图比例；允许某比例不代表该比例质量已验证。生成和验收记录本次实际尺寸。
6. 五页仍为总览、模板、内容、日历、提示词；更多承载账号、插件、库、设置与诊断。不重加已撤回的内容卡、总结、图上批注和全部封面页。
7. 单人单机是当前设计基线，仍存在工作台与插件的跨进程并发。多人协作、自动发布、发布数据回收与模板市场不进入本轮。

2026-10-17 后续实现补充：全局助手、浏览器协议跳转、显式跨宿主上下文交接与 JSON Schema 已落实，见 [统一助手与内置模板验收](统一助手与内置模板验收.md)。最新内置设计扩为十二套（9 通用 / 3 AI），其中六套另有实际 AI 风格参考，区域拆解、提示骨架、参考选择和逐项评审已贯通，见 [自媒体模板与生成流程升级](自媒体模板与生成流程升级.md)。内置设计可直接创建生成请求，但不宣称 AI 还原通过；已有任务保留原宿主，切换只决定新工作。以下对真实 main/CLI 文件库与身份服务的要求仍属于后续桌面实现。

当前浏览器版的数据只能承诺保存到浏览器工作区与用户主动导出的备份。它不能承诺已写入某个操作系统目录，也不能使用浏览器演示授权去放行真实插件。

## 3. 唯一构建鉴权开关

配置入口为根目录 `release.config.json`。`AUTH_MODE` 仅接受 `required`、`disabled`；`prototype` 表明本轮预览构建身份，不能把它改成 false 就视为生产实现完成。

构建生成只读配置，工作台和插件同时携带：

```text
productId/appScope = nova-content-hub
version           = 当前发布版本
protocolVersion   = 协议版本
authMode          = required | disabled
pairId/buildId    = 产品 + 发布版本 + 协议版本 + 鉴权模式
prototype         = true（本轮）
```

应用和插件使用相同生成规则；不能各自在源码里写一份默认授权逻辑。参数缺失/非法直接构建失败。双包命令显式选择两种模式，是构建选择，不是客户端运行时的绕过入口。

| 行为 | 鉴权版 | 免鉴权版 |
|---|---|---|
| 账号与开通状态 | 展示；生产需真实认证和产品授权 | 不要求登录、不显示开通阻挡 |
| 新拆解/还原/生成、受保护写入 | main 与 CLI 分别验证当前权益 | 跳过身份权益检查 |
| 库格式、路径、输入、锁、产物校验 | 执行 | 同样执行 |
| 假登录与状态切换 | 仅明确标注的原型/测试构建 | 无需登录演示 |
| query/localStorage/env 改鉴权模式 | 无效 | 无效 |
| 错配另一模式插件 | 阻止交接，提示获取配套插件 | 同样阻止交接 |

后续 Electron 使用独立安装标识/更新通道避免两个版别互相覆盖；账户凭据不跨产品、用户与模式混用。两模式可共享用户主动选择的业务库，库内不存登录凭据，库也不能决定程序是否需要鉴权。

构建检查必须验证 UI、main、preload、CLI、manifest 与插件清单一致；不能只隐藏账号卡片。发布清单记录文件 hash、协议与配对信息，启动后只核对本产品配套插件，不静默修改用户其他插件。

**能力上限：**免鉴权版分发出去后，持有它的人就拥有该版的本地能力。收费版不能依靠“大家不知道免鉴权版在哪里”保护云资源；云端收费服务仍由服务端校验用户和权限。本地客户端也无法阻止有系统权限的人修改程序或用自己的 Agent 直接读写自己的文件。

## 4. 鉴权流程与状态

### 4.1 认证、产品授权和模型供应商凭据分开

- **认证：**这个会话是谁。后续 Electron 通过系统浏览器执行授权码 + PKCE S256，验证 state/nonce、issuer 和受众；token 留在主进程/系统安全存储。
- **产品授权：**该账号能否使用 `nova-content-hub` 的能力。旅游已开通不自动等于自媒体已开通；必须精确匹配产品 scope。
- **AI 使用权：**外部宿主自己的模型订阅、额度和供应商凭据。产品已开通不代表宿主有生成额度，产品免鉴权也不等于模型免费。

生产 Native clientId 尚未为本产品验证，不复用旅游 clientId。发行版的 issuer/resource/服务地址由构建配置固定，用户不能在设置里替换为自己的授权服务器。原型不连接生产身份服务。

授权码与 PKCE 的安全依据见 [OAuth 安全最佳实践 RFC 9700](https://www.rfc-editor.org/rfc/rfc9700)。此处是实现要求，不表示已经完成真实 OAuth。

### 4.2 用户看到的状态与动作

| 状态 | 页面与允许行为 | 下一步 |
|---|---|---|
| 未登录 | 账号说明；保留本地成果浏览/导出入口 | 打开系统浏览器登录 |
| 登录中 | 显示等待、取消；不可重复发起并发登录 | 成功回调或取消 |
| 已登录、查开通中 | 身份已知、权益未知；不新开付费执行 | 等待一次真实回答 |
| 已开通 | 允许受保护动作，显示最后核查时间 | 正常工作 |
| 未开通/已撤销 | 禁止新生成和正式受保护写入 | 刷新或查看开通方式 |
| 暂时查不到、有效离线凭据尚未过期 | 明确离线与截止时间 | 在有效范围内工作，联网再查 |
| 离线凭据过期 | 保留本地浏览/导出，禁止新生成 | 联网核查 |
| 认证凭据失效 | 清理当前会话、保护已有结果 | 重新登录 |
| 用户/设备/产品/模式不匹配 | 不放行、不自动修成通过 | 重新登录或获取配套版本 |

允许查看和导出用户已有成果是本产品的新设计决定，不照搬旅游的整页封锁。它不允许未授权继续请求付费生成。未接身份服务时，所有这些都是可明确辨识的原型演示状态。

### 4.3 离线凭据与撤销

建议服务端签发短期权益凭据，签名包含 `iss/aud/sub/product/device/iat/nbf/exp/features/kid`。设备绑定方案另经隐私和稳定性验证，不把可变电脑名当绝对硬件标识。客户端和插件只验证，不自行签发。

参考工程的三日有效期可作为待业务确认的上限参考；实际有效期取服务端凭据、产品授权截止和本地支持上限中更早的时间。没有产品到期日就显示未知。网络失败不能本地续期，发现撤销立即使本机会话停用。离线期间无法即时获知服务端撤销，最迟在租约截止或再次联网后生效。

登录/刷新/开通查询应单飞；退出或换号提升会话代次，忽略旧请求晚到的结果。退出即清本地凭据，远端撤销请求失败也不能将用户重新登录。

### 4.4 在途任务遇到到期/退出

阻止新阶段、自动重试和追加生成。对已交给外部宿主的任务发出停止请求，但显示“已请求停止，仍可能返回”；不能声称宿主已取消。已产生的文件允许保留在原任务暂存区，正式提交时重新检查授权与账号、库、输入版本。

旧账号任务不会在新账号登录后自动提交。必要时显示“结果已保留，待重新授权/人工处理”。任何状态转换都不能删掉用户已经获得的产物。

## 5. 插件包与职责

本轮插件放在本仓库 `plugin-src/`，构建产物是预接入契约包。它具备清单、业务 Skill、Hook 入口和请求校验，但不假装已经具备真实文件库写入、模型生成与生产鉴权。

| 部分 | 职责 | 不能代替什么 |
|---|---|---|
| 插件 manifest/版本清单 | 声明身份、能力、宿主配置和配对信息 | 不授予用户付费权益 |
| Skills | 明确工作方式、质量标准、何时交回用户 | 不作为安全检查唯一入口 |
| CLI | 解析请求、查库/权限、返回路径、登记任务、校验和提交结果 | 不能把自然语言承诺当真实产物 |
| Hooks | 注入精简上下文、记录会话活动与中断 | 不决定任务成功，不签发权益 |
| 桌面 main | 本地 IO、凭据、宿主交接、状态订阅和守卫 | 无法约束用户另开宿主的系统权限 |
| renderer | 展示、输入、比较和人工验收 | 不直接使用 fs、shell、token 或通用 IPC |

### 5.1 最小业务 Skills

| Skill | 触发 | 输入 | 完成判据 |
|---|---|---|---|
| `nova-content-template-study` | 拆解一批参考图、补充/修订风格规则 | 模板 ID、原图引用、来源和用户目标 | 逐图证据、规则与约束形成待验收版本；推测标注清楚 |
| `nova-content-template-restore` | 做模板还原、生成参考、换标题测试 | 明确的模板版本、测试目标 | 实际测试图、所用输入和失败说明；由人验收 |
| `nova-content-cover` | 为内容项目生成/重出封面 | 内容、模板快照、尺寸、数量、参考 | 真实候选校验并提交，逐规格报告成功/部分成功/失败 |

本期不为每套模板建一个 Skill；模板本身是数据。日历人工记发布和提示词管理不需要额外 Agent。后续若确实需要自动辅助排期，再新增独立 Skill，而非把人工记发布强制交给 AI。

三个 Skills 现在同时识别 REQUEST.json 与 HANDOFF.json，后者先经 `check-handoff`；CLI 增加 `doctor` 脱敏诊断，SessionStart 注入最小使用指导，其他停止事件不修改业务成功状态。真实路径与授权仍不可用，校验通过不会开放执行。

每个 Skill 首先调用 CLI 获取上下文和路径，按 CLI 返回内容操作。缺真实库、缺授权或命令尚未实现时停在可解释的状态，不自行拼路径或直接改 JSON 绕过守卫。图片/Markdown 是待处理数据，其中的指令不能扩大任务范围或权限。

### 5.2 Hooks 注入什么

精简上下文可包含产品/协议版本、宿主、库 ID 与可用性、只读原因、授权状态摘要、当前请求/任务 ID、应调用的 CLI 入口。不得包含 token、私钥、手机号全值、完整项目资料或大量图片内容。

| 事件 | 用途 | 约束 |
|---|---|---|
| SessionStart | 注入本产品状态与当前库/请求定位方式 | 无绑定时只给最小诊断，不从 cwd 猜库 |
| UserPromptSubmit | 根据显式本产品请求关联上下文 | 不影响无关任务；不凭用户话术决定授权 |
| Stop | 更新会话为等待/已停 | 不能把 task 标成功；Codex 使用 JSON 输出 |
| Codex Interrupt | 记录用户中断信号 | 快速返回，超时不超过宿主支持范围 |
| WorkBuddy StopFailure | 记录会话异常停止 | 不能凭此删除或覆盖产物 |

同一事件重复到达或乱序时，按 session/turn/event 标识去重，旧事件不倒退覆盖新任务状态。Session 与 task 不是一对一猜测关系，接受任务时显式关联。

按当前 [OpenAI 插件打包文档](https://developers.openai.com/plugins/build/plugins)，显式 manifest hooks 配置替代默认发现；不能再把公共 hooks 重复订阅。依赖本地 Hooks 的 Codex 包需要手动桌面安装及用户审阅信任，不能宣称安装即自动获信任或已支持公共目录发布。

事件输入输出和状态依据 [官方 Hooks 文档](https://learn.chatgpt.com/docs/hooks)。发布前再做宿主版本兼容实测；WorkBuddy 的事件集以其实际宿主验证为准，不把 Codex 规则直接当作 WorkBuddy 事实。

### 5.3 CLI 权限与路径契约

本轮预接入 CLI 只提供帮助、最小状态、上下文/请求校验和 Hook 入口；真实 task start/产物提交尚未实现时返回明确的不可执行状态。鉴权版缺少可信授权配置时拒绝受保护命令，不能以原型演示登录放行。

后续正式接口分两类：

- 最小公开诊断：版本、模式、协议、是否已绑定、错误码与修复方式，不吐出项目正文。
- 受保护动作：拆解、还原、生成、编辑及正式提交，进入统一 dispatcher；免鉴权版仍经过格式、路径和输入守卫。

任务受理后返回 `requestId/taskId/libraryId/targetId/host/sessionId/inputRevision`，以及经过验证的绝对 `workDir/inputFiles/templateFile/rulesFile/constraintsFile/outputDir`。Skill 只使用这些返回值；CLI 不依赖宿主启动 cwd。

浏览器原型请求携带 `libraryRoot:null`、`pathsResolved:false`，任何计划中的相对目录都只是契约示意。只有主进程/CLI 绑定真实库、验证 realpath 与目录归属后，才能变成可执行路径。

## 6. 模板从参考到生产资产

### 6.1 三类图片不可混淆

1. **来源原图：**分析证据，记录原始编号、来源、尺寸、hash 和用户提供的使用条件。
2. **还原/换标题参考：**按某版规则实际生成，验证这些规则能否复现和泛化；标明它是测试产物。
3. **项目封面：**在特定内容、标题、尺寸和版本下生产，属于项目批次。

选定一张项目成品不等于它必然适合当下一次参考。出图前展示参考清单、作用和版本，用户可以移除。AI 生成参考不得伪装成原始证据。

### 6.2 拆解不是给图片贴风格名字

每条规则关联原图证据，例如 K03 标题占比、K07 人物与文字的空间关系。识别不了的字体/工具不编具体名字；标成可见特征或推测。拆解至少覆盖信息层级、文字关系、构图、安全区、色彩、变化项、固定项和不宜照搬的素材。

拆解结果分为人可读说明与生成约束：前者解释依据，后者告诉 Agent 本次如何生成。规则不能只写“高级、抓眼、清爽”等不可执行形容词。

### 6.3 还原、换内容、验收、版本

推荐状态：待拆解 → 拆解中 → 待还原 → 还原中 → 待验收 → 可用；失败进入待修，跳过测试明确为未验证。需要重做时保持旧可用版本。

内置原创设计是单独的验证来源：`validation.kind=authored-design`、`aiTested=false`，按随包 manifest 的 ID、版本、规则、比例和素材定义核对，设计规范可用于出图请求。它不带 `accepted/restoreImage`，不属于 AI 还原验收。用户修改关键定义后，重新走拆解/还原路径；备份自报 builtin 不能获得信任。

还原图与目标原图并排人工确认；再以三个差异明显的标题检查风格是否仍可识别。每个结论绑定模板版本、测试图和输入，不用“用户勾选要测试”推导通过。

修改来源、关键规则或出图约束时形成新版本；新版本验收不继承旧版通过标记。已有任务和历史项目仍引用旧版。停用限制新任务选择，不能破坏已有批次或发布记录。

### 6.4 一份项目生成快照

任务开始固定：项目 ID 与标题、模板 ID/版本、拆解/约束文本及 hash、目标比例和像素、数量、原图/还原/优先参考的 ID 与 hash、用户补充要求、宿主、请求与任务 ID。

输入发生变化后，正在运行任务继续使用旧快照，或由用户取消并建立新请求；不能半途读取“最新标题/最新模板”。每一张候选关联所属批次和快照，重复提交 requestId 不得多生成一批。

产物检查包括真实可解码、格式/文件体积、实际像素、比例容差、数量、文件归属与 hash。文字准确、人物符合预期及风格质量由人确认，不能仅靠文件校验宣称质量通过。

## 7. 请求、任务、批次与发布

### 7.1 一套请求协议

```text
protocol = nova-content-hub-request
version = 1
appScope / authMode / pairId
libraryId / targetId / requestId
kind = analyze | restore | generate
templateId / templateVersion
libraryRoot / pathsResolved / paths
skill
options = title / count / format / ratio / pixels
rules = 本次固定/变化规则与证据快照
references = 资产引用与版本说明（无凭据、无大段图片 base64）
createdAt
```

插件校验协议、配对信息、请求种类、目标、模板版本与生成参数；未知字段不能变成权限。校验结果 `validated:true` 与 `executable:true` 分开。原型没有真实库路径时只能是前者。

### 7.2 状态与证据

| 用户状态 | 成立证据 |
|---|---|
| 请求已准备/待发送 | 本地表单验证及请求快照 |
| 已接单/执行中 | CLI 接受回执和任务记录 |
| 等待权限/用户确认 | 宿主信号或明确任务阶段 |
| 已收到部分结果 | 已验证的真实文件，未达到完整请求 |
| 待验收 | 产物已登记，质量尚未人工确认 |
| 成功 | 请求范围内产物校验/提交完成；人工质量结论另记 |
| 失败/中断/失联待核实 | 各自错误、用户事件或缺失心跳证据 |
| 结果待授权提交 | 暂存结果存在，正式写入被当前授权阻止 |

Hooks 观察的是会话，CLI 登记的是任务；同一宿主会话可能接多个任务，不得互相代替。

### 7.3 选定与发布不互相覆盖

每个规格可有当前选定候选；重出产生新批次但保留旧选定。比较与收藏按项目和稳定资产 ID 隔离。候选编号只是显示名，不是全库 ID。

人工记发布固定日期、渠道、可选链接和当时产物引用/hash；以后改选不得改变历史。日历同时保留计划日期与实际日期，清楚标识当前视图依据，不把用户声明冒充平台证据。

## 8. 数据、文件与故障恢复

浏览器原型使用带版本的工作区保存与导入导出；图片有体积上限和可见错误。超过容量、存储被禁止、备份损坏、版本过新时保留原数据。演示授权、凭据、宿主信任不能进入备份恢复后自动放行。

Electron 阶段继续支持普通内容库文件夹，业务路径集中在自媒体自己的 layout 模块：内容、模板库、我的素材、提示词、任务/对话记录、系统元数据。模板版本及测试产物跟模板走，内容候选及批次跟项目走，缩略图缓存跟用户目录走。备份原件不可用硬链接冒充独立副本。

单文件写入使用锁内重读、临时写、刷盘、备份、原子替换和回读。多资源提交先导入/校验产物，再提交批次清单，最后更新任务；用稳定操作 ID 与恢复记录处理任一步退出。不要把多次 rename 称为整个事务。

删除进回收区并可实际恢复；同名用独立 ID/碰撞规则，不能按显示名批量误删。未知文件夹只报告和人工整理，不默默纳入定时清理。大文件、符号链接、压缩包路径和真实路径都在可信 IO 层校验。

## 9. 后续 Electron 实施分解

| 工作包 | 唯一职责 | 必须通过的验收 |
|---|---|---|
| E1 桌面骨架与桥 | 安全窗口、受限 preload、本机设置、资源协议 | 无通用文件/shell能力；IPC 来源、参数和外链校验 |
| E2 内容库模块 | layout/schema、绑定、导入、锁、备份/恢复 | 重开/拔盘/无权限/过新库；并发不丢修改；恢复不覆盖新数据 |
| E3 认证与授权 | Native 登录、开通查询、服务端签名凭据、双版本守卫 | PKCE/取消/退出/换号竞态、篡改/过期/错误产品、断网 |
| E4 正式插件 CLI | 真实路径、受理、阶段、产物提交、幂等 | 一次完整任务；重复/乱序回调；无授权与越界拒绝 |
| E5 宿主适配 | Codex/WorkBuddy 启动、预填、回原会话、诊断 | 冷启动、未安装、未信任、超长指令、对话消失、手动降级 |
| E6 模板与封面闭环 | 证据拆解、还原/换标题测试、快照、候选/选定 | 一套模板三个标题；改模板不污染旧任务；导出 hash 一致 |
| E7 五页与可访问性 | 当前原型真实接入、焦点与键盘、布局 | 关键全流程可键盘操作；窄窗口/缩放；空态和失败状态 |
| E8 发行与支持 | 两版配套打包、签名、公证、升级、脱敏诊断 | 干净机器安装；错配拦截；升级保留库；卸载保留成果 |

E2/E3/E4 接口先统一，再分工实施；每项写入由唯一负责人修改。优先选一个目标系统和一个宿主做真实竖切，随后扩第二系统/宿主，不能一次用开发机结果代表全部平台。

## 10. 本轮与后续验收清单

**原型与契约包：**两模式可构建、配置不可被 UI 变更；业务修改可保存和备份；模板测试意愿/执行/结论分开；生成不再定时器伪造；请求快照可查看/导出；手动结果可导入并挑选/导出；错误日期/链接/格式被拒绝；已发封面固定；错配/未绑定/未知状态诚实显示；插件声明边界清楚，受保护入口在未接授权时拒绝。

**生产发行前：**真实登录开通、可信签名权益、操作系统安全存储、真实文件库事务、两宿主安装与信任、端到端产物回写、目标系统渲染/安装/升级、供应商失败与费用行为均须实测。构建目录名或 prototype 标记不能代替这些验证。

外部前置条件只需产品级配置与测试授权：本产品 Native 应用注册、产品 scope、权益签发接口/公钥、目标 OS 与分发渠道。无需用户交出 root 密码、生产 AccessKey 或已有账号 token。
