# 旧库升级副本与中断恢复

2026-10-18。本批只有源码与定向源码审查，未运行测试、类型检查、构建、探针、应用或宿主，未更新本机安装。不能据此声明旧库升级或商用交付已验收。

## 用户路径

内容库 → 备份与维护 → 升级旧版内容库。选择旧库和外部存放位置后，预览原库、备份和副本三个名称；明确确认后才开始完整复制。当前只支持 schema4 → schema5，当前版本无需升级，未来版本及1至3版明确拒绝，并保留原文件。

流程依次为完整备份、核验备份、恢复独立副本、升级副本、完成凭据。备份与副本使用自动生成的不同新目录，不在原库之内。原库业务文件不升级；备份会取得协调锁，并可能清理经既有规则确认失效的锁，不能宣称源目录完全无任何写入。

完成后显示备份和副本名称，不自动切换；点击“打开升级后的库”才重新核对并绑定这个副本。完成会话结束后可从“打开本机内容库”选择该新目录。正常应用升级与文件库格式升级分开处理。

## 文件与进程边界

- 主进程私有选择持有源库 ID、目录设备/inode、原描述文件 hash 和目标父目录身份。renderer 不能传库路径或任意升级参数；有限 IPC 均不接受 payload，取消预览会撤销私有选择。
- schema4 备份必须明确提供完整 pins，普通备份入口仍默认接受 schema5。只备份，不借备份恢复原库 pending 事务。
- 机器连接记录持久化一个升级 intent；每次 worker 写入前先保存阶段。副本恢复完成后核验原有恢复来源，再持久化目标目录身份，之后才允许升级。
- 核心显式升级 API 校验批准的 schema4 描述 hash；schema5 重入要求同一原描述备份、精确派生描述、升级屏障和完成标记。只读 inspect 不创建锁、不恢复事务、不补标记。
- 桌面完成还要求副本可打开及独立操作凭据。凭据在同目录临时写入并同步，再无覆盖发布到固定名称；不能把单独 schema5 描述或核心完成标记当成桌面成功。凭据包含操作、来源、备份、副本及结果描述 hash。
- 打开副本重新验证固定完成证据与目标身份，随后复用有限绑定、内置安装、监听和提醒刷新。不会接受同路径换目录的替代库。

## 中断和限制

重启后先核验固定结果；查询不执行复制或升级。完整备份或完整恢复的丢失响应可核对后继续；半截复制不会覆盖或续写。用户可保留文件并清除待处理记录，下一次另建唯一新目录。事务不明、身份冲突、损坏元数据或凭据不符均停止，不能自动删库、删锁或伪造成功。

该机制适用于一期单人本地库。路径重验仍有系统调用间隙与 inode 重用限制；不是对抗恶意并发目录替换的原生目录句柄保证。需为完整备份和副本预留足够磁盘空间；当前不提供容量估算承诺。成功凭据保存在目标父目录隐藏文件，不是可随意移走的临时日志。
