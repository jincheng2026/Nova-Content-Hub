# 外部助手写入时的只读刷新恢复

2026-10-18。真实安装版与Codex执行器共享本地库时发现BUSY后提示残留，属于集中验收修复。

## 原因与边界

桌面IPC与图片协议已经由同一个runOperation串行化；不能把Promise.all或两个utilityProcess当作自撞锁。实际外部CLI和桌面读取竞争共享库锁，核心对活进程持锁立即BUSY。自动刷新在执行前清空changesPending，失败后无后续业务变化就不会自动重试；后续焦点刷新成功时preserveError仍保留旧BUSY。

Astra high查证并只读复核实际diff，Sol high唯一实现worker和renderer修复，主线程检查调用及真实diff。没有改变锁粒度、过滤系统目录规则或业务写入语义。

## 最小修复

只对workspace、list、readContent、workspaceLibrary、coverAssets、readCover、raster七个明确只读操作重试BUSY，最多额外三次，等待80/240/600毫秒。固定原参数、单pending槽贯穿等待，关闭时取消timer并拒绝请求；其他错误立即返回。写入、提交、导入、seed和不确定回执恢复均不重放。

后台BUSY携带内容库epoch归属；只有同库action、status和workspace全部成功才清除。前台错误不带该来源，不被自动成功覆盖；后台出现新的非BUSY错误会替代旧后台BUSY并保留。耗尽时显示“内容库暂时被其他操作占用，请稍后刷新；原文件和草稿会保留”。不将失败后的changesPending重新设true，避免acting effect无界循环；下一次焦点、业务变化或手动刷新才再次尝试。

执行代理对旧HEAD运行新增检查，已复现旧提示不清除、后台BUSY丢status和新冲突被遮盖三项失败。修复后的worker/实际App逻辑定向检查10项及两端类型检查通过；真实Electron、当前构建与安装结果另行追加。背景状态检查运行实际App hooks/actions但没有挂载React或Electron，不将其等同原生并发验收。
