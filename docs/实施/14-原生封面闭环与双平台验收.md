## 本单元的数据与操作边界

- 模板组固定版本与一组 style
  样张；生成张数独立。本人照片仅来自显式本人声明，失效时要求重选，用户可明确选“这次不放人物”。样张人物不成为身份素材。内置模板可直接作为请求参考，但不能把未经过真实生图验收的模板改标为已验收。
- main 的系统对话框选择照片；worker 预检完整解码、固定源 hash，main 持久化有限导入意图后入库并解码，再创建照片。同操作重试优先读库内固定
  hash，不要求已导入源文件仍存在；无有效字节不能产生 available 假记录。
- 单一当前库沿用 libraryId/dev/ino 固定绑定。renderer 只传业务 ID、版本、hash 和有限表单；图片 URL 来自当前绑定 epoch
  的授权资源集，换库撤销。worker 完整解码，main 重核原始 hash；不向 renderer 提供磁盘路径或通用读文件能力。
- request 复用可能没有本次 mutationId 回执。core `inspectCoverInput` 捕获准确指纹，`findCoverRequest`
  核对当前标题/原始正文及历史固定包；metadata token 变化允许回查，标题/正文变化拒绝。main 先持久请求意图、再固定
  requestId/hash、再创建同 mutationId 的 attempt。查异常保留意图，不能误判 missing。
- 照片、内容、封面准备与选用/取消意图统一互斥；恢复读当前业务事实，不用历史回执覆盖后来编辑。明确放弃只放弃本机恢复意图，不删除已提交业务历史。
- 助手仅设置中选择，业务表单不重复选择；同一生成任务保留一个继续入口。重复继续同一尝试，明确重试或换助手才创建保留来源的新尝试。打开助手不等于接单，接单不等于生成，submit
  才整批登记候选，人工选用仍单独发生。
- required 缺正式权益时 main/worker 双重拒绝新业务写与 seed；已有成果的查看、核验、导出保持可用。正式权益联调仍待独立应用注册与服务。

## 插件与运行时

真实桌面桥接 `plugin-src/src/bridge/native-handoff.mjs` 与旧原型 `handoff.js` 分开；旧契约继续 executable:false。主进程在系统
appData 的 `NovaIsland/NovaContentHub/handoffs` 写受限本机定位文件，内容仅绑定及固定请求身份，不复制正文/图片或任务状态。URL
仅短 handoff ID，不包含库路径、标题、素材字节。CLI 再验证 pair/platform/arch、原库身份、requestHash 与 host；旧定位不能在同 ID
的替换库恢复事务。

定位文件只供当前用户本机进程使用，不是签名信任根；路径检查没有原子 openat 或 inode 复用防护。本轮不把该限制隐藏成完全沙箱。历史定位允许查询与
submit 幂等回放，重新打开已结束尝试仍被 main/core 拒绝。

真实执行包带锁定官方 Node 24.20.0、许可证、对应 sharp；launcher 固定调用包内运行时，清除 Node 注入变量，不依赖 PATH、宿主私有
Node 或 ELECTRON_RUN_AS_NODE。构建下载及缓存每次校验 archive hash，启动检查版本/系统/架构与字节。清单与 hash
用于损坏和误配检查，正式数字签名另行验收。

官方依据：[Node archive 校验目录](https://nodejs.org/dist/v24.20.0/SHASUMS256.txt)、[Electron shell](https://www.electronjs.org/docs/latest/api/shell)
。链接长度遵守 Windows 2081 字符上限；宿主实际预填与生图行为仍需逐组合验证。
