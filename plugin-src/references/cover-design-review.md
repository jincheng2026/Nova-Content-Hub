# 封面拆解、构图与检查

在模板学习、还原或封面生成前使用本指南。执行身份、输入与输出范围以当前 Skill 和已持久化请求为准；本指南只组织视觉工作，不增加运行权限。用户已选好的模板、人物、标题、比例与数量直接沿用。

## 拆解：事实先于规则

逐张查看本次输入，保留原来的稳定 ID 和 `sourceAssetHash`。为每张图记录可见文字及阅读顺序、主体角色、镜头、动作与接触点、遮挡、标题避让、颜色用途、光源和材质；无法辨认的项写明未知。用“图中事实 → 规则解释 → 本次迁移”区分证据强度。

规则应能指导构图：例如主次字级的相对大小、文字与人物占区、前后叠层、留白位置、强调色承担的作用。未测量的比例标为估计；字体名称不确定时描述字宽、字重、间距与轮廓。

每条固定或可变规则都回指实际看过的原图 ID/hash，并注明适用的构图分支。出现一次的特征只能说明该样张；记录组内反例，避免把常见排布写成全组强制项。来源报告提及但本次未附的图片，继续标为原报告范围，不能补造 `sourceAssetHash` 或观察证据。交回规则 JSON 时使用当前请求支持的字段，不引入新的协议字段。

每条规则用现有规则文本或 observation 写清「适用分支／可见证据／例外／置信度」。例如：双人物互动分支用人物间视线和接触点串联标题；单人物产品演示分支不强制第二个人。置信度来自实际样本中的支持与反例，未逐张统计时不能虚报频次。还要说明失败长相，例如标题挡住眼睛、手与道具不接触、同组另一种版式被误判为错误。

完成标准：整组实际输入均已查看，每条规则有可定位的来源，事实、推断和未知可区分。

## 构图：有意义的候选差异

先记录本次内容要表达的关系，再从已选模板组中选择适合它的构图分支。按以下顺序组织生图提示，值均来自本次固定输入：

已拆解模板先读固定包中的完整 VI、风格 JSON 和定义；整组选中图逐张看全。每张候选选一张主要完整原图及其 sourceKey/hash，说明适用原因并锁定 3–5 个可见的标题层级、动作、景深、遮挡、色材或留白关系；逐项写保持与替换，其他样图只作有明确角色的辅助参考。来源人物、服装、旧 logo 和文案是观察事实，本次身份与内容由本人照或 null、标题、正文、prompt、资料角色决定。结构文档用于读规则，不作为生图图片输入。

1. 目标：当前内容、真实尺寸约束、比例和请求数量。
2. 准确文字：标题、副标题逐字列出，区分获准替换的文字与需要保留的文字。
3. 身份：已选本人照或“这次不放人物”；模板样张只提供视觉关系。
4. 风格依据：模板 ID/版本、实际读取的样张 ID/hash、本张采用的构图分支。
5. 保持与替换：保持该分支的标题层级、主体比例、叠层、色彩角色；按本题替换物件、场景和动作。
6. 画面关系：谁对什么做什么、镜头位置、接触点、遮挡、光源，以及文字如何避开脸和关键动作。

把抽象的“高级感、科技感”落实为可见关系：前景是什么，中景谁在对什么做什么，背景如何承托；主标题和副标题如何分级。例如用户指定托举关系时，说明手掌接触哪个物件、物件前后遮挡谁、视线指向哪里。例子只示范描述的精度，不能给无人物请求添加手或人物。工作台已经保存的选择不重问；真正缺失的必要信息一次集中询问，不能用固定问答轮次拖慢生成。

批量候选的差异来自模板允许的镜头、动作、留白或信息骨架，不靠同图换色凑数。原创探索可以选择不同信息骨架；已选模板则服从组内固定关系与允许变化。出图数量以请求为准，样张数量不决定候选数量。

已选整组样张先学习齐备，再为单张候选选适合的分支。用户明确要求融合时，记录哪套负责主构图、哪套提供指定文字/颜色/装饰关系；冲突约束不能直接拼接。产品标志、界面、数字和品牌颜色使用实际材料与已确认事实，样张中的账号或身份不自动继承。

完成标准：提示中的准确文字、身份、参考角色与固定输入一致，候选差异能解释画面如何服务本题。

## 检查：客观失败与审美选择分开

查看每张真实输出，逐项记为通过、失败或未检查：

| 检查项 | 可观察的判断依据 |
| --- | --- |
| 准确文字 | 逐字核对标题、副标题；额外文字与事实是否来自请求 |
| 身份与人物 | 本人照身份保持；无人物请求未出现人物；来源账号与样例身份未残留 |
| 空间关系 | 手部、接触点、前后遮挡和光源一致；标题避开脸与关键动作 |
| 阅读层级 | 约 180px 宽预览仍能辨别主标题与核心关系；放大检查边界与裁切 |
| 模板约束 | 固定规则满足，所选分支和可变项有对应原图证据 |
| 实际文件 | 实际格式、尺寸、比例和数量满足请求；原始文件与 inbox 副本 SHA256 相同 |

预览只用于观察，输出文件保持工具返回的全部原字节、平台标识、水印与元数据。检查或审美偏好都不构成裁切、缩放、重编码或擦除标识的授权；修订通过生成新候选完成，旧候选和原请求保留。

失败项写明具体位置与下一轮要改的偏差。技术校验成功只说明可以提交；审美取舍和模板验收仍由用户完成，候选生成不改变模板验收状态。提交继续保留 `requestHash`、模板版本、证据 ID、`sourceVersion` 与 `sourcePackageHash` 等已有绑定，不改造或补造缺失字段。

本指南根据本产品的固定请求、证据与人工验收流程重写，方法借鉴及固定来源见 [来源与许可](upstream-notices.md)。无需下载上游文件、安装依赖或执行上游脚本。
