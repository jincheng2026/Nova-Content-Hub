一段的工作流程的时候怎么样让他不乱这个时候才需要我们定一个图那想搞懂这件事情我们还是一样把过去几年的 AI 变化看成四层能力第一层我们去年一直在讲的叫做 promptengineering 提示词工程你看我们最早去用 ChatGPT 大家做的事情都很简单告诉他你是谁然后要做什么比如你是一个资深的运营帮我去写一篇小红书的笔记这个时候你的重点在哪里啊在怎么去提问角色怎么设定要求

写的是不是够清楚输出格式有没有去说清楚 Prompt 解决的是你希望 AI 用什么方式去回答你但很快大家都会发现只会提问啊不太够，比如说你让 AI 去帮你回复客户他连客户买过什么之前投诉过什么产品有哪些限制都不知道他再会说也只是一本正经的去瞎猜于是呢就有了第二层叫做 Context Engineering 上下文工程在这里呢你就不只是告诉 AI 你是客服了还把商品的资料订单信息

客户的历史对话放给他看呢只是给了他一个任务那 Context 呢就是给他做任务需要的信息那大多数普通人对 AI 的误解啊其实就卡在这里以为模型不够聪明其实很多时候不是是他没有拿到正确的信息同样让 AI 去写一份行业报告区别不在于说你有没有去说请深度分析而在于你有没有去给他可靠的数据限定范围和你的真实的需求然后再到第三层叫做 Loop Engineeringok 然后在前两层里面我们看到

他们都只是说一问一答对吧对于 AI 来说但真实的任务呢往往就不是一句话能够去完成的，比如说你让 AI 修一个 bug 他要先读代码定位问题再搜索资料再修改文件再跑测试测试不过再得回来继续改这个就是 Loop 给 AI 一个目标和一组的工具让他自己判断下一步做什么一直的循环一直到任务最终完成为止，所以 Prompt 是告诉他怎么去说 Context 是

告诉他哎需要知道什么那 Loop 呢是让他不只会说而且还能连续的去做事像 Deep Researchcodingagent 很多都属于 Loop Engineering 这一类你给个目标他自己的搜索调整检查最后给你结果但 Loop 也有问题探适合探索性的任务，比如说帮我一去研究这个市场帮我去修这个问题你事先并不知道具体要走哪一步但如果工作本身都很稳定每天都在重复完全交给一个 Agent 自己探索

反而呢不是一个好事，比如说一个电商团队每天都要去处理售后先判断是物流退款还是产品问题物流问题查订单退款问题查规则高风险投诉转人工最后呢还要去记录处理结果这条流程其实已经有一个非常成熟的 sop 了这个时候第四层就出现了就是我们定义的叫做 Graph Engineering 在这里呢你可以把 graph 理解成一个什么理解成一个 AI 团队的流程图什么任

要先做什么可以去并行什么情况走哪条路谁来检查结果都需要去提前的设计好，所以 graph 最重要的不是说同时的去调用很多的 Agent 而是呢把该确定的部分给确定下来把该灵活的部分去留给模型，比如说分类路由审批数据校验这些规则明确的环节用 graph 给它固定下来那查询资料分析复杂问题写报告这些不确定环节仍然可以去放一个 Loop 让 Agent 自己去探索，所以呢

graph 里面可以有很多的 loopgraph 更像是一个项目经理那 Loop 呢更像是哎我在下面开工的每个项目的员工这也是为什么开头我不建议大家一上来就去学 graph 如果你只是想让 AI 帮你写文案做总结查资料一个稳定的 Prompt 加上正确的 Context 就足够了如果你再用 codingagentDeep Research 或者做一项需要反复试错的任务先把 Loop 用明白价值会更大那真正值得考虑 graph

是这三类情况第一个就是流程的是高度重复的，比如说每天处理同类的工单固定生成日报审查合同整理销售的线索第二个就是任务有明确的分支啊，比如说研究的行业报告是政策公司用户评论技术路线可以同时去查到最后再统一的核对和汇总并行的也可以考虑过第三种呢就是结果错不起的像合同财务医疗风控这个任务不能只生成一次的结果

你需要额外加验证人工审批和失败处理这里也能看出来哪些岗位会更早的受到影响不是所有的工作都会被 AI 替代但那些 sop 清楚输入结构化结果更容易验证的岗位会更早的去被设计客户运营基础分析销售的支持流程型的行政都会遇到这件事情他们未来最有价值能力不只是会用一个工具了而是能判断这件事情是交给模型自己探索呢还是应该把它变成一条可控的流程那对普通人
