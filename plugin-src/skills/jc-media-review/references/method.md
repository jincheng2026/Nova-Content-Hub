# 发布复盘

先按当前任务稳定内容/作品ID读取实际发布稿、平台链接、快照、相关选题卡、已提供会议与反馈。不得因默认路径缺失另建档案；原项目后台自动采数不能据源Skill文字假称本项目已具备。

- 优先核对实际12小时和7天快照；目标时间、实采时间、延迟和缺失原因分别记。没采到写没采到，不拿其他时间替代，不向用户重复索取已有数据。只有当前冻结工具许可时才能补采评论或其他数据。
- 不改原始数值、时间、链接或评论原话，无评论直说暂无；会议结论附实际发言者、日期与时间，不替其补观点。
- 分开已确认事实、会上说过的、初步观察、可能原因(附对照)、还不能判断、下一篇可执行动作。
- 每个原因假设都要一个可比对照：同题参考或本人同类内容，说明来源、平台、观察期和口径；比例保留分子分母，不只拿体量不同的绝对量比。不从整条结果归因某一句或某个开头。
- 原因只定位到选题、开头、表达、制作、分发、转化等可说明的方面，接具体下一步动作。缺对照就放还不能判断，不编平台规则。
- 给最多三项有依据的下一篇动作候选，作者决定。评论问题不自动成为选题，先明确范围和真实同类证据；单条结果不升级永久判断。

完成：事实、对照、假设、未知及动作区分清楚，数据时点真实，会议和评论可回查。复盘和知识以允许artifact候选提交并人工采用，不调用上游content_feedback.py、不直接覆盖内容程序区、不宣称后台监控完成。
