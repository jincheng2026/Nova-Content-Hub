# 图形选择字典（P4 选图前必查）

来源：五路一手调研——Zelazny《用图表说话》（麦肯锡）、FT《Visual Vocabulary》（海报原件全文）、Knaflic《用数据讲故事》、Tufte+Few（VDQI/白皮书原件）、Economist 风格手册 v1.2（原件全文）+ NYT/Pew/Reuters 实操。本文件是它们的执行版；与 page-spec.md 配合使用（page-spec 管页面骨架和令牌，本文件管「什么信息用什么图」）。

## 一、选图三步（麦肯锡决策链，顺序不可倒）

1. **先写信息句**（这张图要说的那一句话，也就是它的标题）。
2. **抓句子里的触发词判定关系**：说「占比/份额」→占比；说「比谁大/排第几」→排序；说「涨/跌/自 X 以来」→时间；说「集中在 X 区间」→分布；说「A 越大 B 越…」→相关（图注必须声明「相关不是因果」）；说「从 X 层到 Y 层剩多少」→流向。
3. **按下表选图**。不许先挑好看的图再塞数据；一句话里有两种关系就拆两张图。

## 二、映射表（本报告场景的数据类型 → 图）

| 数据类型 | 首选 | 备选 | 禁做 |
|---|---|---|---|
| 分类计数/赞数排序 | **排序横条**（按值排，主角条用强调色其余灰） | 棒棒糖（细线+端点圆，省墨版） | 竖柱+斜排标签；乱序；断轴 |
| 人群占比（一组 %） | 排序横条＋% 标注 | **华夫格**（10×10 方格，前 N 格上色，「100 人里有 X 个」有体感；只用整数格） | 饼图（人眼读不准角度，五源一致弃用）；环形；3D |
| 构成（部分合成整体，≤5 段） | **单根 100% 堆叠横条**，每段直接标值、去刻度 | 段多时改排序横条 | 饼；堆叠 >5 段；读者只关心谁大时硬画占比图（FT 警告） |
| 同单位两组对照（同指标的前后、两类样本） | **成对横条**（每项两条紧贴：参照组灰、主角组强调色；两组是上限）或**哑铃**（一轨两点一线，强调差距） | **斜率图**（两列点连线，强调方向和反超；线 ≤6 条，连线用内联 SVG 或算好角度的旋转 div） | 双 Y 轴；不同单位用成对条暗示同刻度；超过 2 组的成对条 |
| 漏斗/逐层递减 | **同基线递减横条**（每层一条，条长严格=数值，层间标流失/转化小字）——「漏斗感」由条长递减自然形成 | 居中对齐版（视觉更像漏斗，宽度仍须诚实） | **梯形/金字塔形状编码数值**（宽度面积不与数值成比例＝形状撒谎；FT 词汇表根本没有漏斗图） |
| 五层递进（意识阶梯类） | 层带数值要比大小→同基线横条按阶段顺序排 | 纯示意结构（不带可比数值）→台阶/塔形合法，但读法里注明「形状只表顺序不表数量」 | 台阶高度/塔宽充当数值 |
| 实际 vs 目标/基准 | **子弹图**（背景灰阶区间带+主指标粗条+基准竖刻线） | 成对条 | 红黄绿灯；仪表盘 |
| ≤5 个数、无形态可看 | **大数字卡**（特大数字+口径行+对比锚点——没有参照的数字无法判断好坏） | 6-20 个数且要查值→表格（Tufte：≤20 个数表格胜过图） | 为几个数硬画图；把单个数包进圆环/仪表 |
| 单条高赞证据 | 引文卡＋大号赞数（不构成比较，不画图） | — | 为一条证据做图 |
| 同一种对比跨 N 个切片 | **小倍数**（同图型同刻度的小面板阵列，一行 3-4 格；「唯一变的是数据」） | — | 把第 4 个变量塞进一张图（彩虹分组/双轴/3D） |
| 密集数值表 | **热力表**（去边框、4-5 档分级底色）或表内嵌微型条（td 底部 linear-gradient 画条） | 精确值明细进折叠 | 全框线裸大表 |
| 时间序列（本场景少见） | 折线（≤5 条，超了拆小倍数）；两时点压得住剧情→斜率图 | — | 分类数据画折线；柱形断轴 |

## 三、硬规则（违反任何一条＝图作废）

1. **只信长度和位置**（Cleveland/Few）：要读者比数值，只许用条长或点位编码；宽度、面积、角度、颜色深浅只能表「大概」。这是「弃饼、弃梯形漏斗、弃塔宽编码」共同的地基。
2. **条形零基线**：条长即数值，截轴＝撒谎；想放大微小差异改点图（点不需从零起）或直接给表。
3. **示意/数值一刀切**：塔、台阶、漏斗轮廓、洋葱层宽这类比喻形状，只许当「结构示意」（不带可比数值，或读法注明「形状不表数量」）；一旦读者会拿形状大小猜数，改横条。判据一句话：**读者会不会拿这个形状去猜数？会，就改条。**
4. **灰化+一处强调**（Knaflic）：图内元素默认灰（真灰，不是浅一号的蓝），只把主角加回强调色；有明确比较主角时只强调它；没有主角时可用统一数据色，不规定强调数量。强调色和图上结论文字用同一个颜色——颜色就是图文的连接线。
5. **直接标注，不用图例**：系列名/数值写在图形元素旁边；优先直接标真实值；有意义的小数保留，长序列只标关键点并提供可查明细。斜排竖排文字出现＝换横条。
6. **图题双层制**（Pew/Economist）：结论句标题＋一行小字口径副题（测了什么/样本/时间窗）；图卡自足——被单独截图时结论和口径都在（OWID 三件套）。
7. **图内注释写「发生了什么」**：异常条/关键层旁直接放短句（细引线小灰字）。静态报告没人现场讲解，注释就是讲解，密度要高于幻灯片场景。
8. **数量上限**：类目多时按阅读宽度增加高度、筛选或分组，不机械裁到 4 类；线 >5 拆小倍数（Pew）；堆叠 ≤5 段；成对条 ≤2 组。
9. **表不是降级品**：查精确值、数值挤成一团画不出差别时，表格是首选不是妥协；仅有的可见表按 Economist 规范升级（去边框、关键行高亮、可嵌微型条）。
10. **折叠分级**（NYT Tse「别指望任何人点击」）：影响判断的证据必须在滚动可见层，折叠只放完整性材料；折叠标题写明里面有什么、多少条。
11. **颜色边界**：「其他/未知」永远用灰；时间先后类目用同色由浅到深；红只做禁区语义不进普通分类色序；橙与红不在同一图内承担相邻对比（红色盲下趋同）。发布前灰度截图自查一次可分性。
12. **相关不是因果**：任何「A 高→B 多」的图，图注声明相关口径，否则读者默认因果（FT 类别级警告）。

## 四、纯 CSS 组件对照（960px、无图表库；页面令牌见 page-spec）

- 排序横条：行 grid「标签+轨道+值」，条 div `width:%`，值标条端，无轴无网格。
- 成对横条：每项两行紧贴，上灰下强调。哑铃：相对定位轨道+两圆点+`left/width` 算好的连线 div。
- 斜率图：两列端点+内联 SVG `<line>`（或角度写死的旋转 div）；≤6 条。
- 华夫格：`grid repeat(10,1fr)` 100 格。
- 100% 堆叠条：flex 分段+1px 缝+段内标值。
- 诚实漏斗：递减横条组（左对齐或居中），层间小字标转化/流失。
- 子弹图：灰阶区间带+主条+2px 基准竖线。
- 大数字卡：48-72px tabular-nums 数字+口径行+对比锚点行；一屏最多一个。
- 小倍数：grid 同构迷你图，共享同一 `--max` 保证同刻度。
- 热力表/表内条：td 分档背景色 class；或 `linear-gradient(90deg, var(--accent) var(--w), transparent 0)`。
- 放弃不做：真桑基、和弦、网络图、多点散点、地图——降级为分层堆叠条/哑铃/表格。

## 五、图的验收（并入 publish_check 后的人工五件套）

1. **遮标题测试**：盖住图只读标题，结论成立吗；盖住标题只看图，图指向同一结论吗。
2. **闭眼测试**：看别处→回看，眼睛第一落点是不是该图主角；不是就减强调。
3. **强调计数**：没有无意义的多色与多处强强调，重点由分析问题决定。
4. **比例诚实**：所有条从零起；任何形状的大小若会被当数值读，检查是否严格成比例。
5. **灰度检查**：截图转灰度，层级和主角仍可分。

## 六、解释和定性材料怎样展示

没有数量时，先判断是否真的有需要画出的关系。原话与解释段落常常已经足够，不强制每个板块有图。

| 信息 | 合适的呈现 |
| --- | --- |
| 评论中几个不同的实际场景 | 短段落与原话卡，或同字段的并列卡 |
| 对标材料与本人材料的差异 | 并列卡或简表，双方来源与范围同时可见 |
| 评论提出的问题与视频回答 | 同一问题下并列呈现原话、对应段落和回复覆盖 |
| 已确认的步骤、获取资料过程 | 顺序图；没有检查过的步骤标为未知，不画成已经完成 |
| 一项推断与其他解释 | 连贯段落或并列解释，注明各自依据与缺口 |
| 购买理由 | 有明确购买原话或交易材料才分析；不能把观看理由当购买理由 |

评论条数与获赞不是同一单位，应分成同顺序的两张小图或两个独立刻度区，并分别直接标值。默认模板同时展示二者，移动端按主题放到相邻行。

不用塔宽表示心理深浅，不给推测的情绪或购买倾向打分，不把阶段先后画成用户一定会经过的转化路径。方法论需要的示意图可以留在分析底稿，不能靠图形制造不存在的结论。
