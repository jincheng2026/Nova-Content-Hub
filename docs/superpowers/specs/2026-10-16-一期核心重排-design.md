## 1. 一期是什么

**卖点只有两件事**：① 把一批喜欢的封面拆成可复用的模板；② 用这套模板给一条内容出封面。

总览 / 内容 / 日历 / 模板 / 提示词 **五样都是一期能力**（2026-10-16 产品决策：「最核心的是那几样，但这些都是第一期能力」），改的是
**顺序和深度**，不是砍页。 **物料不再是独立一页**
（同一天定的）：旅行有物料页是因为一场活动要出四类物料（海报/公众号文章/长图/社群文案），跨活动汇总有真价值；我们只有封面一种，而挑图这个动作必须在项目里做（批次上下文在那），汇总页只能看不能挑。它剩下的两个真需求挪去内容页：
**跨项目找图、批量下载、查重、看这个号所有封面** → 内容页顶部「内容 / 全部封面」视图切换。

```
1 总览     2 模板★   3 内容★（含「全部封面」视图）   4 日历   5 提示词   （底部）更多
```

★ 的三页做到别人抄不动，其余按"够用"做。核心链路要能一路走到底不回头：模板拆完 →「用它出」→ 落到一条内容 → 物料里挑 → 排发布。

**一期不做**：正文文案、发布数据回收、 **写总结/复盘**（发完没有数据，总结是空话）、对标账号、定时发布、飞书联动、数字人、多人协作、模板市场。界面上也不留位置，不做灰掉的占位按钮。
**鉴权**：工程一期不做、原型保留完整设计、按 §3 五处预留。 **物料**：不做独立页，能力并进内容页。

## 2. 内容库结构

一个普通文件夹就是插件和工作台之间唯一的约定。老板能直接打开拿图、能整个拷走、能放 U 盘。不用数据库。

```
自媒体内容库/
├─ 内容/                          一条内容一个文件夹：「2026-10-18 对标拆解她为什么三个月涨10万粉」
│  ├─ <日期 题名>/
│  │  ├─ 封面/                    成品图，老板直接拿：第1批/01.jpg … 选定-竖版.png
│  │  ├─ 参考/                    逐字稿、拆解、口述——随便放，不登记也算这条的
│  │  ├─ 其他/                    一次性产物 + _README.md 记「来源/日期/为什么留/可删条件」
│  │  ├─ 原始资料/                老板拖进来的文件，原样保存、不改名
│  │  ├─ 旧版本/                  「<日期> <原因≤20字>」；没做完的、被换下来的、删掉的
│  │  └─ 数据（别动）/             5 个 JSON + 锁/ + 上一版/ + 批注/ + 改动记录.jsonl
│  └─ 已删掉/                     删掉的内容原样放着，能恢复
├─ 模板库/
│  ├─ 能用/<模板名>/               还原测试过了才进这里
│  │  ├─ 模板.json                 参数 + 治理头（§6）
│  │  ├─ 出图约束.md               跟着模板走的提示词，出图时强制读
│  │  ├─ 拆解.md                   规则 + 证据编号（K03 K07…）
│  │  ├─ 原图/  还原测试/
│  ├─ 待拆解/<博主名>/             拖进来还没拆的
│  └─ 已停用/
├─ 我的素材/  账号.json · 正脸照/ · 照片/
├─ 提示词/                         内置起步库 + 老板存的（§10）
├─ 进度记录（别动）/  任务/ · 对话/
├─ 系统（别动）/  内容库.json · 工作文件夹/<任务id>/ · 锁/ · 上一版/ · 工作台设置.json
└─ （根目录没有文件）
```

### 2.1 `layout.mjs` 常量（名字只在这一个文件里定）

```js
LIBRARY_NAME  '自媒体内容库'
ROOT_FOLDERS  [内容, 模板库, 我的素材, 提示词, 系统（别动）]     ROOT_FILES []
LIB_FILE      系统（别动）/内容库.json                          认库 + 格式版本
ACCOUNT_FILE  我的素材/账号.json                                认库的第二标志
TPL_ROOT '模板库'  TPL_READY '能用'  TPL_TODO '待拆解'  TPL_OFF '已停用'
TPL_FILE '模板.json'  TPL_CONSTRAINT '出图约束.md'  TPL_STUDY '拆解.md'  TPL_SHOTS '原图'  TPL_RESTORE '还原测试'
FILES  { project 项目.json, covers 封面.json, posts 发布.json, card 内容卡.json, todos 待办.json }
       // 没有 打勾.json：旅行的"打勾"在我们这里升级成 发布.json 里一条真记录（§8），一份事实只留一处
PROJECT_FOLDERS [封面, 参考, 其他, 原始资料, 旧版本, 数据（别动）]
TRASH '已删掉'（在 内容/ 下）  PROGRESS '进度记录（别动）'  TASK_DIR '任务'  TURN_DIR '对话'
SYSTEM '系统（别动）'  WORK_DIR '工作文件夹'  SETTINGS_FILE '工作台设置.json'
LOCK '锁'  BACKUP '上一版'  BAK_SUFFIX '.bak'  ANNOT '批注'  CHANGES '改动记录.jsonl'
PROMPT_DIR '提示词'   ← 我的素材之外，模板的提示词叫 出图约束.md，不重名
```

认库看 `LIB_FILE`，其次 `ACCOUNT_FILE`；认一条内容看 `数据（别动）/项目.json`（正本没了只剩它的 `.bak` 也认，U 盘中途拔盘的场景）。

### 2.2 版本闸门（今天就写，一天都不能晚）

`系统（别动）/内容库.json`：

```json
{ "schema": 1, "layout": 1, "createdAt": "2026-10-16T10:00:00+08:00",
  "minWorkbench": "0.1.0", "minPlugin": "0.1.0" }
```

- `libraryFormat(lib, { who, version })` 一个函数回答"这个库的格式，我这个程序认不认"。
- 库的 `layout` 比程序认得的 **新** → 整个库 **只读**：插件写命令报 `LIBRARY_TOO_NEW`，工作台弹一次框 +
  总览顶上一行「只能看」，所有写动作拦下（§9 的白名单），读和复制照常。
- 程序版本低于 `minWorkbench` / `minPlugin` → 同样只读。
- **没有这个文件，第一次改目录结构就会废掉所有老用户的库。** 旅行为了补这一步花了一个大版本。

### 2.3 不认识的文件夹（strays）

打开库时根目录/内容第一层出现名单外的文件夹 → 弹一次【挪走，过几天自动清】【不动】；选挪走就进 `系统（别动）/工作文件夹/`
，修改时间改成现在，7 天跟着草稿一起清。 两条旅行踩过的坑直接避开： **打开以后再记**（别在整理流程中间记，会把刚清掉的又记一遍）；
**这个框被别的框顶掉时不算"不动"**，别的框开着就先不弹。

### 2.4 名字规矩 `naming.mjs`（一份，别处不写）

批次 `第N批`；候选 `01.jpg`…`20.jpg`；旧版本文件夹 `<日期> <原因>`，原因 ≤20 字、去掉标点；重名加 `（2）`，数字撞了加 `-2`；文件名上限
32 字，模板名 24 字。

## 3. 鉴权：一期不做，但预留这五处

2026-10-16 产品决策： **鉴权体系独立于旅游工作台，当前阶段先不做，要预留扩展，后面统一加。**
"预留"具体是这五件事——现在做成本≈0，事后补要改几十个文件：

1. **写动作全部收口**。所有会写库的入口走同一个 `write(action, fn)`；将来 `assertWritable()` + `assertEntitled()`
   只插在这一个地方。renderer 每个 `wb:` 动作必须归类成"写/读"， **测试查有没有没归类的**（旅行 read-only.ts 就是这么逼的）。
2. **一个 CLI、一个 dispatcher**。插件命令全走 `content.mjs <cmd>`，鉴权闸门加在 dispatcher 一处，除 `help`/`summary`
   外每条都查（旅行 entitlement.mjs 的规矩）。将来加鉴权不动任何 skill。
3. **scope 常量今天就定死**：`APP_SCOPE = 'nova-content-hub'`，只在一处定义。将来 `entitlement.json` 按 scope 分条，不会长出三个写法。
4. **用户目录今天就用**：`~/.nova-content-hub/`（一期只放 `library.json` 记库在哪）。将来 `entitlement.json` 落进同一目录，不搬家。
5. **数据里不存操作人**。一期单人单机，`项目.json`/`封面.json` 里 **不放** `userId`/`author`
   字段——鉴权是"这台机器这个用户能不能用"，不是"这条记录谁写的"。旅行就没塞。将来加鉴权不需要清洗数据。

**一期界面**： **原型里保留完整的鉴权设计**（更多页的「账号 / 已开通 / 手机号 / 刷新 / 退出登录」照最终形状画），
**工程分阶段实现**——先上写动作收口和 scope/目录预留，再上登录，最后上开通校验和只读降级。 这不和「假按钮零容忍」冲突：
**原型是设计交付物，那条铁律管的是发出去的产品**。文档里这块标一句「工程一期不实现」就够了，代码里留一个默认关的
`FEATURE_AUTH` 开关。 **一期不记消耗**。将来 meter 的数据落在 `进度记录（别动）/任务/<id>.json`（消耗是任务属性），不落
`封面.json`（那是产物台账）。

## 4. 任务与跳转

**没有"工作台先写工单文件"这回事**（我上一轮提的 `待办任务/<id>.json` 已撤回——那是第二份真相，而且会在工作台侧凭空造出一张
AI 还没接单的卡）。照旅行：

```
工作台拼一句话（带 id）→ 填进宿主输入框 → 老板点发送
→ Skill 第一件事跑 content.mjs task start --kind 出封面 --target '<json>'
→ 写 进度记录（别动）/任务/<id>.json（含 target、步骤单、work 工作文件夹）
→ 钩子另写 对话/（UserPromptSubmit=在跑、Stop=在等你、Interrupt=点了停、StopFailure=出错）
→ 工作台照 进度记录 摆卡。AI 没接单就没有记录，界面上真的什么都没有（所以不需要"排队中"）
→ 出完写 封面.json 的批次，task finish
```

- **步骤单在插件里定义**，带 `optional`：出封面 = `看料 → 出图 → 自检 → 确认`；拆模板 =
  `导入原图 → 拆解 → 还原测试(optional) → 确认 → 保存`。
- 话术格式（照 `spokenOf` + `blanks`，说明放最后一行，因为宿主会把 Skill 标签插在话尾）：

```
给「对标拆解：她为什么三个月涨 10 万粉」（id pro-20261018，10 月 18 日发）出封面。
尺寸：竖版 1080×1440。
模板：满版照片大白字（id tpl-bleed）。
一批 10 张。
优先参考：这一条 封面.json 里标了 prio 的那几张，当参考图。
其他要求：
出完登记进这一条的 封面.json，并按步骤单更新进度记录。
$出封面
```

- **参数不落中间文件**：尺寸/模板/张数写在话里（短枚举，不会丢）； **优先参考图的路径不进话**——它本来就在 `封面.json` 里标着
  `prio: true`，AI 自己读文件。
- **名字撞了就写 id**（照旅行 `spoken: twin ? m.id : label`）。
- **AI 不自己拼路径**：`task start`、`cover list` 这些命令回 `folder` / `where` / `prefix`（绝对路径或库根相对路径）。skill 里
  **不许出现 `../`**——物料将来多一层目录，让 AI 数层数一定错。
- 宿主只有 `workbuddy`、`codex` 两家。钩子一张事件表出两份文件（`hooks.json` 公共 + `workbuddy.json` + `codex.json`），
  `unknownEvents()` 打包时查事件名认不认得。Windows 那句钩子命令要套 `cmd /d /s /c`（PowerShell 5.1 会把带引号路径的写法吃成语法错）。

## 5. 尺寸

三层，默认不烦人：

1. **渠道预设**（自动勾）：抖音/视频号→竖版、小红书→方图、公众号→头图、B站→横版。带平台建议像素。
2. **常用比例**：16:9 / 4:3 / 1:1 / 3:4 / 9:16 / 2.35:1。
3. **自定义**：宽×高，存 `系统（别动）/工作台设置.json` 的 `sizes[]`，带名字，跨内容复用。

- **比例是产品事实，像素是可改的默认值**。每个预设带 `{ ratio, w, h, source, checkedAt }`；`checkedAt` 超过 6
  个月，「检查一下」报「这条平台默认值没核过了」。平台规定尺寸会变，写死一份表 = 埋一个会过期的常量。
- **2026-10-16 核到的一手情况**（写进默认值表，核不到的 **留空标「待核」**，不凭记忆填）：

| 版式                | 像素                                             | 来源                                                                            | 状态                                                                                     |
|---------------------|--------------------------------------------------|---------------------------------------------------------------------------------|------------------------------------------------------------------------------------------|
| 竖版（抖音/视频号） | 无公开值                                         | 抖音、公众号公开文档都查不到建议像素；1080×1440 / 900×383 只存在于第三方聚合站  | 视频号助手前端给的是可裁区间 **3:4→1:1、下限 300×300**                                   |
| 方图（小红书）      | 无公开值                                         | 小红书官方 bundle 只说支持 **3:4 和 1:1**，不给像素                             | 比例可信，像素留空                                                                       |
| 头图（公众号）      | 无公开值                                         | 900×383 只在登录后的公众号编辑器里，公开文档查不到                              | 留空                                                                                     |
| 横版（B 站）        | 1146×717、下限 960×600、**比例 16:10 不是 16:9** | 哔哩哔哩创作中心公告 [read/cv0565906](https://www.bilibili.com/read/cv0565906/) | **链接真实存在，但正文 JS 渲染抓不到，数值未独立复核** → 用，但 `checkedAt` 记「未复核」 |

这条表本身就是产品判断： **四个版式里只有一个是官方可查的**，所以界面上"渠道预设"要显示的是 **比例**
（可信）而不是像素（大多不可考），像素那一栏写「按平台习惯 1080×1440」这种措辞比写死数字诚实。

- 校验但 **不拦**：最短边 <720 提示"发出去会糊"；比例 >3:1 提示"太窄，字容易拉变形"；单边 >4096 提示"超出可生成范围，按 4096
  出"。
- **一批 = 一个尺寸**（2026-10-16 定）。勾 3 个尺寸建 3 个任务、3 条进度：「竖版 10/10 · 方图 3/10 · 头图 失败」。一条总进度条会骗人。
- **模板声明自己擅长哪些比例**，且 **不用人填**：拆解时那批原图的宽高在台账里，AI 归纳时就知道这套是竖版拆的还是横版拆的 →
  自动写 `fit_ratios` 和 `needs_relayout`。选了不擅长的比例不拦，但说人话： **「这套是从竖版拆的，出 16:9
  要重排，可能不像。要么只为这个比例再拆一套。」**

## 6. 模板

**2 个通用 skill + 模板是数据**（2026-10-16 定；旧学员版 `cover-vi`/`cover-maker` 和旅行 `机构信息/海报模板/` 两边都是这么做的）：

- `拆封面模板`：逐张看图 → 归纳规则 → 出对照页 → 还原测试。
- `出封面`：读被指定那个模板文件夹的 `出图约束.md` + 参数 → 出一批。

一个模板文件夹 = 一个可售卖资产：能导出、能拷给别人、导入就能用。 **一模板一 skill 的方案否掉**：装 20 套就是 20 个
skill、还要同步到两家宿主两处、删改要重装、做不了"换套风格再出一批"的横向对比、升级要动 N 份。

### 6.1 治理头（照 skill manifest 的思路，`模板.json` 里）

```json
{ "id": "tpl-bleed", "name": "满版照片大白字", "version": "1.0.0",
  "source": "拆自「星河创作社」19 张", "owner": "别人家的",
  "commercial": "只学构图和文字关系，不搬运素材",
  "restoreTest": { "passed": true, "at": "2026-10-12", "against": "K03" },
  "fitRatios": ["3:4","1:1"], "needsRelayout": { "16:9": "标题从上下夹改成左文右图" },
  "usedBy": 4, "editedByOwner": false, "trustNote": "这是公开画面的归纳，不是官方 VI" }
```

- `owner` 只有两个值：`自家的` / `别人家的`。 **从别人账号拆的默认标「别人家的」**，界面和导出包里都带着；`trustNote` 那行原样抄旧版
  `VI拆解.md` 的措辞——看不出的字体名、色值、制作工具不写成事实。
- **还原测试是"能不能用"的闸门**：拿参数重新生成一张，和原图并排，对得上才允许进 `能用/`，否则停在 `待拆解` 旁边标「待修」。
- 再加一道 **换内容测试**：同一套模板套 3 个不同标题，看还认不认得出是同一套。认不出=拆得太浅。
- 状态用目录表达（`待拆解/` → `能用/` → `已停用/`）， **`模板.json` 里不存 status 字段**。

### 6.2 拆解过程要可见

`第 1 步 导入原图 → 第 2 步 逐张看图 → 第 3 步 归纳规则 → 第 4 步 还原测试 → 第 5 步 确认保存`，写步数不写百分比。
拖进来先给反馈：识别到 20 张 / 8 张重复 / 3 张打不开 → 起个名字 → 拆。 旧版 `cover-vi` 两条最值钱的规矩原样搬进产品： **"
缩略图看过不算，每张都要在能看清细节的尺寸打开"**、 **"换名字检查：隐去博主名，结论还分不分得得出他和相似博主"**
——分不出就回原图补动作、字形、空间关系。

## 7. 封面（物料层）

对到旅行的模型： **批次 ≈ 版本，候选 ≈ 版内几张**。选定之后才把那张复制成 `封面/选定-竖版.png` 当"当前版文件"，这样旅行的
`material-versions.mjs`（设为使用 / 删版本 / 改名 / 撤回）逻辑能整段复用。

```json
// 数据（别动）/封面.json —— 一条 = 一个尺寸
{ "id": "cov-v", "size": "竖版", "ratio": "3:4", "px": [1080, 1440],
  "batches": [ { "no": 1, "at": "2026-10-16", "tpl": "tpl-bleed", "state": "done",
    "cands": [ { "no": "01", "file": "封面/第1批/01.jpg",
      "sha256": "…", "bytes": 1748449, "px": [1080,1440],
      "srcPath": "/Users/…/exec-098c.png", "store": "clonefile",
      "prompt": "…", "fav": false, "prio": false, "note": "", "use": true } ] } ] }
```

- **台账**（照第二大脑 `manifest.json` 的 assets）：每张记 `sha256 / bytes / px / srcPath / store`。能去重（"这张和第 3 批 07
  是同一张"）、缩略图不用重解码、老板换过图查得出来。APFS `clonefile` / Windows 硬链接让"原图保存"不真占双倍地方。
- **收藏 `fav` + 优先参考 `prio`**：`prio` 的图下一批真喂回模型当参考。这是"越用越准"唯一实在的机制。
- 筛选：全部 / 已收藏 / 优先 / 还没挑过。 **对比只在同尺寸里**（跨尺寸并排没意义，界面分组隔开）。
- **选定按尺寸各选一张**，进度就是 `2/3 个尺寸已定`。
- 三种重出互不覆盖：`备注改这处`→新批次编号继续、标「参考：第1批 05 + 备注」；`换个尺寸`→只出缺的那组；`换套模板`→新批次并排，
  **不顶掉已选定的那张**。
- 每张能看它那份 `prompt`（可复制、可改后重跑）。 **提示词页不放这个**——那是生产数据，跟着物料；提示词页只放内置起步库和老板存的。

## 8. 状态推导与四态诚实

**状态一律算出来，不写文件**（旅行 + 第二大脑两条铁律）。阶段、缺 N 项、待办 N、旧模板、几个尺寸已定，全是推导。

四件不同的事，不许混（第二大脑铁律 4）： **计划做 / 技术上做完了 / 人工验收通过 / 真发出去了**。

- 一期没有数据回收，所以「真发出去了」只能由人给。做法不是打勾，而是**「记一条发布」 **：哪天、哪个渠道、链接可选 → 生成 `发布.json`
  里一条记录。它比打勾多一下点击，但那一下本来就该做，而且产出的是**数据**不是状态；二期接采集直接往同一份文件补数字，不改结构、不迁移。
- 判定规则只有一条，从头到尾不变： **有发布记录 = 已发**。
- 界面两栏分开：`你说发了`（有记录）和 `平台数据`（一期显示"还没接"，不装）。
- 推导不出的显示"未知"，不猜。

**一期不做往期**（旅行有 `活动/往期/`，满 30
天自动挪）。封面不一样：一条内容发完，它的封面还要被当参考图、被复用构图。挪走会让"优先参考"跨目录找图。`内容/`
一层平铺，靠排序 + 筛选压住；等真有几百条再抄 `pastState`。

### 深夜四（同一会话继续）：图片统一组件 + 灯箱修 bug + 内置基线

- **展示口径（他纠正过一次，别再犯）**：统一的是 **列宽**，不是盒子比例 —— 图按真实像素比例显示，不裁不 letterbox。`auto: true`
