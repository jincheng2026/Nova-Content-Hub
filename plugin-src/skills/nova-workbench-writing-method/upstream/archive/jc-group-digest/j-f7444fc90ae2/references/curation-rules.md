# 策展规则模板（阶段 2）

输入：群画像 + 检查点 1 的四个决定。产出：这个群专属的策展规则文档 + 3 天真实精华 JSON。

核心要求：**规则表最终要翻译成确定性代码跑日更**（原因见 pipeline-setup.md），所以每层的识别特征必须落到程序能判断的具体条件（发送者白名单、长度阈值、时间聚簇、关键词、参与人数），禁止只写「有价值的内容」这种人类才能执行的描述。

## 检查点 1 的决定如何影响规则

| 决定 | 影响 |
| --- | --- |
| 给谁看：内部 / 外部 | 默认都做昵称映射，且过滤手机号、邮箱、住址、身份证件、财务、账号和报名信息。只有获得明确授权且内部站有可验证访问控制时，才可保留真实昵称 |
| 核心内容：原文 / 改写 | 原文：多条按时间聚簇合并成段落，一字不动；改写：AI 参与，日更管线必须加输出验证与失败兜底（见 pipeline-setup.md） |
| 讨论：对话链 / 摘要 / 摘要+点开 | 决定 discussion 的 JSON 结构和前端交互（摘要+点开是已验证的默认推荐：首屏信息密度和完整性兼得） |
| 审核：全自动 / 人工 | 默认人工审核，管线在部署前停下，生成预览、隐私扫描结果并通知用户确认 |

## 通用分类框架（四层，按群定制）

| 层 | 通用识别特征（改成该群的具体条件） | 处理方式 |
| --- | --- | --- |
| 1 核心输出 | 核心输出者白名单内 + 单条较长或时间聚簇成组（间隔 ≤30 分钟归一组） | 按检查点 1 决定处理，提取主题标签，取首句生成标题 |
| 2 有价值讨论 | ≥3 条围绕同一话题、≥2 人参与 | 生成摘要，保留对话链（发送者、时间、内容、引用回复） |
| 3 公告活动 | 含时间、地点、报名方式等结构化要素 | 提取为结构化卡片（活动名、时间、参与方式） |
| 4 噪音 | 拍一拍、单表情、+1/收到/好的、重复打卡、图片视频占位符、系统消息 | 丢弃，不进日报 |

金句提取（可选层）：核心输出中单段、约 8 到 60 字、无链接、观点浓度高的句子，抽出来做 pullquote。每天上限 3 到 4 条，多了就稀释。

## 精选标准（宁缺勿滥，铁律）

- 一天 2 到 3 条核心输出 + 1 到 2 个讨论就是一期合格的日报
- 某天没有高质量内容，sections 输出空数组，前端渲染「今天群里比较安静」，这本身就是诚实的产品体验
- 禁止为了显得有内容而降低入选线。日报的信任来自「出现在这里的都值得看」

## 摘要写作标准

目标：让没看原文的人产生好奇，点开对话链。

- 禁止：「成员们讨论了育儿话题」「大家交流了投资心得」这类废话，它只是把标签改写成句子
- 配方：具体冲突、具体结论、具体数字，三者取其一，控制在 30 字内
- 对比：
  - 坏：「群友讨论了辅食问题」
  - 好：「8 月龄要不要加盐？两派妈妈吵出了儿科指南原文」
  - 坏：「大家分享了工具使用心得」
  - 好：「一条命令省 3 小时：他把周报自动化的完整脚本贴群里了」

## 每日精华 JSON schema（通用基线）

```json
{
  "date": "YYYY-MM-DD",
  "summary": "一句话总结当天（也要过摘要标准，禁废话）",
  "stats": { "total": 157, "selected": 28 },
  "sections": [
    { "type": "reading", "title": "…", "paragraphs": ["已脱敏原文…"], "tags": ["…"] },
    { "type": "pullquote", "text": "已脱敏金句", "who": "群友 A · 时间" },
    { "type": "discussion", "summary": "30字内摘要", "participants": ["群友 A", "群友 B"], "tags": ["…"],
      "messages": [{ "sender": "群友 A", "time": "HH:MM", "content": "已脱敏原文…", "reply": "可选" }] },
    { "type": "activity", "label": "…", "title": "…", "detail": "…" }
  ]
}
```

- `stats` 基线只放 total 和 selected（实测「几人活跃」这类指标用户不关心，展示层砍掉了）
- section 类型按群增删，但改 schema 必须同步改三处：前端渲染、注入脚本、日更处理脚本
- paragraphs 内保留 `\n`，换行由前端转 `<br>`（见 tech-redlines.md）

## 试跑 3 天（规则的验收，不可跳过）

从历史消息选 3 天：消息量多、中、少各一天，用规则实际产出 3 份精华 JSON，逐份人工检查：

1. 分类对不对：核心输出有没有漏、噪音有没有混进来
2. 摘要过不过标准：拿「没看原文的人会想点开吗」自问
3. 金句是不是金句：抽出来单独看还成立吗
4. 少消息那天是否如实输出了安静，而没有硬凑
5. 长清单、多段落的 `\n` 是否保留完整

试跑产物直接留用：检查点 2 的风格 demo 和阶段 3 建站都用这 3 天真实数据填充。
