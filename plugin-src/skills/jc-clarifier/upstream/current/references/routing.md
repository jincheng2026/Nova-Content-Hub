# 路由与边界

## 应该触发

当用户的核心需求是「先把问题想清楚」或「把需求改写成给另一个 AI 的提示词」时触发。

典型表达：

- 帮我想清楚
- 我有个模糊的想法
- 帮我写个提示词
- 我不知道怎么跟 AI 说
- 澄清一下
- clarifier
- 这个问题该怎么问
- 把这个任务写成给 Codex 的 `/goal`

## 不应该触发

这些请求应交给执行类助手或其他 Skill，不要被 clarifier 抢走：

- 用户已经明确要求直接写文章、文案、HTML、PPT、报告、代码。
- 用户要求读取、整理、归档、移动、修改文件。
- 用户要求调研、搜索、查资料、总结网页或飞书原文。
- 用户要求处理截图、视频、音频、数据文件并产出最终结果。
- 用户要求检查环境、运行命令、修 bug、部署项目。
- 用户问一个可以直接回答的事实问题。

如果请求里同时有「帮我写提示词」和执行目标，优先按 clarifier 处理；输出给新聊天使用的执行提示词，不在当前 Skill 内执行。

## 主模式判断

| 模式 | 触发信号 | 输出 |
| --- | --- | --- |
| 轻量澄清 | 用户想法模糊，还没决定要 AI 做什么 | 2-4 个关键选择题，必要时给猜测 |
| 完整提示词 | 用户明确要 prompt、提示词、新聊天任务 | BROK 提示词 |
| 问题提炼 | 用户问「这个问题该怎么问」 | 清晰问题 + 追问清单 |
| 决策提示词 | 用户纠结要不要、怎么选、值不值得 | 决策分析 prompt |
| Skill 修改提示词 | 用户要改 Skill、优化提示词或工具 | 给执行 AI 的修改 prompt |
| Goal 合同 | 用户明确说 `/goal`、Goal 模式、Codex Goal | 可审计 `/goal` 合同 |

## Goal 显式触发门

只有这些表达能进入 Goal 输出：

- `/goal`
- Goal 模式
- Codex Goal
- 帮我写一个给 Codex 的目标
- 把这个任务写成 `/goal`
- 生成 Goal 模式提示词
- 给我一个可复制的 Codex goal

这些表达不能单独触发 Goal：

- 长任务
- 后台跑
- 一直做
- 持续执行
- 直到完成
- 不停地迭代

遇到后一类表达，只能提醒：「这类任务可以考虑 Goal，是否要我写成 `/goal`？」

## Near-neighbor 排除

- BROK 优化器：当用户已经有清晰提示词，只想精修 Role、Key Result、格式时，转给 BROK 优化器。
- 内容写作 Skill：当用户要最终成稿，不是要提示词时，不走 clarifier。
- 代码/项目执行 Skill：当用户要直接修复、实现、测试、部署时，不走 clarifier。
- 飞书/文件处理 Skill：当用户要读取、写入、同步、归档时，不走 clarifier。
- 学习助教场景：如果用户问的是课程概念解释或当前卡点排错，直接帮助学习，不强行转提示词。

## 退出 clarifier

如果用户已经确认要执行原任务：

1. 先输出一版可复制执行提示词。
2. 说明当前 Skill 到此结束。
3. 只有在用户明确要求「现在你来执行」后，才按普通助手身份继续。
