# 按天发布清单与创作到发布衔接

日期：2026-10-19。版本：0.3.23。

## 采用的工作方式

参考用户提供的旅游营销工作台月历下方当天清单，以及本机安装版本的只读界面实现。重点是选日后可直接执行当天安排：时间、渠道、发布标题、状态和操作在一行呈现，具体文字与图片按需查看。参考程序只读分析，提取的临时文件留在忽略目录，不复制进源码或交付包。

日程下方保留一份当天清单，使用关键词、渠道和状态筛选，并按时间排序、每页20条。相同筛选同时应用于月周日历和当天清单。待发布行直接打开实际发布确认，已记录行查看对应历史；打开窗口不写入，用户确认后才保存实际时间。默认视图排除已取消计划，取消筛选保留重新安排入口。

单篇内容的发布计划也使用紧凑排列，每页10条，准备发布的文字、封面和实际历史快照按需展开。复制使用这条计划自己的文字；导出使用它明确选择的封面原图。明确的空文字和无封面选择保持原意。

总览沿用同样的紧凑队列，区分今天没有安排、今天全部记录完成和仍有逾期需核对。“记录已发布”直接进入确认，空日期也能准确跳入日程。封面选定区域提供“安排发布”入口，候选选择待办直接进入已有封面列表。

## 数据与交互约束

- 计划安排和实际发布是两份事实。确认窗口按原计划的时间精度与时区初始化当前实际时间，捕获打开时的CAS token；显示时区和更正后的快照不回写原计划。
- 更正和撤销保留原记录及原因。日程和总览使用当前有效发布快照的日期与标题；更正后的旧记录不重复统计。
- 新增日程选择正常、非示例的单篇内容。已有合集计划仍可编辑、记录、取消、更正和撤销；合集继续作为分类入口使用。
- 窗口暂时收起后保留输入并阻止其他发布写入口；冲突、外部回收或缺失不自动清除草稿。初始目标已缺失时提供可关闭提示。
- 渲染保持分页和可见日期边界。有效发布记录通过每份文档的事件Set与记录Map投影，避免历史记录增多后反复扫描。
- 发布操作仍由用户在平台完成；复制、导出和打开确认窗口均不代表已经发布。

## 验收边界

类型、纯逻辑与真实React/Semi/Electron交互分别验证；真实文件库另通过安装包的renderer、preload、IPC与worker执行记录和更正，并核对正文、计划时间及无关内容字节。大样本DTO交互不能替代磁盘读取或冷启动证明。最终通过项及安装收据在交付前补记。
