GitHub 是什么呢？很多人刚开始学编程，会被三个词搞混：一个是 Git，一个是 GitHub，还有一个是 VS Code。

之前的视频我给大家讲清楚了 Git 的概念，它是记录版本的工具。OK，然后 VS Code 是写代码的地方。那 GitHub 是什么呢？我用一句话给大家解释：它是存放 Git 仓库的网站，同时也是全球最大的代码协作平台。

OK，用一个生活类比去理解它。你可以把 Git 理解成你电脑里面的本地存档系统，记录每一次代码改动。但是它只有一个问题，就是 Git 在你本地，但凡电脑坏了，代码就没了；想要和别人合作，也没有办法。GitHub 解决的就是这个问题。

它相当于是一个代码云盘，但比云盘要聪明很多。它不只是存文件，还能够存完整历史记录的 Git 仓库。每一次 Commit、每一个分支、每一条注释，全部都在。

再类比一下，GitHub 之于代码，就好像 Google Docs 之于文档一样。多人可以同时参与，有完整的修改记录，随时可以回滚。

我以这个图举个例子。每个人，比如电脑 A、电脑 B，可能还有电脑 C 或者电脑 D，他们有自己的个人电脑。每个人都可以在自己的电脑里面用 Git 工作，每个都有一个 Git 仓库。它可以通过 `git push` 把代码推到 GitHub 上，电脑 B 也可以把自己的本地修改推送到 GitHub 上，包括 C、D。同时，它也能够从 GitHub 上拉取代码。

所以，所有人都可以围绕着同一个 GitHub 仓库做各种协同，历史记录也是完整共享的。

OK，那大家可能会问，A、B、C、D 这么多人操作，会不会有冲突？所以 GitHub 有关键的一些点，包括 Issue、PR、Actions，来保证代码同步以及避免冲突。GitHub 不只是一个代码云盘，它在存储上还叠加了一整套协作工具。

再说 GitHub 里面的几个关键词。第一个关键词叫做仓库，Repo 或者 Repository。仓库是 GitHub 上最基本的单元，简称 Repo。一个项目对应一个仓库，里面包含这个项目全部的代码、所有历史提交记录、分支、文档，以及下面说到的 Issue 和 PR。

仓库可以是公开的，叫 Public，也可以是 Private。Public 就是任何人都能看到，Private 就是只有被邀请的人或者自己才能看到。

OK，然后再说第二个关键词，就是 Issue。Issue 直译下来就是「事件」，在这里面叫做问题追踪。Issue 是 GitHub 内置的任务管理系统，你可以用它记录 Bug、提功能需求、做开发计划。每一条 Issue 都可以被讨论、指派给某个人、打上标签，或者关联到某次 Commit。

对于开源项目来说，Issue 也是用户和开发者沟通的主要渠道。发现了 Bug，你就可以在项目里面提 Issue，作者看到以后也会回复。

第三个关键词叫 PR。PR 全称叫做 Pull Request，直译过来叫做「拉取请求」。这个是 GitHub 里面最重要的协作机制，也是很多人第一次听到会困惑的一个概念。

它的逻辑是这样的：你不能直接往别人的主分支提代码，而且也不应该这么做。正常的方式是你创建一个新的分支，在这个新分支里面完成改动以后，然后发起 PR，请求把这个分支的改动合并进主分支。

其他人看到你的 PR 以后，会做一遍 Code Review，就是审查你的代码，然后发现你的代码问题，提出修改意见。这样来回几次以后，发现这个代码没问题了，大家讨论达成一致，PR 就会被合并，也就是你的代码会合并到主分支，从而改动正式进入主线。后面的人用到这个代码以后，可能有些代码就是你写的了。

所以 PR 的本质就是改代码之前先讨论，改完之后再审查。这让团队里面每一行代码在进入主线之前，都经过了至少一个人的眼睛。

第四个概念叫做 Actions。GitHub Actions 可以定义为自动化流水线，这是 GitHub 最近最重要的功能之一。具体怎么做呢？你可以在仓库里面写一个配置文件，告诉 GitHub，每次有人 Push 代码，就自动运行测试；如果测试通过，就自动部署到服务器。

这套机制其实也可以叫做 CI 或者 CD，中文名字叫持续集成或者持续部署。在 GitHub Actions 出现之前，搭建这个流程需要额外的工具和服务器。现在它内置在 GitHub 里面，免费额度对个人项目来说也完全够用。

同时，GitHub 不仅仅只是一个远程的 Git 仓库，它还是开源的家园。GitHub 上托管了现在超过三亿个仓库，其中很大一部分都是开源项目。像大家熟知的 Linux 内核、Python、React 框架、VS Code，本身全部都在 GitHub 上开源。

这意味着什么呢？第一，你可以直接在 GitHub 上看到这些顶级项目的源代码，学习世界上最优秀的工程师怎么写代码。

第二，可以做 Fork。在它的右上角有个 Fork 命令，复制任何公开代码到你的账号里面，自由修改。

第三，给开源项目提 PR、贡献代码，让自己的名字出现在 Linux、React 等项目的提交历史里面。

第四，在 Issue 区跟全球的开发者讨论技术问题。开源社区的协作也就建立在 Git 加 GitHub 这套工具里面。

好，讲完 GitHub 这个仓库以后，我们再回到 AI 这个概念。GitHub 跟 AI 编程到底有什么关系？GitHub 是 AI 编程工具链里面最重要的节点，原因我觉得有三个。

首先，GitHub Copilot 就是 GitHub 出品的。微软收购 GitHub 以后，把 OpenAI 的代码模型和 GitHub 的海量代码库做了一个结合，做出了第一个大规模商用的 AI 代码助手。今天所有的 AI 编程工具，都在某种程度上和 GitHub 竞争或者兼容。

第二个，就是 AI 生成的代码最终要落地到 GitHub。无论是 Claude Code，还是其他 AI 工具，生成代码都需要做 Commit、Push、PR，这套流程来管理。你不懂 GitHub，AI 帮你写完的代码，你就不知道该怎么安全地落地、交付和协作。

第三个，就是 GitHub 是你的技术名片。招聘市场上越来越多的公司会直接看候选人的 GitHub 主页：你做过哪些项目，提交过哪些代码，参与过哪些开源项目。对于没有工作经验的新人来说，一个活跃的 GitHub 主页会比一份简历更加有说服力。

最后再总结一下，Git 是一个工具，GitHub 是一个平台。Git 在你的电脑里面工作，GitHub 在云端连接所有人。

Git、GitHub 和 VS Code，它们三者的关系就是：在 VS Code 里面写代码，用 Git 记录每一个代码版本，然后用 GitHub 跟全世界分享和协作。
