# 内容路由与多方向探索

先理解内容，再排序风格。路由只决定「优先级」，不负责自由设计画面，也不替用户取消其他风格。风格确定后必须回到 `examples.md` 检索完整案例。

## 一、共享内容简报

每轮只建立一次，供所有候选共用：

```text
一句话内容核心：
内容类型：
真实证据：
不可虚构：
核心冲突／结果：
指定文案：
人物与比例：
```

## 二、内容类型

### product_demo

有真实产品、设备、UI、操作结果或前后对比。

优先：产品数据证据、深色工具实测、资料拼贴。  
不得用重新生成的假 UI 替代用户给出的真实素材。

### data_insight

有真实数字、趋势、实验结果或统计异常。

优先：数据编辑海报、资料拼贴、纸媒观点。  
只画用户提供或已核实的数据；无数据时不能凭空增加坐标和比例。

### abstract_mechanism

解释因果、认知机制、反直觉规律或结构性问题。

优先：电影事件隐喻、数据编辑图形、纸媒观点、漫画冲突。  
不得因为主题包含 AI 就自动生成蓝色 UI 和仪表盘。

### tutorial

强调步骤、方法、从 0 到 1、可以照着做。

优先：纸媒教程、真实产品证据、资料拼贴。

### comparison

两个产品、模型、方案、阶段或力量之间有明确对比。

优先：漫画冲突、对比构图、数据编辑海报。  
只比较两个主要对象。

### character_story

强调团队、角色分工、多个 Agent 或拟人对象。

优先：纯色扁平角色世界、资料拼贴、漫画冲突。

### personal_opinion

强调个人判断、态度、经历或情绪。

优先：电影事件隐喻、纸媒观点、极简／正面对视构图。

## 三、推荐与实验

探索模式默认：

- A 级：2～3 个内容匹配度最高的方向
- B 级：1～2 个有潜力但更冒险的方向
- C 级：明显不适用的风格不主动生成；用户明确指定时仍可作为实验执行

实验方向也必须忠实于自身视觉 DNA，不能降低审美标准。

## 四、从内容路由到案例检索

推荐风格后，为每个方向写出需要寻找的案例关系：

```text
需要的人物任务：
需要的主视觉体量：
需要的标题几何：
需要的动作／冲突：
```

先按这些空间关系在 `examples.md` 和 `assets/examples/` 中找案例，不按「都是 AI 主题」「都是蓝色」「都是科技感」匹配。

- 找到接近案例：保留其空间骨架，再替换内容。
- 只有材质接近：材质案例只能做辅助，仍需另选一个空间骨架案例。
- 没有完全同类：选动作关系最接近的案例，不允许直接退回仪表盘、图标栏或普通居中海报。

## 五、视觉命题

视觉命题必须包含：

```text
主体：
正在发生的动作：
冲突或结果：
观众记住的轮廓：
```

合格：

> 高速运转的 AI 任务流水线不断把待判断事项推向人的大脑，判断闸门开始过载。

不合格：

> AI 注意力管理，科技感，做一个数据面板。

视觉命题只负责说明案例要替换成什么事件，不能脱离案例独立指挥生成。

## 六、跨风格去重

同一任务生成多个风格时，禁止只改变：

- 背景颜色
- 面板圆角
- 图标颜色
- 人物左右位置

每两个候选至少改变两项：

- 主视觉对象
- 空间事件
- 材质载体
- 标题几何
- 人物任务

如果两个候选缩小后轮廓相同，其中一个必须重新构思。
