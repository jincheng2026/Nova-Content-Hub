# 锦成规律提取助手

把 vault 里已入库的对标素材整理成可追溯的规律库：先出六字段汇总底稿，再从底稿提炼三份规律文件。素材采集与入库不归本 skill 管，只处理已经在 02_内容素材 里的内容。

## 工作目录与开工检查

1. 在包含 `02_内容素材/` 与 `03_内容规律/` 的 vault 根目录工作。用户未指定时默认 `~/AIJinCheng/个人IP与内容/第二大脑/`；找不到该结构就停下来问，不猜路径。
2. 开工先读 vault 根的 CLAUDE.md 和 `00_个人背景/` 的定位文件。vault 通用规则（真实信息、来源路径、排除 `_` 开头辅助文件等）以 vault 配置为准，本 skill 不重复也不覆盖。
3. 递归扫描 `02_内容素材/已参考/*/*/` 与 `02_内容素材/未参考/*/*/`。一条有效素材 = 一个素材目录，目录内单个 `笔记信息.md` 承载全部文档信息（含并入的逐字稿），图片、视频是附件。

## 第一步：六字段汇总

写入或更新 `03_内容规律/_规律提取汇总.md`。每条素材一节，节标题带编号和真实标题（如 `## 素材 08 · 第1集｜什么是大模型（抖音）`），正文只有六个字段：素材文件、平台与形式、标题、平台文案、封面/首帧文字、口播开头 1-3 句原文、口播结构。

硬规则（细则和示例见 [字段细则](references/field-rules.md)）：

- 素材文件中没有的字段写「未采集」；无逐字稿的素材，口播两字段一律写「无逐字稿」，不得用标题、封面或视频描述倒推口播内容。
- 素材目录有图片时，按文件名顺序读取全部图片并逐张记录图中文字；画面无文字写「无可读文字」；无法读取的图片记录具体路径，不得跳过或推测。
- 抖音标题必须用平台真实标题字段（TikHub `item_title`）核实，不能拿视频描述第一句顶替——描述是标题与正文拼接后的产物。
- 标题、平台文案、封面文字、口播开头是四个不同位置，分开识别，不得互相顶替。
- 口播结构按逐字稿实际讲述顺序用箭头连接，包含结尾动作，不套现成模板、不提前压缩步骤。
- 汇总阶段只做摘录，不写任何跨素材结论。

## 第二步：三份规律文件

基于汇总底稿生成或更新 `03_内容规律/` 下的 标题规律.md、开头规律.md、正文结构规律.md。

- 同一种做法至少出现在 2 条素材中才写成候选规律；只出现 1 次的放进「单条观察」区，不冒充规律。
- 每条候选规律必含五要素：大白话解释、适合什么内容、不适合什么内容、不可照搬点、来源素材。
- 来源素材用「素材编号《真实标题》（平台）」引用，带 ID 的完整路径只保留在汇总文件的映射里，规律文件里不出现。
- 不写「这样一定会爆」「平台算法喜欢」等无法由素材证明的因果结论；只描述素材里实际出现的做法和出现次数。
- 自己改写的示例必须标注「AI 示例」，与素材原文区分。
- 每份规律文件末尾列「待确认」清单：把握不足、样本不够或需要用户拍板的点。
- 不删除、不覆盖用户已确认的规律（带「状态：」标注的条目视为已确认）。用户确认后按其指示标注状态：本期可用 / 以后再试 / 已删除；「已删除」条目移到文档末尾的「已删除」区并保留删除原因。未经用户确认不自行标注、不自行删除。

## 增量模式

用户说「我搜集了新内容，帮我更新内容规律」或类似表述时：

1. 对比汇总里已有的素材编号，只处理 `已参考/` 和 `未参考/` 中新增的素材目录，编号顺延追加到汇总，不重写已有条目；素材在两类之间移动不算新增。
2. 新素材与已有规律逐条对比：能支撑已有规律的，在该规律的来源素材里追加引用并注明补强日期；出现新模式且 ≥2 条的，新增候选规律；只有 1 条的进「单条观察」。
3. 不重复生成已有规律，不改动已确认条目的正文。

## 失败处理

- 图片读不出：在汇总对应字段记录具体文件路径，继续处理其他素材。
- 素材缺文案、缺图、缺逐字稿：按字段规则如实标注，完成后向用户汇报缺口清单。
- vault 结构不符或找不到素材目录：停下来向用户确认路径，不自建目录。
- 自检不通过：先修复再交付，不带病交付。

## 交付前自检

```bash
python3 scripts/check_patterns.py <vault根目录>
```

检查汇总字段完整性、规律条目五要素、来源素材数量下限和禁用因果表述。通过后向用户汇报：整理了多少条素材、缺口清单（缺逐字稿/缺图/缺文案/不可读文件）、候选规律与单条观察数量。
