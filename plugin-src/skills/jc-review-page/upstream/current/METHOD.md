# 审稿页

锦成改稿时要同时看到三样东西：原稿原样、每处改成什么、凭什么改。聊天里列清单他得回翻原文，改完还要等 AI 回一遍全稿。这个技能把三样东西放进一页，他在页面里改完直接拿走。

## 什么时候用

- 手上有一份原稿（运营写的、AI 写的、锦成写的都算），和 3 条以上修改建议，需要锦成逐条拍板。
- 锦成说「依据是什么」「让我看到」「我直接在上面改」。
- 少于 3 处的小改动，直接在聊天里给原句和改句，不做页面。
- 这条稿在第二大脑里已经有创作页的，不做审稿页，改法用 jc-gongzuotai-write 的 suggest 放进创作页，免得一条稿两个页面、在哪改的说不清。审稿页只留给还没有创作页的稿，比如运营单独写的文案。（2026-09-30 锦成同意）

## 步骤

1. **原稿原样放。** 一个字不改，空行分段、一行一句。原稿有排版问题也不顺手修，修也要单列成一条建议。
2. **每条建议一条 change。** `old` 取要改的最小片段（整句或句中几个字），必须在原稿里只出现一次；新加内容用 `insert_after` 挂在某一整句后面。删掉就是 `new` 写空。
3. **依据按来源分类型写，写具体。** 类型：`voice` 参考视频口播、`frame` 参考视频画面、`caption` 发布文字或标题、`meet` 会议、`you` 锦成之前的改稿或表态、`rule` 已确认判断、`plat` 平台规则、`op` 原稿自己的内容、`ai` AI 自己的判断。
   - `voice` 必须带时间码，引号里一字不差。写之前用逐字稿搜一遍原话，搜不到就不能用引号。
   - 标题和发布文字只能标 `caption`，而且要说明「视频里没说」，不能当成视频依据。违反的样子：把 L-earn 发布文字里的「每次都从头讲一遍」写成「L-earn 原句」，锦成以为视频是这么讲的。
   - 没有外部依据的就标 `ai`，直说是自己的判断。违反的样子：把 AI 自己加的「先看结果」混在参考依据里，被追问才承认。
4. **结论分四种。** `must` 已定要改，只用于锦成已经确认过的方向；`optional` 待你定；`keep` 不用改、保留原稿，用来解释为什么不动；`wait` 等实测再定，比如要录屏才知道软件会不会弹出某一步。
5. **生成。** 写好 `spec.json`（格式见脚本开头注释），运行：
   `python3 scripts/build_review_page.py --spec spec.json --out <内容包>/审稿页.html`
   核对不过会逐条列出，改了再跑。
6. **按锦成的用法验收一遍再交。** 打开页面，点一条「采纳」，在左边高亮句里直接改一个字，看右边卡片是否同步，再点「复制提词稿」，看复制出的文字是否正确。只看生成成功不算验收。
7. **交付说三件事。** 页面链接；用 Chrome 打开才能自动保存，预览窗口会提示存不上；改完点「复制提词稿」直接用，想同步进文件再点「导出结果」发回来。
8. **锦成发回导出结果后。** 把「当前稿子全文」原样存进工作稿，不润色、不改标点；改稿日志记一笔「锦成在审稿页改」。只指出会影响录制或发布的问题，最多三条，不把全稿再复述一遍。锦成再贴一版回来时，先用程序逐行比对，只报告差别。

## 不能做的

- 不在页面里夹带没列成建议的改动。违反的样子：「全部采纳」后得到的稿子和工作稿对不上，因为有几句顺手改了没列卡片。
- 不把审稿页当真源。真源是内容包里的工作稿；页面只是改稿入口，改完要落回文件。
- 同一份稿子的 `key` 不要换，换了锦成浏览器里存的进度就读不到了。
