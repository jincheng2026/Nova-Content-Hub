## 冷启动证据

[只读诊断日志](../verification/production/2026-10-19-workbuddy-hook-diagnosis-01.log)关联了实际宿主与macOS日志：WorkBuddy在00:49:03.743启动Hook并从spawn开始计5000ms；`amfid`在00:49:03.765进入该安装缓存的`runtime/node`，`syspolicyd`在00:49:07.450完成扫描，跨度3685ms；Hook在00:49:08.743超时。该冷扫描已消耗大部分预算，剩余运行时启动、完整性检查及并发冷启动的个别贡献没有独立计时，不能声称单一因素已完全复现。

同一安装wrapper的五次热运行139–169ms，保持stdin打开的探针776ms返回受限输入超时，三份相同Node临时副本首次启动1514–2783ms、再次36–39ms。受控副本没有复现超过5000ms的原生超时。参考插件依赖已装Node的热路径，不能拿它的5秒预算证明本产品新复制固定Node的冷启动足够。诊断未修改Hook预算、宿主设置、签名或系统安全策略。

## 0.3.1交接顺序与信任来源

源码统一版本为0.3.1。`workbench/src/main/assistant-runtime.mts`提供`launchWithAssistantRuntime`；`desktop.mts`的封面与模板入口共用它，覆盖Codex、WorkBuddy。设置就绪查询仍只读元数据，不在轮询时执行Node。明确发起或继续交接时按以下顺序执行：

1. 确认对应宿主已安装、启用匹配版本的执行Skill；读取应用随包可信市场目录中的`package-files.json`，核对格式、schema及完整release，不能把宿主缓存自行重封的清单当信任来源。
2. 以可信清单逐项核对宿主实际安装缓存的完整包树，包括路径、类型、大小、可执行位和SHA256。共享`plugin-src/src/lib/package-snapshot.mjs`采用稳定文件读取、读前读后身份核对及有界流式摘要，拒绝越界链接与读取中变化。仅Codex允许缺失可信清单中目标恰为`../semver/bin/semver.js`的`node_modules/.bin/semver`链接；已存在但被改动的链接、其他缺项和WorkBuddy同类缺项仍拒绝。运行后WorkBuddy的受限非执行占用元数据另按[41](41-WorkBuddy使用标记与再次交接.md)校验，不能把它当作可信程序载荷。
3. 对固定Node和`runtime/launch.mjs`在完整验证前后核对文件身份，再以`execFile`直接运行这个宿主缓存的固定Node和固定`[launcher, 'doctor']`参数。不开shell、不搜索PATH、不改跑应用内另一份Node、不跨交接缓存验证结果；移除Node/Electron及动态加载注入环境变量，关闭stdin，最长30秒、输出各限64KiB、超时SIGKILL。
4. 只有进程成功、stderr无非空白内容且JSON满足`ok:true / authMode:disabled / library:unbound / imageGeneration:false`，才创建handoff信封并打开助手。doctor不绑定内容库、不生图，也不代替执行Skill随后读取context、认领和提交。

任一步失败沿现有`NOT_READY`恢复路径返回，保留固定尝试，不因预检失败创建新业务请求。预检把首次固定Node启动移到助手短Hook预算开始前；没有延长Hook超时、删掉校验或关闭系统安全。文件身份与摘要检查降低替换风险，但最后检查与执行之间仍有窗口，不声称完全解决同UID恶意进程竞态，也不保证所有机器首次Hook都不会超时。
