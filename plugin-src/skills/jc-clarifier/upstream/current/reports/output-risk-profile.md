# 输出风险画像

## 主要风险

1. 欠澄清 / 空心交付  
用户确认方向后，Skill 直接输出看似完整的提示词，但缺少产品、证据、渠道、素材、成功标准等关键输入，导致执行 AI 只能生成泛泛方案。

2. 过度澄清  
用户已经说清楚时还继续追问，增加摩擦。

3. 越界执行  
用户给素材或目标后，Skill 直接开始写成品，而不是输出给新聊天的提示词。

4. Goal 误触发  
用户只说「长任务」「一直做」，Skill 就直接输出 `/goal`。

5. 空泛提示词  
输出「认真分析」「尽量完整」「做得高级」这类不可验收描述。

6. 行家视角空心化  
Role 写成「你是专家」，但没有判断手感、常见错误和验收标准。

7. 主入口膨胀  
把案例、评分细则、Goal 长规则继续堆回 `SKILL.md`。

## 质量守门

每次修改后检查：

- `SKILL.md` 是否只保留触发、边界、主流程、分支选择和输出摘要。
- Goal 详细规则是否只在 `references/goal-mode.md`。
- 普通输出是否符合 BROK 合同。
- Goal 输出是否包含验证、约束、边界、迭代策略、完成条件、暂停条件、进度、预算。
- 直接执行类请求是否被排除。
- 高依赖背景任务是否追问关键缺口，或写入 `Missing Inputs` / `Assumptions`。
- 默认中文输出是否不使用 emoji。

## 最小样例

正例：

- 用户：「帮我写个提示词，让 AI 帮我设计课程作业」
- 行为：澄清后输出 BROK，不直接设计作业。

反例：

- 用户：「直接写一篇朋友圈」
- 行为：不应触发 clarifier；应执行写作任务或调用写作类 Skill。

边界例：

- 用户：「这个任务很长，你一直做」
- 行为：可以提醒适合 Goal，但不能直接输出 `/goal`，除非用户明确要求写成 Goal。
