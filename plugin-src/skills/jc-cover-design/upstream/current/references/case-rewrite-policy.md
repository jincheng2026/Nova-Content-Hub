# 完整案例检索与改写

本文件把成熟封面案例转译成可生成画面。案例是主生成依据；风格规则和视觉命题只负责选择、改写和否决。

## 一、选择案例

先看空间关系，再看表面风格。按以下顺序匹配：

1. 人物与主视觉的动作关系
2. 标题与人物、主视觉的遮挡关系
3. 主视觉轮廓、体量和方向
4. 前中后景层次
5. 材质、色彩与题材

每张候选只选 1 个主要案例。可以再参考 1 个材质案例，但不能拼接两个不同构图骨架。

## 二、形成案例卡

生成前写出：

```text
案例锚点：
保留的空间骨架：
保留的标题几何：
保留的人物任务：
保留的主视觉体量：
替换后的内容主体：
删除的原案例元素：
不可继承：原文案、商标、账号、他人身份、无关装饰
```

至少保留 3 个可以在缩略图中看出的结构关系。只保留颜色、字体或「科技感」不算案例改写。

## 三、改写原则

- 保留关系，替换内容：保持「谁在什么位置、对谁做什么、谁遮挡谁」，替换成当前主题的对象和动作。
- 保留体量，不复制物件：案例若以一个占画面 45% 的大道具为核心，新画面也应有同等级主视觉，但不必复制原道具。
- 保留标题几何，不复制原字：保持满宽、四角、压底、倾斜纸条或红黑字块等结构，逐字使用用户新文案。
- 保留人物任务，不复制他人身份：案例人物负责托举，新人物也应托举；只使用用户唯一身份参考。
- 删除无任务装饰：不能解释标题、动作或阅读方向的图标、粒子、卡片和光效不继承。

## 四、转成生成语言

完整生图规格必须包含：

1. `3:4 竖版构图`
2. 画面唯一记忆点
3. 人物位置、可见范围、表情、双手动作、视线
4. 主视觉外观、体量、位置、方向、动作和结果
5. 前景、中景、后景及遮挡关系
6. 标题逐字文案、分级、位置、字号关系和造型
7. 统一材质、主色和强调色
8. 必须保留的真实证据
9. 明确禁止的模板化元素

禁止只写：

- 高级、电影感、科技感、审美在线
- 保持视觉命题
- 构图有张力
- 材质统一

这些是评价语言，不是可生成画面。

## 五、真人安全

- 含其他真人的案例图先用 `view_image` 观察，只把结构写成文字。
- 生图时不把该案例图与用户人脸同时输入。
- 人物、标题和主视觉仍在同一次构图中生成；输入隔离不等于画面拆分。
- 只有身份修复失败时，才启用无人物背景或确定性抠图备用流程。

## 六、失败判定

出现以下任一项，说明案例改写失败：

- 只继承配色，没有继承空间骨架。
- 人物换成站立、抱臂或指向空处的通用姿势。
- 主视觉退化为仪表盘、图标栏或几张悬浮卡片。
- 标题变成普通多行居中排版。
- 人物、标题、内容像三个独立模块。
- 案例的记忆点被抽象规则和安全区抹平。
