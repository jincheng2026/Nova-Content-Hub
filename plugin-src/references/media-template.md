# 自媒体模板设计与生成

这份指南用于通用自媒体和 AI 专业内容，补充视觉工作流。它不提供运行权限；先完成 REQUEST/HANDOFF 校验，缺实际能力时停在明确状态。

模板学习时按 [封面设计检查的拆解部分](cover-design-review.md#拆解事实先于规则) 记录事实、规则和原图证据；还原与封面生成时按该指南的构图与检查部分组织提示、逐张核验。该指南补充可观察的完成标准，现有请求、提交和人工验收步骤继续有效。

## 先选内容结构，再选视觉形式

`audience=general` 覆盖观点、清单、教程、对比、访谈、生活图文、产品评测与资讯。`audience=ai` 覆盖概念解释、工具实测、Agent
工作流。领域分类不决定画面必须发光；AI 的专业性体现在输入条件、过程、证据、限制和验收。

优先按用户本次目标、已有素材与长短标题匹配 `scenario/contentType/useCases/fit/unfit`
。用户已选定模板和参数时直接沿用，不重复问卷。没有实测材料，不补造性能数字、对比结果、排名或“提效”结论；没有真实采访，不给虚构人物加真实身份。

## 一套模板的设计记录

保留以下信息，使规则能实际指导生成：

1. 面向什么内容与读者，在哪些场景不适合。
2. 背景、主体、标题、辅助信息的区域关系与叠层顺序。
3. 字形、字重、主次大小、配色与边界；估计的比例标成估计。
4. 必须稳定保留的视觉关系。
5. 可替换的文字/主体、可省略的块，以及长标题和变比例如何重排。
6. 来源里的身份、事实、logo、肖像等哪些不自动继承。
7. 从背景到主体、再到文字的客观提示骨架，准确文字与本次变量分开。
8. 可见的验收问题，以及失败时下一轮只改什么。

本项目字段为 `anatomy` 的区域/用途/规则/可变标记和 `generation` 的提示骨架、主体/文字/参考策略、变量、排除项与质量清单。变量使用
`{title}`、`{ratio}` 等已声明的键；示例值是演示，不能静默变为项目事实。未提供的可选项移除整块或说明缺失；必填信息缺失时集中指出，不编造。

## 参考资产的角色

| 资产                    | 用法                                                                 | 不能据此认定                         |
|-------------------------|----------------------------------------------------------------------|--------------------------------------|
| 来源原图                | 拆解风格与证据                                                       | 自动获得图中人的身份或素材复用许可   |
| 原创设计原图/换标题 SVG | 说明版式和可变范围                                                   | 模型已经还原或泛化成功               |
| AI 生成风格参考         | 按请求选中的整组样张提炼共同风格与构图差异，保留生成提示、尺寸和版本 | 人工还原验收通过、真实测评/采访/报道 |
| 用户的主体素材          | 用户允许时帮助保持该主体                                             | 可以读取其他项目素材或发送未选图片   |
| 本项目选定/收藏候选     | 用户选择作为同一项目的延展参考                                       | 可以跨项目自动复用                   |

不要默认把有完整文字的来源封面当作编辑底图。学习规则、参考风格、保持主体、修改现图是不同操作；交接时写明每张图的用途。未选任何图也是有效选择，意味着只按规则生成。当前浏览器只交接资产
ID，不代表图片文件已送达宿主。

### 本人照片与模板组合

收到用户明确选择的本人照时，先按请求的参考 ID
核对实际附件：本人照只决定身份；模板样图只决定构图、镜头、排版和材质；本次内容说明决定主题、物件与准确文字。身份附件未收到时先指出缺少哪张，不能拿模板里的样例人物代替用户。浏览器导出的本地参考版可能经过缩放压缩，不声称是未经处理的原始相片。

使用本人照保持可辨认的五官、脸型和发型，按本次场景重新组织姿态、受光和身体关系；模板里的其他人、原文字和品牌不继承。用户选择不放人物时制作无人版本。用户本次人物选择与模板示例主体类型冲突时，以本次选择调整主体分区，并保留可读标题和必要留白；实质无法兼容才集中说明。

人物、前景物件与标题形成清楚层次，镜头透视、主光方向和接触阴影一致，标题避开脸与关键动作；用约 180px
宽缩略图复查标题、面孔与主要动作。一批候选保持同一身份、主题和风格，通过镜头、表情或布局形成有意义的差异，逐张核对手部与文字。身份、衣服与构图素材分别记录角色，不把一张图的全部内容自动继承。

## 学习一套与融合两套

一个模板是一组样张：共同的配色、字体与信息层级属于固定关系，组内不同的布局、镜头距离、留白和元素位置属于可变化范围。只有视觉语言互不相容时才拆成不同模板。生成时逐一按请求
references 的稳定 ID 与版本核对已附图片，参考完整选中组；缺少已选样张先列出缺项，不静默只看第一张。每版生成数量以
options.count 为准，与样张张数独立，不逐张照搬原文或输出同构重复图。浏览器总参考预算 32 张，用户可明确取消部分参考；SVG
仅作结构示意，不计真实样张。用户明确要融合时，一套承担主要构图，另一套只借明确的字体/色彩/装饰关系，形成新的统一设计草稿，并记录来源。不要拼接两个互相冲突的完整提示。融合草稿未经实际还原与人工验收，不升级原模板的验证状态；当前没有自动融合命令。

## 还原与泛化

还原回答“规则是否表达准确”；换长标题/换主题回答“同一套规则能否容纳不同内容”。每次测试记录模板版本、准确输入、实际图像工具、完整提示、图片与偏差。AI
风格图从生成工具返回，只说明产生了图，不能当作该模板通过测试的证据。

标题逐字准确、缩略图可读、边界安全、固定规则满足、来源身份未残留逐项记为通过/失败/未检查。只有已检查并符合的项能记通过；失败写明位置与下一步，保留旧候选。生成后又改关键规则，需要新一轮验证，旧报告保持原版本。

本指南借鉴旅游工作台的流程分工，并针对自媒体重新编写；没有复制其专有模板文本、行业字段、图形或程序。公开方法和许可见 [来源记录](upstream-notices.md)。
