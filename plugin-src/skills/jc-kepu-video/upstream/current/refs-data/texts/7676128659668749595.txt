Git 和 GitHub 已经是当前 AI 时代所有人必会的基本功之一了，今天我就给你带来一期我爷爷都能听得懂的纯小白基础教程。现在的你不需要像传统程序员一样学会大量的 Git 命令行，只需要掌握 Git 和 GitHub 的几个核心概念，就可以用自然语言指挥 AI 完成各种操作。

第一部分啊，我们先理解什么是 Git，什么是 GitHub。我们先用一个最简单的【疑似：比喻】，Git 就像游戏里面的存档点，你每要打 Boss 前，或者打通关之后，你都会去存一次档，后面即使失败了，还可以回到之前的状态。有了 Git 之后，不管你用 AI 来做什么样的东西，即使今天 AI 给你改错了，你也可以让它完美地去还原。而 GitHub 是什么呢？GitHub 是世界上最大的开源社区，有超过一亿个免费的公开仓库，你可以在里面找到各种内容，不管是变声器【听不清：申图】提示词，甚至是小学一年级到高中的全套课程、格式转换的项目，或者简历的模板，只能说你想得到的，或者你想不到的，在上面都可以找得到。同时你也可以通过 GitHub 帮你云端存档，方便你跨设备也能顺畅开发你的项目，或者与其他人协同开发。所以说，一个是你本地的后悔药，一个是你云端的存档中心，同时你还可以在上面找到各种各样的内容。

第二部分啊，就是 Git 到底该怎么用呢？其实非常简单，比如说这里我给自己做了一个待办清单的网页，我会发给它这段提示，是说：哎，请检查这个项目有没有启动本地的版本管理，如果没有，帮我去建立本地的 Git 存档，其实是最重要的。然后发给它之后呢，你就会发现它很快帮你完成了本地的 Git 存档，然后初始化呢，Git 的仓库默认分支是这个主分支，所以说你看，不用写任何的命令行，AI 就会自动去完成设置。接下来我会说：哎，请你帮我去确认当前项目能常运行，如果没有明显的问题的话，帮我建立一个本地的存档，然后名字写清楚完成的什么，但是不要推送给 GitHub，这样这个项目就会有一个明确的存档点。以后每完成一个真正能用的功能呢，都可以让 AI 再存一个稳定的版本，比如说你可以看到这个，就是项目的一个存档点。

接着我会说啊：请你帮我确认当前项目如果能正常运行，确认没有明显的问题之后，就帮我存一个本地的存档，然后写清楚完成了什么，然后不要推送给 Git，这样这个项目就有一个明确的存档点，每完成一个真正新的小功能，都可以让 AI 再留一个稳定的版本。

那如果过程中已经改了很多版了，那你就不用只说你改了什么东西，你可以发给它说：哎，出现了问题，告诉我这几轮分别改了什么，然后列出可以恢复的稳定的版本，然后这个时候呢，它就会给到你差异和可选版本，列出来，然后确认能够恢复到比如说之前存档的那个稳定版，然后它才会执行。所以说，最重要的不是说会不会 Git 的命令，而是让 AI 在恢复之前先回答三个问题：改了什么，准备恢复到哪里，以及会丢掉哪些内容。

但是很多时候啊，旧版本也不是一无是处的，对吧？比如说现在这个新版本的界面更好看，旧版本的数据保存会更稳定，那我不想二选一，我就让它变成一个最新的版本啊，所以说你可以保留新版，以及拿回旧版的部分，然后给到一个新的稳定版本。那怎么做呢？我会告诉 AI 说：哎，请你帮我去比较当前版本跟之前的稳定版本，然后给出一个合并的方案，确认之后再生成一个新的版本。确认方案之后呢，AI 就会对照两个不同的版本，把需要的部分重新组合，再建立一个新的稳定的存档。所以说呢，Git 不是后悔药，它还让 AI 有机会帮你看见以前怎么做和现在怎么做，再帮你取长和补短。

第二大部分啊，就是 GitHub 怎么使用呢？其实 GitHub 也是全程可以用自然语言去操作。首先第一步，我们先注册 GitHub 的账号，也非常简单，进入它的网页之后，这里面去选择 Sign Up，选择完了之后呢，你就可以去选择你对应的一些注册信息，比如说你可以用 Google 的邮箱或者苹果的邮箱，然后或者你直接填写对应的邮箱，点击注册，然后输入这个验证码，输入完了之后呢，你的账号就注册好了，你就可以点进去登录，登录进去就是你自己个人的主页。同时这里呢，你可以去搜索，比如说我这里搜索 resume，也就是简历，那你就可以看到非常非常多完整的简历的一个项目。当然，就像我们刚刚那种本地版本已经稳定之后，如果想再做一份远程的备份，就可以用 Git 去进行推送，那怎么做呢？也非常简单啊，比如说我就发给它说：哎，请帮我检查一下这台电脑是否已经连接了 GitHub，如果没有呢，就让我完成授权。这个时候它就会自动去安装好【疑似：GitHub CLI】，然后让你去触发登录，后续呢，你就可以非常快速地完成对应的登录，比如这里，然后就点击对应的授权，授权完了之后，它会给你邮箱的一个验证码，然后把邮箱验证码填写好之后就完成注册好的。但是即使注册好的，也不是着急把整个文件夹都上传，其实 GitHub 呢，更适合放一些代码项目的说明，或者一些依赖的清单，或者必要的配置示例和运行必须的一些小型资源，不适合直接把所有的东西都放进去。所以说我会发给它说：哎，请你帮我先去检查，说上传到 GitHub 上面的内容，保留这些必要的东西，排除一些依赖这种东西，或者本地的一些大视频或者文件。然后 AI 就会把会上传什么和不会上传什么列出来，我确认仓库是私有的，再让它执行。刷新这个 GitHub 的页面，其实你就可以看到你的所有代码和每一次的运行版本，它就已经上传好了。当然，就像刚刚介绍的，GitHub 有一个另外很重要的功能，就是搜索其他的开源项目，除了去 GitHub 上面搜索关键词，一个项目一个项目地翻开来看，还有一个更简单的方式，就是根据你自己的需求去寻找项目，比如说呢，我想要去做一个音频转文字的项目，如果是以前，我就要自己去搜索，但现在你可以直接发给 Codex 说：哎，我想要做一个这样的项目，帮我去 GitHub 上面搜索具体有哪些现成的项目可以直接使用，然后它就能够很快给到你对应的项目参考和它的建议，然后你就可以再让它进行下载和试用，就没问题了。
