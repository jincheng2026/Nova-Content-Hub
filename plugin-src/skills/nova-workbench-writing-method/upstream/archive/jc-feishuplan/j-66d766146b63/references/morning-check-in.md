# 每日未完成任务自动顺延

适用：用户要求「每日任务自动顺延」「把之前任务顺延到今天」或配置定时检查。

## 首次配置

自动顺延是可选能力，只能在用户明确开启后运行。首次必须确认：

- 目标 Base URL 或 `app_token`；
- 目标表名或 `table_id`；
- 用户希望的执行时间，未指定时才建议每天 11:00；
- 实际字段中哪些对应任务名、计划日、原计划日、状态、未办处理和 AI 判断。

不把任何固定 Base 名、表名、视图名、token 或用户身份写死在 Skill 里。

## 执行顺序

1. 以当前时区和当前日期计算「今天」。
2. 现场读取目标 Base 的真实 schema，不复用未验证的旧 token 或旧字段名。
3. 查询「计划日 < 今天」且「状态 != 已完成」的记录，检查分页完整性。
4. 跳过已完成、等待外部、已取消和无计划日记录。
5. 原计划日为空时，先写入顺延前的计划日；已有原计划日时保留，禁止覆盖。
6. 只更新作战日期和顺延来源字段；不新增重复任务，不改完成状态，不改真实截止日期。
7. 先 dry-run，再串行写入；写入后回读同一范围，确认无遗漏且原计划日未丢失。
8. 时点任务的原时点已过时，只在 AI 判断字段追加「原时点已过，今天需重新确认时点」。

## 离线补跑

- 如果电脑休眠、关机或网络不可用，客户端恢复后的首次执行可补跑。
- 补跑前先检查今天是否已有成功回读记录；有则静默退出，禁止一天重复写入。
- 不得声称能证明用户是否打开过飞书页面。

## 极简输出

最终消息不超过 120 个中文字符，只说顺延数量、是否失败和一个下一动作。

```text
已自动顺延 N 项到今天。先打开今日任务视图看第 1 项。
```

```text
没有需要顺延的旧任务。今天按今日任务视图继续。
```

```text
今天自动顺延失败，请打开未完成任务视图检查；未验证前不会重复写入。
```
