API 是什么？API 能做什么？

Hello，各位，今天给大家介绍一个非常基础，但是又常常被忽略，也常常会有风险的东西，叫作 API。不管你是在做 AI 工具、做 AI 工具自动化，还是想搭建自己的产品，你都绕不开这个东西，API。

但大多数人要么完全不理解，要么用错了方式去用它。所以今天我们就来彻底把它讲清楚。

OK，那 API 全称是什么？是 Application Programming Interface，中文翻译过来就是应用程序编程接口。听起来会很复杂，但其实你每天都在用它。

比如我们来打个比方，你去餐厅吃饭，你不需要进厨房，不需要知道怎么炒菜，你只需要告诉服务员，我要一份宫保鸡丁，不要辣。那服务员就把你的需求传递给厨房，厨房做好以后，再给服务员，再把它端给你。

这个服务员，我们给它定义为 API。那你就是客户端，也就是发出请求的人；而服务器和系统就是厨房，相当于接收到请求、真正做处理的人。那服务员也就是 API，它就是中间的桥梁，定义了你能够点什么、怎么点，然后结果怎么返回。

所以在这里，你作为客户端，你不需要知道服务器或者厨房内部怎么运作，你只需要按照菜单的格式点菜就行。这个就是 API 的核心逻辑。

OK，那我们实际来看一下它到底长什么样。我们现在来打开一个真实的 API 请求。比如我去调用 OpenAI 的 API，问它“你好，今天天气会是什么样的？”所以你看，它其实就是一段有格式的请求：你要发去哪个地址，也就是 URL；你的身份凭证是什么，也就是 API Key；以及你要说什么，也就是 Message 里面的内容。然后它就会返回给你一个 JSON 格式的结果，里面就是 AI 的回复。

OK，我们再举一个更日常的例子。假如你有某个天气 App，它怎么知道今天是几度呢？它可不是说，我的 App 里面装一个温度计，自己去测温度。它是在后台调用气象局或者天气数据服务的 API，然后 API 去访问气象局，气象局返回温度结果，最后再返回给天气 App，拿到这些数据，在 App 上展示给你。

OK，再以地图导航为例，路线怎么来？也是一样，调用比如高德地图的 API。然后你用微信登录第三方 App，也是一样，调用微信的授权 API。用 AI 写作工具，那就是调用 Claude 或者 GPT 的 API。

所以你看，几乎所有你用到的软件和工具，背后其实都是在用 API 互相通信。

OK，那讲完了 API 是什么，我们再来聊一聊 API 到底能够做什么。我这里给出三个典型场景。

第一个场景，就是你可以做自动化工作流。比如我在用 Zapier 或者 Make，当我收到一封客户邮件的时候，它会调用比如 Gmail 的 API 读取内容；拿到内容以后，再调用 Notion 的 API 创建一条任务；再通过 Slack API 发送通知给团队。所以整个过程零人工，但这背后是三个 API 在协同工作。

第二个场景，搭建你自己的 AI 产品。很多人都会用 GPT 的网页版，但如果你想把 AI 能力嵌入到自己的工具里面，比如说你想搭一个自己的客服系统、自己的笔记软件、自己的销售助手，那你就需要用 API。

这里就是我给出的几行代码示例。所以你看，就这几行代码，你就拥有了一个 AI 助手的核心能力。剩下的就是，你看怎么把这个 API 包装起来。

好，那第三个场景就是数据的获取和整合。比如电商平台想分析竞争对手的定价，财务团队想自动拉取每天的汇率，运营想监控社媒上的品牌关键词，这些也都可以通过对应平台的 API，实现数据的自动获取和整合。你不用手动复制，也不用截图，直接就进数据库。

OK，那前面我们讲的，包括 API 是什么，包括 API 能用来干什么，其实都算是基础入门内容。那现在我们再聊一聊更深的东西，这也是很多科普视频不会讲到的地方。

第一个就是 API 的两种主流形态，一个叫作 REST，一个叫作 GraphQL。我们平时说的 API，大部分都是 REST API。它的逻辑就是，每个资源对应一个 URL，你通过不同的方法，比如大家经常看到的 GET、POST、PUT、DELETE 来操作它。

它的好处就是逻辑很清晰，很容易理解，也是目前最主流的方式。但 REST 有个问题，如果你想获取用户的名字和他最近发的帖子，你可能就需要调用两个接口，第一个就是 GET User，第二个就是 GET User Posts。而且可能它的接口返回了很多你不需要的字段。

所以这个时候，GraphQL 提出就是希望能够解决刚聊到的这些问题。它能够让你自定义，我到底需要的是哪些字段，只要发一次请求，它就能精准地获取到，不多也不少。Facebook 开发的这套方案，现在在中大型项目里面也非常流行。

第二个比较关键的，就是 API 的鉴权机制。为什么你的 API Key 绝对不能泄露？因为 API Key 就是你自己的身份证。平台用它来判断这个请求是谁发的，它到底有没有权限，它用了多少额度。

如果你的 API Key 被泄露了，比如现在大家很火的“龙虾”，经常会有 API Key 泄露风险，那别人就可以拿到你的身份去调用 API。产生的费用你自己来付，数据被访问了你也不知道，严重的时候甚至能够把你的账户给清空掉。

我这里也列举几个很常见的泄露方式，看你们有没有中招。第一个，比如说你想把你写的代码开源出来，上传到 GitHub，但是你的 API Key 写在代码里面，你忘记删了。第二个，你把 Key 粘贴在截图里面发给朋友。第三个，你自己用完了不删除，留在公用电脑的浏览器里面。

所以正确做法就是，Key 应该存在一个 `.env` 文件里面，不要上传到代码仓库。然后给 Key 设置最小权限。第三，一定要定期轮换这个 Key，因为各个 API Key 平台都会有一个重新生成的机制。第四，一定要设置你的用量告警。如果你发现这个用量并不是你现在的实际使用量，那你就得赶紧看你的 API Key 是不是泄露了。

OK，然后第三个点，我们叫作 Rate Limit。大家是不是有时候想，为什么你的请求有时候会失败呢？因为每个 API 服务都会有速率和并发的限制。意思就是，你每分钟或者每天最多能调用几次，或者每分钟同时能调用几次，超了就会报错。

另外要注意，这不是一个 Bug，这是设计。平台需要防止滥用，也要保护服务器资源。所以实际开发中，你必须要知道：第一，清楚你订阅的这个资源，它的 Limit 是多少；第二，你要额外做好重试机制；第三，批量操作的时候要做好请求排队；第四，我们聊的 Token 消耗并不等于请求次数。你一次请求可能会消耗一百个 Token，也可能会消耗一万个 Token，它主要看你的请求内容。

OK，还有一个关键点，叫作 Webhook。这个是反向 API 的概念。普通的 API 是你主动去问，比如说你问“有没有新的订单？有没有新的消息？”那 Webhook 就是它主动跟你讲，“我有新的订单了，我通知你。”

举个例子，比如说你接入一个支付平台，用户付款成功以后，支付平台会立刻向你指定的 URL 发送一条消息，告诉你说这个订单 123 已经支付成功了。你不需要每秒做轮询，比如说一秒钟问一下这个 API。它拿到信息以后，主动推给你，更加实时、更加高效。这个在支付回调、GitHub 提交通知以及自动化触发器里面都非常常见。

那最后总结一下今天讲的内容。第一个，我讲了 API 是什么。API 最直接的理解就是应用之间通信的桥梁。通过 API 做通信，就好像服务员一样，传递我们顾客的请求，然后给到厨房，以及把厨房的结果给到顾客。

那 API 能做什么呢？包含自动化工作流，包含搭建 AI 产品，包含做数据的获取和整合，几乎是无所不能的。

那专业层面上，你需要知道的有四点。第一，就是 REST 和 GraphQL，它们各自的适用场景。第二，API Key 是一个非常重要的东西，千万别泄露。第三，Rate Limit 是一个比较常规的设计，它就是为了防止服务器的请求量过大，一定要做好错误处理。第四，Webhook 是一个反向 API，用来做实时推送。

那如果你想真正掌握 API，下一步就是去动手，选一个你在用的工具，去找它的 API 文档，试着发出你的第一个请求。那踩过这几个坑以后，你就真的懂了，API 到底是个什么东西。
