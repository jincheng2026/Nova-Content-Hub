hello 大家好，今天这个视频呢，想和大家聊一下，就是我们现在经常听到的 AI Model、AI Agent、Harness 架构这些东西到底是什么，它们的区别和联系在哪里。

那我们首先来聊一下 AI Model 吧，像我们现在都经常听到的 LLM，其实就是我们现在最常见的大模型，然后它是基于 Transformer 架构做出来的模型，它可以根据你的问题，一个 token 一个 token 地去预测下一步它要生成的内容是什么，现在搭配一些 VLM 模型，它也可以去做这种多模态的理解。然后现在 AI Model 它和 AI Agent 最大的区别，其实就是因为刚刚讲了，Transformer 架构其实是让它一个 token 一个 token 去预测下一个词是什么，所以 AI Model 它能做的就是想和生成，它其实没办法去做动作、去帮我们完成任务、给你交付一个结果，它其实是做不到的，它只能做思考和生成。

然后 AI Agent 它和 AI Model 最大的一个区别，就是它给这个 Model 外面套了一层 Harness 架构，让它从只能想，变成了可以去帮我们执行任务、交付结果。那这个 Harness 它到底是什么东西呢？其实简单来讲的话，它的架构其实就分三层：第一层，就是它可以去帮助模型做工具调用，也就是 Tool Calling，我们平时看到的联网搜索、调 API、GitHub Push，然后以及各种各样的工具，它都可以用这个 Tool Calling 去把它调用过来，也就是给模型增加了一些外挂。

然后第二点的话，就是它可以把我们模型执行完这个 Tool Calling 以后的任务结果，返回给模型，让模型再看一下这个结果，然后思考出来下一步我们应该怎么样去执行。而第三点的话，也就是它可以去完成一个循环，最经典的范式就是 ReAct 范式，比如我们拿到了一个任务，然后它去做任务拆解，然后每一步小任务执行完的结果，它都返回给模型，模型再去思考，思考完了之后再给出下一步动作，然后它再去执行，再去思考，再去迭代，就是这样一个不停循环的流程，其实就是这个 ReAct 范式。然后我们想要完成这样一个任务，其实都得不停地去修改，然后不停地去迭代，去改掉 bug，最后才能给你一个达到预期的、可交付的结果，这其实就是 Harness 架构最主要的三个点。

然后后面的话，我想和大家聊一下，关于我们现在市面上看到的各种各样很火热的 Agent，因为它其实有很多，分类也很多，可能很多人都很好奇，我到底应该去学哪一种，我今天就来讲一下我了解到的这些。

比如说第一类，也就是 Agent 开源架构，像 OpenCode 还有 DeepSeek 新发布的它的 Harness，还有【疑似：Amp Agent】，这些都是现在非常火热的开源 Agent 架构，我们可以把它部署到自己的电脑、自己的服务器上然后去运行，它最大的特点就是它是开源的，它是高度可定制的，它的各种权限参数我们都可以根据自己的喜好去调，它就很适合比如说极客、深度开发者，我们需要一个非常适合自己的高度定制化 Agent，那是很适合我们用这一类开源的 Agent 去做。

然后第二类的话，可能平时 Coding 比较多的朋友就会用到，像 Cursor、Trae，然后还有 VS Code Copilot 这样的，我们打开这种 Agent，它的界面其实是和我们代码编辑器的界面是一样的，只不过在右边或左边多一个小的对话窗口，然后我们就可以看到代码的工作页面，然后它去修改哪些地方，在那个小窗口去和它对话，它的 Harness 架构最大的特点，其实就是服务于我们的代码工程，它可以把我们的目录以及文件各种东西给它联系起来，然后它整个运行逻辑，也就是围绕着改代码、给你一个完整的可运行的代码文件这样一个逻辑来的，所以其实这类 Agent，你让它去干别的杂活它也可以干，但是它会更加适合去做这种代码编辑的工作。

然后第三类，也就是现在最火的一类，也是最好用的一类，就是这种可视化编辑界面的 Agent，比如说像 Codex 和【疑似：扣子空间/秒哒】这样的，我们打开它其实就和我们平时用网站上面的那个模型是差不多的，它是一个非常可视化的对话窗口，然后我们可以看到它每一步调用了什么工具，做到了哪一步，哪里需要你去执行任务等等，它就非常适合这种新手小白，以及一些个人独立开发者等等，但是当然 Codex 能力确实很强，但它有一些弊端，比如说 Codex 它现在只能接 OpenAI 家的模型，没办法用别的家的模型，但是国内的【疑似：扣子空间】它就很巧妙地解决了这点，我们可以用它去接各种各样的模型。

然后再到第四类，也就是这种终端运行类型的 Agent，比如说 Claude Code，还有 Codex 的 CLI 版本，这些的话它最大的特点就是它非常快，它的权限非常大，然后我们在使用它的时候，其实是需要一定的代码基础的，因为你至少得会敲几行命令，你才能用得起来它，它就是完全生活在你的终端里面，没有花里胡哨的各种界面，直接在你的本地去运行各种各样的文件，这种类型的 Agent 其实就很适合这种深度开发者，以及原本就有技术基础的人，它就会非常方便，而且它会很快，效率会很高，开销会稍微小一点，当然如果你用的是 Claude 模型，它的开销也少不到哪去，还是很贵的。嗯，基本上就是市面上现在很火热的这四款 Agent。

然后我个人的话，其实是比较推荐大家先去使用【疑似：扣子空间】和 Codex 这类的可视化 Agent，因为它第一能力非常强，第二非常好上手，特别是【疑似：扣子空间】，我们在国内不需要各种各样的条件，我们直接就可以使用，而且它可以接各种各样的模型，这也是为什么我们一直在录的都是【疑似：扣子空间】的教程，因为它非常便捷。
