# 封面设计

本 Skill 的制图结果固定为 **3:4 竖版中文封面**。先按本次请求区分解释或评审、提示词交付和实际制图：仅解释、诊断或评审时交付相应结果，不自动生图；只需要提示词时按提示词模式交付，无须使用固定口令；明确要求制作封面时，默认直接调用已授权范围内可用的图像生成工具并交付图片。

本 Skill 的首要目标是高审美，不是规则完成率。默认从成熟完整案例中寻找最接近的视觉结构，保留其标题、人物、主视觉和空间关系，再替换成当前内容。规则用于否决失败稿，不能代替具体画面。

## 读取顺序

每次执行只读取任务需要的文件：

1. 读取 `config.md`，确认人脸参考、模型和本地偏好。
2. 读取 `references/content-routing.md`，提炼内容核心并排序风格。
3. **完整读取 `references/examples.md`**，从提示词案例和 `assets/examples/` 成品图中寻找构图锚点。
4. 读取用户指定或本轮推荐的风格文件。
5. 读取 `references/case-rewrite-policy.md`，把案例空间结构改写成当前任务的完整生图规格。
6. 读取 `references/viral-cover-grammar.md` 和 `references/aesthetic-qa.md`。
7. 需要真人时读取 `references/face-reference-policy.md`。
8. 只有需要补充风格来源时读取 `references/reference-index.md`；只有用户明确选择「狗哥风格字体」时读取 `references/dog-font-policy.md`。

不要默认读取全部风格文件。案例图先用 `view_image` 观察；不得把含其他真人的案例图与用户人脸同时输入生图模型。

## 三种模式

### 探索模式（默认）

适用于用户未锁定单一风格、要求多生几张、要求推荐同时尝试其他风格的情况。

1. 先形成一份共享内容简报。
2. 推荐 2～3 个高适配风格，并说明一句理由。
3. 再选择 1～2 个实验风格；用户指定数量或风格列表时严格按用户要求。
4. 每种风格最终只交付 1 张，分别选择 1 个完整案例作为构图锚点；禁止同一面板换颜色冒充不同风格。
5. 先编译完整生图规格，再把标题、人物、主视觉和背景作为一个整体直接生成。
6. 审美失败可以内部迭代；「每种风格 1 张」限制最终交付数量，不限制淘汰失败稿。
7. 展示全部合格候选，等待用户选择后进入精修。

用户已经提供文案、风格列表、人物素材或视觉约束时，不得重复询问。

### 生产模式

适用于用户指定一个成熟风格、要求复刻已选方案或继续迭代某张封面。

1. 读取指定风格及其核心参考。
2. 保留已确认的视觉命题和标题结构。
3. 只修改用户指出的问题，不擅自更换风格家族。
4. 生成后重新执行案例对照审美门与最终交付门。

### 提示词模式

本次交付是提示词时使用。仍须完成内容诊断、视觉命题、风格选择和审美预检，但不调用生图工具。仅要求解释或评审时，只完成对应分析，不自动转入提示词编写或生图。

## 核心工作流

### 1. 建立共享内容简报

严格保留用户指定的中文文案，另外提取：

- 一句话内容核心
- 内容类型
- 已有真实证据
- 不可虚构的事实
- 观众应记住的冲突、结果或动作
- 人物身份和已确认比例

### 2. 检索完整案例

为每种风格从 `references/examples.md` 和 `assets/examples/` 中选择 1 个最接近的构图锚点。优先匹配顺序：

1. 人物任务和主视觉的动作关系
2. 标题几何与遮挡层次
3. 主视觉体量和空间骨架
4. 材质与色彩
5. 主题词相似度

不能只因为同为「AI」或同为深色就选案例。记录：

- 选中的案例
- 必须保留的 3～5 个结构关系
- 必须替换的内容元素
- 不得继承的原文案、商标、他人身份和无关装饰

没有完全同风格案例时，选择空间关系最接近的案例，再用风格文件约束材质；不得跳过案例直接自由设计。

### 3. 建立视觉命题并改写案例

视觉命题回答：

> 如果这张封面只能留下一个画面，观众应该记住什么？

视觉命题必须是可画出的事件、物件关系或信息图形，不得只是「科技感」「高级感」「注意力管理」等抽象词。

探索模式下，不同风格必须改变至少两项：

- 核心主视觉
- 空间关系
- 材质载体
- 标题几何
- 人物任务

按 `references/case-rewrite-policy.md` 把案例改写成可直接生成的完整画面规格。必须具体写出：

- 人物在什么位置，手、眼神和身体朝向哪里
- 主视觉是什么，占多大，正在发生什么
- 标题分几级、在哪里、与谁互相遮挡
- 前景、中景、后景分别是什么
- 哪些结构关系来自案例，哪些内容已被替换

「视觉命题」「高级感」「材质统一」等设计术语不能直接充当生图描述。

### 4. 选择模型输入

- 真人封面每张只输入 1 张用户身份参考。
- 含其他真人的完整案例只用 `view_image` 观察并转译为文字，不与用户人脸同时输入。
- 无真人、无巨大遮挡块且构图完整的参考，确有必要时才作为风格输入。
- `assets/style-references-safe/` 不是默认输入源；出现大色块、空洞或构图残缺的遮挡图只能做局部材质观察，不能作为构图锚点。
- 产品、UI、设备和数据素材按证据需要输入，不得用虚构界面替代。

### 5. 一体化生成完整封面

默认把以下内容在同一次构图中生成：

- 标题组
- 内容主视觉
- 用户人物及其动作
- 必要的辅助证据
- 统一背景和材质

人物必须从构图开始就参与托、指、推、挡、揭、观察、操作或裁判关系。禁止先做一张完整背景，再把同一个抱臂人物贴到空角落。

本次请求已授权实际制图时，生成前先完成完整生图规格；用户未要求审核提示词时不暂停、不重复询问，在已有工具与付费授权范围内直接调用图像生成工具。解释、评审或提示词交付不自动进入生图阶段。

### 6. 案例对照验收与内部迭代

每张生成后同时查看：

- 生成结果
- 选中的完整案例成品或案例提示词
- 对应风格文件

按 `references/aesthetic-qa.md` 写出具体对照证据，不能只打分或宣布「通过」。

- 整体审美、构图或风格失败：在本次允许调整的范围内返工；整体制作已获授权且不涉及用户明确锁定部分时，重新生成完整封面。不得为了通过审美检查改动用户要求保留的背景、人物、文案或其他部分；确实无法同时满足保留要求与验收标准时，说明冲突，取得扩大修改范围的明确授权后再继续，不降低验收标准或宣称已完成。
- 只有中文错误：优先局部修字或重排标题。
- 只有人物比例、边缘或身份失败：按 `face-reference-policy.md` 做局部身份修复。
- 同一风格内部可以淘汰失败稿，最终只保留并交付 1 张。

### 7. 最终交付验收

逐张检查：

- 中文逐字准确
- 身份一致
- 人物比例和手势清楚
- 人物不遮挡关键词和核心证据
- 视觉命题仍然成立
- 与选中案例具有可识别的结构继承，而不是只继承颜色
- 人物、标题和主视觉组成同一个画面，不像后期贴图
- 与其他候选不是同一模板换色
- 手机缩略图中最大关键词和主视觉轮廓可辨认

不合格主动修正后再交付。最终直接展示图片，并标明风格名称和本地路径。

## 不可妥协规则

- 用户指定文案不得擅自增删改。
- 没有真实产品素材，不得生成似真 SaaS 后台冒充产品证据。
- 没有真实数据，不得虚构坐标、百分比、增长曲线或研究结论。
- 抽象内容优先转译为事件隐喻、编辑图形、角色冲突或纸媒方法，不默认使用仪表盘。
- 每张图只使用一个主视觉命题和一个主要材质系统。
- 审美优先于流程完成率；身份和中文作为硬否决条件，不能反过来决定整张图必须使用贴图流程。
- 人物身份验收与整体审美验收分开；任何一项失败都不得交付。
- 无人物背景＋确定性抠图只用于身份修复或用户明确要求，不得作为默认构图流程。
