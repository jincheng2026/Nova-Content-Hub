沿用参考项目当前的身份与设备授权流程：系统浏览器 OIDC Authorization Code + PKCE S256 → Electron 主进程持有登录会话和本机设备钥 → NovaAuth 签发产品权益断言 → 桌面与插件共用验签规则。只使用一个产品 `nova-content-hub`，不引入标准版/Pro、多身份供应商、付款、兑换码或通用授权框架。

`Device-Proof` 采用参考的 EdDSA JWS：header 为 `{typ:'device-proof+jwt',alg:'EdDSA',jwk:{kty:'OKP',crv:'Ed25519',x}}`；payload 为 `{htm,htu,iat,jti,ath,bh}`。`ath` 是当次 access token 的 SHA-256/base64url，`bh` 是实际发送 JSON 字节的 SHA-256/base64url；先序列化一次再同时哈希和发送。重试生成新的 jti，并用刷新后的 token 重算 ath。时间偏差依据可信 HTTPS 响应 Date 校正，`clock_skew` 有界重试一次，不无限重试。依据：[devices.ts:67](/Users/mac/code/ide/NovaIsland-Tech/Nova-Travel-Marketing-dashboard/workbench/src/main/auth/devices.ts:67)、[重试与会话 generation:207](/Users/mac/code/ide/NovaIsland-Tech/Nova-Travel-Marketing-dashboard/workbench/src/main/auth/devices.ts:207)。

### 4.2 主进程登录、持久化和设备钥

在 `workbench/src/main/auth/` 放少量职责文件：可信 config、OIDC+loopback、session/store、device、auth service；沿用 TS/Node/Electron，不移植 Vue 页面或旅游业务配置。系统浏览器完成登录；仅监听 `127.0.0.1` 随机端口，固定路径、state 严格相等、一次消费、超时/取消关闭 listener；token 交换完成前回调页只能说「已收到登录回调」，不能预报已登录成功。

检查 token 的 issuer、audience、azp、sub、nonce 和真实时间范围。参考 `oidc.ts:233` 只检查 exp/iat 的类型，不能照搬成完整时效验证。参考允许直接 TLS code-flow token 响应不验 ID token 签名；本产品若沿用该边界，必须保证响应仅来自固定可信 token 端点，磁盘数据不作为重新完成身份验证的替代，且 OAuth token 绝不当作权益断言。权益必须单独严格验签。

token 和设备钥只由主进程使用 safeStorage 加密写入本产品 userData，目录与内容库、导出包分离。macOS/Windows 使用各自系统保护机制；系统加密不可用时 token 可仅留内存并明确提示，设备钥不允许临时内存降级或明文落盘。设备首次生成 Ed25519，JWK thumbprint 按 `{crv,kty,x}` 字典序 JSON 计算 SHA-256/base64url；key 稳定存在，不因退出、库切换或升级删除。损坏/解密失败显示设备恢复状态，不能每次启动悄悄换钥造成席位耗尽。

写盘沿用本项目受限路径、临时文件、fsync/rename与错误报告习惯，不照搬参考 Windows 失败后直接覆盖目标的非原子回退。退出先终止本机会话、取消旧请求、使共享权益失效，再尽力远端 revoke；本地 token/权益失效写入失败必须显示错误，不能把清理失败报告为插件已退出。

### 4.3 共用权益校验与插件只读记录

新增一个桌面和插件共同使用的纯验签模块，和分开的「主进程写记录」「插件只读记录」适配；不允许插件 CLI 暴露写 grant、签名或传任意 key/now/audience 的命令。保存服务端原始签名 assertion，不重签、不把解析出的 allowed 布尔值当持久授权。

校验顺序：有界字节/JSON/JWS → 精确 3 段 base64url → alg/typ/crit → 已知 kid → Ed25519 签名 → 精确 issuer/audience → 非空 sub、有限且合理的 iat/exp（exp > iat）与 clock_offset → 未过期与允许的时间偏差 → 本机 ldev。cnf.jkt 必须是有效字段，主进程再对当前会话 sub 和本机钥 jkt；服务返回字段缺失、签名错误、未知钥、错产品、错设备均不产生授权。不要只复用参考 `readEntitlement().state==='ok'` 而遗漏主进程的 sub/jkt 比较。

本产品 ldev 使用自己的命名空间：`SHA256('nova-content-hub|' + lower(hostname) + '|' + lower(username))`，按参考方式 base64url。这是拟定客户端算法，须和服务端接受 ldev 的合同一起确认。只发送散列，不发送电脑名/用户名。它不是设备私钥持有证明；插件没有 safeStorage 设备私钥，只能核对这个本机提示。因此该方案能挡普通复制，不能宣称抵抗主动伪造同名机器、同系统用户或修改客户端。

记录位置由主进程和插件共用本产品的系统应用数据定位函数，不能放进内容库或备份，也不沿用 `~/.nova-travel-marketing`。macOS 与 Windows 使用同一逻辑结构、各自系统基目录；固定位置、受限普通文件、大小上限与防符号链接处理继承本项目 handoff 文件边界。schema 4 成功记录仅 `{schema:4,assertion}`；拒绝提示只含 assertion:null 与必要原因，提示永远不能放行。只允许当前桌面主进程发布/清除记录，Codex、WorkBuddy 执行相同插件校验。

## 5. 过期、撤销与离线的确定规则

1. 只有验签通过且当次未过期的断言能放行；桌面另要求会话账号与设备钥一致。缓存 `entitled` 状态不能越过 exp。每次业务入口重新判定，不能只在登录/刷新时检查。
2. 网络失败、超时、5xx 或刷新后仍 401 作为暂时不可达；保留会话，但只能用原有且仍有效的签名断言，没有有效断言则拒绝。明确 token `invalid_grant` 才清失效会话；新断言验不过不写入、更不能延长旧断言。
3. 明确 not_entitled、user_disabled、device_revoked、名额/换机限制立即停止本次授权并发布无 grant 的拒绝记录；不因旧断言尚未过期继续在该桌面放行。退出、换账号、明确登录失效先撤掉旧共享 grant，防止旧异步响应重新发布。
4. 主进程打开、登录成功、用户刷新、恢复前台/唤醒时查询；运行中可沿用参考的 15 分钟刷新/失败 5 分钟重试作为本地调度建议，不宣称服务 SLA。网络重试有上限、单飞和 generation，短时多事件合并。
5. 离线有效期只看服务签名 exp，并且不能超过签名的 scope_until（如存在）；不另赠本地宽限期、不把系统时钟调整当续期。按签名 clock_offset 校正时间并检测明显回拨；普通桌面无法给出不可回滚的可信离线时钟保证。
6. 离线插件无法即时知道服务端撤销，最长残余有效窗口受断言 TTL 限制；本地拒绝记录仍可能被有权限的人回滚。若产品要求强实时撤销，需要改变合同、在操作时联网或使用在线桌面授权服务，不能承诺当前只读离线 grant 已做到。现阶段不擅自增设该服务。
7. 本地拒绝/清除写入失败时，桌面立即拒绝并提示「插件授权记录未能同步失效」；记录故障待恢复，不能报告全端已撤销。已有离线副本最多持续到签名到期这一风险必须如实说明。
