Git 是什么？今天给大家讲的就是 Git。

想象这样一个场景，你用 AI 去生成一段代码，运行起来挺好的。然后你让 AI 再进行下一步的优化，结果发现新版本出了问题。你想回退到上一个版本，却发现这个版本的代码没有保存下来，所以这段好用的代码就这么消失了。这个就是没有 Git 的世界。

所以今天就给大家讲 Git。先给大家讲一下 Git 是一个什么。Git 是一个版本控制系统，用来记录文件的每一次变更，让你能够随时回到任意一个历史状态。比如说有一、二、三、四到 N 个版本，你能回到任意一个。所以你可以把它想象成一个无限存档的游戏系统。每隔一段时间，你就打一个存档，随时可以读取任何一个时间节点，都不会丢失。

更具体来说，Git 管理的是四个区域。第一个是工作区。工作区里面包含的是你正在编辑的文件，就是你所能看见的代码。

第二个区域是暂存区。暂存区包含的是你准备提交的文件，相当于是打包待寄的区域。

第三个就是本地仓库。本地仓库就是已经正式记录的历史版本，它存在你自己的本地电脑里面。

然后再是远程仓库。远程仓库存在远程云端，比如大家熟知的 GitHub。在这里可以团队共享，也能够做异地备份。

看到这四个区域以后，Git 提供了一系列核心操作，来串联起从工作区到暂存区、到本地仓库、到远程仓库的一系列流程。

首先是 `git add`，主要是把工作区里面的代码加入到暂存区。然后是 `git commit`，把暂存区里面的代码提交到本地仓库。接下来是 `git push`，把本地仓库的代码推到远程仓库。

OK，以上就完成了工作区的代码到远程仓库的流程。那从远程仓库怎么拉到本地呢？用的是 `git pull`。接下来还有 `git checkout`，包括 `git restore`，把本地仓库里面不同版本的代码同步到工作区。

OK，以上就整体把 Git 里面基础的一些分区，包括基础的一些操作，给大家讲完了。

接下来再讲 Git 的下一个灵魂，叫做分支，Branch。分支是 Git 里面最强大的特性，也是最容易被新手忽视的一个。

我在这个图给大家写了一个不同版本代码向前推进的简示图。上面我们叫做主分支，定义为 Main。你看，主线是在稳定推进的。然后你可以比如说在 C3 这个版本里面分叉出一条叫做 Feature 的分支，在这个分支里面自己做实验、开发新功能，完成以后再合并到主线。

这个的好处就是你的主线从来不会被破坏。你可以保证 Main 分支里面每一个版本都是没有 Bug、没有问题的。Feature 分支是做新功能开发的，你可以在里面做各种尝试、调试，当它稳定以后，再把它合并到主分支里面。

所以这套机制直接解决了一个很古老的工程问题，就是怎么同时维护线上的稳定版本和开发中的新功能。

所以，以上从下面的基础到上面的分支，就是 Git 里面两个最核心的点。接下来讲一下为什么 AI 编程前，你还是必须要搞懂 Git。这个其实不是学完 Git 再去用 AI 的顺序问题，而是工作方式的根本性转变。

首先，AI 生成的代码是不可信的，你需要能够快速回退。你看，AI 写代码速度很快，但出错的频率也很高。它可能改了五个文件，结果只有三个是对的，另外两个会引入新的 Bug。没有 Git，你根本就不知道 AI 改了哪里，也无法精准地回退到某一个节点。有了 Git，你可以直接通过 `git diff` 看清楚这些改动，然后通过 `git reset` 做回退。

第二个，AI 编程是一个小步快跑的节奏。所以在小步快跑这个节奏里面，Git 是最好的伴侣。好的 AI 编程方式，是提一个小需求，让 AI 实现，再验证，再 Commit，再去提下一个需求。每次验证通过，你最好就 Commit 一次；失败了，就 Reset。这种可以把它最直观地理解为存档到读档的循环，让你对代码的掌控感完全不一样。

第三个点，AI 其实还可以直接操作 Git，但是你还是得看懂 AI 到底怎么操作 Git。现在的 AI 编程工具，比如 Claude Code、Cursor、GitHub Copilot，都可以自动执行 `git add`，包括 `git commit`，甚至还能帮你写 Commit Message。但如果你不懂 Git，你就无法判断它到底在做什么，这个命令到底做得对不对。比如当它执行 `git push --force` 的时候，你知道那意味着什么，是不是会影响后续的一些编程？

第四个点就是团队协作。团队协作里面必须要用 Git。不管你是独立开发者，还是团队里面用 AI，代码的协作、Review、部署都建立在 Git 上。不懂 Git，你就无法参与这套工作流。

OK，所以 Git 其实有很多命令，但是也不需要一口气学完所有命令。我在这里给大家展示了需要掌握的基础操作，大家可以截图做个笔记，然后自己记下来。

最后总结一下，Git 不是进阶工具，它是现代编程的基础设施，就像写作需要保存文件一样基本。在 AI 编程时代，代码生成的速度大幅提升，但随之而来的是更高频率的试错、更多文件的改动、更复杂的协作场景。Git 就是为了应对这一切而生的。

所以搞懂 Git，不是为了成为工具的专家，而是为了真正掌握自己的代码，不管它是人写的，还是 AI 写的。
