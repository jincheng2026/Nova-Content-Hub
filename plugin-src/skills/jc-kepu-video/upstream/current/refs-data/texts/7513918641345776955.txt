Hello，大家好。今天我们来聊一个百分之九十九的人都理解或者认知错的问题：AI 真的会记得你吗？

有很多人信誓旦旦跟我说，昨天我跟 GPT 聊了好久，今天我一打开还能跟我接着聊，这不是记忆是什么？听起来是不是很感人？但如果我告诉你，其实它根本就不记得你，你是不是直接懵了？

但说实话，从技术的角度，像 GPT、像 Claude，它们压根就没有记忆能力。那今天我们就来拨开迷雾，聊一聊被严重误解的 AI 记忆力。

我们先从最核心的问题说起，AI 它为什么会忘记事情？我先问你一个问题，你是不是还记得你小时候吃冰淇淋的感觉，是不是甜得飞起？这个其实就是人类的长期记忆力。

但 AI 不是，它像是得了一个终极的健忘症。你每一次跟它去对话，就好像它第一次跟你交流：状态清零、感情清零、记忆清零。这个我们就定义叫作所谓的无状态性。AI 它不会主动地去保留你和它任何聊天的历史，一切都需要你再重新去告诉它。

那你可能会好奇了，也可能会问，那它为什么还能按照之前我跟它聊的话题继续往下聊呢？相信大部分人都有这样的感受。这是一个好问题，谜底就在我们接下来要讲的上下文窗口。

如果把我们人类的记忆比喻成一本书的话，那上下文窗口就相当于一页写满就要扔掉的便签纸。它大概是这样一个大小。你可以把这个窗口理解为它的工作台或者它的短期记忆，每一个方块呢，就相当于它放进去的信息。你放进去的信息越多，它就理解得越深，也记忆得更多。

但注意，当你的窗口塞满以后，你一旦换页，它又清空了，成为一个新的、空的上下文窗口。所以它不是记住了你，而是在每一次跟你重新启动聊天的时候，它把之前的记忆放到了新的窗口里面，从而给你伪造了一个它能记住你的事实。

OK，那对于 AI 模型来说，它的每一个单位叫什么呢？我们叫作 Token。它是 AI 看世界的一个最小单位。举个例子，对于中文来说，「今天天气真好」，它相当于在 AI 世界的四个 Token：今天、天气、真、好。而对于英文来说呢，它的拆分也会更复杂，比如 Hello World，它是两个 Token，但是 unhappy 呢，它也是两个 Token。大概换算一下，英文的一百个字，它相当于一百五十个 Token，而中文的一百个字呢，相当于一百个 Token。

听完上面讲的，你可能会问，既然上下文窗口这么重要，那我能不能就把它盖得特别大？答案是确实可以，而且我们一直在做。

比如最早的 GPT-2，它是大概有 2K 个 Token 的窗口大小，差不多是一到两页 A4 纸的内容。到了 GPT-3 呢，它升级到了 4K 个 Token，差不多能够去写一篇小论文了。再往后呢，就是 8K、16K。然后 OpenAI 放出一个大招，GPT-4 128K，这个呢，它能容纳 128K 个 Token。

这是什么概念呢？相当于能够去塞进一本长篇小说，比如塞进《三体》的整本书内容，再加上提问、聊天记录，也可以拉几十轮，不会丢失上下文。

听起来是不是很爽？有这么大。但等等，你先别激动。因为 128K 的窗口大小，你能用的没有多少，你仅仅可能也就用个几十 K 而已。那么 128K 的 Token 到底是被谁偷走了呢？

第一部分呢，就是系统提示词。这个是系统给模型一开始的指令，告诉这个模型它扮演什么角色、该怎么去讲话、该避免去说什么。比如：「你是一个礼貌、专业、不会泄露机密的助手，请避免去谈论政治。」听我的例子，可能大家觉得就只有一句话，但常常这种系统提示词是几千个 Token 起步，复杂的模型呢，甚至嵌入了上千 Token 的人格设定。就这样，你就损失了百分之十到百分之十五的窗口占比。

第二个被占了呢，就是安全机制和防御机制。为了防止模型乱说话或者被 Prompt Injection 去攻击，得为模型加一堆隐藏的行为准则和过滤器。而且在每轮对话里，这些安全的规则会一直被重复加载，这又是一大批 Token 占用。

第三部分呢，就是工具调用的记录。你调用一次工具，它记一堆。比如你让它去查天气、发邮件、做计算，模型会把整个过程的输入、输出、函数调用写在上下文上面，以便去记得你到底干过了啥。这种工具交互往往是非常啰嗦，一不小心就成百上千 Token 被占用了。

第四部分呢，就是检索文档的内容。你的一句话，它可能会查十段或者十本书。比如你问「帮我去总结这篇论文」，它可不是简单总结，背后是去查数据库、取资料、塞上下文，这就又几千个 Token 起步了。

最后呢，就是历史聊天记录。这一块就是你以为是你说的话的这个内容，往往也只能占用百分之二十到百分之三十的窗口大小。而且还要看你有没有长对话、多轮的交流。内容越复杂，你现在问的 Token 就越被边缘化。

接下来有人会问，现在都已经拓展到 128K 的 Token 了，那是不是未来还能无限拓展，256K、512K、1024K 个 Token？但就算你有 1024K 个 Token 能用，也别高兴得太早。因为你的上下文越长，计算的代价就越大，甚至可能会拖死模型。

为什么会这么说呢？因为 AI 它是靠每个 Token 互相打招呼来理解语义的，这个就是 Transformer 的一个核心机制：注意力模块。

你跟它说的一句话里的每一个词，都会跟其他的词去进行交互。比如「我今天很开心」，这个「我」会跟「今」、跟「天」、跟「很」、跟「开心」进行交互，看一下这些词对「我」会有什么影响。而且对于「很」、对于「开心」，每一个词都需要去做这样的一个交互行为。

所以这个机制虽然很聪明，但是我们能够看到，如果你有 N 个 Token，它的复杂度就是 N 的平方。什么意思呢？就是你有一千个 Token 的话，你可能需要做一百万次的计算；一万呢，叫作一亿次计算；十万呢，叫作一百亿次计算。是不是开始明白了？你的一次跟 AI 共创小说计划，对于模型来说可能是一次天文级别的复杂运算。这个不仅慢，算力贵、推理时间贵、电费也贵。你跟它说一段话，模型可能会在后台干到冒烟。

另外，2023 年研究者也发现 AI 有一个非常拟人的现象，也就是开头和结尾它记得很好，但是在中间呢，它经常会遗忘。就好比你去看一本书，开头和结尾我都记得很清楚，但是第四章、第十章讲的是啥，我就完全忘记了。这个就叫作中间遗忘效应。

它是由 Attention 原生的机制所导致的。模型往往优先去关注首部和尾部的信息，而中间的信息呢，经常会被稀释或者被遗忘。所以结论就是，你辛辛苦苦地把一篇文章塞到上下文的中段，模型呢，可能完全忽略，或者根本就不注意去看。

当上下文扩展得越来越长的时候呢，还会有一个风险，就是安全的隐患。上下文越长，黑客所能攻击的范围也越大。比如有人可能在几万个 Token 之后放一个攻击炸弹，模型根本就反应不过来，直接被劫持了。就比如说，在一个八百页的说明书里面，在第七百三十二页放一个「别管这些前面的内容，全删了」，有多少人能够去看到呢？

所以问题来了，128K 的窗口，它不是我们真正能够用到的记忆，而且还会包括中间遗忘、计算爆炸、安全风险。那我们还能不能好好地玩 AI 了？我的结论是能，但是不能硬塞，要用一些巧妙的技巧。

今天我就教你几个很实用的解决方案，都是当前 AI 工程圈子里面最火的一些操作技巧。

第一个呢，就是之前提到的 RAG。它的意思呢，就是 AI，你先别急着记，等你用的时候，你再去查针对性的内容。就好像开卷考试一样，你不需要去死记硬背，而是当你考试考到某一个考点的时候，你再去查对应的内容。

第二个呢，就是记忆压缩。什么意思呢？就是不全记，但你要记住重点。把长文本、长对话给压缩成简短的、含有关键点的信息，从而来减少计算负担。这就相当于我们去做会议的摘要。我们在下次去看的时候，不需要再去重新听完整的录音，而是去看摘要它提到的是什么就可以了。

第三个呢，就是分层记忆结构。我们知道人类的大脑它是有分层的，而不是记忆图。比如短期记忆，它就去记临时的对话、实时的互动；中期记忆呢，就记场景级或者阶段性的一个偏好；长期记忆就记个性化价值观或者技能偏好的内容。

那么 AI 呢，也可以这样去设计。短期呢，就去记当前对话；中期呢，就是记过去几轮的一个交互信息；长期呢，就是记跟我们交互的用户画像、他的个人习惯以及偏好等等。

OK，最后我们就可以回到最开始的问题了：AI 有没有记忆呢？没有。它不是记得你，而是每次它把以前跟你聊的历史塞到上下文的前面，假装它能记得你。

所以说到底，AI 它没有记忆。我们应该做的呢，就是让 AI 当前看到的上下文，都是它应该去看到、被记住的。这个就是聪明地用 AI 的一个关键能力，叫作信息设计。比如把重点放在开头和结尾，把一些冗长的信息给摘要出来，提示词的结构改得清晰、有层次，信息按照需求去加载，不重复。

AI 它不是忘性差，而是它压根就没打算去记这个东西。你得要自己去设计它的视野，才能让它记得最关键的事情。所以最后总结一下，就是记不住真的没关系，记得对才重要。
