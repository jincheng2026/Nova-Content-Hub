如果你用了两天的 WorkBuddy，会发现你的积分根本不够用，对吧？今天我就教给你怎么给 WorkBuddy 去配置第三方模型。简单来说是工作流工具的调用，但模型我可以换成其他更便宜或者更【听不清】的。目前推荐方案，首先第一个是 DeepSeek，成本非常【听不清：低】，能力够得上大模型的水平，可以在代码任务上提升明显，而且成本非常低，可以大量调用。

配置呢，我先获取 DeepSeek 的 API key。我搜索对应 DeepSeek 开放平台，进入到它的 API 开放的一个位置，然后这里面去点击 key，然后创建 API key，然后随便输一个名称，然后就可以快速得到你的对应的 API key。但这里有一个点需要注意，就是它只有在创建第一次的时候能够复制出来，后面的话就只能够新建一个 key 才行。获取 key 之后呢，要么就直接跟 WorkBuddy 对话去配置，要么就进入到设置里面去进行填写，非常简单，我们可以看一下，我们进去之后呢，我就只需要把对应的 key 和 URL 发给它，它就能够很快帮我配置好。配置完了之后，你就可以在右下角里边去点击对应的 Pro 或者【听不清】模型。还有一种方式就是你点击右下角这里面，进入到"配置自定义的模型"，然后这里面你就可以去选对应的提供商，比如深度求索，然后写你的 API key，然后保存就 ok 了，非常简单，几分钟就可以搞定。

第二种呢，就是去连接 Codex 订阅的账号，相对比较复杂一些，不如直接用原来简单的方式。WorkBuddy 在国内的话，工具的连接、环境的配置、工作流的搭建，其实会更加方便一些，它针对国内的用户而去提供这种模型的方案，配置更简单。我们只要发给 WorkBuddy"你能不能帮我配置一下 Codex 订阅"，可以啊，然后方案就是官方的地址、代理的方式，然后就让它帮我配置好。一开始我配置两个模型，也就是【听不清】和【听不清】，但是实际上我并不知道用的是思考强度【听不清：哪一档】，那我就给它对应的一个建议的思考强度模型。配置好了之后，我又发现一个坑点，就是如果发图片，它识别不了，然后我就让它去查核心原因，它就给到对应的根因，说是使用了类似 data 的 URL 去发送图片，而不是【听不清】，然后它就能够给我修复好。

后面我们怎么去选呢？其实如果你的需求主要是写代码或者自动化一些的项目，我觉得现在 DeepSeek 已经完全够用的了，但是如果你本身也有 Codex 订阅，那你拿来用也是 ok 的，那你就可以对应地在工作流里面权衡模型成本或者能力，然后再进行选择。
