## 业务目标

用户选择内容库和一个新备份目录即可保存全部本地成果。恢复时选备份及新目录，验证成功后才允许工作台绑定新库。原库、备份不被覆盖；既有目标即使为空也拒绝。界面不要求用户操作
JSON、复制路径或解释事务。

备份保存原始正文、图片、模板全部版本、提示词、软删除、发布快照、生成请求与回执、事务历史、未登记资源和空目录。精确排除运行锁
`系统（别动）/库锁`，不按扩展名遗漏用户文件，不执行备份中的脚本或 HTML。

## 实际协议

`backupLibrary(root,destination)`、`verifyBackup(backupDir)`、`restoreBackup(backupDir,destination)`
共用现有文件核心，没有第二套业务存储。备份是标准文件夹：

```text
新备份目录/
  manifest.json
  entries.ndjson
  data/                       # 原始树与空目录
  COMPLETE.json               # 最后独占发布，绑定清单与描述文件哈希
```

源库拿共用写锁，但不先调用普通 open/recover，避免备份前悄悄改变待恢复现场。文件分块复制和
SHA256，核对文件身份、时间、成员与复制前后的完整集合；清单逐行读写。只接受普通文件与目录，拒绝符号链接、跨平台非法路径及大小写/Unicode
归一化冲突。

恢复先核验包，复制到目标卷暂存目录，再恢复有限事务并核验业务引用。未完成事务的第三种外部字节导致拒绝，不覆盖。COMMITTED
只归档，不覆盖后续外部正文。created/claimed 封面尝试包括已软删内容一律标记 `RESTORED_INTERRUPTED`，保留历史 ID
并等待明确的新尝试，不自动启动助手。已提交回执与候选保持幂等身份。

最终目录以 mkdir 独占创建，文件独占安装；内容库描述文件最后发布。已发布后的同步异常明确返回 `outcome: committed`
，不误导用户重复建库。失败现场保留，下一次选新目标，不以删除现场模拟恢复。

Electron 用目录选择器调用同一核心。大量同步文件操作应放受控工作线程，不能阻塞 renderer/main 界面事件循环。

测试覆盖原始 BOM/CRLF/无尾换行、空目录、软删除、模板/照片/发布快照、历史与

## 尚未证明的事项

稳定观测复制不是 OS 原子快照，也不抵御持续恶意同权限进程。SHA256 证明字节一致，不证明备份来源可信。当前 macOS 临时目录与故障注入不能替代
Windows 真机、真实第二卷、真实磁盘耗尽/权限、掉电和 Electron 界面验收。旧库描述文件备份不是整库降级方案；更高 schema 继续拒写。
