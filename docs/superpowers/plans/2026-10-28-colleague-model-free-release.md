# 同事可用版与无模型权重交付 Implementation Plan

> **For agentic workers:** Use `executing-plans` or `subagent-driven-development` to execute the checkboxes. 产品代码、版本冻结和打包统一由「继续开发账号切换续接」负责；审查对话只写审查与交接文档，避免两个会话改同一份代码。

**Goal:** 先交付一个可供同事安装、打开自己的第二大脑、复用已有 Qwen3-ASR 并使用本人 TikHub Key 的安装包，再按同一验收表完成全部 CRUD、界面和原 Skill 流程闭环。

**Architecture:** 保留现有原位库、固定任务、来源版本和宿主插件契约。增加独立于应用资源的本地 ASR 发现与验证入口，默认不把任何模型权重装入工作台；任务只使用经过验证的运行环境。业务方法仍由助手读取对应 Skill、调用受控工具并等待作者确认。

**Tech Stack:** Electron / TypeScript / React / Node.js；现有 Python Qwen3-ASR 或 MLX 环境；现有 TikHub 服务代理。

**Spec:** 本文「用户要求」；根 `AGENTS.md`；`docs/design/内容工作台设计标准.md`；`docs/reviews/2026-10-28-colleague-readiness-review/README.md` 及其证据。审查证据截止 2026-10-28 15:34，后续修改必须重新核对，不能重复修复已经关闭的问题。

## Global Constraints

- 应用名称「自媒体工作台」，公司「杭州新岛橙灵智能科技有限责任公司」，版权「© 2026 杭州新岛橙灵智能科技有限责任公司」。平台、元数据、签名、安装后验收按根 AGENTS.md。
- 当前开发会话中的原任务和排队用户要求全部保留；本计划调整交付顺序，不取消旧任务。审查工具只能读已提交消息，执行者须自行核对后续实际收到的排队消息。
- 同事已安装 **Qwen3-ASR，本地 Python 或 MLX 运行**，用户已明确确认。不能当作聊天 Qwen，也不能把 Qwen-ASR 描述成写稿或生图模型。
- 用户已确认同事电脑是 **Mac M 系列（Apple Silicon）**，首包目标为 `darwin-arm64`。具体 macOS 版本尚未取得，不把开发机 macOS 26 的成功推及全部系统；其他平台后续独立验收。
- 下一份交给同事的包就不带模型权重；此要求更新了 `docs/handoffs/2026-10-28-local-asr-model-package-follow-up.md` 中「以后再拆包」的时序。保留旧文件作历史记录。
- 不更改真实资料库、个人凭证或活跃助手缓存来做验收；用独立用户数据目录和可丢弃库副本。真实付费采集只用已有明确授权、预算及用户本人配置的凭证。
- 不自动下载模型、不静默改用云转写，不猜原会话、不自动批准宿主权限；未知能力如实显示。
- 不能在另一个任务仍改源码时取混合版本打包。产品负责人完成当前原子修改后冻结，后续改动与已冻结产物分别记录。

## 用户要求与交付顺序

第一检查点是**新的轻量同事试用包**，不是再转发带权重的 0.5.2。必须打通打开库、本地转写、TikHub 配置、助手插件和核心内容主线；资料损坏、越权写入、错误正式入库等问题不得带入。独立低风险功能完善可以在首次包之后继续，但随包说明须逐项写明限制，不能称“所有功能已完成”。

第二检查点是**最终业务可用版**：所有已承诺实体的 CRUD/恢复、原有数据渲染、内容生成方法、异常恢复、安装升级分别有证据。第一检查点不会终止第二检查点。

原开发需求继续执行：内容默认卡片/可切列表；全部与合集同样支持；待办/暂缓/已写统一分页目录和枚举状态；所有持续增长集合统一分页；去掉截图红框和冗余小字但保留必要提示；助手跳转；原 Skill 顺序；资料正确沉淀；第二大脑版本标记和远端同步按原授权继续。

## Task 2：接入已安装的 Qwen3-ASR

**Files:** `workbench/src/main/local-asr-runtime.mts`、`service-tools.mts`、`desktop.mts`、`service-settings.mts`；`workbench/src/shared/service-contracts.ts`、`service-validation.ts`；`workbench/src/renderer/service-settings.tsx`。可增加同目录独立发现模块，避免把扫描逻辑堆进 UI。

**接口方向:** 发现候选 → 验证解释器/依赖/模型类型和权限 → 实际短音频试转写 → 登记选中环境 → 任务冻结引用。现有 `AsrSettings.localExecutable/localModelPath/localEngine` 可复用；结果需区别「未发现 / 发现但不可运行 / 可转写 / 可提供真实时间码」，不能只有文件存在布尔值。

- [ ] 先给新发现逻辑建立可注入目录和可执行探针测试：标准环境、路径含中文空格、Python 缺模块、无权访问、模型仅下载未安装环境、错误架构、多个候选、模型已移走、超时、取消。
- [ ] 自动检测明确支持的现有安装方式：已登记环境、常用虚拟环境与 Hugging Face 缓存/用户模型位置。界面入口显示「检测本地模型」；后台有界扫描，不能全盘递归或执行任意发现的脚本。GUI 进程不能假设继承终端的 PATH。
- [ ] 找不到非标准安装时允许选择现有 Python 环境和模型目录，随后走同样验证；不给用户一个假成功状态，也不强迫重新安装已存在权重。明确支持目录与检测边界。
- [ ] 区分 `qwen_asr` 与 `mlx_audio` 的实际调用适配；保留平台/架构/依赖验证。旧内置运行时 macOS 26 限制不能原样套在同事已有外部环境，也不能直接删掉兼容验证。
- [ ] 自动选用唯一可用配置；多个可用配置保留稳定选择。任务冻结环境身份；切换环境不能改变运行中任务。环境失效时有重新检测与重试路径。
- [ ] 用一个真实短音频和一个 MP4 在选定环境完成转写，关闭网络后再验证本地路径；不从开发仓库临时借用未登记依赖。检测成功须包含实际结果，而非只检查 import。
- [ ] 单独验证时间码与媒体解码：Qwen 文本、真实分段/词级时间码、MP4 解码是不同能力。已有环境能提供什么就标什么；缺少对齐依赖时提示具体补齐项，不能捏造时间码或宣布完整视频拆解可用。
