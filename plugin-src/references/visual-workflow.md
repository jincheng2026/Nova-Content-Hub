# 模板与封面视觉工作流

这是三个业务 Skills 共用的项目规则。先通过请求契约；当前预接入包不可执行，下列流程供真实适配器接通后使用。纯对话咨询可以返回建议，但不得写成工作台已生成、已验收或已登记。

## 拆解

把模板理解为可验证的视觉关系。对每张参考区分：观察到的事实、可迁移的规则、只属于这张图的内容，以及不确定项。可观察的标题大小关系、主次顺序和留白比“高级感”等词更有用。

按这些问题形成短说明：

- 内容第一眼被什么吸引，随后读到什么？标题、主体、辅助文字之间是什么关系？
- 主体和文字占据什么区域，边缘留白是否足够？使用估计时注明估计。
- 哪些颜色、字重或图形关系跨原图保持，哪些随内容变化？
- 哪些元素仅是来源身份，不能自动延续到用户封面？

规则 JSON 与说明分开。假设只有第 1 张原图的证据如下，可导入格式为：

```json
{
  "fixed": ["主标题分两行置于左上，主体位于右下；标题不压住主体"],
  "varies": ["替换标题文字和主体；保持主次关系"],
  "evidence": [{"sourceIndex": 0, "rule": "第1张图中标题和主体分处对角，边缘可见留白"}]
}
```

示例句不等于所有模板规则，必须根据实际看到的原图改写。`sourceIndex` 从 0 开始，必须落在本次原图列表中。当前模板导入还支持
audience/scenario/contentType/useCases/anatomy/generation；格式和资产身份见 [自媒体模板设计](media-template.md)
。这些是模板定义扩展，不直接增加 v1 请求字段。

## 还原

先说明参考用途：版式、色彩、主体复用或编辑目标。文字描述的风格参考与工具实际加载的图片分别记录。只有用户明确允许复用的人物和素材才作为主体输入。

每次调用前，在真实适配器返回的任务目录记录以下说明；路径未解析时不自行建库或猜测目录：

```text
请求与模板版本：来自当前快照
本次目标：还原，或指定标题的泛化测试
准确标题：用户原文，换行意图单独说明
画布：目标比例与像素，不假设工具必然原生支持
固定规则：逐条列出
变化范围：本次允许改变什么
参考：资产ID → 用途 → 实际提供给工具的输入
保留项与排除项：源于用户和模板；不注入来源人的隐私信息
实际工具与完整提示：调用前记录
```

生成后查看实际图片。结构、颜色和文字分别比较，记录可见偏差，不编造相似度百分数。换短标题、长标题和不同主题能验证泛化能力，但只能执行已授权的测试。工具不支持所需参考、尺寸或编辑能力时，报告能力缺口与可行选项。

## 封面

生成说明使用主题表达、色彩、表现形式、文字层级、视觉强度五个观察维度；值来自当前模板和用户内容，维度不是必须反复询问的五道题。已选模板优先保持其具体规则，不套统一配色、字体或留白百分比。

图像工具按当前请求和宿主能力使用。Codex 中已有原生 imagegen
时遵循它的可用指令；其他宿主遵循自己的真实接口。工具返回的文件先保留，再由适配器导入任务暂存区，不能假设工具支持任意保存路径或参数。缺少工具不自动使用
API Key、安装脚本或其他账户。

验收记录区分两层：

| 检查 | 证据与结论                                                                       |
|------|----------------------------------------------------------------------------------|
| 文件 | 真实可解码、实际像素、比例、数量、hash；由适配器校验，未校验记未知               |
| 视觉 | 标题逐字准确，主体符合要求，文字可读且不越边，固定规则满足；实际查看并交用户验收 |

纠错时描述一个主要偏差，保存新提示与新候选。错误文字通过图像工具重做；不能用覆盖旧文字制造已修复的结论。裁切或缩放后重新检查尺寸与构图，并保留原件。失败候选不自动覆盖选定图，完成生成不自动发布。

这份文档只规定业务工作方式，不新增 CLI 命令、请求字段、授权或文件写入权限。来源选择和差异见 [借鉴说明](upstream-notices.md)。
