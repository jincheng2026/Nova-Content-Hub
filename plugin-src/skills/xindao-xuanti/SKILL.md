# xindao-xuanti：从资料推荐选题

## 进入本任务

先判断进入方式，再执行。

**工作台任务模式**（由工作台派发的任务进入）：

1. 读 [共同任务契约](../../plugin-src/resources/production-contract.md)，执行 doctor、context 和当前 attempt 的 claim。任务 kind 为 research，产物为选题候选；本 Skill 不采集、不采评论、不产生采集费用。
2. 从冻结请求与 context 取用户资料：一句话灵感、素材笔记、已验收的调研结果、雷达收录候选或已有内容，可以混合。先读当前内容与已采纳知识，同一批资料不重复索取。
3. 产物结构与提交按 [产物结构](../../plugin-src/resources/production-artifacts.md)；候选卡属于研究类产物，选定与建内容由工作台在验收后处理。

**直接对话模式**（用户在聊天里直接要选题）：跳过任务契约，直接按本方法执行；候选菜单发在对话里，用户在对话里选定即视为确认。

## 核心规则

1. 没有具体资料不开题。资料完全不足以形成选题时，只追问一项最关键的材料；不从热门话题里凭空猜题。
2. 选题名是内部工作名称，不是最终发布标题。标题示例只作参考，最终标题由后续包装任务决定，两者互不阻塞。
3. 推荐是给选择，不是替决定。每份菜单给一句推荐和理由；选不选、改不改由用户定，未选中的候选保留可回看。
4. 不编造。用户的经历、数字、身份、结果没有依据时用占位写法（如「〔一年更新 N 条〕」），并在追问里向用户要，不替用户发明。
5. 「看的人多」只说明覆盖面可能大，不是流量预测。不用爆款、必火、流量密码一类承诺性说法，也不预测互动、收藏、转化、评论区热度或涨粉效果，不承诺任何播放结果。
6. 给用户的所有文字用大白话，每行只说一件事；方法内部术语只在本 Skill 文件内使用，不进菜单、理由和提问。
7. 分析过程留在内部。用户问「为什么」「展开」时再给比较和理由；默认交付控制在一屏内。

## 按阶段读取方法

| 阶段 | 执行前必读 | 产出 |
| --- | --- | --- |
| 接收资料、判断能不能开题 | [资料接收](references/material-intake.md) | 内部素材清单；缺口说明或一项追问 |
| 从资料扩出候选方向 | [选题扩层](references/topic-expansion.md) | 3～4 个受众递进的候选与内部校验记录 |
| 出菜单、追问、定题交接 | [候选菜单与定题](references/candidate-menu.md) | 选题卡菜单、推荐理由、选定后的交接字段 |

## 停等与追问

- 默认一次交菜单，不停等：底气类追问（最多 2 个）附在菜单末尾，用户采纳时可顺带回答。
- 只有资料完全开不了题时才停等索取材料；停等时说清缺的是什么、有了它能落到哪。
- 用户提出新想法或要合并几个候选时，先一句复述理解，再按选题卡字段补全，确认后交出。

## 交付与停止

菜单按 [候选菜单与定题](references/candidate-menu.md) 的固定格式交付。用户选定后：

- 工作台任务模式：把选定卡片按交接字段随产物提交，由工作台建内容；工作名称用选题名，标题示例标记为待正文定稿后复核。
- 直接对话模式：输出交接字段后停，等用户确认再继续。

选题确定即停止。写正文、起最终标题、封面文字与图片、开头逐字稿、正文结构和发布节奏都不属于本 Skill；用户问下一步时，用一句话说明那属于内容创作任务，不展开执行，也不提前交付其中任何一项。

## 边界

- 不采集平台数据、不采评论、不调用外部付费服务；选题只依据用户给的资料与工作台已有材料。
- 不改写用户已有正文；资料里含在写稿子时，只出候选不动稿子。
- 资料真实但方向受限时，如实说明受限原因并给能做的层，不为凑数放宽或编造。
