## 构建与查看

在仓库根目录运行 `npm run build:both`，分别打开：

- `dist-prototype/auth-required/index.html`。
- `dist-prototype/auth-disabled/index.html`。

修改根 `release.config.json` 的 `AUTH_MODE` 后运行 `npm run build`，生成该模式工作台与配套契约包。两模式共享产品 scope，但
pairId 不同；不能混配。构建产物不带临时截图页和自检页。

## 一次模板到封面的手动验收

1. 鉴权预览先选择“鉴权演示 → 已开通”；免鉴权预览直接操作。
2. 选一套有原图的模板，或新建模板并导入小图。现有示例不自动宣称已完成还原测试。
3. 在模板详情“导入规则 JSON”中使用真实拆解结果。测试数据结构如下，内容应替换成图中可见事实：

```json
{
  "fixed": [
    "标题保持左上留白"
  ],
  "varies": [
    "随内容换标题"
  ],
  "evidence": [
    {
      "sourceIndex": 0,
      "rule": "第1张原图左上有标题留白"
    }
  ]
}
```

4. 创建还原请求、查看快照；原型不发送、不生成。拿到实际测试图后“导入还原图”，对照原图人工验收。仅创建请求不会变成通过。
5. 从模板明确选择目标内容，或在内容“出封面”中选择已验收模板。检查本次规则、证据、参考、标题、比例和目标像素。
6. 查看/下载请求 JSON；手动记录宿主已接单后导入实际候选。图不符目标尺寸时验收应失败，并保留已导入结果。
7. 验收候选、选定并下载。以后更换选定图，已记发布的历史封面不跟随变化。
8. 导出工作区备份；重开核对内容，再用备份恢复并核对。恢复前先下载当前备份，损坏或非法备份不能覆盖当前数据。

请求可用实际打包后的 CLI 做预检：`node dist/content.mjs check-request --file REQUEST.json`。鉴权包缺真实授权时拒绝；免鉴权包也只校验，
`executable:false`。未绑定时路径槽位不可用。

## 限制与交付用语

- 浏览器单文件上限 1 MiB，工作区上限 4 MiB，适合小样本原型体验。大图与大量素材使用后续桌面存储；重要结果主动下载并保留原件。
- 数据存在当前浏览器，清理站点数据会影响它。示例中的静态图片依赖随包图库；用户导入图随浏览器备份保存。部分浏览器对 file
  预览中内置图的读取/剪贴板有限制，实际失败应提示，不能报下载完成。
- “已在宿主手动接单”是用户登记；原型不具备自动检测或取消宿主任务能力。状态、模板验收不构成服务端授权。
- 本地只读恢复、浏览与导出不等于允许继续使用付费 AI；真实应用到期/退出的策略见蓝图。
- 当前不含任何生产凭据或权益签名私钥，不自动安装插件、不修改信任或账户配置、不操作旅游工作台的库。

### 蓝墨编辑室视觉规范（2026-10-17）

界面使用浅灰纸面、深蓝文字与克制蓝操作。主操作为蓝色实底，次操作白底描边，重复的逐行处理使用浅蓝次按钮；待补和待确认用琥珀，错误用红，成功用绿，运行用紫。普通说明文字与主按钮对比至少
4.5:1，焦点统一蓝色描边；卡片 12px、控件 8px、弹窗 16px 圆角，不使用彩色扩散阴影。

参考 [Semi 语义变量](https://semi.design/zh-CN/basic/tokens)、[按钮层级](https://semi.design/zh-CN/basic/button)
与[卡片结构](https://semi.design/en-US/show/card)，沿用本项目的离线原生组件，无新增组件库依赖。13 张示例 SVG
是本项目原创稿纸、取景、模块连线与台阶日历几何插画，均标注虚构演示素材；图库路径和用户自定义图片保持原有存储契约。

自动检查：`node --test test/visual-system.test.cjs` 验证语义色对比与示例 SVG 的数量、元素白名单和安全性。页面与交互仍需浏览器实测，原型边界提示保留。

## 2026-10-17 模板组语义

一个模板是一组同风格、不同构图的真实样张。15 套 v4 每套 2 张 PNG；SVG
独立列为结构示意，不计样张。列表显示缩略带和真实组数量，详情有缩略选择及上一张/下一张。翻阅只影响当前查看位置，不写封面或模板。

生成默认带整组真实样张与本次本人照片，切模板保留本人照和当前内容的候选；“更多参考”可明确取消，页面分别显示本组使用数、整组数和每版生成数。总参考最多
32 张，超过预算拒绝提交且不截断；每版生成数量仍为 1–20。规则要求从整组提炼共同配色、字体、信息层级，并学习组内构图差异形成候选。

点击“导出本次全部参考图”，将整组风格图与本人照一起附给助手。导出文件以请求参考 ID 命名；旧请求按 templateVersion
解析可信旧定义或归档索引，保持请求快照不变。自建原图替换与删除均进入回收区，归档只存指纹索引，不重复图片字节；清理或丢失原图后会明确报错。

v3 完整目录保存在 `builtin-templates/legacy-v3.json`，仅未修改且可用的出厂定义在启动时安全升 v4，归档旧定义；失败与修改后的定义不自动覆盖。

预算拒绝。真实浏览器 ZIP 下载、宿主附图与本人替换生图仍需单独验收。

### 整组 ZIP 下载修正

真实 Chrome 检查发现连续两次图片下载会触发浏览器限制，造成只保存第一张。现在整组样张和“本次全部参考图”均只下载一个
ZIP，无需用户调整多文件下载设置；包名含模板 ID 或请求 ID，包内以稳定参考 ID 命名。单张本人照片仍直接下载图片，多张照片打包。所有图片先逐一完成读取和
MIME 校验，再产包；任一文件失败均不提交半包。

ZIP 使用无依赖 STORE 格式，包含 UTF8 文件名标记、CRC32、中央目录与 EOCD。测试以系统 `unzip -t` 独立检查真实包，以 Python
标准库读取验证文件名及逐字节一致，破坏图片字节后的 CRC 检查必须失败。仅支持经典 ZIP 的 4 GiB 范围，超限明确拒绝；当前模板与浏览器容量远小于此限。

## 任务与助手入口收敛

项目右侧按真实任务状态展示一个入口：待交接继续、执行中查看进度、待验收查看结果、失败或中断查看处理、已完成查看既有结果。没有真实请求时才交接项目摘要。多个任务先在仅属于该项目的列表中单选，排序不会默认选择任务。旧演示、旧模板任务、完成记录与移交源任务保留在历史中；项目封面旧版本请求仍可合法推进。侧栏和总览共用同一当前待办集合，避免把历史演示计作待办。全局打开当前助手、整理资料和排发布等不同业务动作保留。

同次创建多个尺寸时，展示本次完整任务列表，不再默认交接最后一个尺寸。任务查看先显示状态、尺寸数量和属于本任务的真实候选图；请求与返回
JSON、原会话记录及复制下载收在详情中。验收需要先呈现对应批次，其他批次不能借作证据；结束任务不提供默认继续。

模板页只显示当前步骤的主动作，其余导入、重新拆解与历史在“其他操作”。可用模板维持可用状态，再次还原必须从次级操作明确发起。拆解和还原导入在打开时绑定所选任务
ID 与模板版本，落库时复核任务存在、执行中且版本一致；同版本多条执行任务需先明确选择。图片读取期间状态或版本变化会拒绝导入，不改记到其他任务。

交接弹窗底部保留一个主按钮与关闭；参考图 ZIP 放在准备区，超长内容必须下载 HANDOFF.json
的说明与按钮直接可见。首页、备用复制、单独照片导出与技术详情收进“其他交接方式”。请求、桥接、鉴权协议与持久化业务模型未修改；浏览器状态仍为人工登记，不证明外部执行成功。
