## 飞书写入协议

用户完成唯一一次候选确认，或最初已明确要求加入计划 / 写入飞书时执行。写入前必须完成全部技术步骤，但不得再请求第二次人工确认。

### Step 1：确认目标 Base

必须拿到或发现这些信息：

- Base URL 或 app_token
- table_id 或表名
- view_id 可选
- 目标表用途是否是计划任务池

如果用户只给了飞书链接，先解析链接；解析不了就让用户补链接或 app_token/table_id。

### Step 2：读取真实 schema

先读取目标表字段结构，至少确认：

- 字段名
- 字段类型
- 是否必填
- 单选/多选选项
- 日期字段格式
- 关联字段是否需要 record_id

STOP：没有读到真实 schema，禁止写入。

### Step 3：字段映射

把 skill 字段映射到真实 Base 字段。

规则：

- 优先写入现有字段，不擅自新建字段。
- 找不到同名字段时，先给映射建议，不写入。
- 类型不匹配时，先报告；不要把日期写进文本字段、把文本写进单选字段。
- 只有用户明确同意，才允许创建新字段或改字段类型。

字段映射输出：

```text
字段映射 dry-run：

| Skill 字段 | 飞书字段 | 类型 | 处理 |
| --- | --- | --- | --- |
| 事项 | 事项 | 文本 | 可写 |
| 计划日期 | 计划日期 | 日期 | 可写 |
| AI 推断 / 待确认 | 未找到 | - | 暂不写，建议新建或映射到 AI处理备注 |
```

### Step 4：去重检查

写入前按这些信号查重：

- `事项 + 主题 + 计划日期`
- `原文证据`
- `来源摘要 + 下一步动作`
- 已有 `飞书记录 ID`

发现完全重复时，跳过新增并返回已有记录 ID。发现无法安全判断的近似重复时，不写该条并报告冲突；不要把去重变成例行二次确认，也不要擅自覆盖已有记录。

### Step 5：dry-run

生成即将写入的记录数、字段、风险和跳过项。可在最终结果中回报，不以此暂停流程或再次询问用户。

```text
写入 dry-run：
- 目标表：____
- 将新增：N 条
- 将跳过：N 条
- 疑似重复：N 条
- 不会改动已有记录
- 不会创建新字段
```

STOP：schema、字段映射、去重或 dry-run 未完成时禁止写入；技术检查通过后直接进入 Step 6。

### Step 6：写入与验证

技术检查通过后立即写入，不再请求人工确认。

写入后必须：

- 返回新增记录 ID
- 读取刚写入的记录做验证
- 报告成功、失败、跳过、疑似重复
- 如果部分失败，不自动重试大批量写入；先报告失败原因

不要自动删除已写入记录来「回滚」。删除飞书记录是破坏性操作，必须另行确认。

### Step 7：按用户授权同步 Apple 日历

这是可选能力，不得默认用户已授权。只有用户明确要求同步 Apple 日历，且 Step 6 的飞书写入和回读验证成功后，才执行本步骤。

同步条件：

- 用户给出了明确的执行日期和开始时间；只有「今天 / 明天 / 本周」而没有具体时间时，不自动创建日历事项。
- 目标日历默认用「工作」。
- 默认时长 30 分钟；原文给出时长或结束时间时，以原文为准。
- 默认添加提前 30 分钟和提前 5 分钟两次显示提醒。
- 日历标题只写 `事项`；备注可写 `下一步动作` 和飞书记录 ID，不复制原文证据或敏感信息。

执行方式：

```bash
osascript <jc-feishuplan 安装目录>/scripts/apple-calendar-event.applescript \
  "工作" "事项标题" 2026 7 27 9 30 30 "30,5" \
  "下一步动作：……；飞书记录 ID：……"
```

脚本按「目标日历 + 标题 + 开始时间」查重。返回：

- `created|<uid>|<title>`：创建并回读验证成功。
- `duplicate|<uid>|<title>`：已有同名同时间事项，不重复创建。

Apple 日历同步失败时：

- 不删除或回滚已经写入成功的飞书记录。
- 报告原始错误、飞书记录 ID 和未同步条目。
- 不静默改用其他日历，也不批量重试。

如果用户明确说「只写飞书」或「不要同步 Apple 日历」，本次跳过 Step 7。
