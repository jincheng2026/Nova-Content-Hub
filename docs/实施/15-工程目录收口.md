## 目标结构

```text
Nova-Content-Hub/
├── docs/                   设计、实施与原始验收证据
├── plugin-src/             唯一插件源码与业务文件核心
│   ├── src/bridge/         助手交接
│   ├── src/commands/       有限 CLI
│   ├── src/lib/            文件库、解码、导入、维护与种子
│   ├── resources/          模板、提示词、固定样张与来源
│   ├── schemas/            协议结构
│   ├── skills/             Skills 唯一原文
│   ├── scripts/            构建和同步
│   └── tests/              插件与跨入口验证
├── workbench/              TypeScript + React + Semi UI 桌面端
│   ├── src/main/           Electron 有限系统能力
│   ├── src/preload/        隔离桥
│   ├── src/renderer/       产品界面
│   ├── resources/brand/    用户指定图标
│   ├── prototype/          保留的历史浏览器原型
│   ├── scripts/           桌面/原型/图标构建验证
│   └── test/              原生验证
├── plugin/                 构建生成的执行包/契约包，不作源码
├── package.json            共用开发/检查命令
└── release.config.json     构建配对配置
```

根锁文件、README 与 IDE/Git 配置保留。node_modules、缓存与构建目录不成为业务源码。旧 dist 由构建重新生成，原始证据搬迁保留字节，不重写其历史命令和绝对路径。

## 迁移约束

- 五个共享模块保持兄弟目录，插件与桌面消费同一份；业务模块不迁入 renderer，不复制第二套 CRUD。
- 旧备份模型的纯代码收在 browser-import/legacy；原型接收同步副本，插件不反向依赖 workbench/prototype。原 CommonJS/UMD 语义保持，工作台 package 的 ESM 配置不得改变历史模块加载方式。
- 固定图库、模板/提示词目录及来源清单归插件 resources。catalog 中的图库及来源逻辑路径保持；种子、迁移和发行包采用同一实际资源布局。
- 两类插件、两种授权构建、原生 utility worker、源码测试和仓库外产物都更新路径。旧 cover-runtime 入口继续由发行构建生成兼容转发。
- 旧检查若依赖源码空格或 cwd，改为定位实际模块及验证其业务边界；不得删除真实断言来让格式化或搬迁通过。
- 完成依据为固定资源 hash、严格类型、完整 verify、仓库外 CLI/解码/原生探针；Windows、真实宿主和安装包仍按14逐组合验收。

根 README、npm 清单/锁、release.config.json、IDE/Git 配置与隐藏本地备份保留；没有 workspace、新依赖、框架替换或业务 JavaScript 迁移。node_modules 是安装目录，不是业务源码；用户实际内容库及旅游项目资料未动。`docs/reviews/prototype-model-check.mjs` 明确为2026-10-16修复前缺陷断言附件，保留其历史源码字节，不作为当前可执行验收。

`sync-bridge` 检查三条生成链：唯一 bridge → 原型及 legacy 的 handoff，唯一 legacy core → 原型 core。模板生成器从唯一 catalog 同时生成原型和 legacy 的 builtin-templates.js，生成文本保留原字节和原头部标识。两份 CommonJS package 边界保持历史 UMD 语义。插件源码和发行包采用同一个 `plugin-src/src/lib` / `plugin-src/resources` 相对布局，无导入 workbench 的反向依赖。

catalog 内的 `图库/...`、`assets/ai-reference-prompts/...` 继续为业务逻辑路径。种子/导入按 resources 实际来源解析，原型在展示和下载时解析资源 URL，产物复制固定资源并恢复包内 URL。HTML 验证图库只改资源 URL；历史 raw 日志、JSON、PNG/JPG 的内容和历史绝对路径不重写。

`.gitattributes` 固定源码 LF，固定图库、来源资产、品牌与 raw 证据使用 -text。临时 index 的 `core.autocrlf=true checkout-index` 在 macOS 实测 217 个固定/原始文件字节相同，72 项 catalog 资源匹配原长度及 SHA-256，源码保持 LF。这是换行保护测试，不是 Windows 真机测试，见 [autocrlf 记录](../verification/production/2026-10-18-directory-autocrlf.log)。
