# 写前核查

按锦成原则，说法只要那条视频数据好就能借，不追来源，可以为通俗牺牲一点准确。但两类东西写稿时单独处理。

## 时效类：写前必核，过期就换

- 价格和额度：某个 Agent 云端版多少钱、谁送积分、免费额度多少。
- 产品动态：谁合并了谁、谁刚发了什么、某功能还是不是实验功能。
- 版本号和参数：GPT 几、上下文多少 K、一次处理多少 Token。
- 工具名单：现在「主流的三家」是哪三家。

核法：写稿当天查官方页面或产品内实际界面；查不到的在稿里标「⚠️ 待确认」，不带进最终稿；查到的在改稿日志里记来源和日期。

## 简化类：可以用，后台留一句准确说法

- 「大模型是脑子，Agent 是手脚，工具是 MCP 和 CLI」（把协议和命令行并列）。
- 「Harness 等于 Agent 减大模型」。
- 「MCP 是手脚」和「Agent 是手脚」两种说法都有人用且数据都好，一条稿只用一种。
- 「算力就是 token」（混用）。
- 「智能体不需要提示词」。
- 「API 就是钥匙」（把接口和密钥混在一起）。
- 「深度学习是专业深度」。

用法：口播照通俗版说；在 `定稿.md` 末尾加一节「后台准确说法」，一条一句，评论区有人较真时用。

## 选题层面

追新模型、新功能、新论文的题在三个账号上都在 2 倍以下，不进合集。新东西出来时做「它落在哪一格」，不做新闻。
