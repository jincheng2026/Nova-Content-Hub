## 统一验证顺序

功能源码收口后再按此顺序执行，不在开发中零散宣称通过：

1. 当前提交完整 `npm run verify`，记录 Node/npm、提交、完整日志、失败和实际覆盖。它包括原型、共享文件核心、插件、资源与桌面；不能只挑新用例。
2. 修复整批失败，并针对失败机制核对调用端、夹具与文档；不删校验或降低断言让结果变绿。完整通过后进入真实桌面验收。
3. Mac 当前源码构建/安装/启动，实际五页、窗口交互、常驻、文件系统、照片、模板组与发布全流程；使用独立合成验收库，不改参考应用业务库。
4. 两助手插件安装、Skill 预填、真实输入读取、生成、完整解码入库、人工选用和导出；保留失败、取消、重试、换助手与重启证据。宿主会话结束不是成功。
5. Windows、Intel Mac/Apple Mac 安装、升级/回滚、卸载保库；容量与流畅性、普通用户操作；补签名/公证及正式发行证据。前面通过不能代替这些条件。

## 判定边界

功能队列的源码收口只代表可以开始集中验证。测试未跑、包未打、应用未装或真机矩阵缺失时均保持未验收。外部签名、另一系统设备或宿主能力不能用模拟数据伪装完成；如受阻，应记录具体资源与已完成证据，并继续其他可独立验证工作。
