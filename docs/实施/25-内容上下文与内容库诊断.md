## 内容相关的使用路径

- 内容详情增加“用提示词继续创作”，沿用保存/放弃草稿保护；读取已保存内容后进入提示词页。
- 提示词页可选择活动内容。弹窗保留打开时的标题/正文快照，默认不含正文；用户明确勾选后，左侧预览才追加本次内容，复制与预览一致。个人资料、图片、附件和渠道文案不自动加入，也不修改原提示词或内容。
- 变量填写不会因是否带正文的勾选被重置。关闭或 Escape 丢弃填写前确认；本次输入进入现有未保存编辑保护。
- 模板页新增本机照片上传、本人声明和“管理我的照片”入口。声明默认关闭；照片导入不自动选入生成，保留“这次不放人物”。管理复用原照片管理页面，不增加第二套照片事实或全局助手选择器。

## 内容库检查

新增有限 `inspectLibraryHealth()`。renderer 不提交路径；main 仅将当前保存的库 ID、根目录身份和路径交给固定 utility worker，后者调用共享文件核心的新诊断导出。该入口不依赖业务列表/当前库正常打开，也不清除 pending。

核心不调用会自动恢复事务的 openLibrary/locked/recover，不修复、改写或删除业务对象。使用原协调锁，检查前后核对根目录 dev/ino 和库 ID，以及已读取文件的稳定指纹。锁的创建、释放和原有安全回收属于协调写入，不宣称磁盘零写入。

检查范围：六类对象与必要结构、模板不可变版本、引用资产摘要、请求/结果证据、发布快照及保存日志。待恢复日志先检查，相关对象标为未核实，不把事务中间态定为损坏。未登记/暂存文件保持原样。原严格打开、业务读写和备份恢复语义不变。

结果区分目录不存在、无法读取、身份替换、不安全路径、格式不支持和具体对象问题。不含正文、图片、完整路径或原始异常。界面提供逐项原因和已有备份/恢复路径；脱敏导出仅增加白名单状态、数量及错误码，不输出对象 ID 和业务文字。普通读取失败时展开维护入口，保留上次显示数据与草稿，并明确显示尚未完整读取。

## 有界检查与源码审查

- 最多 2,000 个对象、4,000 个不同资产摘要、2,000 个事务、2,000 个请求。
- 总工作预算 20,000（包含 JSON 节点、目录项、读取及循环），JSON 深度64；普通文件8 MiB、图片或资产64 MiB、累计读取512 MiB；协作式时间预算10秒。系统单次阻塞调用不构成严格实时期限。
- 问题列表最多200项，保留预算耗尽标志；超过任一预算或扫描期间发生变化，返回 incomplete，不能显示健康。重复验证也消耗预算，较大的正常库可能需要后续分段诊断；本版不假装完成全量。
- Astra high 只读复核了新扫描器与原 helper 默认语义，未发现新的 P0/P1。两项 P2 已按源码建议修补：事务父目录未知项不能漏报；无法枚举待恢复日志时，受影响对象和缺失 workspace/default 均保守标为未核实。
- Node 不提供 openat 全程路径固定，现有库规则仍面向单人可信本机磁盘，不宣称支持不可信共享目录或网络盘协作。
