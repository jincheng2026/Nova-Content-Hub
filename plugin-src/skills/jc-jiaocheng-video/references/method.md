# 教程与口播共创

根据冻结请求、已有内容和用户材料区分教程或观点口播，只有真正不明且影响结果才询问。先读取适用定位、最新确认稿、参考拆解和相关已采纳判断；只按阶段追溯，不整库加载私人判断或口气样本。

- 第一目标是让具体读者获得一个可感知结果，并有真实理由相信。不是默认写长篇完整手册。先核对核心事实、必要前提与边界、可展示的结果/过程/对比；不成立就回到本轮叙事决策。
- 从参考提炼给谁、得到什么、如何证明和主动不讲什么，再结合作者真实材料提出叙事建议。关键取舍依共同契约澄清；已确认方向或用户明确要求直接给稿直接沿用，不重复确认。
- 完整稿承接已定叙事，保留来源类型：视频口播(真实时间)、画面、标题/发布文字、会议、本人的事实、已确认判断、AI判断；引号逐字核对，发布文字不冒充视频口播。
- 观点口播依赖作者独有判断或一手证据；教程另将口播、实际画面、录屏、证明结果和制作成本配对。零基础操作说明复制什么、粘贴到哪、发给谁、执行什么、看到什么算成功；未实测的过程不能说已验证。
- 交付当前完整稿和准确逐句建议，读回用户手改/批注，变更保留原因。教程另交镜头/录屏/素材清单，口播不强加演示步骤。不承担剪辑、渲染或自动B-roll。
- 标题、封面、简介独立确认并忠于已定稿，平台承接与规则须核对当前事实，不套上游旧平台禁令作为永久政策。不因包装需要虚构结果。
- 发布前轻量自检理解、真实性、实际交付、承诺与公开边界；不打分、不增加流程状态。问题定位到具体句子/画面与依据，阻塞核心真实性就暂停对应部分。
- 反馈分原话、改动、AI归纳与实际结果。重复证据才能提规律，单条只留案例或补证据；长期知识和Skill修改分别经用户明确采用，不自动升级。

完成：一个明确收获、可信证明、当前完整稿、教程制作配合(如适用)、独立包装状态、来源与真实缺口可检查；不把一条内容成功宣称流程成熟。
