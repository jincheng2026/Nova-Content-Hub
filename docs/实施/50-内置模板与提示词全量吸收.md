## 可生成状态与证据边界

沿用既有稳定 builtin 模板安装与生成请求契约。127 张原图全部安装为 `style`，完整拆解与风格 JSON 作为 `structure` 附件，并将完整拆解原文绑定到模板 `designNotes`/`rules`。界面已有读取完整 style 资源和 rules 的路径，实际生成请求也固定完整 definition 与所选样张。

新增模板的 `validation.kind` 为 `source-verified-design`，规则来源 hash 可回查，且 `accepted:false`、`aiTested:false`。可以通过已有 builtin 模板路径准备生成，但没有创建学习任务、还原产物、AI 验收或人工验收记录。来源报告中的观察和复用建议是已有资料，不冒充本次逐图审美审查。来源报告提及的秋芝 90 张、鹿一家 32 张及旧本机页面不在本次交付范围；实际只宣称收到 30/30 张，报告原文保留并明确这一限制。

本次生成边界写入 `fixed`/`generation`：只借鉴风格与构图，不继承旧文字、作者脸部、发型衣服、账号字标和事实；本人照是本次身份依据；未选择本人照时按无人版执行。每张候选选择一个主要参考构图，不把不同分支的最大头、最大字和所有道具混成一张。人物、文字与画面质量仍需实际生图后人工检查。

## 已安装库的补装与保护

`library-seed.installBuiltins` 增加同事目录预检，全部来源文件 hash、完整规则与提示词原文对应关系通过后才开始写对象。新建、显式打开库、迁移完成及维护完成有既有 seed 调用，但 `controller.initialize()` 仅执行绑定加载，不会在重启时自动补装已绑定旧库。种子安装测试验证的是入口被调用后的幂等与数据保护，不能证明旧库重启会触发它。

旧库无需手工重新选择同一个库：设置页的“更新内置模板与提示词”入口应复用既有 `retryBuiltins` IPC。该 main 接口会检查当前库、鉴权、其他待处理写入及未完成导入，再调用 seed；允许自己的 `seedPending` 恢复。界面不能因笼统 `blocked` 包含 `seedPending` 而禁用这一重试，也不能绕过其他待处理状态。本轮采用显式更新，不在 `initialize()` 的安全读取路径增加静默写入。调用后沿用 `nativeAction` 的状态及工作空间刷新，使新增资源在当前库可见。

模板采用新的 `builtin-colleague-*` ID 和 v1，不占用原有模板 ID/版本。文件核心继续按 ID、版本、包 hash 幂等：同版本改内容冲突，不能覆盖旧包；现有原模板 hash 和已固定内容/生成请求不变。回收站模板不会复活。

提示词先检查当前及回收站 builtinKey，再比较真实正文。已有同正文自建或备份导入条目时跳过，不接管其所有权；已有修改、停用和删除均优先，不静默覆盖或复活。来源正文变化不允许在原 key 下覆盖用户编辑；未来来源版本升级须另行设计用户可更新、已修改、已删除的处理，不在本次加入自动覆盖。

各项逐笔安装，中断可重试；不宣称全库原子事务。构建脚本已有递归复制 resources 和 library-seed 的路径，静态检查不需改 build/marketplace-builder；本次未执行打包和安装。

已存在资产按预检 hash 经 `readAsset` 核对后复用，缺少时才走原 `importAsset`；重装不会反复暂存和同步写入整批原图。已有同 hash 坏文件仍拒绝，预检与导入之间来源发生变化也拒绝。
