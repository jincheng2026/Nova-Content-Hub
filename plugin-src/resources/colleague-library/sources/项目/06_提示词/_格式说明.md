# 常用提示词目录怎么写

这个目录是工作台「提示词」页的唯一数据来源。工作台只读这里，页面上不能新增或修改正文；要加一条，就在这里新建一个 md 文件。

- 一条提示词一个 `.md` 文件，放在哪个子目录，页面上就属于哪个分类；直接放在本目录下的算「未分类」。
- `when` 是卡片的第一行，也是搜索时最先匹配的字段；找提示词时记得的是处境，不是名字，所以这行最重要。
- 卡片位置以页面上拖动为准，顺序存在 `_排序.md`，没列进去的条目按 `_分类顺序.md` 的流程排在后面。
- 文件名以 `_` 或 `.` 开头的不会被读取，本说明就是这样被跳过的。分类在页面上的左右顺序由 `_分类顺序.md` 决定，新建分类记得加进去。
- 文件开头是三横线包起来的字段区，正文就是要复制的提示词本身，不要再写「用途」「使用场景」这类章节，说明写进 `summary`。

```
---
title: 页面上显示的名字
when: 什么时候会想起它，用自己当时会说的话写，比如「两个选项都有道理，纠结选哪个」
summary: 一句话说清它会做什么、给出什么
tags: 可选，多个用顿号分开
source: 可选，来自哪里
---
提示词正文，从这里开始整段被复制。
```

- `tags` 是页面上的筛选标签，用来按来源或用途批量看，比如「卡兹克」「旧提示词库」；`source` 写完整出处，只在弹窗里显示。
- 页面右键卡片可以选中和删除；删除是把文件移到总库 `.trash/日期_提示词-分类-文件名.md` 并登记，不会永久删除。
- 正文里要每次填写的地方写成 `{{名称}}`，页面会先让你填再复制；`{{时长|30秒 / 60秒}}` 竖线后面是给自己看的提示，不会进入复制结果。
- 方括号 `[...]` 不会被当成变量，留给要求 AI 按格式输出的占位。
- 用过几次、最近什么时候用，记在旁边的 `常用使用记录.jsonl`，每复制一次追加一行；不改动 md 文件。
