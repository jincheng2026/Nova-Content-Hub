从零开始学 AI，到底应该怎么走？我最近在研究一份 GitHub 上的开源学习地图，叫做【疑似：Awesome AI Agents】，专门为想学 AI Agent 的中文用户整理了结构化路径。一共有七个阶段，每个阶段都有必做的练习和必修的内容。所以今天这期视频，我就按照这份地图的逻辑来给你讲清楚。

先说一个很重要的前提：你到底是想用 Agent，还是想造 Agent？这份地图一开始就做了一件很聪明的事情，它把学习路径分成两条。

一条叫做 Track A，CLI Power User，适合你想用 Claude Code、Codex 这些现成的 CLI Agent 工具，把自己的工作效率拉上去，但不打算从零写 Agent。

另外还有一个叫 Track B，Agent Builder，适合你想从零打造自己的 Agent，学框架、写 ReAct、设计多 Agent 系统。

而且这两条路径并不是互斥的。很多人是先把 A 走通了，把现在的工具用顺了，然后再回来走 B，了解底层原理。但不管你走哪条，前面三个阶段，也就是从 Stage 0 到 Stage 2，必须一起走，是共同的基建。

OK，前面的 0 到 2 这三步就是基础准备，大概一到两周。这个阶段的目标，就是确认你有没有出发、到达 Track A 或者 Track B 的资格。

需要什么呢？第一个，基础的 Python，能够写函数、会用 API、看懂 JSON。还要会 Git 操作，比如 `git clone`、`git commit`、`git push`，以及养成使用命令行的习惯。我之前的「深入浅出学习 AI」这一系列视频都有讲过，你可以回头看一看。

OK，如果这些你都学会了，可以直接跳到下一步；如果有缺，那就从这里开始补齐。

第 0 步学会了，接下来第一步是什么呢？LLM 入门，其实大概也只需要一周。很多人以为自己懂 AI，但其实只是用过 GPT，这两件事真的差得很远。

在这个阶段，你需要真正搞清楚的事情是：LLM 是什么，为什么上下文窗口有限制，各家大模型到底有什么区别，什么场景用哪个，还有本地 LLM 怎么跑。比如怎么用 Ollama 在自己的电脑上跑一个模型，这个跑起来是什么体验。当你知道这些以后，才能说：「我真正懂了 LLM。」

到 Stage 2，就是 Prompt 的设计，这里也花一到两周。这个阶段不是教你怎么和 AI 对话，而是教你怎么精准控制模型的输出。

里面有三个核心。比如 System Prompt 怎么写、角色怎么定义、行为边界怎么约束；包括 Few-shot 的示例，给几个例子往往比写一堆规则有效得多；还有 Chain of Thought，CoT，让模型先推理再给结论，这个在复杂任务里面效果最显著。

走完这三个步骤，我们才真正到了分岔路口。

如果你选 Track A，就是 CLI Power User 这条路径。这条路有三个子阶段，也需要大概三到五周。加上前面的基础，整体就是六到八周学完。

A1 阶段，你要了解市面上六款主流的 CLI Agent 工具，知道各自的特点，选一个安装起来，跑通第一个任务。

到 A2 阶段，变成工作流。在这里你需要知道怎么写 `CLAUDE.md`，让工具记住你的项目背景；怎么通过 Skills 提高效率；怎么把一个复杂任务拆成多步骤，交给 CLI Agent 处理。

A3 阶段做集成，CI 和 CD。怎么把 MCP Server 接到 CLI 工具里面，让它能够操作你的本地文件、数据库、外部服务；怎么接 CI 的流程，直接自动化；以及成本控制和可观测性。

好，这个就是 Track A 的 A1、A2、A3 过程。

如果你选 Track B，Agent Builder，这个就更加复杂了。这个主线路径真的是从零打造 Agent 的这条线。

Stage 3，就是工具调用和 Agent 入门，这块也是两到三周。这个是整条路线最核心的部分。这个阶段你要彻底搞清楚，比如 Function Calling，函数调用是怎么工作的。

你看，LLM 本身只能生成文字，但通过工具调用，它可以告诉你的代码：「我需要调用这个函数。」你的程序执行，把结果喂回来，LLM 继续推理。这个循环就是 Agent 的核心机制。

然后是 ReAct 模式，Reasoning 加 Action，让模型先思考再行动，每一步都能看到推理过程。这个是大多数 Agent 的决策骨架。这个阶段有五个必做的动手练习，地图上也特别强调了：光看不练，后面一定会卡住。

Stage 4，就是 Agent 框架，这块需要两到三周。学完底层原理以后，这个时候才是学框架的时候。里面会覆盖四个主流框架，包括 LangGraph，适合需要精准控制流程的复杂任务；包括微软出品的 AutoGen，多 Agent 的对话式协作；包括 CrewAI，角色扮演式的团队协作；包括 Smolagents，轻量简洁，适合快速原型。

但我的建议还是先选一个深入搞懂，而不是四个都浅尝一遍。搞懂一个框架的设计逻辑以后，其他的真的是触类旁通。

Stage 5，Claude Code 的整个生态，计划三到四周。这个阶段有两条路径要走，也是整条路线的核心。

第一个，MCP，Model Context Protocol，一个能够连接外部工具和服务的协议。你自己写一个 MCP Server，就能够让 AI 直接操作你的本地文件、调用数据库、接入 Notion，甚至接入你公司内部的系统。

另外除了 MCP，还有 Skills 和 Plugins。这个是 Claude Code 生态的完整工具栈。走完这个阶段，你才算真正理解现代 Agent 怎么跟外部世界交互。

Stage 6，记忆系统和 RAG，计划两周。你看，Agent 本身是没有记忆的，就像金鱼，三秒以后都忘记了。这个阶段解决两个问题。

第一个，长效记忆，怎么用向量数据库存储跨会话的知识和偏好。第二个，RAG，检索增强生成，把你自己的文档知识库接进来，让 Agent 能够查资料。

另外还有一个重要细节，就是 RAG 的坑不在流程，而在细节。文档怎么切分，Embedding 模型怎么选，检索结果怎么排序，每个细节都影响最终效果。

Stage 7，就是多 Agent 协作。这块是最后一个阶段，就是从一个 Agent 干活到一群 Agent 协作的跨越。核心问题是怎么分工，谁负责规划、谁负责执行、谁负责审核；怎么通信，用共享内存还是消息传递；怎么评估整个系统的效果；怎么加日志、加追踪，让你能看懂 Agent 在干什么。

所以你看，Track B 其实涉及很多过程。走完 Track B 的主干，时间大概得五到六个月，每周得投入五到八个小时的学习量。

另外走完主干以后，这份地图还提供了五条延伸路线，按你的身份去选。如果你是研究人员，重点是文献整理、配合写作、多 Agent 写作 Review 的流程。如果你是软件工程师，重点是 Cursor 等 AI 编程工具，以及 Code Review 的自动化。如果你是知识工作者，比如顾问、PM、分析师，重点是 Email 处理、会议纪要、报告自动化。如果你是普通用户，就不一定要写代码，可以直接跳到日常使用者这条路线，从 Claude.ai 开始用起。

最后也再说几个容易犯的错误。

第一，不要一上来就扑框架。Stage 3 的工具调用和 ReAct 必须得手写一遍，搞懂之后再用框架，出了问题你才知道卡在哪里。

第二，不要跳过动手练习。这份地图每个阶段都有必做练习，这是光看不练就学不会的部分，不是装饰。

第三，不要贪多。两条路径先选一条走完，不要同时走 A 和 B，精力会被稀释。

第四，不要追求通用 Agent，先做垂直场景。只做 Code Review 的 Agent，比什么都能干的 Agent 要有用得多，也好落地得多。

最后一句话送给大家：走完 Stage 0 到 Stage 2，你就能够决定自己要用工具还是造工具。选好方向，按阶段来，不要跳级，也不要跳练习。
