# jc-group-digest 群精华日报网站生成器

把一个微信群的高价值内容变成自动日更的精华日报网站，让群成员不爬楼也不掉队。整套流程从真实群消息出发，反推群成员需要什么，再决定做什么样的站。

## 能力边界

- **输入**：一个本机 wechat-cli 能访问的微信群（群名即可）
- **输出**：已上线的精华日报网站（Cloudflare Pages）、每日自动更新管线（macOS launchd）、一页运维说明
- **依赖**：macOS、本机微信、`wechat-cli`、Node.js、`npx wrangler` 和使用者自己的 Cloudflare 账号
- **不做**：群管理、发消息、图片视频语音内容策展（只做文本精华）

## 全局铁律

1. 一切判断基于真实消息。禁止凭群名想象群的样子。
2. 三个检查点必须出选择题，每题带基于群画像的推荐和理由。客户端有结构化提问工具时使用它；没有时就在对话里用简短选项，禁止出空题让用户凭空选。
3. 精选标准宁缺勿滥：某天没有高质量内容就明说「今天群里比较安静」，禁止硬凑。
4. demo 和正式站可用当前群的真实精华数据，但默认先映射昵称、删除联系方式、住址、财务、身份信息和报名信息；禁止占位假文。
5. 示例和正式站都不得夹带其他用户的真实群名、昵称、项目路径或网站数据。
6. 上线前必须做隐私扫描和人工预览。未明确得到群管理员与涉及成员的授权，不得公开真实昵称或可识别原文。
7. Cloudflare Pages 默认视为公网发布。“内部版”如无可验证的访问控制，也必须按对外版脱敏。

## 五阶段三检查点

```
阶段 -1 首次配置 → 阶段0 拉取踩点 → 阶段1 群体质分析 → [检查点1 内容策略拍板]
→ 阶段2 策展规则生成 → [检查点2 审美风格挑选]
→ 阶段3 建站 → [检查点3 上线前预览]
→ 阶段4 部署 + 日更管线
```

### 阶段 -1 首次配置

首次使用先读取 [`references/setup.md`](references/setup.md)，只处理当前缺失项。涉及 `sudo`、本地微信进程读取或 Cloudflare 登录时，必须停下说明风险，等用户明确授权。

### 阶段 0 拉取踩点

- **做什么**：用 wechat-cli 拉目标群消息，近 30 天或全部，以够做判断为准。先 `wechat-cli sessions` 或 `contacts` 确认群的完整名称（群名常含活动名或书名，必须用完整名），再 `wechat-cli history "<完整群名>" --start-time <日期> --format json` 拉取，落盘为原始 JSON。
- **为什么在这个位置**：一切后续判断都必须基于真实消息，不允许凭群名想象群的样子。
- **产出**：原始消息 JSON 文件。

### 阶段 1 群体质分析

- **做什么**：从消息里分析四件事：价值分层（谁是核心输出者、什么是高价值内容、成员真实经验碰撞在哪、噪音占比多少）、活跃时段分布（按小时统计，供日更时间决策）、群成员痛点的原话证据（「爬楼爬的好辛苦」这类）。方法见 `references/group-analysis.md`。
- **为什么在这个位置**：内容策略错了，网站再好看也没人看，所以分析必须在任何建站动作之前。
- **产出**：群画像文档（内容分层表、核心成员表、痛点证据、活跃时段分布）。

### 检查点 1 内容策略拍板

用当前客户端的结构化提问工具，或在对话里出四个简短选择题，每题附基于群画像的推荐和理由：

1. **给谁看**：内部（需有可验证的访问控制）或外部（对外展示）。两者默认都脱敏；只有授权充分且访问受控时才可保留真实昵称。
2. **核心输出者的内容怎么处理**：原文完整保留 或 AI 改写提炼（若群画像显示无单一核心输出者，此问改问「最高价值层的内容怎么处理」，选项不变）
3. **讨论怎么处理**：完整对话链 / 一句话摘要 / 摘要点开看对话链
4. **审核方式**：默认人工过一遍再发。只有完成脱敏试跑、访问边界和失败回滚验收后，才可单独授权全自动上线。

### 阶段 2 策展规则生成

- **做什么**：把检查点 1 的决定翻译成这个群专属的分类规则表（每层的识别特征、处理方式、过滤规则）、精选标准、每日精华 JSON schema，然后用历史消息实际试跑 3 天（选消息量多、中、少各一天），人工检查输出质量。模板与方法见 `references/curation-rules.md`。
- **为什么在这个位置**：策展规则必须先被真实数据验证，才有资格进入自动化，否则日更管线会每天生产垃圾。
- **产出**：策展规则文档、3 天真实精华 JSON。

### 检查点 2 审美风格挑选

- **做什么**：根据群画像推导 2 到 3 个候选视觉方向（群气质到视觉语言的映射方法见 `references/style-mapping.md`），每个方向做一个单页 demo，必须用阶段 2 的真实精华数据填充。本地起服务，给局域网地址让用户手机上挑。
- **为什么在这个位置**：审美在完整建站前定，返工成本最低；demo 用真数据，是因为占位文字看不出中文排版和长短消息的真实效果。
- **产出**：用户选中的风格 demo。

### 阶段 3 建站

- **做什么**：在选中 demo 基础上完整实现：时间线、日期切换、讨论摘要点开展开对话链、标签筛选（点击须平滑滚动定位到匹配卡片）。单文件 HTML，数据内联 JS 变量。动手前必读 `references/tech-redlines.md`，每条红线都是踩过的坑。
- **为什么在这个位置**：内容规则和审美都已拍板，此时建站只剩执行，返工面最小。
- **产出**：完整 index.html 及数据文件结构。

### 检查点 3 上线前预览

本地起服务加局域网地址，让用户手机确认。同时扫描真实群名、昵称、手机号、邮箱、住址、身份证件、账号和报名信息。用户确认脱敏结果和访问边界后才允许部署。

### 阶段 4 部署 + 日更管线

- **做什么**：wrangler 部署 Cloudflare Pages（项目名含群的英文标识，用户可改）；参考模板配日更管线（拉当日消息、生成当日精华 JSON、注入、重新部署、写日志），launchd 定时。更新时间的判断依据：看阶段 1 的活跃时段分布，选群安静且当天内容已基本完整的时间点，给用户一个有理由的选择题确认。模板、部署红线、运维说明模板见 `references/pipeline-setup.md`。
- **为什么在这个位置**：自动化必须建立在已被验证的策展规则和已被确认的网站之上，最后做，管线才不会每天放大一个错误。
- **产出**：上线 URL、pipeline 脚本、launchd plist、一页运维说明（怎么看日志、怎么手动补跑、怎么停）。
