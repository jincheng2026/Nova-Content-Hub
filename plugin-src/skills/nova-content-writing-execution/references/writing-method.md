# 叙事、写稿与制作安排

## 1. 回读当前真源

以当前 contentId 的已保存正文、确认状态和本轮用户要求为起点。读取相关参考拆解、用户本人提供的事实与已采纳知识。只按当前阶段选择规则；来源之间冲突时优先当前可核实事实和用户明确要求，历史个案保留适用范围。

已有作者口气样本时读一到两条用户指定、可使用的同类作品及其明确改稿偏好。没有时采用清楚自然的口语并逐步记录反馈，不把参考作者的身份、经历、口头禅或私人样本写成用户事实。

接到他人初稿或旧稿，先在后台逐段标清：来自哪个参考、用户事实、会议记录、已确认观点，还是原稿作者/AI 的推断。先判断骨架能否成立，再润色句子。核心事实、结果或第一人称经历缺失到无法真实写稿时，集中问一个关键问题；非关键细节可以留待补或换成有依据的说法。

## 2. 确定叙事

把技术或知识转换为一个具体场景中的变化：观众原先在做什么、卡在哪、看完获得什么、哪项证据证明可信。主要收获可以是理解、尝试方法或看到可信结果，选一个为主，不强求每条短视频都教会完整操作。

给推荐叙事前核对：

- 面向哪种具体使用场景和需要，观众已经知道多少。
- 作者真正要表达的判断；个人口播需要可公开的一手经历、操作或观察支撑。
- 用什么实际结果、例子、过程或来源证明；有哪些前提、哪些内容本条不讲。
- 内容顺序和关键转折，以及现有录屏、补录能力和目标长度是否支持。

默认用简短方案说明开头、推进顺序、每段作用和证明位置；只有存在真实取舍才给两个方案。一般 1–2 轮即可确定，已明确方向或要求直接给稿的用户不重复确认。把模糊讨论写为待定，不冒称用户已锁定观点。

内容形式按任务选择：

| 类型 | 叙事重点 | 必须检查的证据 |
| --- | --- | --- |
| 教程 | 具体任务、关键动作、可见结果；步骤深度随承诺决定 | 操作入口真实、结果能展示、关键步骤可以照做 |
| 口播 | 作者判断、真实经验、例子和态度；听起来像在讲给一个人 | 第一人称材料属于本人；二手信息与亲历分清 |
| 科普 | 观众的疑问、必要概念、解释、证据及适用边界 | 来源可靠；类比只帮助理解，不替代事实；推断有标注 |

科普分支为通用适配方法，不声称已获得原作者完整私人科普规则。

## 3. 写当前完整稿

按叙事先抓最需要判断的开头、关键论证和结尾；方向明确时直接完成全文。每段至少增加新的理解、证据、动作、结果或判断；删掉重复报幕和没有实际内容的过渡。

教程可用同一个真实任务贯穿输入、处理、人工判断和结果；若参考本身是并列场景或能力清单，保持真实关系。先让观众知道为何值得做、结果可信，再交代必要方法，避免开头堆参数和工具名。

局部改稿只动用户重新打开的部分，保留已确认文字，回看前后衔接。每轮提供可独立读懂的当前完整候选，并另记原句→新句、谁改、理由来源；变更记录读 [反馈方法](feedback-method.md)。原稿锁定后，包装任务只发现冲突并提出具体问题，不暗改正文。

初稿使用 draft；叙事使用 narrative。draft.text 是唯一正文候选；段落结构放 data.composition，绑定本稿 SHA256、UTF-16 起止范围和稳定 UUID，段内关联主参考／补充参考／效果样例、原话和画面。段落中的文字始终从正文范围读取。录制指令放独立分镜步骤或配套说明，保持提词稿可直接朗读。结构字段以产物合同为准。

## 4. 教程画面与录制清单

教程按段落或关键操作生成表格，纯口播仅在画面确实帮助理解时使用：

| 段落/口播引用 | 观众看到什么及其作用 | 已有素材与来源 | 作者要录 | 剪辑要做 | 缺口与完成判据 |
| --- | --- | --- | --- | --- | --- |
| 使用实际段号与原句 | 录屏、结果、真人或图示；说明证明哪一点 | 对应资产或尚缺 | 必录/可选、具体动作 | 剪接、标注、对照等 | 看到什么才算拍齐 |

关键操作说明输入/复制什么、放在哪个界面、怎样触发、成功后应该看到什么。实际产品操作未确认时先核实或明确待实测，不编具体按钮。核心承诺依赖的结果画面必须真实可取；普通氛围或装饰镜头可交剪辑判断。

分镜可使用 segmentId 关联稳定段落，owner 区分 screen（录屏）、self（本人口播）、editing（后期），optional 标记可选镜头。steps 各含稳定 UUID、where（在哪发／先点哪里）、prompt（要发送的内容）、expect（预期结果）、caution（注意事项）。提示词只放 steps.prompt，不混入口播；通读、镜头完成与录完确认都由用户按当前正文版本明确操作。整篇创作的 bundle 不夹带 filming，等用户采用正文后以独立版本任务交回清单。

汇总作者必录、可选和剪辑工作，按实际录制顺序排列。没有现成素材的项目标缺口，不写“已有”。这是制作安排和素材交接，不执行自动剪辑或发布。

## 5. 交付前自查

在后台通读一次，检查主要收获是否明确、长句是否好念、称呼是否一致、所有数字/经历是否有来源、教程承诺是否能兑现。时长用实际试读或说明采用的估算口径；没有真实试读时明确未实测。

当前稿、叙事和配套制作清单能相互对应；已确认部分保持一致；新候选和已采用版本分清。提交前按审稿方法核对 context 最新版本，正文变化时重新基于当前稿完成，不用旧建议覆盖。

### 对标抖音原片与真实逐字稿

若本任务冻结了 media 权限，已有规范作品 URL 可执行 `production fetch-media --handoff ID --stdin`，JSON 仅为 `{claimToken,workerId,url}`。短链不支持，需用户补充 `https://www.douyin.com/video/数字编号`。收到 grant 后以其 referenceId 执行 `production asr`；命令返回 reference 最小结构与真实识别结果。保留 reference 的 id/url/platform/mediaAssetHash，将真实 text/segments 写入 transcript artifact；分析另写 analysis，不改原始逐字稿。原片和逐字稿提交为候选，用户采用前不写入 creation。重新读取 context 可恢复本 attempt 的 mediaGrants；同一作品重用已有 grant。旧任务未冻结 media 时不扩权，不用 import 或路径绕过。费用未知、原片不可用或本地 ASR 失败时提交真实阻塞，不捏造转写。
