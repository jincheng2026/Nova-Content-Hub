# 原型备份导入实施

日期：2026-10-17。状态：只读预检已实现，schema5主体已合入，真正导入正在隔离worktree实施。预检阶段由主线程独占；新阶段交由Sol high唯一负责 `browser-import/**`、输入图片解码及必要照片占位接缝，主线程负责外围接入与审查，避免重叠修改。

## 目标交互

入口“导入旧工作台”打开系统文件选择器。选备份后显示内容/模板/照片/计划数量，以及必须补充的文件和历史未知项。主操作“导入并打开”，默认在文档目录创建新的内容库，位置可选；不要求复制路径、改JSON或到浏览器打开链接。已存在的库不覆盖、不自动合并。

已知内置资源由安装包解析；缺失图片保留原记录，用“补充文件”直接打开文件选择器，不按备份里的 srcPath 读取任意文件。不能使用的照片/样张不进入生成请求。导入结果列明成功项与待补项，原始备份始终保留，不能用一个模糊“全部成功”遮住未知历史。

上述是待接入的界面目标，当前没有相应 Electron 按钮。

## 已实现预检

`inspectBrowserBackup(absoluteFile)` 用稳定普通文件读取，限原型4 MiB，拒绝文件符号链接，读取前/FD/读取后核对身份、大小、mtime/ctime，严格UTF-8/JSON。只执行仓库可信 `Core.validate`，复用原型关系及危险字段验证；备份中字符串只作数据。

返回源字节hash/大小、旧libraryId、对象数量、按内容/物料作用域区分的资源键、资源待解析状态、宿主偏好建议和必要提示。报告不带图片base64、私人文案、会话或模拟信任记录。原始字节包括BOM/CRLF保留给后续不可变归档。

embedded-unverified 只说明存在字节，不能当成解码通过；reference-unresolved/missing 明确未解决。预检不创建库、不写磁盘、不联网、不自动读srcPath，也不接受演示安装/信任/授权为真实状态。

验证6项通过，日志 `verification/production/2026-10-17-browser-import-inspection.log`：重复旧候选ID按所属物料区分、私人内容不出现在报告、srcPath不读、坏JSON/UTF8/凭据字段/高版本/超限拒绝、符号链接拒绝、读取中替换检测、BOM/CRLF字节保全。测试使用合成备份，没有读取同事私人库。
