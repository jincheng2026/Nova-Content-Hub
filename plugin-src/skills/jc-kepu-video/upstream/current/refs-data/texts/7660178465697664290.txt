首先我先要理解，Codex 为什么会做成这样。一个页面分为两件事：设计和工程。像颜色、【听不清：兼类】这种设计的问题，像表单、状态管理，或者数据请求，这种是工程的问题。Codex 很擅长工程的实现，但是它不擅长设计，所以说我们要利用其他的平台来弥补 Codex 的短板。那怎么做呢？我一步一步教你。

第一步，先确定设计风格，你可以去像这一类网站去看案例，上面有大量高质量的演示效果，我们可以看到这些效果还蛮不错的。下一步，我不是让你直接去复制，肯定不符合你实际的需求，对吧？你可以去看看你想要的是类似极简的，还是一些暗黑的科技风，还是其他的效果，然后最终选择你喜欢的风格。

第二步，要确认产品的需求，你可以基于你的需求，让 Codex 输出一个产品需求文档，这个很重要，因为这个决定了需要哪几个页面，每个页面有哪些模块，每个模块是什么功能，等等等等。你可以发给 Codex 这段提示词，其实也就是基于你的想法、参考的风格，不先写代码，先出一份前端的需求文档，然后再进行你下一步的操作。我们可以看到，我把对应的需求发给他，能够很快地输出一份产品需求文档给我，它生成一个 PRD 的 Markdown 文档，我这就能够方便我下一步拿去给到这种平台去操作。

第三步，就是什么呢？你可以理解为一个免费的设计平台，它先做设计的原型，基于你要的风格、你实际的需求，输出你的第一版方案。我们可以看到，我打开 Stitch 的官网，把我的 PRD 文档和喜欢的这种参考图【听不清：给到它】，然后这里 Pro 模型是目前非常好的一个模型，然后这边我参考的参考图，然后我的 PRD 就能够快速地生成原型，效果是不错的。OK，这就是它最终修改的效果啊，如果你想要修改，就标注输出你想修改的点，我说去掉这个绿色的边条，它就能够快速地重新去画一版，你看到这里，明显效果就已经重新修复好了。

当 Stitch 已经输出原型图之后，如何让 Codex 去使用呢？我们打开 Stitch 之后，第一步，这里面我去点这个导出，导出之后，这里面去选择这个 MCP。第一步的话，你要【听不清：codep】，也就是这里面去配置，然后将对应的这个 MCP 的密钥复制出来，然后发给 Codex，说帮我配置一下 MCP 啊，这是第一步最关键的东西。然后你看到它能够快速地去完成初始化的配置，然后有了这个配置之后，那后呢，你点导出，再点 MCP，然后就可以把对应画面的对应的一些 Title 和 ID 复制下来，复制下来之后呢，发给 Codex，让它把这些代码拉到本地，它本质上还是对应的一些代码内容。然后再下一步，你就发给 Codex，请严格按照项目文件里面的 Stitch 的原型图，严格复刻对应的一些页面效果，然后以产品需求为准，设计一个高保真的前端效果。你可以看到，它能够很快地把刚才那个对应的图片、代码内容放到你的前端项目里面去。

第五步啊，也就是让 Codex 去补充后续的交互和逻辑，在有了基础的设计规范和大体的框架之后，就可以让它去补充。比如我们这边已经有了输出，它说，我把对应的这个边条去掉，然后另外帮我补上一些暂时无法点击的模块内容，它就能够很快地一步一步去帮我优化迭代。看到，就是已经把对应的绿色边条去掉了，说明有了这种基础规范，Codex 就能做好功能设计。
