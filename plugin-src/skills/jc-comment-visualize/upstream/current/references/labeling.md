# 标注规则（P2 动手前必读）

来源：2026-08-14 抖音 AI 教程调研实战（15 条视频、508 条评论、两轮人工复核），规则都被真实数据检验过。

## 长短评分流

| 类型 | 判定 | 处理 |
|---|---|---|
| 长评 | ≥35 字，且不是提示词刷屏墙 | 逐条深读，一条一张证据卡 |
| 短评 | <35 字 | 重复简单留言可合并；具体任务、卡点、反例同样深读 |
| 噪声 | 空白、纯表情、纯 @、单字 | 计数后剔出分母 |

赞数 ≥3 的短评应复核；低赞但问题具体的短评也要读。点赞不能证明它代表多少人。

## 聚类正则起点（按实际语料调整，别照抄不改）

```python
PROMPT_WALL = re.compile(r"从今天起.{0,6}回答我任何问题|文风对标规范|请全面化身为反方")  # 换成当次语料里的刷屏句头
BEG   = re.compile(r"^[@\s]*(求|资料|skil|skill|分享|谢谢|感谢|老师|大佬|发我|一份)+[\s。！!，,~〜\[\]a-z一-龥]{0,12}$")
AT_BOT = re.compile(r"^@(豆包|DeepSeek|deepseek)")   # @AI 代劳提取
EMOJI  = re.compile(r"^(\[[^\]]+\]|\s|[?？!！。.~〜]|@\S+)*$")
PRAISE = re.compile(r"^(厉害|牛|太强|神了|有点东西|学到了|谢了|好用|支持|收藏了)[!！。~〜\[\]a-z一-龥]{0,10}$")
```

聚类数字必须可复算：脚本存进任务目录 normalized/，页面里的每个计数都能重跑得出。

## 证据卡字段（长评深读，一条不缺）

```text
引文        原文摘录，关键词用 <mark> 高亮（高亮的是暴露需求/情绪的词，不是随便加粗）
赞数        采集时快照，页面上注明这一点
属地        ip_label，省级
明确说了什么  记录评论者给出的场景、任务、问题或反馈；推断另列
可以怎样解释  说明依据与其他解释；没有额外信息时不猜潜在心理
```

好的卡：「引文『我是司机，准备跟领导说下次材料让我来写』（135 赞·陕西）→ 暴露：非文字岗也被摊派写作，AI 让他敢抢活 → 意味着：身份反差是这个选题的钩子」。
差的卡：「这条评论说明用户很有热情」——既回不到需求也给不出动作，删。

## 想当然改判纪律（真实事故驱动）

1. 每个主题归纳完，**逐条核对赞数构成**：权重前三的评论真的属于这个主题吗？
   事故原型：729 赞的「公司按 token 消耗量排名」（开发者反讽）被顺手归进「论文去AI味」，主题权重从 3 赞虚抬到 732，排序整个失真。发现方式就是这步核对。
2. 挂话题标签 ≠ 内容相关：「#剪映让好作品告别AI感」话题下大量真实萌宠视频、「ai」可能是 Adobe Illustrator。按标题印象归类的，回原文重读。
3. 一条评论只算一次观察，禁止从单条评论写「观众普遍」「大家都」；多条独立评论同一指向可写成样本中的重复信号，仍不能外推为普遍规律。
4. **引用历史计数必须重算**：凡引用旧报告/旧洞察卡里的计数，重跑正则按当前语料核对后再用，不许照抄。事故原型（2026-08-21 深读核证）：王牌笔杆子洞察卡记「@豆包 托管 80 条占 63%」，重数实为 108 条占 85%；「求指令 31 条」按可回查口径根本数不出（实为 17 条）——首次目测的数字一旦进了台账，会被后续所有引用继承。

## 主题统计口径

评论条数与获赞总数分别展示。需求报告默认按已复核评论条数排序，也允许查看获赞排序。图注写清视频、层级、已复核数量与多标签情况。未取得的获赞保留缺失，不补零。不同单位分开画，不能把条数和获赞混在同一刻度上，更不能用它们估算购买意愿。

## 证据标签三档

- `评论实证`：有 cid 有原文
- `推测`：由评论提供的情境作解释，必须标出范围；不猜未披露的年龄或其他个人属性
- `待验证`：方向判断，样本不够
