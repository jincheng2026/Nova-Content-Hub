如果你刚安装好 Codex 啊,这是不设置可以让你的 Codex 提升百分之九十的方法,其实很多时候不是 Codex 不够,而是你和它的配合方式没有设置好。OK,我们现在开始。

第一就是让 Codex 更懂你。你可以先看一下,比如说我们打开设置、个性化指令,然后这里面可以去设置你的自定义指令。比如说语言,会让它用中文跟我沟通,但是代码和命令变量名要用英文跟我沟通。然后呢,包括一些安全红线的问题,比如说不提交一些密钥或者一些敏感的信息,默认去直接执行,但是对于少部分的一些高风险的动作,会去做一些拦截。然后同时,比如说一些工作流程,会让它先在【听不清】之前写一些【听不清:失败用力】,再做一些修复。然后以及一些代码的标准,比如说不让它把一些文件写得过大,因为像 AI 写的一些代码写得很长,AI 修起来也很麻烦。然后包括一些用户的一些【听不清:编号】,比如说跟我用【听不清】沟通,然后直接执行,而不是频繁地做一些权限确认。所以这些 AGENTS.md 的设置啊,就会让它以后每次去新开一些新的任务,都能够知道我的工作习惯,不需要每次都重新再告诉它一遍。

第二部分就是让 Codex 去输出效率更高。很多人一上来就会让 Codex 开写代码,但很多时候你自己都没有想清楚你的需求,它写出来的东西也不一定会符合你的预期,然后你再让它改,来回沟通,其实时间反而花得更多。而这个时候可以用到 Plan 模式,或者【听不清】模式。我们可以看到,我们点击进去,选择这里面的计划模式,然后给它发一个需求,它能够快速处理,处理完了之后呢,包括这里会给你提一些疑问,然后你选你自己的需求是怎么样的,然后最终给到你一个完整的计划,可以选择跳过,然后在这里面去点击选择你的目标模式,然后再让它按计划去推进,直到执行完成。简单理解啊,就是 Plan 是想清楚路线,就是它最重要到哪里。

第三就是让 Codex【听不清】,其实现在 Codex 有不同的模型和思考的强度,很多人可能都不知道该怎么选,我可以看看这里面的能力和用量的对比,其实分为三个模型,以及不同的思考强度。对于我用而言的话,像【听不清】和 Medium,其实它的性价比相对就高一些,然后往上,提升的能力并没有太多,但是费用是翻倍的。当最【听不清】的时候,你可以用 Max 模型。总结下来的话,就是比如说你写一些文案或一些普通的问题,【听不清】就不错;然后你要一些常规的开发,Medium;然后一些复杂的排错,你可以用 Max。当然,如果你预算有限,你可以让它多跑几步,其实 Medium 或 Max 质量也非常不错。

第四步啊,就是让 Codex 输出质量更好。比如说你现在有一个项目正在运行,但是又想让 Codex 去开发一个新的功能,如果直接让它改当前代码,就很容易影响你现在这个正在用的版本,对吧?这个时候你就可以用 Worktree,你可以理解成同一个项目单独给它开一个空间,让 Codex 在这里面去开发,这样原来的一个项目会继续正常运行,但是新的功能可以单独去测试,甚至你可以同时做好几个方案,最后选择最好的一个,完成以后呢,去检查代码的变化,跑测试,确认没问题再合并回来。

所以说,这四步连起来就是一整套 Codex 工作流啊。第一步,先告诉它我的工作习惯,对吧;第二步,复杂的任务可以让它想清楚,然后设置目标;第三步,就是根据任务选择合适的模型;第四步啊,需要改代码的时候,不影响当前正在运行的项目。这样使用 Codex,效果就会让它直接写代码会好很多。
