# 人工发布后的收口

仅在用户明确要求发布后归档/收口时进入。内容生产、剪辑、自动发布、创建定时任务和安装后台服务都不属于本方法。

1. 用当前稳定内容ID、平台作品ID、标题、发布时间、时长、封面与文件哈希等实际证据识别已发布对象。只读本轮显式材料，不扫描Downloads、桌面或其他项目。多个候选/冲突合并成一次关键澄清，不能仅凭修改时间认回作品。
2. 冻结真实发布文本、校正版逐字稿、字幕、封面角色及已提供资产指针。录制前稿不是实际成片逐字稿。用户未提供成片时记录真实缺口，ASR/平台补采仍需当前授权；不移动/删除原始资产或中间证据。
3. 平台预期发布、已发现、实际发布状态分别描述。未找到/歧义/鉴权失败不能写已发布，不把公开搜索叫创作者中心自动发现。平台版本分别保留，不在发布后生成标题/简介/封面冒充真实版本。
4. 一条内容保持唯一归档身份，重复调用优先复用已有记录；输出本轮新增或补充候选。知识副本/引用必须指向实际来源，不复制一套当前稿，不直接写manifest程序区。
5. 有真实发布前预测/押注时记录来源和哈希，不修改历史预测；不存在可为空。需要12小时/7天观察时只提出目标时间与所需数据，若应用没有已验收调度能力，明确监控尚未创建。晚采数据保存目标与实采时间，不能伪装准点。
6. 单平台失败与成功分别记录，归档候选、知识候选与监控建议可部分交付；不以一种成功掩盖另一项未完成。

完成：身份依据、真实资产与发布版本、各平台已知状态、缺口、幂等补充方案和未来观察建议完整，经executor提交回执。发布记录候选与工作台已采用归档不同，不声称本方法安装了原包后台能力。
