## 交付与能力边界

用户拿到的是匹配自己系统和架构的一份完整本地市场，无需额外安装 Node 或手动拼浏览器请求链接。维护者生成目录，
宿主负责展示与安装；用户在宿主内确认安装、启用以及必要的 Hooks 信任。构建不读写用户宿主配置、不注册市场、不运行宿主
Hooks、不替用户点安装。工作台交接仍以固定 handoff ID 和既有提交事实为准。

两种授权模式隔离。`required` 因可信权益未接入而拒绝 cover 业务读写；`disabled` 仅用于无鉴权实验。模板学习、还原验收、
项目封面三项 contract Skill 保持不可执行；只有 `nova-content-cover-execution` 在 disabled 模式具备原有真实文件执行能力。
插件不提供模型额度；打开插件详情、打开助手、接单、生图、提交成功是不同事实。

## 可移动的市场结构

```text
plugin/marketplace/auth-required/darwin-arm64/
├── .agents/plugins/marketplace.json       Codex 目录
├── .codebuddy-plugin/marketplace.json     WorkBuddy 目录
├── README.md
├── package-files.json                    构建者生成的子包全树清单
└── nova-content-hub/                      原执行包完整副本
    ├── .codex-plugin/plugin.json
    ├── .codebuddy-plugin/plugin.json
    ├── bin/run-node + run-node.cmd
    ├── runtime/                          固定 Node 24.20.0 与许可证
    ├── plugin-src/                       四项 Skill、CLI、资源与共享核心
    ├── cover-runtime/                    保留兼容入口
    ├── node_modules/                     锁定 sharp 及对应原生模块
    └── integrity.json
```

disabled 位于独立 `auth-disabled` 目录；其他原生系统/架构位于独立 `<platform>-<arch>` 目录。两个目录文件均指向市场根下的
`./nova-content-hub`，无需回到仓库查找代码。整体市场可以移动，子包也能整体复制到宿主缓存；不能只复制 Skill 或 manifest。

Codex 市场名示例 `nova-content-hub-auth-disabled-darwin-arm64`。名称不带版本，以便同一产品/模式/平台升级；原插件 name
保持 `nova-content-hub`。清单描述、界面市场标题均说明实验、鉴权未接入及非商用，不把安装策略当作可信鉴权。

## 维护者构建与核验

在仓库根目录使用对应系统、架构的原生环境：

```sh
npm run build:cover -- --auth both
node plugin-src/scripts/marketplace-builder.mjs --auth both
node --test plugin-src/tests/marketplace.test.mjs
NOVA_MARKETPLACE_INTEGRATION=1 node --test plugin-src/tests/marketplace.test.mjs
```

Windows PowerShell 的集成测试命令为：

```powershell
$env:NOVA_MARKETPLACE_INTEGRATION = '1'
node --test plugin-src/tests/marketplace.test.mjs
```

无 `--auth` 时使用根 `release.config.json` 的固定默认模式。包装器只处理已有本机执行包，不下载 Node、不运行 npm、
不重生成包内 manifest/release/integrity。先比对原发布配置、系统与架构、Node 官方归档锁及已记录 Node/许可证 hash，
再核验原 integrity 完整路径集合和四项 Skill 能力。复制后对全部文件字节、执行位及相对链接再次核对；Node hash 不重算写回。

市场根的 `package-files.json` 为后续只读安装匹配提供唯一全树清单；它在子包外，不改变子包或原 integrity schema。
格式固定为 `nova-content-marketplace-package-files`、`schemaVersion:1`，`release` 包含完整固定发布配置（含 pairId、
AUTH_MODE、platform、arch）。`entries` 的 key 相对子包根，覆盖全部目录、普通文件与安全相对链接：文件记录
`sha256/bytes/executable`，目录记录 `directory:true`，链接记录原始 `link`。生成前再次核对源和副本全树，拒绝不安全 key。
原 integrity 只覆盖部分关键入口，不能据此认定安装副本全树可信；匹配时必须从可信市场读取此构建清单，与安装目录完整比对，
不能接受安装副本自报的清单或 hash。该清单仍不是数字签名。

已损坏/混模式/异架构包、缺 hash、改 Skill 能力、符号链接逃逸或额外顶层用户文件会被拒绝；验证失败不替换已有市场。
允许 npm 自身指向包内文件的相对链接，原样保留，避免安装缓存继续指向源仓库。构建源必须是本仓库生成的纯运行包，
不能混入内容库、用户素材或凭据。integrity 用于一致性核验，不提供数字签名或外部下载来源认证。

## 宿主入口与人工步骤

Codex 按官方格式使用对象 source、完整 policy 与 category：

```json
{
  "name": "nova-content-hub-auth-disabled-darwin-arm64",
  "interface": {"displayName": "Nova Content Hub · 实验插件 · 鉴权未接入 · 非商用 · disabled · darwin/arm64"},
  "plugins": [{
    "name": "nova-content-hub",
    "source": {"source": "local", "path": "./nova-content-hub"},
    "policy": {"installation": "AVAILABLE", "authentication": "ON_INSTALL"},
    "category": "Productivity"
  }]
}
```

`source.path` 相对**市场根目录**，不相对 `.agents/plugins/`。官方兼容旧 `.codex-plugin/plugin.json`，故本次不改原包格式。
Codex 支持本地市场 root 的 CLI 注册，但注册会写用户配置，本次未执行。人工准备时可打开本地详情：

```text
codex://plugins/nova-content-hub?marketplacePath=<encodeURIComponent(市场根/.agents/plugins/marketplace.json 的绝对路径)>
```

`marketplacePath` 是 JSON 文件的绝对路径，**不是市场根目录**。打开详情不等于安装或信任。停留在详情与安装确认界面，
由用户确认后再继续；若宿主不能识别，记录版本与实际错误，不改用户配置绕过。

WorkBuddy 使用 `.codebuddy-plugin/marketplace.json`，结构沿用已存在的旅游工作台市场：顶层 `name/owner/metadata`，
`plugins[]` 的 `source` 为 `./nova-content-hub` 字符串并含 `name/description/version`。原插件清单不变。官方确认插件页
`+` 接受市场地址；其当前公开页面未精确承诺本地路径与解析格式，故需要在实际 GUI 中核验目录发现、插件详情、安装/信任
及缓存后的 Skill 路径。不能将另一个项目的现用格式当作本产品已安装成功的证据。
