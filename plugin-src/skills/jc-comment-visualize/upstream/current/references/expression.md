# 把分析写得清楚

出页和复核文案时读取。分析底稿可以使用方法论；报告交给读者的是观察、解释、证据和取舍。原评论、访谈和逐字稿引文逐字保留，分析文字按本文件改写。

## 一段话怎样写

先说观察到了什么，再解释它为什么值得关注。必要时补一条原话、另一种解释或适用范围。各句应接得上，不把四项机械地写成四个标签。

例如，观察到有人已经做出了工作台，却觉得步骤更多：可以解释为「能生成页面，还不等于减少了原来的工作」。接下来应核对原来的操作步骤和实际使用结果。没有证据时，不把它写成用户怕失败、缺乏行动力或有付费意愿。

关键解释通常需要一个短段落。不要为了两行限制，删掉主语、对象或推理过程。细节多时分段；重复数据和完整引文才放进折叠。

## 应保留的内容

- 明确判断，以及支撑判断的具体差异。例如两类评论的内容不同，而不是只罗列两个分类数。
- 有背景的原话。交代来自哪条视频、什么层级、何时采集；别让读者猜指代。
- 对同一材料的其他解释、反例和适用条件。一个准确的限制通常比反复写「仅供参考」更有用。
- 与使用者实际材料的对照。建议要说清做什么、怎样判断有用；不只写「加强」「优化」「持续关注」。

## 应改掉的表达

| 常见问题 | 改写方法 |
| --- | --- |
| 用口号代替发现，如「声量与钱包错位」 | 写清是哪两组数和哪两类评论不同；没有交易证据就不提钱包 |
| 猜测没有说出口的心理，如「真正害怕的是……」 | 先写评论明确表达的顾虑；可能的解释须有原话依据及其他解释 |
| 把判断写成警句，如「收藏是行动的替身」 | 分开说可见的收藏量与未知的实际使用情况 |
| 连用「不是……而是……」「所以→」「本质上」 | 直接写本段发现的对象、行为和影响；只有确实纠正一个误解时才用对比句 |
| 滥用比喻，如「弹药底仓」「过路口」「赞池」「收割」「供血」 | 用材料范围、评论者出现次数、获赞总数、资料获取等具体名称 |
| 每段都加模型名称、阶段编码、情绪词标签 | 将它们留在底稿，正文使用评论者的处境和问题 |
| 每个标题都是夸张结论 | 标题写这一节回答的问题，或证据足够支持的判断；未验证的因果不进标题 |
| 将提问者一律分成真需求、伪需求、最近会付钱 | 描述他要完成什么、卡在哪里、问题是否得到回答；购买意愿另看直接证据 |

上表用于识别写法，不是禁用普通词的词典。「保持原文」「高质量导出」等有明确对象的表达可以成立。不能为了躲避机检换掉关键原话、篡改引文或把分析藏进证据标签。

## 改写示例

以下为表达示例，不是可直接套用的研究结论。

- 原写法：「这个评论区不是社区，是过路口。」
  改法：「本次记录里，大部分评论者只在一条视频下留言。我们还不知道他们是否看过其他视频，也不能据此判断是否形成了稳定社群。」
- 原写法：「观众拿走清单，账号什么也没留下。」
  改法：「部分观众在评论区请 AI 整理内容。这说明文字版值得考虑；这些观众之后是否关注或领取资料，目前没有数据。」
- 原写法：「最想掏钱的人，正躺在零赞区排队。」
  改法：「一些低赞评论提出了具体的操作问题。选题时值得单独查看这些卡点，但它们还不能证明付费意愿。」
- 原写法：「四股劲里有两股半年没人管。」
  改法：「已读材料中，费用和使用门槛的回答较少。需要核对其余作品与回复后，才能判断作者是否遗漏了这些问题。」

## 出页后的复核

先只读首屏和各节标题，确认能看懂研究对象、主要发现和建议。再逐段检查：主语清楚吗，抽象词是否可以换成具体动作，判断有没有越过引文，每段是否真的增加了信息。保留有必要的解释，不把报告压成一组结论口号。

机器只提示已知的生硬写法并核对引用。它不能判断分析是否有价值，不能把「词语没有命中」当作自然表达通过。
