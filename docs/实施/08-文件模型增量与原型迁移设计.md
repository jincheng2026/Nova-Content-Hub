# 文件模型增量与原型迁移设计

日期：2026-10-17。Astra high 基于真实源码提出、主线程收敛。主体schema5模型已合入（`6d01314`、`2280653`、`d62abe6`）；完整导入仍未实现，未实现的接口不得当成现有能力。事实差异见 `07-五页原型到文件库覆盖清单.md`，精确现有API以file-library/README.md为准。

## 版本与有限对象

下一单元统一采用库 schema 5、内容 schema 4、提示词 schema 2、新发布快照 schema 2。复用当前锁、捕获/安装事务、回收站、幂等 mutationId 和不可变资产。不建立通用 JSON patch、文件 API、实体注册平台。

增加两个内部固定类型：workspace（唯一 ID `default`）、collection（UUID）。对应 `库配置/default/配置.json` 和 `合集/<id>/合集.json`。新增事务 schema 3 严格列明有限类型；继续读取旧事务 schema 1/2，不重写旧历史。普通旧内容/提示词可惰性升级，但不得由 cover 的 extend() 把较高内容 schema 降回 3。

## 库配置与机器偏好

库配置只保存可携带业务事实：

```js
{
  profile: { name, intro, avatarAssetHash, marks: [{ key, value }] },
  defaults: { photoId: null, templateId: null, coverCount: 4 },
  channels: [{ id, name, ink, bg, requiredRatio, builtinKey, deletedAt }],
  promptCategories: [],
  customRatios: []
}
```

默认模板/批量数是新增偏好，旧备份不存在，不宣称恢复。默认照片或模板被软删/本人声明失效后，返回明确的默认项失效事实，不静默改选；生成仍逐次固定输入。渠道稳定 ID 与名称分离，自定义 `channel-<uuid>`，改名不破坏引用；软删后历史可读，新计划不可再选。比例规范化去重，平台比例不能冒充已验证的像素要求。

新库/旧库首次建立配置包含原型已有5渠道：douyin、xiaohongshu、wechat-channels、wechat-official、bilibili，显示名与颜色沿用原型；产品可编辑比例初值分别3:4、1:1、3:4、47:20、16:9，不声称平台强制标准。旧未登记渠道引用保持可读，导入按引用补齐，不因新登记表破坏旧计划。

有限方法：readLibrarySettings、updateProfile、setGenerationDefaults、create/update/trash/restoreChannel、setPromptCategories、add/removeCustomRatio，均复用 editToken/mutationId。

全局 host、showSample、motion、最近绑定目录在 Electron userData 另存机器偏好，后续由有限偏好接口管理。演示 auth、安装/版本/trust、bridge、clientId、路径与 lastCheck 不迁成可信能力。导入只能提示旧 host 偏好，不能声称宿主已安装或已授权。

## 内容、合集和多规格封面

内容新增 recordedDate、plannedDate、preferredTemplateId、channelIds、isExample；日期只存 YYYY-MM-DD 或 null。createdAt 继续代表新文件对象建立时间。主正文不由各渠道文案拼接；旧原型没有基础正文时保持为空。

合集是独立对象，保存 title、dateRange、memberIds、channelIds，以及其自身附件/计划/发布。只允许成员为内容，不嵌套合集，不复制成员正文/候选/任务。提供 create/read/update/list/trash/restoreCollection、setCollectionMembers；正在被使用的成员先移出合集再删除。总览与日历只做投影。

原型 materials 表示输出规格，而现核心 materials 是输入附件，不改后者含义。内容新增 coverVariants（id/name/ratio/preferredTemplateId/selectedCandidateId）。候选仍单份，补 variantId、favorite、原显示编号/备注和可选来源。selectVariantCover 只改对应规格；selectedCover 仍是内容主封面，不替代所有尺寸。

导入批次单独保存 importedCoverBatches：旧批次序号/日期/模板组/candidateIds/参考 candidateIds/原状态/来源。新任务运行批次从既有 request/attempt 派生，不另存第二套运行状态。旧模板只有组 ID 的历史版本保持未知；旧 done/running 状态不能创造真实 claimed/committed 任务。

缺字节附件、候选或模板原图保存显式 unavailable 的导入引用与原 ID，不造假资产、不放宽真实任务的 assetHash 验证；不能作为生成输入，后续可补文件。有限来源记录与真实执行数据分开。

## 渠道计划与发布历史

savePublicationPlan 扩展为每条计划独立 text、coverChoice 和明确时间精度：

```js
schedule = { precision: 'date', date: '2026-10-18' }
// 或 { precision: 'local-minute', date: '2026-10-18', time: '19:00', timezone: null }
// 或 { precision: 'instant', at: '2026-10-18T11:00:00.000Z', timezone: 'Asia/Shanghai' }
coverChoice = null // 或 { variantId } 或 { candidateId }
```

新计划显式给 text，空字符串也是真实事实。旧 schema4 计划保留引用基础正文的语义，直到用户明确编辑；不静默改空。无时区的旧 date+time 保留墙钟值，不擅自套当前机器时区；只有日期不填午夜。recordPublication 同样允许明确精度。

快照 v2 同时冻结基础正文、发布文案、当时渠道名称、具体封面/hash/模板版本、计划与发布精度。发布时解析规格选择到具体候选。旧 v1 快照原字节/hash 不改。

原型 pub.snapshot 没冻结历史文案；当前 post.text 只迁入当前计划，历史 publicationText 必须标 unknown。无旧封面快照时不拿当前选图补历史。更正/撤销发布追加事实记录，不能删改旧快照；撤销后可重新登记且新旧可读。对应有限 correctPublication、retractPublication，不做通用事件框架。

提示词 v2 增 enabled，setPromptEnabled 与软删分开；原型 off 映射 !enabled。配置保存分类顺序/空分类，显示与现有提示词分类并集。非受控 builtinKey 的用户内容不被安装器覆盖。

## 升级与导入次序

schema4→5：拿锁恢复 pending，保存 descriptor 原字节，建立 `事务/升级到5` 旧写入器屏障，建立有限目录/默认配置，最后发布 descriptor5。中断可重入，当前记录若变更须经既有事务保留原字节；历史 intent、模板版本、发布快照不重写。更新备份协议核验/恢复验证、种子安装和 cover 扩展器，并用真实旧 writer 检查屏障。

浏览器导入另一个实施单元 `browser-import/`，inspectBrowserBackup/importBrowserBackup 两入口，只导入新库。保留原始输入字节/hash与不可变 ID 映射，暂存中完成验证和转换，描述文件最后独占发布。

顺序：原始字节与安全校验 → 有作用域的全 ID 映射 → 可获得的实际资产 → 照片/模板/提示词 → 渠道配置 → 内容/附件/规格/候选 → 合集成员 → 计划/历史发布 → 默认引用 → 软删/旧任务 → 全库校验与发布。候选映射键含 projectId/materialId/candidateId，不能只按旧 candidateId 全局映射。原型引用但渠道表未登记的名称保留建档并注明来源。

资产只接收实际 data URI、用户明确选择的文件或受控内置包资源，重新算 hash/完整解码。不按备份 srcPath 自动读取本机文件、不自动下载任意 URL、不执行脚本、不把同事私人内容变成内置分发。

## 必要验收

- 全字段合成库与回收站逐项比对；两内容重复旧候选 ID 不串图。
- 两渠道不同文案/规格；当前正文/选图/渠道名变化不改历史发布。
- date、local-minute 无时区、instant 三种精度保持；录制日不填导入日；历史缺证据保持 unknown。
- 默认失效、提示词停用、软删恢复分别正确；缺文件不能生成。
- 升级各阶段中断、真实旧 writer 拒写；新库备份恢复、种子重入、cover 提交不降 schema。
- 原始备份/映射/异常明细可读；机器演示状态不变成真实信任。
- Windows/Mac、两宿主、Electron 与安装包各自独立验收，不能从文件测试推导。

执行分两单元：先 schema5 文件模型与有限 CRUD，再浏览器导入器。完成这些之前不大范围迁入五页，避免 UI 再造第二套 localStorage 事实。
