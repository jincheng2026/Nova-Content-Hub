# 五页原型到文件库覆盖清单

日期：2026-10-17。以下表格记录schema4阶段的原始迁移缺口；schema5主体已按 `08` 合入，完整导入仍在实施。依据为 `原型/core.js` 的 validate、原型数据结构及 `file-library/index.mjs` 的实际有限接口。不能因为已有四类对象和封面任务，就宣称五页全部数据可迁移。

## 已有事实与缺口

| 原型事实 | 文件核心现状 | 迁移要求 |
| --- | --- | --- |
| 内容标题、正文、资料、生成候选 | 已有原始 Markdown、内容元信息、资产与请求回执 | 保留旧编号映射及原始备份；旧模拟任务不能变成真实执行证据 |
| 原型 materials 为输出规格→批次→候选，含编号/收藏/参考 | 文件核心 materials 表示输入资料附件，含义不同 | 不能按同名字段复制；独立保存输出规格/轮次关系，候选本体仍单份 |
| 模板组、多样张、规则和版本 | 已有 immutable 版本包与资源清单 | 保留分组、版本、结构/风格资源角色，不降成一张缩略图 |
| 本人照片、默认照片、账号介绍、头像、标记 | 已有照片及 isOwnPhoto；缺 profile 和默认引用 | 默认引用属于库，样例人物不得成为本人；身份声明不可凭旧截图推定 |
| 自定义尺寸；拟新增默认模板/一批张数 | 请求逐次明确输入；旧备份没有后两项已持久字段 | 默认只影响新请求，不能改写历史快照；用户可选择这次不放人物 |
| 渠道名称、颜色、所需封面尺寸及用户渠道 | 计划仅接受 channelId；无渠道目录 | 稳定 ID 与名称分离，改名不破坏历史，删除不使旧发布失去可读信息 |
| 合集、成员、录制日和合集起止日期 | 内容无合集与描述性日期 | 保留真正内容归属，不复制成第二条内容；录制日不等于创建/导入时间 |
| 每渠道文案、所用物料/封面、可只有日期的计划 | 当前计划要求 scheduledAt + timezone，共用正文/selectedCover | 补齐每渠道草稿与封面引用、仅日期语义；不为缺失时间杜撰 00:00 |
| 已发布快照 | 已有固定正文/标题/封面/模板版本与人工发布记录 | 扩展渠道语义时保留旧快照原字节，不用当前正文覆盖旧发布 |
| 提示词分类、自定义分类、停用状态 | 已有分类/正文/来源/tags；缺停用和分类目录 | 停用与删除分开；同事私人提示词不得成为内置分发内容 |
| 全局助手、示例显示、库绑定；减少动画另存 UI 状态 | 前三者在 SETTINGS；motion 不在业务备份内 | 机器偏好与库业务数据分开；只有设置选助手，任务复用一个继续入口 |
| 安装/信任/版本/账号授权演示状态 | 原型模拟 | 不作为真实检测、已授权或插件配对结果迁入 |
| 回收站对象、旧发布图片、附件原始字节 | 原生软删除与资产可保全 | 各种回收对象逐项映射；外链/缺失原图明确列出，不伪造已导入 |

## 下一步约束

下一轮先由 Astra 对缺口做一次合并的数据增量设计，复用现有有限对象事务和升级屏障。不要逐字段创建通用注册表框架，也不要用一个可任意写 JSON 的接口绕过规则。

导入只接收用户选定的原型备份文件，先用仓库内可信 validator 校验数据，再导入一个新库，保留原始备份与旧 ID → 新 ID 映射。不得扫描浏览器凭据、执行备份脚本、将演示授权变成正式权益。中断/重复导入可核对已提交 mutationId；不能依赖“导入一次应该没问题”。

验收需要一份涵盖内容/合集/多渠道/日期无时间/每渠道文案/多封面/录制日/历史版本/软删/本人照/默认引用/私有提示词的合成样本，逐项比对活动数据与原始备份。原始归档可作为保全，但不能代替业务可用的迁移。随后再把五页接到同一文件真源，日历和总览不另存内容副本。

架构复核补充：旧备份未含默认模板/批量数，不得宣称恢复不存在的设置；motion 不是 core 导出字段。PROJECTS.dates.record 是录制日，pub.at 也可能只有日期，二者均不能伪装成精确 UTC 时间。

原型 pub.snapshot 只保存封面信息，未保存发出时的文案。迁移可保留当前 post.text 为当前渠道文案，但历史发布文案必须标明未知，不能伪装成可信的旧快照。

后续落实：schema5已补配置/合集/录制日/每渠道文案与选图/日期精度/提示词停用及历史发布有限接口，完整466项验证通过；精确契约见file-library/README.md。真实导入尚未完成，缺字节照片占位/同ID补图为明确后续接缝，不能把本表全部标成可迁移或用原始归档代替活动数据。
