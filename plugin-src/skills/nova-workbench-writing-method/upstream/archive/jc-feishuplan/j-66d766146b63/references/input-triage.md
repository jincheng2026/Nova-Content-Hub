## 输入分诊

处理口喷、长文本或混合输入时，先逐条分类，再提取任务。分类不等于写入；只有「任务」进入任务池候选。

| 类型 | 判断信号 | 处理 |
| --- | --- | --- |
| 任务 | 有明确行动意图，并能识别对象、交付物、跟进动作或责任人 | 进入候选任务 |
| 可能任务 | 有推进意图，但动作、对象或是否真要做不明确 | 放「可能任务」，等待一次确认 |
| 背景 | 只解释原因、现状或上下文 | 不入任务池；作为候选任务上下文 |
| 想法 | 「可以考虑」「以后想」「感觉能」「有空研究」等可能性表达 | 不入任务池；建议进入对应项目想法或决策讨论 |
| 资料 | 链接、案例、参考对象、截图、课程或待阅读材料，未要求处理 | 不入任务池；建议进入对应素材或资料真源 |
| 项目状态／业务决策 | 已完成、暂停、放弃、优先顺序、范围边界或明确选择 | 不入任务池；建议写项目日志或项目真源；其中另有下一动作时单独拆出任务 |
| 长期规则／偏好 | 会改变以后 AI 行动的要求 | 不入任务池；按记忆或规则协议处理，不由本 Skill 写入 |

### 判断顺序

1. 先问：原文是在描述，还是明确要求推进一件事？
2. 再问：能否写出不靠猜测的「下一步动作」？不能则不是明确任务。
3. 时间词不能单独把内容变成任务；「以后想研究」仍是想法。
4. 动词也不能单独证明是任务；「这个网站先别做」是决策，不是“停止网站”任务。
5. 一句话可以拆成多类。例如「SenseVoice 以后可以接内容系统，明天先整理现有脚本」应拆为一个想法和一个任务。

### 输出合同

有非任务内容时，候选任务前先输出：

```text
不进入任务池：
1. 【想法／资料／背景／项目状态／业务决策／长期规则】
   原文：____
   判断：____
   建议去向：____
   当前动作：不写入 / 待指定位置
```

建议去向必须指向已知真源；不确定时写「待指定位置」，不要自行创建新表、新文档或新目录。用户明确说要保存非任务内容但没指定位置时，只问一次保存目标。

### 快速正反例

- 「以后想研究个人网站怎么提高转化」→ 想法，不是任务。
- 「明天列出个人网站转化的 3 个问题」→ 任务。
- 「这个网站先别做」→ 业务决策，不创建“停止网站”任务。
- 「这是一个参考视频」→ 资料；若同时说「今晚拆解开头」，后半句另建任务。
- 「WorkBuddy 视频优先，PPT 往后排」→ 优先顺序决策；已有任务则更新，不新建重复任务。
- 「把 WorkBuddy 视频封面改一下」→ 任务；缺日期不编日期。
