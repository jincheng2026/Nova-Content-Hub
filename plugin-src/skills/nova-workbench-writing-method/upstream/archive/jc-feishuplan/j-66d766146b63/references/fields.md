## 字段体系

字段分三层：日常可见字段、默认入库字段、按需后台字段。

### 日常可见字段

日常视图默认只显示这些字段。

| 字段 | 存在理由 | 填写规则 |
| --- | --- | --- |
| 事项 | 让用户知道这条任务是什么 | 用一句人话描述，不写成长段背景 |
| 下一步动作 | 把任务从标题变成可执行动作 | 必须是下一步能做的动作；不清楚就标待确认 |
| 计划日期 | 决定哪天进入视野 | 用户明确说今天/明天/某天时填写；只有本周/本月时不要硬编具体日期 |
| 主题 | 替代复杂项目结构，用来按方向归类 | 如内容项目、知识库、客户项目；AI 可推断但要标记 |
| 状态 | 判断任务处于什么阶段 | 确认前是 `待确认`；确认入库后通常是 `未开始` |
| 卡点原因 | 只在卡住时帮助处理阻塞 | 没有卡点就留空，不强行填写 |

### 默认入库最小字段集

确认后默认只写这些字段。真实写入飞书时，还要以实际 schema 为准。

| 字段 | 为什么默认写 |
| --- | --- |
| 事项 | 主任务名 |
| 下一步动作 | 保证可执行 |
| 计划日期 | 支持今天/明天视图 |
| 计划窗口 | 承接本周/本月/近期 |
| 主题 | 支持方向归类 |
| 状态 | 支持看板流转 |
| 来源摘要 | 保留背景 |
| 原文证据 | 防止 AI 乱提取 |
| AI 推断 / 待确认 | 暴露猜测 |

### 按需后台字段

这些字段默认不写，只有在原文明确出现、用户要求、或目标 Base 已有且必要时才写。

| 字段 | 存在理由 | 启用条件 |
| --- | --- | --- |
| 来源类型 | 区分口喷、聊天、会议、文档等 | 长文本、会议、聊天记录 |
| 来源标题 / 对象 | 后续回查知道来源是什么 | 有文档名、会议名、聊天对象 |
| 证据位置 | 长文回查定位 | 有段落、时间戳、页码、发言人 |
| 原文链接 / 附件 | 回看完整材料 | 用户给了链接或附件 |
| 原文存档 ID | 关联来源收件箱 | 已建来源表 |
| 提取置信度 | 优先检查可疑任务 | 长文本或低置信提取 |
| 截止日期 | 记录真正 deadline | 原文明确出现截止、必须、交付前 |
| 交付物 | 明确产出 | 原文有文档、教程、页面、方案、表格等 |
| 关联人 | 协作和沟通 | 原文出现真实人名/组织 |
| 上下文 | 执行补充信息 | 执行必须知道但不适合放标题 |
| 优先级 | 辅助排序 | 原文有明显轻重缓急 |
| 任务类型 | 统计和筛选 | 用户要求分类或 Base 已有该字段 |
| 预估工作量 | 安排时间块 | 用户要求或任务明显可估 |
| 依赖 / 前置条件 | 防止无法启动 | 等资料、等回复、等权限 |
| 关联任务 / 父任务 | 支持合并和拆解 | 多任务之间有关联 |
| 创建方式 | 追踪来源 | 需要区分口喷/AI提取/会议提取 |
| 创建时间 | 滞留和回查 | 自动写入时可由系统填 |
| 复盘记录 | 完成后沉淀经验 | 完成后才填 |
| AI 处理备注 | 记录拆解/推断原因 | 有复杂合并、推断、冲突 |
| 飞书记录 ID | 避免重复创建 | 真实写入后由系统回填 |

### 字段准入规则

新增字段前先问四个问题：

1. 谁会填它：用户、AI、飞书自动化，还是没人填？
2. 谁会看它：用户日常看、AI 后台看、复盘看，还是没人看？
3. 它影响什么动作：执行、查证、复盘、归因、自动化，还是只让表看起来完整？
4. 如果删掉它，会造成什么具体损失？

如果答不出来，字段不进主表；如果只是偶尔有用，进后台隐藏；如果和已有字段重叠，合并。

默认合并策略：

- `所属项目`、`月目标`、`方向` 优先合并为 `主题`
- `重要度`、`紧急度`、`风险级别` 默认不同时存在，先合并为 `优先级`
- `资料链接` 和 `原文链接 / 附件` 合并，除非一个是执行资料、一个是来源证据
- `最终交付物` 简化为 `交付物`

## 推荐 Base 结构

默认主表是 `任务池`。如果用户经常给长文本或口喷，建议增加一个轻量来源表。

### 表 1：任务池

任务池存确认后的任务。日常视图只展示 6 个可见字段，后台字段保留给 AI。

默认视图：

- `今天就看这张`：计划日期为今天，状态不是已完成
- `明天先放这里`：计划日期为明天
- `本周交付`：计划窗口为本周，或截止日期在本周
- `本月推进`：计划窗口为本月，且不适合放进今天
- `卡住了`：状态为卡住，或卡点原因不为空
- `后台｜全部任务`：显示全部字段，给 AI 和复盘用

### 表 2：来源收件箱

来源收件箱只用于保存原始输入，不要求用户每天看。

| 字段 | 存在理由 |
| --- | --- |
| 来源时间 | 找回原始输入 |
| 来源类型 | 区分口喷、聊天、会议、文档等 |
| 原文 / 摘要 | 保留输入上下文 |
| 处理状态 | 未提取、待确认、已入库、部分入库 |
| 关联任务 | 回连已生成任务 |

如果用户暂时不想建第二张表，也可以先只在任务池里保留 `来源摘要`、`原文证据`、`原文链接 / 附件`。
