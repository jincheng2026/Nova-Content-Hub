## 1. 最终用户拿到什么

交付「自媒体工作台」本地应用、与它配对的助手插件、快速开始说明、版本说明及可核对的验收记录。用户已确认同事目标为 Apple 芯片 Mac，明早优先交付并原生验收 `darwin-arm64`。同事安装应用与所选助手的配套插件后，选择自己的第二大脑文件夹，即可读取已有资料、创建和修改内容、启动带正确 Skill 的助手任务并接收结果。日常操作由界面完成，不要求记路径、改 JSON 或自己运行 Node 服务。

首要业务验收路径：打开已有第二大脑 → 找到真实选题与当前工作稿 → 新建/继续一篇内容 → 可选调研和参考拆解 → 同一助手上下文创作和修改 → 采用标题、制作封面 → 结果归入同一内容目录 → 重开仍能继续。新用户另验新建知识库、定位访谈和第一篇内容。

技术栈固定为 Electron、React、TypeScript、真实 Semi UI。旧 Next/Radix 界面和 launchd 双服务架构作为来源研究，适用的业务解析规则逐项重构至新应用。保留 Nova 已有可用能力，不以同事版缺少入口为由缩减它们。

## 2. 本轮范围与冲突处理

- 本轮必须形成可用闭环：开库/建库、知识库资料加载与管理、定位、选题、参考、调研报告、账号研究、雷达、拆解、创作改稿、标题与简介、封面模板、任务、反馈知识、提示词、已有日程与人工发布记录、设置与库维护。
- 同事工作台中的内容页面和既有 Nova 功能逐项建对照，既能读取历史资料，也具备实际需要的新建/导入/修改入口。不是只交一套只读看板。
- 更新后的统一规范为默认基线。用户明确的“打开现有第二大脑直接用”与“一篇内容集中存放”优先于旧库 schema、导出式 Markdown、固定路径、旧归档层级及先迁库才能使用等实现惯例；逐项在实施记录中写明调整原因与替代验证。
- 保留路径边界、用户资料保护、版本冲突、费用授权、任务回执和真实状态这些使用保障。兼容旧库不等于执行其中任意脚本，提速不等于跳过数据写入核验。
- 本轮不新增拍摄、剪辑、录屏口播、发布前预测、自动发布、云同步或新的无人值守监控。已有相关文件可读，已有发布记录和日程继续保全。发布后历史复盘可读、可手工记录，新的自动采数复盘系统不冒充既有能力。
- 私域、运动、X 独立收藏服务、飞书与个人网站属于原版库外集成，单列实际依赖及来源；内容主流程不依赖它们。当前包没有的程序、媒体或账号权限不能靠读取 Vault 补出，也不能显示为正常空数据。
- dbskill 沿用此前范围决定，不纳入本轮。

## 3. 知识库和工作台运行资料的分工

### 3.1 打开已有第二大脑

默认接入用户明确提供的 `/Users/mac/Downloads/第二大脑交接包_2026-10-16/第二大脑/`，开发阶段使用保留路径结构的隔离副本。选择文件夹后识别结构、根身份、入口文档、T 编号、当前稿件、引用与外部依赖，不要求先转成 Nova 原有目录。

已有文件原位保留；导航声明的 HTML/Markdown/JSON 当前来源各自识别。未知文件也可搜索和定位，按能力阅读；旧交互 HTML 的结构化数据通过适配器进入新编辑界面，需要旧服务的部分明确列出，不能因为预览能打开就宣称编辑可保存。

同事包的 10 月 26 日资料与独立第二大脑的 10 月 16 日资料分别识别、比较。相同 T 编号跨库不自动合并，mtime 和包日期不决定权威。库外来源仅在明确配置后挂载，不能按原作者 HOME 广搜并静默并入。

### 3.2 新建知识库

```text
第二大脑/
├── 00_个人背景/
├── 01_对标账号/
├── 02_内容素材/
├── 03_内容规律/
├── 04_选题库/
├── 05_内容草稿/
├── 06_发布复盘/
├── skills/
├── AGENTS.md
├── CLAUDE.md
├── README.md
├── SOURCE_OF_TRUTH.md
└── .workbench/
```

- 初始化目录说明、选题模板、选题/草稿总览、稳定编号及来源规则；允许用户自己的内容分类，不能硬编码同事的全部栏目。
- `AGENTS.md` 管目录职责、真实信息、公开边界、编号、稿件权威、修改保护、Skill 路由与结果登记。
- `SOURCE_OF_TRUTH.md` 管当前入口、内容身份、来源、路径、阶段、版本和引用关系；`README.md` 提供人工导航，`CLAUDE.md` 指向同一规则。
- `skills/` 留给知识库自己的扩展与规则，登记配套插件方法入口及版本。所有正式交付业务 Skills 从插件安装，不要求用户再复制第二套方法到库内，不让两份同名 Skill 独立漂移。
- 已有 AGENTS/SOURCE_OF_TRUTH/README 保留人工内容，仅按明确管理区块更新工作台导航；规则冲突展示差异，不整体替换原文件。
- 初始化不放同事私人经历、成绩、账号、密钥或绝对路径；重复执行不覆盖用户新增、修改或删除的资料。

### 3.3 一条内容锁定一个目录

新内容分配稳定 UUID 和 T 编号，默认创建 `05_内容草稿/Txxx_题名/`。显示名变化不改变身份；目录改名或移动通过受控操作修复引用。已发布状态本身不强制移动新内容目录。

```text
05_内容草稿/Txxx_题名/
├── 内容说明.md
├── 调研/
├── 参考资料/
├── 参考拆解.md
├── 素材包.md
├── 叙事.md
├── 工作稿.md
├── 标题与简介.md
├── 封面/
├── 反馈与版本/
└── 发布记录与复盘/
```

按实际产出建立文件，不提前铺满空文档。该篇的调研、拆解、草稿、候选、已采用稿、包装、封面、反馈与版本均可从这个目录找到。内容候选经提交回执校验后自动归档，用户采用单独记录；原始共享素材保留一份，内容目录用可追溯引用连接，不复制成多份独立事实。

`04_选题库` 保存选题卡及指向内容目录的入口；`06_发布复盘` 聚合发布与复盘入口，不再生成另一份可独立编辑的当前稿。旧库草稿、已做及库外正式视频档案保持原位，按原有真源读取；不因新目录规则批量搬历史文件。

独立研究先保存为 `02_内容素材/调研报告/R_<ID>/`；从某篇内容发起的研究直接保存到该篇的 `调研/`。复用独立报告时建立关联，不按标题猜测归属，也不要求下载后再上传。

### 3.4 运行资料

`.workbench/` 维护库描述、稳定 ID 映射、索引、任务请求与回执、事务恢复和库级资源。应用内置资源随应用；用户自建模板、提示词、照片等库级资源随库保存。机器设置、助手连接偏好和密钥分别由应用数据目录及系统安全存储管理。

正文和用户规则以真实知识文件为准；索引和运行投影可重建。历史不可变快照可以保留，不能再生出第二份各自可修改的“当前稿”。

## 4. 功能交付清单

每项都核对入口、真实输入、保存落点、可继续动作、取消/失败恢复和重新打开后的状态。

1. **开库与建库**：选择已有目录、新建空白库、最近使用、切库、重新扫描、库状态及缺失来源提示。打开已有库不强制定位或先配置云端 Key。
2. **个人定位**：查看/编辑已有定位，使用 `xindao-interview` 新访谈、续访、局部调整；个人、账号、内容、主页包装逐关确认和保存，保留待确认。后续任务实际读取相应定位版本及公开边界。
3. **选题与灵感**：一句话新建、导入已有稿、分类、搜索、编辑、回收/恢复、来源和 T 编号；允许直接创作、已有参考起步、已有稿件继续修改。
4. **对标账号**：新建、链接与资料录入、编辑、导入、查看已有档案、发起账号研究、关联报告和参考；区分自己的账号定位与对标账号。
5. **素材与参考**：链接/文本/本地文件进入同一导入区，保留原文、媒体、字幕和来源；去重、转写、纠错、使用状态、采用理由与关联内容可查。
6. **调研报告**：保留并补齐“新建调研”“手工新建报告”“导入报告”、编辑、阅读、关联账号/选题、采用参考与回收；支持助手和手工两条路径。Markdown 原位报告与已有 HTML 都有真实读取落点。
7. **爆款雷达**：保留现有平台、方向、阈值、时间窗口、预算、来源证据、资格判断、收录/排除、加入选题和继续创作。已存在资料可复用；无服务时可读已有结果与录入可核实材料。
8. **内容创作**：一个对象内聚合目标、选中参考、拆解、叙事、当前稿、建议、批注和任务。默认一个“开始/继续创作”主入口；分阶段动作在高级区域。改稿先给候选/差异，明确采用才改当前稿，保存不清除后续输入。
9. **标题与封面**：独立标题、封面文字、简介可查看/修改/采用；保留模板查看、学习、还原、自建/导入、人物照片、封面生成、选用、批注、下载与完整图片预览。
10. **任务与继续**：查看任务、进度、关联内容、两类等待、继续、取消、重试、切换助手、结果及回执。外部打开失败保留同一任务，不能又创建一笔。
11. **知识与提示词**：读取既有规律与知识，保存明确反馈、采纳/否决及原因；提供实际需要的新建、编辑、搜索、分类、收藏/复制、回收/恢复。全局规则变更仍由用户确认，不让单次反馈自动改 AGENTS。
12. **发布与日程**：保留人工计划、日历、文案复制、封面下载、打开平台、人工发布记录、历史快照和已有复盘读取；导出不等于已发布。新增人工复盘记录归本篇目录并可从 06 定位。
13. **设置与维护**：资料、库级默认、助手与插件安装、外部服务、模板资源、诊断、完整知识库备份/恢复、升级、导出及帮助。备份不能只覆盖隐藏运行库却显示“整库已备份”。

## 5. 插件与全部业务 Skills 的交付

### 5.1 用户只安装配套插件

应用设置展示当前助手、插件状态及匹配版本，提供对应安装入口与安装后重新检测。正式流程需要的执行 Skill、业务 Skill、references、脚本及必要资源全部纳入同一发行插件；Codex 与 WorkBuddy 各有正确 manifest 和安装引导。

构建同时更新 Skill registry、角色分类、依赖、完整性哈希、manifest、发行配对和运行检测。只有文件在目录里不算已接入；安装成功也需真实任务验证。

### 5.2 方法路由

- 定位：采用本次 `xindao-interview` 作为新版默认；旧 `shengcai-positioning-interview` 保留兼容来源/路由，避免两个同类访谈同时触发。
- 研究：`jc-media-research`、账号/赛道研究与现有雷达方法。
- 入库与规律：`jc-benchmark-intake`、`jc-pattern-extractor`、`jc-topic-generator`。
- 转写与拆解：现有受控转写适配、`jc-video-analysis` 及参考拆解方法；缺少原件的专用方法由明确命名的 Nova 适配能力承接，按相同输入输出验收，不冒充取得原件。
- 写稿与共创：`jc-content-writer`、`jc-jiaocheng-video`、`jc-gongzuotai-write` 及已有整篇创作方法；保留用户显式触发的专项限制，避免后台擅自套用私人教程流程。
- 包装与封面：`jc-cover-copy`、现有包装方法、模板执行与封面执行 Skills。
- 反馈与记录：现有反馈知识方法、`jc-media-review` 和发布收口的适用记录规则；停止使用的 B-roll 等方法只保留历史来源，不自动变成活跃工作流。

原始业务 Skill 中私人路径、直接改正文、外部调用和旧运行依赖改接冻结上下文与共享文件接口。执行 Skill 管接单/进度/等待/提交，业务 Skill 管方法与候选；用户不用自己选择十几个 Skill。

### 5.3 统一任务链

业务动作 → 检测插件及方法版本 → 冻结库身份、对象、当前文件版本、授权范围、目标目录和业务方法 → 打开所选助手并带执行/业务 Skill → claim → progress/两种等待 → submit → 核对回执与文件候选 → 按字段合同确认/采用 → 原位保存与刷新。

阶段确认支持受控检查点保存，例如定位确认一关就落盘，不等整场结束；正式稿件采用、任务提交和阶段确认分别记录。两种等待、失败、取消、重试、终态、继续与切助手对每个正式助手分别验证。没有可靠原会话标识时提供正确恢复方式，不猜会话，不自动批准。

`xindao-interview` 附件 README 的“无论先做什么都强制完成定位”仅为来源建议，本产品不采用。已有定位含 `_v0.1` 等历史命名时先识别原件，不能只因不存在无后缀新文件就重启访谈；中途可暂停，旧用户可以直接工作。

## 6. 实施架构与关键接口

采用“原位 Vault 适配层＋现有 schema 5 运行内核”，保留旧 Nova 库读取分支。共享适配实现放 `plugin-src/src/lib/`，Electron 与配套 CLI 复用，避免界面和助手各写一套目录规则。

旧精确 `LibraryBinding` 继续描述运行库，新增独立 `VaultBinding` 描述用户选择的知识库根及身份、版本和映射；固定任务中携带版本化 Vault 上下文。不能简单在旧 binding 塞字段或取消 createLibrary 空目录校验。

用户已在 Codex 项目中打开第二大脑。新助手任务的项目目录/启动 cwd 使用显式绑定的 Vault 根，使本库 AGENTS 与 SOURCE_OF_TRUTH 能被正确定位；运行库绑定单独传递，不让助手把隐藏运行根误当知识库。应用仍从用户选择的根建立绑定，不能仅根据宿主当前显示的项目名猜测内容库，也不改变其他聊天的工作目录。

适配层至少承担：识别、打开/初始化、列举、读取、创建/修改、回收/恢复、重扫、任务上下文冻结与结果应用。所有可写目标来自主进程建立的对象映射；renderer 传业务 ID 与有限字段，不获得任意文件写入能力。

每次保存核对原文件基线，先准备带 mutationId 的变更计划与候选，再校验受影响目标、逐文件原子替换并留回执，最后更新运行投影和导航。跨文件操作为可恢复事务，恢复未完成前不能把半更新显示成成功。已有 HTML 内嵌状态用专门适配器修改受管理数据，不能全文正则替换未知内容。

重点接线范围：

- `plugin-src/src/lib/file-library/`：原库桥接、生产上下文、任务归档、备份/健康检查与映射；新增独立 Vault 模块承载文件职责。
- `plugin-src/src/bridge/production-handoff.mjs` 及生产 CLI：冻结上下文、Skill 路由、文件版本、提交与回执。
- `plugin-src/scripts/build.mjs`、插件 manifests、`plugin-src/skills/`：区分 executor/business-method，完整性清单覆盖依赖。
- `workbench/src/main/`：绑定、controller/worker、文件监控、归档读取校验、插件检测和启动。
- `workbench/src/shared/`、`preload/`：有限 API 的类型、严格校验和版本。
- `workbench/src/renderer/`：开库/建库、各模块新建与导入、内容工作区、任务、知识及设置；复用公共 Semi 组件。

归档输出与主进程目录验证同时修改；备份覆盖完整 Vault；watch 同时识别原位文件与内部任务变化；健康检查核对用户文件、映射、引用和任务，不能只检查运行库。
