# JC Chendian

## 目标

把当前会话确认过的文字和资产追加到一个待发布内容包，供使用者查看和后续发布收口。同一条内容无论调用多少次，都只保留一个文件夹。

这不是发布收口，也不是全盘聊天归档。

## 硬边界

- 只读取当前会话中已经明确确认、选定或定稿的内容。
- 不扫描其他会话，不回溯整个项目，不从相似文件猜结论。
- 不把草稿、备选项、模型建议或未确认版本当成正式结果。
- 不推测视频已发布，不访问抖音、小红书、视频号，不启动监控。
- 不移动、不删除源文件；二进制资产只做 APFS 克隆或普通复制。
- 不按每次调用新建文件夹；先检查现有待发布内容包。
- 不对相似选题做低置信度自动合并；有歧义只问一次。
- 不静默覆盖已有不同定稿或人工修改过的 `内容.md`。
- 多个候选无法区分时，把全部歧义合并成一次询问。
- 用户要沉淀的是协作规则、AI 行为偏好、方法论、项目制度或复盘教训时，不运行本 Skill；改写能约束后续行动的最近 `AGENTS.md`、对应 `SKILL.md` 或项目真源。

## 一次调用流程

### 0. 首次配置

首次使用或换电脑时先读取 [`references/setup.md`](references/setup.md)。默认把当前工作目录当成内容项目根目录；用户有指定项目时，通过 `JC_CONTENT_ROOT` 或脚本参数显式指定，不猜他人的目录。

### 1. 先找现有内容包

每次先运行：

```bash
python3 <skill目录>/scripts/capture_decision.py --list-pending
```

判断当前内容是否属于已有 `content_id`：

- 同一条视频的标题、简介、封面文字、横竖封面，必须使用同一 `content_id`；
- 当前会话、选题、定稿内容能唯一对应时直接追加；
- 只有相似但不能确定时，把全部候选合并成一次确认；
- 明确是新内容时传 `--new-content`，创建一个新包；
- 已有待发布内容包时，如果既不传 `--content-id` 也不传 `--new-content`，脚本必须拒绝
  写入，防止同一内容被静默拆开。

### 2. 识别本次已确认结果

只收集当前会话里已经确认的项目：

- `title`：正式标题；
- `description`：正式简介；
- `cover_copy`：正式封面文字；
- `script`：完整逐字稿；
- `decision`：明确业务决定；
- 二进制资产：正式封面、图片或当前会话产生的其他已确认文件。

没有明确确认的项目不沉淀。当前会话没有任何已确认结果时，直接说明，不创建空回执。

### 3. 运行确定性脚本

先解析本 `SKILL.md` 的真实路径，再调用同目录下的
`scripts/capture_decision.py`，不要依赖当前工作目录。

```bash
python3 <skill目录>/scripts/capture_decision.py \
  --topic "AI 剪辑 Skill 正式开源" \
  --content-id "<属于现有内容时必填>" \
  --field "title=正式标题" \
  --field "cover_copy=正式封面文字" \
  --asset "cover_horizontal=/绝对路径/横屏封面.png" \
  --asset "cover_vertical=/绝对路径/竖屏封面.png" \
  --source-thread "<能取得时填写当前任务 ID>"
```

可重复使用 `--field` 和 `--asset`。值含换行时直接作为单个参数传入，不先改写内容。
明确为新内容时，用 `--new-content` 替代 `--content-id`，两者不得同时使用。

已有字段出现不同定稿时，脚本默认拒绝覆盖。只有用户明确说「用新版替换旧版」时才传
`--replace-field title`；资产同理使用 `--replace-asset cover`。横竖封面、平台封面优先
使用不同角色，不互相覆盖。

人直接查看这里：

```text
<内容项目根目录>/内容数据统计/待发布沉淀/
└── YYYY-MM-DD-选题/
    ├── 内容.md
    ├── 封面-横屏.png
    ├── 封面-竖屏.png
    └── .system/
        ├── manifest.json
        └── receipts/
```

`内容.md` 集中展示本次已确认的标题、简介、封面文字、逐字稿和决定；正式资产使用
`封面.png` 等可读文件名放在旁边。

每个新包还会生成稳定 `archive_key`：

```text
YYYY-MM-DD-选题__content_id后6位
```

它是 AI 和程序的跨目录识别名，会写入 `内容.md`、manifest 和事件回执。
以后由 AI 保存的成片、源片、字幕和封面应保留这个识别名作为文件名前缀；
用户手工从剪映导出的旧文件不要求手工重命名，发布后收口程序仍必须通过
`content_id + 平台时长 + 发布日期 + 同目录证据` 找回。

程序仍在 `内容数据统计/.runtime/chendian-inbox/` 保存事件回执和稳定资产，但那只是
技术底座，不要求用户管理。`content_id` 标识一条内容，`event_id` 标识一次定稿沉淀；
完全重复调用不新增事件。

### 4. 报告

成功时只给一行：

```text
已沉淀：7 月 27 日「AI 剪辑 Skill 正式开源」正式封面，等待发布后收口。
```

如果追加到已有内容包，明确说「已追加」；新建时说「已沉淀」。不逐项展开技术路径。

## 与发布收口的关系

`jc-chendian` 只保存「当前会话已确认的结果」。如果使用者另外安装了发布收口 Skill，它可在人工发布后读取本内容包；本公开包不假设该 Skill 必然存在。发布后的真实平台版本始终以创作者中心事实为准。
